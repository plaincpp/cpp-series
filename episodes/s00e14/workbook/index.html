A

Part A: Concept checks

12 questions

Q1

L1 · Recall Short answer heap

What is the heap (the free store)? Give two differences between a local variable and an object that new makes.

Show answerHide answer to Q1

The heap (the free store) is memory that the program gets at run time with new. Differences:

  1. Lifetime: a local variable ends at the end of its block. A heap object stays alive until a delete (ex03).
  2. Clean-up: C++ destroys a local variable for you. You must delete a heap object, or it leaks (ex15).
  3. Size: the size of a heap array can come from run-time input (ex08).

Q2

L1 · Recall Short answer new-expression

Ticket* t = new Ticket{7}; does two steps. Name them in order. Then name the two steps of delete t; in order.

Show answerHide answer to Q2

new Ticket{7}: 1. operator new allocates memory for one Ticket. 2. The constructor Ticket(int) runs. delete t;: 1. The destructor ~Ticket() runs. 2. operator delete frees the memory. delete does the steps in the reverse order (ex02, ex34).

Q3

L1 · Recall Multiple choice delete-expression

int* score = new int{90}; makes one int. Which line frees it correctly?

  • a) delete[] score;
  • b) delete score;
  • c) score = nullptr;
Show answerHide answer to Q3

b) delete score;. Memory from new needs delete. Option a) is undefined behavior: GCC and Clang warn with -Wmismatched-new-delete, and AddressSanitizer reports alloc-dealloc-mismatch (operator new vs operator delete []) (ex11). Option c) does not free the memory, so the int leaks.

Q4

L1 · Recall Short answer memory-leak

What is a memory leak? Is a leak undefined behavior? Which tool finds a leak?

Show answerHide answer to Q4

A leak is a heap object that the program cannot reach and never deletes. A leak is not undefined behavior: the program runs, but it uses more memory. LeakSanitizer finds leaks (ex15).

Q5

L1 · Recall Short answer double-delete

Define a double delete and a use after delete. What does the standard say about the two bugs?

Show answerHide answer to Q5

A double delete is a second delete of an object that the program deleted before. A use after delete is a read or a write through a pointer after the delete of its object. The standard makes both undefined behavior (cppreference: delete expression, lifetime). AddressSanitizer reports attempting double-free (ex19) and heap-use-after-free (ex20).

Q6

L1 · Recall Short answer unique-ptr-preview

Which header declares std::unique_ptr? Which C++ standard added std::unique_ptr, and which standard added std::make_unique?

Show answerHide answer to Q6

<memory>. C++11 added std::unique_ptr, and C++14 added std::make_unique (cppreference: unique_ptr, make_unique).

Q9

L2 · Apply Multiple choice delete-expression

Buffer has a member int* data_. It holds the result of new int[n]{}, or nullptr when n is 0. The destructor is ~Buffer() { delete[] data_; }. Is this destructor correct when data_ holds nullptr?

  • a) No. delete[] on a null pointer is undefined behavior.
  • b) No. delete[] on a null pointer throws an exception.
  • c) Yes. delete[] on a null pointer does nothing.
Show answerHide answer to Q9

c) Yes. delete[] on a null pointer does nothing, the same as delete (ex12; cppreference: delete expression). So the destructor needs no if (data_ != nullptr) check. Options a) and b) are common myths.

Q10

L2 · Apply Short answer memory-leak

Which GCC and Clang flag turns on LeakSanitizer on Linux? Name three facts that a LeakSanitizer report gives about each leak.

Show answerHide answer to Q10

-fsanitize=address. On Linux, AddressSanitizer includes LeakSanitizer. Add -g to get file names and line numbers. For each leak, the report gives:

  1. The size in bytes.
  2. The number of objects.
  3. The call stack of the new that made the memory, with the file and the line.

Example from ex15: Direct leak of 16 byte(s) in 1 object(s).

Q11

L2 · Apply Multiple choice double-delete

You build ex19 (a double delete) with -Wall -Wextra and no optimization. What do GCC 14 and Clang 19 do?

  • a) They report an error, because the code deletes one object two times.
  • b) They give a warning -Wdouble-free.
  • c) They give no warning. A run-time tool such as AddressSanitizer finds the bug.
Show answerHide answer to Q11

c) They give no warning. A run-time tool such as AddressSanitizer finds the bug. GCC 14 and Clang 19 give no warning for ex19 at -O0. AddressSanitizer reports attempting double-free, with the lines of the two delete expressions and the new. A double delete is a run-time bug, so the program compiles.

Without a sanitizer, the C library of this toolchain (glibc) also stops ex19 with free(): double free detected in tcache 2. But glibc does not find each double delete, and it gives no line numbers. Valgrind also finds it.

Q12

L2 · Apply Short answer unique-ptr-preview

A std::unique_ptr is a local variable of a function. When does it delete its object? Name three paths out of the function.

Show answerHide answer to Q12

It deletes its object at the end of its scope, when the destructor of the std::unique_ptr runs. This occurs on each path out of the function:

  1. The normal end of the function.
  2. An early return (ex24).
  3. An exception that leaves the function (ex25).

D

Part D: Explain why

9 questions

Q34

L2 · Apply Explain why heap

In ex03, open_ticket returns, but main can still use the Ticket. A local Ticket in open_ticket ends at the return. Explain the difference.

Show answerHide answer to Q34

Rule: a local variable has automatic storage, and an object from new has dynamic storage. C++ destroys a local Ticket at the end of its block. The object from new stays alive until a delete. At the return, only the local pointer ends: the function returns a copy of the address. So main can use the object, and main must delete it (ex03).

Q35

L3 · Analyze Explain why new-expression

In ex33, the constructor of Sensor throws, and LeakSanitizer reports no leak. Who frees the memory, and why can only new do it?

Show answerHide answer to Q35

new frees the memory itself. When the constructor throws, new calls the matching operator delete, and then the exception continues (cppreference: new expression). Only new can do it: the caller never gets the address, so no pointer exists that it can delete (ex33, ex34).

Q36

L4 · Senior Explain why delete-expression

Why must memory from new[] go back with delete[], and memory from new with delete? Use ex09 in your answer.

Show answerHide answer to Q36

Rule: delete[] must destroy each element, and delete destroys one object. In ex09, delete[] calls three destructors in reverse order: end 3, end 2, end 1. To know the count, new[] usually keeps it in hidden memory before the elements (Itanium C++ ABI, array cookies). The two forms also call different functions, operator delete and operator delete[]. A mismatch is undefined behavior (ex10, ex11).

Q37

L2 · Apply Explain why memory-leak

A leak is not undefined behavior, and the operating system takes back the memory when the process ends. Why is a leak still a bug?

Show answerHide answer to Q37

A leak keeps memory that the program can never use again. In a program that runs for a long time, such as a server, memory use grows with each leak. In a loop, it grows with each pass: ex18 loses 400 bytes in 100 passes. Also, the destructor of a leaked object never runs, so a file or a connection that it holds stays open.

Q38

L3 · Analyze Explain why memory-leak

ex17 leaks when check throws, but ex25 does not leak. The two functions do the same work. Explain why.

Show answerHide answer to Q38

Rule: when an exception leaves a function, C++ destroys the local objects of the function (stack unwinding). In ex17, the exception from check skips the line delete[] buffer;, and a raw pointer has no destructor. In ex25, a local std::unique_ptr owns the buffer. Its destructor runs during stack unwinding, and it frees the buffer.

Q39

L3 · Analyze Explain why double-delete

score = nullptr; after delete score; makes a second delete score; safe. Why does it not make ex22 safe?

Show answerHide answer to Q39

score = nullptr; changes only the variable score. backup is a copy of the address, and it keeps the old address. So *backup is still a use after delete (ex22). A null value protects only the pointer that gets it, not its copies.

Q40

L3 · Analyze Explain why double-delete

Without sanitizers, a use after delete often writes the old value. Why can this occur, and why must you never trust that output?

Show answerHide answer to Q40

delete gives the memory back to the allocator, but often nothing writes new data in it at once. So a read can find the old value. The read is undefined behavior: the allocator can reuse the memory, and the optimizer can change the code. A different compiler, flag or input can give a different value or a crash. Use AddressSanitizer, which reports heap-use-after-free (ex20).

Q41

L2 · Apply Explain why unique-ptr-preview

Why does auto second = first; not compile when first is a std::unique_ptr<int> (ex26)? Why does auto second = std::move(first); compile?

Show answerHide answer to Q41

Rule: a std::unique_ptr must be the only owner. A copy makes two owners, and both delete the object: a double delete. So the class marks its copy constructor with = delete, and the compiler rejects the copy (ex26). std::move(first) selects the move constructor. It gives the pointer to second and sets first to null, so one owner remains (ex27).

Q42

L4 · Senior Explain why unique-ptr-preview

People say that std::unique_ptr has zero cost. Explain this claim with ex29. Which costs does it not remove?

Show answerHide answer to Q42

With the default deleter, std::unique_ptr<int> holds only the raw pointer: sizeof gives 8, the same as int* (ex29). Its destructor does one delete, the same work as correct manual code. Costs that it does not remove:

  1. The allocation and the free in the allocator, which take time.
  2. The access through a pointer, which can be slow when the object is not in the cache.
  3. A deleter with data makes the std::unique_ptr larger.
  4. On the Itanium C++ ABI, a function gets a std::unique_ptr parameter in memory, not in a register, because it has a destructor.

Part F: Design and trade-offs

5 questions

Q49

L4 · Senior Design heap

A function uses a table of 1000 int values for its work only. Compare three designs: a local std::array<int, 1000>, new std::array<int, 1000>{} with delete, and std::make_unique<std::array<int, 1000>>(). When does each design fit? Give a recommendation.

Show answerHide answer to Q49

Structure of a strong answer:

  1. Local std::array: no heap, no delete, and C++ destroys it at the end of the function. 4000 bytes on the stack is not a problem, but the stack has a fixed limit.
  2. new with delete: the same heap cost as std::make_unique, and a leak on each path that skips delete (ex15, ex17).
  3. std::make_unique: use the heap with no leak risk. Use it when the object is too large for the stack, or when it must outlive the function.

Recommendation: the local std::array. Use std::make_unique only for a very large table. Do not use the raw new.

Q50

L4 · Senior Design new-expression

A program reads a count n at run time and needs n scores. Compare new int[n]{}, std::make_unique<int[]>(n) and std::vector<int>(n). Talk about the size, the clean-up, growth and copies. Give a recommendation.

Show answerHide answer to Q50

Structure of a strong answer:

  1. new int[n]{}: you must keep n, and you must write delete[] on each path. It cannot grow. A copy of the pointer does not copy the elements.
  2. std::make_unique<int[]>(n): it frees the array on each path. You still keep n. It cannot grow. You can move it, but you cannot copy it.
  3. std::vector<int>(n): it keeps the size and frees the elements on each path (ex32). It grows with push_back, and a copy copies the elements.

Recommendation: std::vector<int>. It has the same heap cost and removes the work of the other two designs.

Q51

L4 · Senior Design memory-leak

A team finds leaks in a server that runs for weeks. Compare three plans:

  1. A review rule: "each new has a delete".
  2. LeakSanitizer in the test builds.
  3. A rule: "no new and no delete in new code".

Which plan or mix do you recommend? Why?

Show answerHide answer to Q51

Structure of a strong answer:

  1. Review rule: cheap, but people miss paths, such as an exception from a called function (ex17).
  2. LeakSanitizer in test builds: it finds real leaks, with the line of the new. It finds only leaks on the paths that the tests run. AddressSanitizer makes the tests slower (Clang documentation: about 2x).
  3. "No new and no delete": std::unique_ptr, std::make_unique and containers prevent most leaks by design (ex24, ex25).

Recommendation: a mix. Use the rule for new code, and LeakSanitizer in the test builds to find the leaks in old code. A review is the last check.

Q52

L4 · Senior Design double-delete

Two parts of a program use one heap object: a Scheduler and a Logger. Each part has a raw pointer to it. Who must delete the object? Compare three designs:

  1. One owner with a std::unique_ptr, and raw pointers for the other part.
  2. A copy of the object for each part.
  3. Shared ownership.

Give a recommendation.

Show answerHide answer to Q52

The question "who deletes it?" needs one clear answer. Structure of a strong answer:

  1. One owner with a std::unique_ptr, and raw pointers or references for the other part: clear and cheap. The owner must live longer than the other part, or the raw pointer dangles.
  2. A copy for each part: no shared object, so no double delete. A change in one copy does not change the other copy, and the copy costs time and memory.
  3. Shared ownership (std::shared_ptr, Season 1, S01E24): the object lives while one part uses it. It costs a counter and makes the end of the object less clear.

Recommendation: one owner that lives longer than the Scheduler and the Logger. Use shared ownership only when no part can be the owner.

Q53

L4 · Senior Design unique-ptr-preview

Compare three parameter types for a function that uses a Ticket: const Ticket&, Ticket* and std::unique_ptr<Ticket> by value. What does each type tell the caller about ownership? When do you use each type?

Show answerHide answer to Q53

Structure of a strong answer:

  1. const Ticket&: the function only reads the Ticket. It does not own it, and the Ticket cannot be null. Use it as the default.
  2. Ticket*: the function does not own the Ticket, and the pointer can be null. Use it when "no ticket" is a correct value (C++ Core Guidelines, rule R.3).
  3. std::unique_ptr<Ticket> by value: the function takes the ownership. The caller must write std::move. Use it when the function keeps the Ticket, for example in a container (C++ Core Guidelines, rule R.32).
G

Part G: Interview questions

8 questions

Q54

L3 · Analyze Interview heap

What is the difference between the stack and the heap in C++? When do you use each one?

Show answerHide answer to Q54

Structure of a strong answer:

  1. Main fact: the stack holds local variables. C++ destroys them at the end of their scope. The heap holds objects from new, which live until delete.
  2. Example: in ex06, the pointer has 8 bytes on the stack, and the object has 4000 bytes on the heap.
  3. Limit: the stack is fast but has a fixed size, and the compiler must know the size of each local variable. The heap is slower and needs an owner. Use the stack by default.
  4. Follow-up: "Where are the elements of a local std::vector?" On the heap. The std::vector object is on the stack, and its destructor frees the elements.

Q55

L3 · Analyze Interview new-expression

What happens, step by step, when you write new T{args}? What happens when the constructor throws? What happens when no memory is available?

Show answerHide answer to Q55

Structure of a strong answer:

  1. Main fact: new calls operator new(sizeof(T)), then runs the constructor on that memory, then gives a T* (ex34).
  2. Constructor throws: new calls operator delete on the memory, and the exception continues. No destructor runs (ex33).
  3. No memory: operator new throws std::bad_alloc. The form new (std::nothrow) T returns nullptr (cppreference: new expression).
  4. Follow-up: "Can a class change how it allocates?" Yes. A class can declare its own operator new and operator delete, as in ex34.

Q56

L3 · Analyze Interview delete-expression

What is the difference between delete and delete[]? What happens when you mix them?

Show answerHide answer to Q56

Structure of a strong answer:

  1. Main fact: delete destroys one object and calls operator delete. delete[] destroys each element in reverse order and calls operator delete[] (ex09).
  2. Mix: undefined behavior. GCC and Clang warn with -Wmismatched-new-delete when they see both lines. AddressSanitizer reports alloc-dealloc-mismatch (ex10, ex11).
  3. Limit: a pointer to one object and a pointer to the first element have the same type. So the compiler cannot always find the mismatch.
  4. Follow-up: "How do you prevent it?" Use std::vector, or std::make_unique<T[]>, which uses delete[] (ex28).

Q57

L4 · Senior Interview memory-leak

How do you find a memory leak in a C++ program? How do you prevent leaks in new code?

Show answerHide answer to Q57

Structure of a strong answer:

  1. Find: build the tests with -fsanitize=address -g. LeakSanitizer gives the size, the count and the line of the new (ex15, ex18). Valgrind and heap profilers are other tools.
  2. Prevent: no owning raw new in new code. Use std::make_unique, containers and values, so a destructor frees the memory on each path.
  3. Limit: LeakSanitizer finds only leaks on the paths that run. A cache that grows with no limit is not a leak for the tool, because the program can still reach the memory.
  4. Follow-up: "What is an indirect leak?" Memory that only another leaked block can reach (LeakSanitizer documentation).

Q58

L4 · Senior Interview double-delete

What is a dangling pointer? Give three ways to get one, and tell how you find and prevent each.

Show answerHide answer to Q58

Main fact: a dangling pointer points to an object whose lifetime has ended. A read or a delete through it is undefined behavior. Structure of a strong answer:

  1. A pointer after delete (ex20, ex22). Find: AddressSanitizer, heap-use-after-free. Prevent: one owner with std::unique_ptr.
  2. A pointer to a local variable after its scope ends (S00E13). Find: GCC -Wreturn-local-addr, Clang -Wreturn-stack-address, and AddressSanitizer (stack-use-after-return). GCC can change a direct return &local; to a null pointer, so its report can be different (S00E13). Prevent: return by value.
  3. A raw pointer from get() after the owner ends (ex31). Find: AddressSanitizer. Prevent: return the owner, not get().

Follow-up: "Does p = nullptr after delete solve it?" Only for p, not for its copies (ex22).

Q59

L3 · Analyze Interview unique-ptr-preview

Why do you write std::make_unique<T>(args) and not std::unique_ptr<T>(new T(args))?

Show answerHide answer to Q59

Structure of a strong answer:

  1. Main fact: with std::make_unique, the code has no new. The owner gets the object in the same expression, so no raw owning pointer exists.
  2. Example: auto t = std::make_unique<Ticket>(7); writes the type one time.
  3. History: before C++17, f(std::unique_ptr<T>(new T), g()) could leak when g() threw. C++17 changed the evaluation order rules (cppreference: make_unique, order of evaluation).
  4. Limit: std::make_unique cannot use a custom deleter. For a private constructor, a factory must use new.
  5. Follow-up: "Is std::make_shared the same?" Partly. It also avoids a raw new. It also puts the object and the counter in one allocation, where std::shared_ptr<T>(new T) needs two allocations (Season 1, S01E24; cppreference: make_shared).

Q60

L4 · Senior Interview unique-ptr-preview

How does std::unique_ptr make a function safe for early returns and exceptions? What is the name of this technique?

Show answerHide answer to Q60

Structure of a strong answer:

  1. Main fact: the std::unique_ptr is a local object. C++ runs its destructor on each exit from the scope: the end, a return or an exception. The destructor deletes the object (ex24, ex25).
  2. Name: RAII, "Resource Acquisition Is Initialization". An object owns a resource, and its lifetime controls the lifetime of the resource.
  3. Limit: when no handler catches an exception, the program calls std::terminate. Then the stack unwinding is implementation-defined (cppreference: exceptions).
  4. Follow-up: "Can a destructor throw?" It must not. Destructors are noexcept by default.

Q61

L4 · Senior Interview heap

Must you ever write new and delete in modern C++? Give the rule and the exceptions.

Show answerHide answer to Q61

Structure of a strong answer:

  1. Rule: do not write an owning new or delete in application code (C++ Core Guidelines, rule R.11). Use values, containers, std::make_unique and std::make_shared.
  2. Exceptions: you write a container, a smart pointer or an allocator. A library takes ownership of a raw pointer. A class has a private constructor, so a factory writes std::unique_ptr<T>(new T).
  3. Limit: a raw pointer that does not own is still correct, for example a parameter that can be null.
  4. Follow-up: "Is a new in a std::unique_ptr constructor correct?" Yes, but only when std::make_unique cannot work, for example with a custom deleter.
