A

Part A: Concept checks

12 questions

Q1

L1 · Recall Short answer iterator

What is an iterator? Which operator gives the element at the position of an iterator, and which operator moves it to the next position?

Show answerHide answer to Q1

An iterator is an object that marks a position in a container. The operator * gives the element at that position, for a read or a write. The operator ++ moves the iterator to the next position (ex01). For a map element, it->first gives the key and it->second gives the value (ex05).

Q2

L1 · Recall Short answer begin-end

v is a std::vector<int>. To which positions do v.begin() and v.end() point? Why must the code not read through v.end()?

Show answerHide answer to Q2

v.begin() points to the first element. v.end() points to the position after the last element. That position is not an element, so a read through v.end() is undefined behavior. In ex10, ASan reports heap-buffer-overflow. When the vector has free capacity, ASan can miss the read, but the behavior is still undefined. Use v.back() to read the last element.

Q3

L1 · Recall Short answer half-open-range

What does the notation [first, last) mean? How many elements does the range have, and when is the range empty?

Show answerHide answer to Q3

[first, last) is a half-open range: it includes the element at first and stops before last. The range has last - first elements, or std::distance(first, last) for map and list iterators too (ex08). The range is empty when first == last (ex09).

Q4

L2 · Apply Multiple choice iterator

Which container gives random-access iterators, so that it + 3 and last - first compile?

  • a) std::list<int>
  • b) std::map<int, int>
  • c) std::vector<int>
Show answerHide answer to Q4

c) std::vector<int>. A vector iterator is random access, so it can jump, subtract and compare with < (ex04). Map and list iterators are bidirectional: they move only with ++ and --, so it + 3 does not compile (ex06, ex17).

Q5

L1 · Recall Short answer std-sort

What does std::sort(first, last) do? Which operator compares the elements by default? How do you sort in descending order?

Show answerHide answer to Q5

std::sort(first, last) puts the elements of the range in order from the smallest to the largest. By default, it compares the elements with operator<. To put the largest first, give a third argument: std::greater<>{} (ex13) or a comparator function such as bool higher(int a, int b) { return a > b; }.

Q6

L2 · Apply Multiple choice std-sort

What must a comparator comp(a, b) for std::sort return?

  • a) true when a must come before b
  • b) A negative number, zero or a positive number, as for qsort in C
  • c) true when a and b are equal
Show answerHide answer to Q6

a) true when a must come before b. The comparator gives a "less than" answer, not a three-way result as for qsort in C. A comparator that returns true for equal values breaks the rule of std::sort (ex20). Source: cppreference, Compare.

Q7

L1 · Recall Short answer std-find

What do std::find, std::find_if and std::count_if return?

Show answerHide answer to Q7
  • std::find(first, last, value) returns an iterator to the first element equal to value, or last when there is none (ex22).
  • std::find_if(first, last, pred) returns an iterator to the first element for which pred returns true, or last (ex25).
  • std::count_if(first, last, pred) returns the number of elements for which pred returns true (ex24).

Q8

L2 · Apply Multiple choice std-find

A program must know how many ages in a vector are 18 or more. It has the function bool is_adult(int age). Which algorithm does it use?

  • a) std::find_if
  • b) std::count_if
  • c) std::count
Show answerHide answer to Q8

b) std::count_if(ages.begin(), ages.end(), is_adult). It counts the matches (ex24). std::find_if gives only the first match. std::count counts the elements equal to one value, so it cannot use is_adult.

Q9

L1 · Recall Short answer erase-remove

What does std::remove(first, last, value) do to the range? What does it return?

Show answerHide answer to Q9

std::remove moves each element that is not equal to value to the front of the range, in the same order. It returns an iterator to the new end of the kept elements (ex27). It does not change the size. The elements after the new end have unspecified values.

Q10

L2 · Apply Multiple choice erase-remove

What does the C++20 function std::erase_if(v, pred) return for a std::vector?

  • a) Nothing: its return type is void.
  • b) An iterator to the new end of the elements.
  • c) The number of removed elements.
Show answerHide answer to Q10

c) The number of removed elements, as a size_type value (ex29). Source: cppreference, std::erase, std::erase_if (std::vector). The erase-remove idiom with std::remove gives the new end iterator.

Q11

L1 · Recall Short answer iterator-invalidation-basics

What is an invalid iterator? Name two operations on a std::vector that can make iterators invalid.

Show answerHide answer to Q11

An invalid iterator does not point to a valid element any more. The operations *, ++, -- and == on it are undefined behavior. The code can only assign a new value to it, for example it = v.begin(), or destroy it ([iterator.requirements.general]). On a std::vector, push_back with a reallocation makes all iterators invalid (ex32). erase makes the iterators at and after the erased position invalid (ex31).

Q12

L2 · Apply Multiple choice iterator-invalidation-basics

v is a std::vector<int>, and v.size() < v.capacity(). Which iterators does v.push_back(5) make invalid?

  • a) All iterators into v
  • b) Only v.end()
  • c) No iterators
Show answerHide answer to Q12

b) Only v.end(). Without a reallocation, the elements stay in the same block, so the other iterators stay valid. The old end() is invalid, because the end of the elements moved one place. Source: cppreference, std::vector::push_back.

Part D: Explain why

10 questions

Q37

L3 · Analyze Explain why iterator

std::find works on a std::vector, a std::list and a C array. std::sort does not compile on a std::list (ex17). Explain why. Answer in three sentences.

Show answerHide answer to Q37

Rule: each algorithm needs a minimum iterator category. The function std::find only reads each element and moves with ++. So every input iterator works, from a list iterator to a pointer into a C array (ex12, ex18). The function std::sort jumps and subtracts iterators, so it needs random-access iterators, and a list iterator is bidirectional (ex17). Source: cppreference, std::sort.

Q38

L2 · Apply Explain why begin-end

Explain why a loop compares it != v.end() and why the loop body never reads *v.end(). Answer in two sentences.

Show answerHide answer to Q38

Rule: end() is one position after the last element, not an element. The loop stops when it reaches end(), so the body sees only real elements, and a read of *v.end() is undefined behavior (ex10).

Q39

L3 · Analyze Explain why half-open-range

In ex09, std::sort gets an empty vector and needs no special case. Explain why the half-open range makes this safe. Answer in two sentences.

Show answerHide answer to Q39

Rule: an empty range has first == last. The algorithm tests first != last before it reads an element, so on an empty range it does no work and reads nothing (ex09).

Q40

L3 · Analyze Explain why std-sort

Explain why a comparator for std::sort must return false for comp(a, a). What occurs with the comparator a <= b in ex20? Answer in three sentences.

Show answerHide answer to Q40

Rule: the comparator must be a strict weak ordering, so comp(a, a) must be false ([alg.sorting]). The partition step of libstdc++ (__unguarded_partition in bits/stl_algo.h) puts the pivot at the start of the range. Its right scan, while (comp(pivot, *last)) --last;, has no bounds check. That scan stops at the pivot only because comp(pivot, pivot) is false. With a <= b, equal values do not stop the scans, so a scan can read outside the range: the behavior is undefined. The debug mode stops with comparison doesn't meet irreflexive requirements (ex20).

Q41

L4 · Senior Explain why std-sort

In ex21, std::sort uses 11642 comparisons for 1024 elements, and n log2 n is 10240. Explain why the cost of std::sort is O(n log n). Explain why libstdc++ does more comparisons than n log2 n. Answer in four sentences.

Show answerHide answer to Q41

Rule: from C++11, the standard gives a limit of O(n log n) comparisons for std::sort (cppreference, std::sort). In libstdc++, std::sort is an introsort: a quicksort with a depth limit. The limit is 2 log2 n levels (std::__lg(__last - __first) * 2 in bits/stl_algo.h). At the depth limit, it changes to a heap sort, so the worst case also stays O(n log n). The partitions are not exact halves. A final insertion sort on parts of up to 16 elements (_S_threshold = 16) adds more comparisons, so ex21 counts 11642, about 1.14 times 10240.

Q42

L3 · Analyze Explain why std-find

Explain why std::find returns an iterator, and not an index or a bool. Answer in three sentences.

Show answerHide answer to Q42

Rule: an algorithm sees only iterators, not a container. An iterator works for every container: a std::list and a std::map have no index, and a bool gives no position for the next step. With the iterator, the code can read the element, start the next search at it + 1 (ex25) or erase the element.

Q43

L3 · Analyze Explain why erase-remove

Explain why std::remove cannot change the size of a vector. Explain why both compilers warn about ex26. Answer in three sentences.

Show answerHide answer to Q43

Rule: std::remove gets two iterators, and an iterator cannot get its container, so it cannot call erase or change the size. It moves the kept elements to the front and returns the new end, which the caller must give to erase (ex27, ex28). In libstdc++, std::remove has the attribute [[nodiscard]], so both compilers warn when ex26 ignores the result (-Wunused-result).

Q44

L3 · Analyze Explain why iterator-invalidation-basics

Explain why push_back sometimes makes all iterators invalid, but at other times makes only end() invalid. Answer in three sentences.

Show answerHide answer to Q44

Rule: a vector keeps its elements in one block with room for capacity() elements. When size() == capacity(), push_back allocates a larger block, moves the elements and frees the old block, so all iterators point to freed memory (ex32). When there is room, the elements stay in place, and only end() changes (cppreference, std::vector::push_back).

Q45

L4 · Senior Explain why iterator-invalidation-basics

Explain why it = v.erase(it); is correct in a loop, but v.erase(it); ++it; is not. Then explain why one std::erase_if call is faster than many erase calls on a large vector. Answer in four sentences.

Show answerHide answer to Q45

Rule: the function erase makes the iterators at and after the erased position invalid, and it returns an iterator to the next element. The statement it = v.erase(it); uses that new valid iterator. But ++it after v.erase(it) uses an invalid iterator: ex31 runs past the end, and ASan reports heap-buffer-overflow. Each single erase moves all later elements one place to the front, so many erase calls cost O(n * n) (cppreference, std::vector::erase). The function std::erase_if moves each kept element at most one time, so it costs O(n).

Q46

L2 · Apply Explain why iterator

In ex07, *it = 0 does not compile. The iterator it comes from begin() on a const std::vector<int>&. Explain why. Answer in two sentences.

Show answerHide answer to Q46

Rule: on a const object, begin() returns a const_iterator, and its operator* gives a const reference. A write through a const reference does not compile: Clang writes cannot assign to return value because function 'operator*' returns a const value (ex07).

Part F: Design and trade-offs

4 questions

Q55

L4 · Senior Design erase-remove

A vector holds 1 million log lines, and about half of them must go. Compare three designs: an iterator loop with it = v.erase(it), the erase-remove idiom, and std::erase_if. Talk about the cost and the risk of bugs. Give a recommendation.

Show answerHide answer to Q55

Iterator loop with it = v.erase(it): correct (ex30), but each erase moves all later elements. With 500000 erases in 1 million elements, that is O(n * n): about 10^11 element moves.

Erase-remove idiom: one pass of std::remove, then one erase of the tail: O(n) (ex28). The risk: a call of std::remove without erase keeps the size (ex26).

std::erase_if: the same O(n) pass in one call (ex29). It returns the number of removed elements and has no step to forget.

Recommendation: use std::erase_if (C++20). Use the erase-remove idiom only with an older standard. Do not erase one element at a time in a loop on a large vector.

Q56

L4 · Senior Design std-find

A program has a std::vector<int> with 1 million IDs that do not change. It must check 10000 IDs against it. Compare three designs: std::find for each check, a sort one time and then std::binary_search, and a copy into a std::unordered_set<int>. Give a recommendation.

Show answerHide answer to Q56

std::find for each check: O(n) for each check, so up to 10000 * 1 million = 10^10 comparisons (ex21 shows 1024 comparisons for 1024 elements).

Sort one time, then std::binary_search: the sort is O(n log n), about 2 * 10^7 comparisons. Each check is O(log n), about 20 comparisons. The data stays in one contiguous block, with no extra memory. Source: cppreference, std::binary_search.

std::unordered_set<int>: each check is O(1) on average. But each element is a separate node on the heap, so the set needs more memory and a longer build.

Recommendation: sort a copy one time and use std::binary_search, because the IDs do not change. Use std::find only for a few checks or a small vector.

Q57

L4 · Senior Design iterator-invalidation-basics

A program keeps the positions of some "important" elements of a std::vector<Task>, and it adds new tasks at the end all the time. Compare three designs: keep iterators, keep indexes, and use a std::list<Task>. Give a recommendation.

Show answerHide answer to Q57

Iterators: each push_back with a reallocation makes all of them invalid (ex32). This design is not correct for a vector that grows.

Indexes: an index stays valid after a reallocation, because it does not hold an address. It stays correct while the program only adds at the end. An erase before the index moves the element to a different index.

std::list<Task>: an insert does not make list iterators invalid, and an erase makes only the iterators to the erased element invalid (cppreference, std::list). The cost: a heap node for each task and a slow walk, with no random access.

Recommendation: keep indexes in a std::vector. Use a std::list only when the program must also insert or erase in the middle and keep the positions.

Q58

L4 · Senior Design std-sort

A table of players must show the highest score first. Players with the same score must stay in alphabetical order of name. Compare two designs. Design 1 is std::sort with a comparator that compares the score and then the name. Design 2 is a sort by name, then std::stable_sort on the score. Give a recommendation.

Show answerHide answer to Q58

std::sort with a two-key comparator: return a.score != b.score ? a.score > b.score : a.name < b.name;. This is a strict weak ordering, and one O(n log n) sort gives the full order.

Name sort, then std::stable_sort on the score: also correct, because std::stable_sort keeps the name order inside each score (ex16). The cost: two sorts, and std::stable_sort can need extra memory.

Recommendation: use one std::sort with the two-key comparator. It shows the full order in one function. The two-pass design is useful when the data is already in name order.

Q59

L3 · Analyze Interview iterator

What is an iterator in C++? What are iterator categories? Which category do std::vector, std::list and std::map give?

Show answerHide answer to Q59

Main fact: an iterator is an object that marks a position in a range. It gives the element with * and moves with ++. Algorithms work on iterators, so one algorithm works on many containers.

Categories: each category adds operations.

  • Input and output: the weakest categories. An input iterator reads each element one time (std::istream_iterator). An output iterator only writes (std::back_insert_iterator).
  • Forward: ++, *, ==, and more than one pass (for example std::forward_list).
  • Bidirectional: also -- (std::list, std::map) (ex05).
  • Random access: also it + n, it[n], last - first and < (std::deque, and a vector iterator too) (ex04).
  • Contiguous (C++17 and C++20): random access, and the elements are in one block: std::vector, std::array, pointers (ex12). Source: cppreference, Iterator library.

Limit: an algorithm states the category that it needs. std::sort needs random access, so it does not compile on a list (ex17).

Follow-up questions:

  • How do you move a bidirectional iterator by n? With std::next(it, n) or std::advance, in n steps (ex05).
  • What is a const_iterator? An iterator that gives read-only access (ex07).

Q60

L4 · Senior Interview erase-remove

Explain the erase-remove idiom. Why is it necessary, and what did C++20 add for it?

Show answerHide answer to Q60

Main fact: v.erase(std::remove(v.begin(), v.end(), x), v.end()); removes each x from v in one O(n) pass (ex28).

Why it is necessary: std::remove sees only iterators, so it moves the kept elements to the front and returns the new end. Only the container can change the size, so erase removes the tail (ex27). Without erase, the size stays the same (ex26).

C++20: std::erase(v, x) and std::erase_if(v, pred) do both steps and return the number of removed elements (ex29). They also work on std::map (ex38) and other containers.

Follow-up question: What values are after the new end? Unspecified values. Do not read them.

Q61

L4 · Senior Interview iterator-invalidation-basics

Which operations on a std::vector make iterators invalid? Compare the rules for a std::vector and a std::map.

Show answerHide answer to Q61

Main fact for std::vector:

  • push_back or insert with a reallocation: all iterators, pointers and references become invalid (ex32).
  • push_back without a reallocation: only end() becomes invalid.
  • erase and insert: iterators at and after the position become invalid (ex31).
  • reserve with a larger capacity, shrink_to_fit, and clear also make iterators invalid.

std::map: each element is a separate node. An insert makes no iterator invalid, and an erase makes only the iterators to the erased element invalid (cppreference, std::map).

Tools: ASan reports heap-use-after-free (ex32), and -D_GLIBCXX_DEBUG stops with attempt to increment a singular iterator (ex35).

Follow-up question: How do you add elements in a loop over the same vector? Use an index loop up to the old size (ex34), or collect the new elements in a second vector.

Q62

L3 · Analyze Interview half-open-range

Why does the standard library use half-open ranges [first, last) and not closed ranges [first, last]?

Show answerHide answer to Q62

Main fact: a half-open range [first, last) makes the common cases simple.

  • The size is last - first, with no + 1 (ex08).
  • An empty range is first == last, so it needs no special value (ex09).
  • [a, b) and [b, c) join with no gap and no overlap, so a split at mid is simple (Q18).
  • "Not found" can be last, a position that every range has (ex22).

Example: E. W. Dijkstra gives the same reasons for indexes from 0 in "Why numbering should start at zero" (EWD831).

Limit: last is not an element, so code must never read through it (ex10).

Follow-up question: How do you get the last element? v.back(), or *(v.end() - 1) on a non-empty vector.

Q63

L4 · Senior Interview std-sort

What is the complexity of std::sort? Is it stable? What is a strict weak ordering, and what occurs when a comparator breaks it?

Show answerHide answer to Q63

Main fact: the function std::sort does O(n log n) comparisons. The standard gives this limit from C++11. In libstdc++, it is an introsort, so the worst case also stays O(n log n) (Q41). In ex21, it does 11642 comparisons for 1024 elements.

Stability: std::sort is not stable. Use std::stable_sort to keep the old order of equal elements (ex16).

Strict weak ordering: the comparator obeys four rules ([alg.sorting]):

  • comp(a, a) is false.
  • comp(a, b) and comp(b, a) are not both true.
  • If comp(a, b) and comp(b, c), then comp(a, c).
  • The relation "neither is before the other" is also transitive.

A comparator with <= breaks the first rule: the behavior is undefined, and the debug mode stops (ex20). A comparator with != breaks the second rule.

Follow-up questions:

  • Can std::sort sort a std::list? No. It needs random-access iterators. Use list.sort() (ex17, ex18).
  • How do you sort in descending order? Use std::greater<>{} or reverse iterators (ex13, ex11).

Q64

L4 · Senior Interview std-find

What does std::find return when it finds nothing, and what does it cost? Why do you call m.find(key) and not std::find on a std::map?

Show answerHide answer to Q64

Main fact: std::find returns last when it finds nothing (ex22). It compares the elements one by one, so the cost is O(n): at most last - first comparisons, 1024 for 1024 elements in ex21.

Map: the call std::find(m.begin(), m.end(), value) needs a full std::pair as the value. It walks over the nodes one by one, so it costs O(n). The member function m.find(key) uses the order of the tree and costs O(log n) (cppreference, std::map::find).

Limit: a read through the result without a check against end() is undefined behavior. In ex23, ASan reports heap-buffer-overflow, but with free capacity ASan can miss the read.

Follow-up questions:

  • How do you get the index? it - v.begin() for a vector (ex22).
  • What is the C++23 short form for a test? std::ranges::contains(v, x) (ex19).
