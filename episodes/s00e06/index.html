C++ Functions: Parameters, Return Values, Overloads

What you learn

  • Write a declaration and a definition of a function, and tell which build step stops without one of them.
  • Use default arguments, and write each default one time, in the declaration that the callers see.
  • Predict the output when a function changes a parameter that it gets by value.
  • Predict which overload the compiler calls for an argument, and find an ambiguous call.
  • Explain the call stack, and find a missing return with -Wall and UBSan.

Question 7 of 42 L1 · Recall function-declaration

The declaration is enough for the compiler. The linker must find the definition in an object file, so it reports undefined reference to `square(int)' (ex03).

Question 8 of 42 L2 · Apply function-declaration

True or false: A function declaration can leave out the names of the parameters, for example int square(int);.

A declaration needs only the parameter types. The names in a declaration are optional, and they can be different from the names in the definition.

Most teams keep the names in a header, because they help the reader. The compiler uses only the types to check a call.

Question 9 of 42 L4 · Senior function-definition

An inline function can have a definition in each translation unit, if all the definitions are the same. Without inline, the linker reports multiple definition of (workbook Q34). #pragma once does not help, because it works in one translation unit only.

Question 10 of 42 L3 · Analyze function-definition

True or false: int twice(int value) and int twice(const int value) are two different overloads.

A top-level const on a value parameter is not part of the function type. The two lines define the same function, so the compiler reports redefinition (ex19).

The const only stops the body from a change to its own copy. The caller cannot see the difference, so the compiler cannot select between the two.

Question 14 of 42 L3 · Analyze pass-by-value

True or false: In the call show(next_id(), next_id()), C++ always calls the left next_id() first.

The standard does not set the order of evaluation of function arguments. From C++17, the compiler evaluates one argument fully before the next, but the standard does not set the order. GCC 14 writes 2 1 and Clang 19 writes 1 2 for the same program (ex12, ex13).

Both results are correct C++. When the order is important, call each function in its own statement.

Question 25 of 42 L3 · Analyze function-overloading

Put in order: Put the ranks of overload resolution in order. Start with the best rank.

Drag the handle, or use the arrow buttons. With a row focused, press Alt + Up or Alt + Down.

  1. Exact match, for example int to int
  2. User-defined conversion, for example const char* to std::string
  3. Promotion, for example char to int
  4. Standard conversion, for example long to double

The compiler compares the rank of the conversion for each argument, and the better rank wins. When no candidate is better than all the others, the call is ambiguous (ex16).

Question 26 of 42 L3 · Analyze function-overloading

Choose one: What is the result when you build this program?

long to int and long to double are both standard conversions with the same rank. No overload is better, so GCC reports call of overloaded 'show(long int&)' is ambiguous (ex16). On x86-64 Linux, long has 64 bits, so a double cannot hold every long value exactly.

Question 27 of 42 L3 · Analyze function-overloading

Choose one: The linker gets show(int) and show(double). How does it tell them apart?

This is name mangling: the symbol name includes the parameter types (ex14). extern "C" turns mangling off, so C code can call the function. Only one function with that name can have C linkage. An overload with C++ linkage is still possible.

Question 28 of 42 L4 · Senior function-overloading

A const char* overload is an exact match for a string literal, so it wins. The order of the declarations does not change overload resolution, and warning flags do not change it.

Question 32 of 42 L1 · Recall default-arguments

C++ has no syntax to skip an argument. Arguments fill the parameters from the left, and only the last parameters can use defaults.

Question 34 of 42 L4 · Senior default-arguments

Choose one: A library header has int line_width(int width = 8);. Version 2 of the library changes the default to 10. You link your old object files with version 2 and do not compile them again. What does line_width() return in your code?

The compiler puts the default value into each call, in the code of the caller. Your old object file passes 8 until you compile it again with the new header. For this reason, a library can prefer an overload to a default argument.

Question 37 of 42 L1 · Recall call-stack

Choose one: main calls sum_of_squares, and sum_of_squares calls square. Which frame is at the bottom of the call stack while square runs?

main is the first call, so its frame is at the bottom. The frame of square is at the top, because it is the newest call (ex25).

Question 38 of 42 L2 · Apply call-stack

Put in order: Put the steps of one function call in order.

Drag the handle, or use the arrow buttons. With a row focused, press Alt + Up or Alt + Down.

  1. The caller evaluates the arguments
  2. return gives the value to the caller
  3. The body of the function runs
  4. The frame comes off the call stack, and the caller continues
  5. A new frame with the parameters and the return address goes on the call stack

The caller evaluates the arguments before the call. The frame holds the parameters, the local variables and the return address. At return, the frame goes away, and the program continues at the return address.

Question 39 of 42 L2 · Apply call-stack

True or false: In a recursive function, each call has its own copy of each local variable.

Each call gets a new frame on the call stack, with its own parameters and local variables. In ex26, each factorial call has its own n and result.

For this reason, return 2 and return 6 in ex26 come from different result variables in different frames.

Question 40 of 42 L3 · Analyze call-stack

Choose one: A program calls depth(100000000). The build uses AddressSanitizer. What is the result?

Each call needs a new frame, and the stack has a fixed size: 8192 KiB in the toolchain container. The program uses all of the stack and crashes. AddressSanitizer reports stack-overflow with the frames of depth (ex27).

Question 41 of 42 L4 · Senior call-stack

Choose all that apply: depth(100000000) from ex27 crashes with a stack overflow. Which changes remove the crash? Select all correct answers.

Select all that apply.

A loop uses one frame for all the steps. A std::vector that you use as a stack keeps the work on the heap, which can be much larger than the call stack. Warning flags, const and a larger return type do not change the number of frames.

Question 42 of 42 L4 · Senior function-declaration

Choose one: square.h declares int square(int value);. square.cpp defines long square(int value) and does not include square.h. main.cpp includes the header and calls square(7). What is the result?

GCC and Clang give both functions the symbol _Z6squarei, so the linker connects the call to the wrong function. The program breaks the one definition rule, and the tools can stay silent. Include square.h in square.cpp: then the compiler reports the conflict.
