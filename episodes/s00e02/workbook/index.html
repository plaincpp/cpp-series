Part D: Explain why

9 questions

Q35

L2 · Apply Explain why main-function

main in ex01 ends with no return statement, and the build has no warning. The function sign in ex14 also ends with no return for zero, and the compiler warns. Explain why the two cases are different.

Show answerHide answer to Q35

The rule: the standard gives main one exception. When main gets to the end, the effect is return 0;. For any other function that returns a value, an end with no return is undefined behavior. Thus ex01 is correct, but sign(0) in ex14 is not. UBSan reports execution reached the end of a value-returning function without returning a value. Source: cppreference, return statement.

Q36

L3 · Analyze Explain why iostream

Run ex05 in a terminal, and you see step 1 and step 2. Run ./app > out.txt or ./app | cat, and you see only step 1. Explain why.

Show answerHide answer to Q36

The rule: the C library buffers standard output in two ways. To a terminal, it uses a line buffer: each '\n' sends the line out. To a file or a pipe, it uses a full buffer: the text goes out when the buffer is full, or at a flush.

In a terminal, the text step 2\n goes out at its '\n'. In a file, it stays in the buffer, and std::abort stops the program before a flush. Sources: C standard 7.21.3 (C17; 7.23.3 in C23), glibc, Buffering Concepts.

Q37

L3 · Analyze Explain why compiler-warnings

Ex15 has one missing quote. GCC prints 389 lines, with one warning, three errors and many notes. Explain why one mistake gives so many messages, and why you read the first error first.

Show answerHide answer to Q37

The rule: after an error, the compiler continues, so that it can report more errors. But after the missing quote, it reads the next code in the wrong way. The second error, no match for 'operator<<', comes from the first.

GCC then lists each operator<< that it tried, as notes: 136 lines with note:. Only the first error names the cause. Correct it, then build again. Clang prints 5 lines for the same mistake.

Q38

L3 · Analyze Explain why compiler-warnings

Ex13 reads total before it has a value. GCC prints no warning at -O0, but it warns at -O2. Clang warns at -O0. Explain why.

Show answerHide answer to Q38

The rule: GCC finds many uninitialized reads with data-flow analysis, which runs as part of the optimization. At -O0, GCC does less of this analysis, so it misses the read in the loop of ex13. At -O2, it warns 'total' is used uninitialized. Clang runs its own analysis before the optimization, so it warns at -O0 (captured/ex13.O0.clang.txt). Build with two compilers, or also with -O2. Source: GCC, Warning Options (-Wuninitialized and -Wmaybe-uninitialized: the warnings depend on the optimization).

Q39

L3 · Analyze Explain why compiler-warnings

Your team builds with -std=c++23 -Wall -Wextra -Wpedantic -Werror. A file from another project gives unused parameter 'x' [-Wunused-parameter], and the build stops. Explain how to turn off only this warning. Explain why this is better than to remove -Wextra.

Show answerHide answer to Q39

The rule: the name in brackets is also a flag. -Wno-<name> turns off that one warning. Add -Wno-unused-parameter after -Wextra. In cpptv-toolchain:1, the build then passes on GCC and Clang, with -Werror still on.

If you remove -Wextra, you also lose all its other warnings. For example, Clang reports the int and unsigned int comparison of ex17 only with -Wextra. Better still, turn the warning off only for the files from the other project. Source: GCC, Warning Options ("Each of these specific warning options also has a negative form beginning '-Wno-'").

Q40

L3 · Analyze Explain why exit-status

Ex05 calls std::abort(), and echo $? prints 134. The program has no return 134. Explain where the value comes from.

Show answerHide answer to Q40

The rule: std::abort stops the program with the signal SIGABRT, which is signal 6 on Linux. When a command stops on signal N, bash gives the status 128 + N. 128 + 6 = 134. A segmentation fault (SIGSEGV, signal 11) gives 139. Source: bash, Exit Status.

Q41

L2 · Apply Explain why compiler-flags

Explain why you give -std=c++23 on each build, although the compiler has a default standard.

Show answerHide answer to Q41

The rule: each compiler and each version has its own default standard. GCC 14 and Clang 19 use gnu++17. GCC 10 used gnu++14, and MSVC uses C++14. With the default, std::print does not compile (ex16).

Thus the same code can build on one computer and fail on another. -std=c++23 gives the same language on each computer. It also turns off the GNU extensions that conflict with ISO C++. -Wpedantic warns about most of the others, for example a variable-length array. Sources: GCC 11 changes ("The default mode for C++ is now -std=gnu++17 instead of -std=gnu++14"), MSVC /std.

Q42

L3 · Analyze Explain why iostream

Many tutorials write using namespace std; and then cout. This series always writes std::cout. Explain why. The program below does not compile. Use it in your answer.

Show answerHide answer to Q42

The rule: using namespace std; makes all the names of the namespace std visible without the prefix. The standard library has many names, for example std::count. Thus a name of your own can clash with a name of the library. In cpptv-toolchain:1, GCC and Clang stop with reference to 'count' is ambiguous for the program.

With std::cout, you see where each name comes from, and your names cannot clash with the library. In a header file, using namespace std; is worse, because it changes each file that includes the header. Source: cppreference, namespaces (using-directives).

Q43

L3 · Analyze Explain why compiler-explorer

In ex18, main calls square(7). g++ -S writes the assembly in AT&T syntax. With -O0, the assembly of main has call _Z6squarei. With -O2, it has movl $49, %esi and no call. Explain why.

Show answerHide answer to Q43

The rule: at -O2, the optimizer puts the body of a small function into the caller (inlining). Then square(7) becomes 7 * 7. The compiler calculates this at compile time and loads 49 into the register for the argument of operator<< (movl $49, %esi). Compiler Explorer shows the same code in Intel syntax with demangled names by default: mov esi, 49 and call square(int). At -O0, the default, the compiler does not optimize, so main calls square. Source: GCC, Optimize Options.

Part F: Design and trade-offs

4 questions

Q52

L4 · Senior Design compiler-flags

Your team starts a new C++ project. Design the compiler flags for three builds: the build on a developer computer, the build on the build server, and the release build. Give the trade-off of each choice.

Show answerHide answer to Q52

A strong answer gives three builds and a reason for each flag:

  • Developer build: -std=c++23 -Wall -Wextra -Wpedantic -O0 -g -fsanitize=address,undefined. -O0 -g makes the debugger easy to use. The sanitizers find bugs such as ex14 at run time. Cost: the program is slower. The Clang documentation gives a usual slowdown of 2x for AddressSanitizer.
  • Build server: the same flags plus -Werror, on GCC and on Clang. Also build one time with -O2, because GCC finds some uninitialized reads only with optimization (ex13). Cost: more build time.
  • Release build: -std=c++23 -O2, often with -g in a separate debug file. No sanitizers, because they make the program slower.

Recommendation: put the flags in the build file, not in the memory of each developer. Source: Clang, AddressSanitizer.

Q53

L4 · Senior Design iostream

A new command-line tool writes text to the terminal. Compare std::cout, std::print and std::printf for it. Talk about type checks, format errors, the C++ standard that each one needs, and the formats of your own types. Give a recommendation.

Show answerHide answer to Q53

A strong answer compares the three on four points:

  • Type checks: the stream and std::print know the type of each value. The function std::printf trusts the format string. Thus %d with a double is undefined behavior (Q32). GCC and Clang warn about it, but only for a format string that the compiler can see.
  • Format errors: the compiler checks the format string of std::print. For example, std::print("{} + {} = {}\n", 2, 3) has three {} and two values. It does not compile on GCC 14 and Clang 19.
  • Standard: std::print needs C++23 and a new library: GCC 14, or Clang 19 with libstdc++ 14 or libc++ 18 and later. In cpptv-toolchain:1, ex02 builds with clang++ -stdlib=libc++ too. std::cout and std::printf work with every standard.
  • Your own types: std::cout uses an operator<< that you write. std::print uses a std::formatter specialization. std::printf cannot print your own types.

Recommendation: use std::print for new code with C++23. Use std::cout when the compiler is older. Use std::printf only for C code.

Q54

L4 · Senior Design exit-status

Design the exit statuses of a command-line tool that copies files. Scripts and a build server call it. Which values do you use, and which values do you not use? Give the reason for each choice.

Show answerHide answer to Q54

A strong answer uses few values, and documents them:

  • 0: success. Scripts use && and if, which test for 0.
  • 1: the operation failed, for example a file that the tool cannot read.
  • 2: wrong use, for example a missing argument. The bash builtins use 2 for this case, and grep uses 2 for an error.
  • Do not use 126 and 127: bash uses them for "not executable" and "command not found". Do not use 128 and more: bash uses 128 + N for a program that stops on signal N (134, 139).
  • Do not use values above 255, or a count of errors: the shell keeps only the low 8 bits (Q31).

Also write a clear message to std::cerr before you return a value that is not 0. Sources: bash, Exit Status, GNU grep, Exit Status.

Q55

L4 · Senior Design compiler-warnings

Your team talks about -Werror. One person puts it in every build. Another person puts it only on the build server. Compare the two designs, and give a recommendation for an open-source library that other people build.

Show answerHide answer to Q55

A strong answer compares the two designs:

  • -Werror in every build: no warning can stay in the code. Risk: a new compiler version adds new warnings, and the build fails for users who did not change the code. Also, each compiler groups warnings in its own way. Ex17 warns on GCC with -Wall, but on Clang only with -Wextra.
  • -Werror only on the build server: the server uses fixed compiler versions, so the result is the same each time. A change with a new warning cannot pass the server. Developers see warnings, but their build does not stop.

Recommendation: for an open-source library, do not put -Werror in the build files that users run. Turn it on in your own build server, with each compiler that you support.

Q56

L3 · Analyze Interview main-function

What is special about main in C++? What happens before main starts and after it returns?

Show answerHide answer to Q56

A strong answer has these parts:

  1. Main fact: main is the start of the program. Its return type must be int. It cannot be static, and the program must not call it.
  2. Before main: the startup code gives values to global variables and runs the constructors of global objects. Then it calls main(argc, argv).
  3. After main returns: the startup code calls std::exit with the return value. std::exit runs the destructors of global objects and flushes the C streams. The low 8 bits of the value become the exit status. An end with no return gives 0.
  4. Follow-ups: "What does std::abort skip?" The destructors and the flush, so the program loses the text in the buffer (ex05). "Can main call itself?" No. GCC -Wpedantic warns ISO C++ forbids taking address of function '::main', and Clang warns with -Wmain. Source: cppreference, main function.

Q57

L3 · Analyze Interview iostream

What is the difference between std::endl and '\n'? When does it matter?

Show answerHide answer to Q57

A strong answer has these parts:

  1. Main fact: '\n' writes a new line. std::endl writes a new line and flushes the stream.
  2. Example: ex19 writes 1000 lines to a file. In cpptv-toolchain:1, strace counted 2 write calls with '\n' and 1000 with std::endl (captured/ex19.writes-*.gcc.txt). Each write is a system call, so the std::endl version is slower.
  3. When it matters: on a terminal, the output is line buffered, so you see no difference. In a file or a pipe, the flush costs time, but it also keeps text safe before a crash (ex05).
  4. Follow-ups: "How do you flush without a new line?" Use std::flush. "Is std::cerr buffered?" It flushes after each output operation, so a crash does not lose an error message. Source: cppreference, std::endl.

Q58

L4 · Senior Interview compiler-warnings

Why do you build with warnings on? Is a clean build enough?

Show answerHide answer to Q58

A strong answer has these parts:

  1. Main fact: warnings find bugs at compile time, before a test runs, at almost no cost.
  2. Example: ex12 reads an uninitialized variable, and ex14 gets to the end of a function with no return. In C++23, both are undefined behavior, and both give warnings.
  3. Limit: a clean build is not enough. Each compiler finds different bugs. GCC finds the read in ex13 only with -O2, but Clang finds it at -O0. Some bugs show only at run time.
  4. Practice: build with -Wall -Wextra -Wpedantic on two compilers, use -Werror on the build server, and run the tests with sanitizers.
  5. Follow-ups: "Does -Wall turn on all warnings?" No. -Wextra adds more, and -Wshadow is in neither (Q34). "Can you turn off one warning?" Yes, with -Wno-<name>, for example -Wno-unused-parameter (Q39). "Is an uninitialized read always undefined behavior?" In C++23, yes. C++26 makes it erroneous behavior: a wrong program with a defined result, which the tools can report (P2795, cppreference, default initialization). Source: GCC, Warning Options.

Q59

L3 · Analyze Interview exit-status

How does a shell script or a build server know that a program failed? What exit status does a program get when it crashes?

Show answerHide answer to Q59

A strong answer has these parts:

  1. Main fact: each program gives an exit status to its parent process. 0 means success, and other values mean failure. The text that the program writes does not change the status.
  2. In the shell: the parameter $? holds the status of the last command. The operator && runs the next command only after 0. The operator || runs it only after another value. The option set -e stops a script at the first failed command.
  3. A crash: in bash, a program that stops on signal N gets the status 128 + N. The status is 134 for std::abort (SIGABRT) and 139 for a segmentation fault (SIGSEGV).
  4. Follow-ups: "A pipeline ./tests | tee log.txt fails. What is $??" It is 0, the status of tee. Use set -o pipefail to get 1. "What is 127?" bash could not find the command. Source: bash, Pipelines.

Q60

L4 · Senior Interview compiler-flags

What does -O2 change? Why can a bug appear only in the -O2 build?

Show answerHide answer to Q60

A strong answer has these parts:

  1. Main fact: -O2 turns on many optimizations. For example, the compiler inlines small functions, keeps values in registers and removes code that has no effect. In ex18, main has no call to square and uses 49 directly.
  2. Why a bug appears only at -O2: the optimizer uses the rule that the program has no undefined behavior. A program with undefined behavior can work at -O0 by chance and fail at -O2. Also, GCC finds some uninitialized reads only at -O2 (ex13).
  3. Cost: a longer build, and debugging is more difficult, because the debugger cannot show some variables.
  4. Follow-ups: "How do you find such a bug?" Build with sanitizers and with warnings at -O2, and test the -O2 build. "Is the bug in the compiler?" Almost never. First look for undefined behavior. Source: cppreference, undefined behavior.

Q61

L4 · Senior Interview compiler-explorer

How do you find if the compiler inlines a function or removes a call? What are the limits of the method?

Show answerHide answer to Q61

A strong answer has these parts:

  1. Main fact: look at the assembly. In Compiler Explorer, select the compiler and the version. Type the flags, for example -std=c++23 -O2. Then look for a call to the function.
  2. Example: in ex18, g++ -S -O0 (AT&T syntax) gives call _Z6squarei in main. _Z6squarei is the mangled name of square(int). With -O2, main has movl $49, %esi and no call. The website shows the same code in Intel syntax with demangled names by default: call square(int) and mov esi, 49.
  3. Limits: the website can use another version or other flags than your build. A small test does not have the context of your real build: the other files, link-time optimization (-flto) and your flags. Thus the optimizer can give a different result in the real code.
  4. Follow-ups: "How do you check on your own computer?" Use g++ -S -O2 main.cpp and read main.s, or objdump -d on the executable. "Does inline force inlining?" No. The compiler decides. "Can you compare GCC and Clang?" Yes. Add a second compiler pane, and the website shows the two outputs side by side.

Q62

L4 · Senior Interview iostream

C++ already had std::cout and printf. Why did C++23 add std::print?

Show answerHide answer to Q62

A strong answer has these parts:

  1. Main fact: std::print joins the type safety of std::cout and the short format strings of printf.
  2. Details: the compiler checks the format string against the arguments. A wrong count of {} does not compile (Q53). With printf, a wrong % code is undefined behavior. With std::cout, a format such as std::hex stays on the stream for later output.
  3. Limit: it needs C++23 and a new standard library. Older compilers do not have <print>.
  4. Follow-ups: "How do you print your own type?" Write a std::formatter specialization. "What is the relation to std::format?" std::format (C++20, <format>) returns a std::string, and std::print writes the same text to a stream. Source: cppreference, std::print.
