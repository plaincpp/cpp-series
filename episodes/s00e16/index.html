Iterators and Standard Algorithms in C++

About 12 min 44 quiz questions 64 workbook questions
Start the quiz Open the workbook Compiler Explorer (opens in a new tab)

What you learn

  • Explain what an iterator is, and use begin, end, * and ++ to visit the elements of a container.
  • Explain why end() is one position after the last element, and find the bug when code dereferences it.
  • Use std::sort, std::find and std::count_if on a range, and predict their results.
  • Use std::erase_if to remove elements, and explain why std::remove alone does not change the size.
  • Find the loops where push_back or erase makes an iterator invalid, and write the correct loop.

Question 6 of 44 L2 · Apply iterator

A vector iterator is random access, so + and - compile (ex04). Map and list iterators are bidirectional, so + and - do not compile (ex06). The functions std::next and std::distance work on map and list iterators one step at a time. On a vector iterator, they jump in one step.

Question 9 of 44 L3 · Analyze iterator

True or false: A range-for loop over a std::vector uses an index, so it does not use iterators.

The standard defines the range-for loop with begin(), end(), !=, ++ and * ([stmt.ranged]). So ex03 writes the same output with both loops.

A range-for loop is an iterator loop that the compiler writes for you. That is why it works on a std::map and a std::list, which have no index.

Question 17 of 44 L1 · Recall std-sort

Question 19 of 44 L3 · Analyze std-sort

Choose all that apply: Which comparators for int values are correct for std::sort? Select all correct answers.

Select all that apply.

A comparator must be a strict weak ordering ([alg.sorting], cppreference, Compare). The operator <= gives true for comp(a, a), so it breaks the first rule (ex20). The operator != gives true for both comp(a, b) and comp(b, a), so it breaks the second rule. The function std::sort with either operator is undefined behavior. A comparison of std::abs values is correct: it puts -3 and 3 in the same group.

Question 20 of 44 L4 · Senior std-sort

Choose one: With libstdc++, about how many comparisons does std::sort do on 1024 shuffled int values?

ex21 counts 11642 comparisons, near n log2 n = 10240. From C++11, the standard gives a limit: O(n log n) comparisons. A simple quadratic sort needs about n * n / 2 = 500000 comparisons.

Question 21 of 44 L2 · Apply std-sort

Question 31 of 44 L2 · Apply erase-remove

Put in order: Put the steps of v.erase(std::remove(v.begin(), v.end(), 0), v.end()); in order.

Drag the handle, or use the arrow buttons. With a row focused, press Alt + Up or Alt + Down.

  1. v.size() now gives the number of kept elements
  2. std::remove returns the new end of the kept elements
  3. std::remove moves each element that is not 0 to the front
  4. erase destroys the elements from the new end to v.end()

The function arguments run first, so std::remove runs before erase. erase then removes the tail and changes the size (ex28).

An algorithm works on a range of iterators. It cannot get the container from an iterator, so it cannot change the size. The container erases the tail with erase (ex27, ex28).

Question 35 of 44 L3 · Analyze iterator-invalidation-basics

Select all that apply.

A reallocation makes all iterators invalid. The function erase makes iterators at and after the erased position invalid. So an erase at index 0 makes it invalid, but an erase at index 4 does not. Without a reallocation, push_back makes only end() invalid.

Question 37 of 44 L2 · Apply iterator-invalidation-basics

True or false: An insert into a std::map makes the iterators to the other elements of the map invalid.

A map keeps each element in a separate node. An insert links a new node and moves no element, so no iterator becomes invalid (cppreference, std::map::insert).

The rules are different for each container. A std::vector keeps its elements in one block, so a reallocation makes all its iterators invalid (ex32).

Question 43 of 44 L4 · Senior begin-end

Choose one: An interviewer asks: why does end() point after the last element, and not to the last element?

An empty container has no last element, but it has end(), and begin() == end() (ex09). So an algorithm can return end() for "not found" (ex22). Also, end() - begin() is the size. end() is not an element: a read through it is undefined behavior (ex10).
