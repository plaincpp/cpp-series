A

Part A: Concept checks

12 questions

Q1

L1 · Recall Short answer value-category

Every expression in C++ has two properties that do not depend on each other. Name the two properties.

Show answerHide answer to Q1

A type and a value category. For example, count and count + 1 both have the type int, but count is an lvalue and count + 1 is an rvalue (ex11).

Q2

L1 · Recall Short answer lvalue

What is an lvalue? Write one sentence, and give two examples of lvalue expressions that are not the name of a variable.

Show answerHide answer to Q2

An lvalue is an expression that names an object or a function. Thus it has an identity. Except for a bit-field, the built-in & gives its address. These lvalues are not the name of a variable:

  • *p, a[i], ++x and x = y
  • a call to a function that returns T&
  • a string literal (ex05, ex07)

Q3

L1 · Recall Short answer rvalue

What is an rvalue? Write one sentence, and give three examples of rvalue expressions.

Show answerHide answer to Q3

An rvalue is an expression that the program can move from. Most rvalues are values or temporary objects with no name. Examples: 42, count + 1, count++, std::string{"a"} and a call to a function that returns by value (ex11). The cast std::move(x) is a special rvalue: it refers to the object x (an xvalue, S01E04).

Q4

L1 · Recall Short answer value-category

State the address test and the assignment test. Tell which test is exact for a built-in type and which test is only a hint.

Show answerHide answer to Q4
  • Address test: the built-in &expr compiles only when expr is an lvalue (ex03).
  • Assignment test: the built-in expr = value compiles only when expr is a modifiable lvalue (ex04).

The address test is exact for a built-in type, but not for a bit-field. A bit-field is a modifiable lvalue, but the built-in & rejects it. GCC: attempt to take address of bit-field. Clang: address of bit-field requested. The assignment test is only a hint: a const lvalue fails it, and a class rvalue passes it, because operator= is a member function (ex08).

Q5

L1 · Recall Multiple choice rvalue-reference

Which declaration makes r an rvalue reference?

  • a) int& r = count;
  • b) const int& r = 42;
  • c) int&& r = 42;
  • d) int* r = &count;
Show answerHide answer to Q5

c) int&& r = 42;. && declares an rvalue reference. a) is an lvalue reference, b) is a reference to const, and d) is a pointer.

Q6

L1 · Recall Short answer rvalue-reference

To which value categories can each reference type bind: T&, const T& and T&&?

Show answerHide answer to Q6
Reference Binds to
T& a modifiable lvalue only
const T& an lvalue or an rvalue
T&& an rvalue only

ex09 shows all three. ex10 shows that int&& rejects the lvalue count. Source: [dcl.init.ref].

Q7

L2 · Apply Multiple choice lvalue

What is the value category of the string literal "abc"?

  • a) An rvalue, as 42 is an rvalue
  • b) An lvalue of type const char[4]
  • c) A prvalue of type const char*
Show answerHide answer to Q7

b) An lvalue of type const char[4]. A string literal is an array object with static storage. Thus &"abc" compiles, and sizeof(*p) gives 4 (ex07). 42 has no object, so it is an rvalue.

Q8

L2 · Apply Short answer lvalue

int& first(std::vector<int>& v) and int size_of(const std::vector<int>& v) exist. Give the value category of the call first(values) and of the call size_of(values). Tell which call can be on the left of =.

Show answerHide answer to Q8

first(values) is an lvalue, because the function returns int&. size_of(values) is an rvalue, because the function returns by value. Only first(values) = 7; compiles (ex05 uses the same rule with at).

Q9

L1 · Recall Short answer rvalue-reference

Which C++ standard added rvalue references? Name one library feature that they made possible.

Show answerHide answer to Q9

C++11. Rvalue references made move semantics possible: move constructors, move assignment, std::move and move-only types such as std::unique_ptr. They also made perfect forwarding possible.

Q10

L2 · Apply Multiple choice expression-vs-type

int&& r = 42; comes first. What does decltype(r) give?

  • a) int
  • b) int&
  • c) int&&
Show answerHide answer to Q10

c) int&&. decltype on the name of a variable gives the declared type (ex15 checks it with static_assert). The expression r is still an lvalue of type int.

Q11

L1 · Recall Short answer overload-on-reference

The overloads f(T&) and f(T&&) exist. Which overload does an lvalue argument select? Which overload does an rvalue argument select?

Show answerHide answer to Q11

An lvalue argument selects f(T&). An rvalue argument selects f(T&&). ex11 uses this pair to show the category of six expressions.

Q12

L1 · Recall Short answer overload-on-reference

The pair f(const T&) and f(T&&) is in every class that can copy and move. Name the two special member functions that make this pair for construction.

Show answerHide answer to Q12

The copy constructor T(const T&) and the move constructor T(T&&). An lvalue argument selects the copy constructor, and an rvalue argument selects the move constructor (ex17). The copy assignment and the move assignment make the same pair for =.

Part D: Explain why

9 questions

Q34

L2 · Apply Explain why rvalue

Explain why int* b = &(count + 1); does not compile, but int* a = &count; compiles (ex03).

Show answerHide answer to Q34

Rule: the built-in & needs an lvalue operand ([expr.unary.op]). The variable count names an object, so it has an address. The expression count + 1 is a new value with no name, so it has no address. GCC: lvalue required as unary '&' operand. Clang: cannot take the address of an rvalue of type 'int' (ex03).

Q35

L2 · Apply Explain why lvalue

Explain why ++count = 10; compiles, but count++ = 10; does not compile (ex05, ex06).

Show answerHide answer to Q35

Rule: the expression ++count gives the variable count after the change, so it is an lvalue ([expr.pre.incr]). The expression count++ gives a copy of the old value, so it is an rvalue ([expr.post.incr]). The built-in = needs a modifiable lvalue on the left, so only ++count = 10; compiles. ex05 writes 10 for count, and ex06 does not compile.

Q36

L3 · Analyze Explain why value-category

Explain why "an lvalue is an expression on the left of =" is not a correct definition. Give one lvalue that cannot be on the left and one rvalue that can be on the left (ex08).

Show answerHide answer to Q36

Rule: the category tells if an expression has an identity. It does not tell where the expression can be.

  • An lvalue that cannot be on the left: const int limit = 10;. limit has an address, but limit = 11 does not compile.
  • An rvalue that can be on the left: make_title() = "final" with std::string make_title(). Here = calls the member function std::string::operator=. A member function can run on an rvalue (ex08).

So the "left of =" form is only a hint. Use the address test.

Q37

L2 · Apply Explain why rvalue-reference

Explain why int&& r = count; does not compile, but int&& r = std::move(count); compiles (ex10).

Show answerHide answer to Q37

Rule: int&& binds only to an rvalue ([dcl.init.ref]). The variable count is an lvalue, so the first declaration fails (ex10). The expression std::move(count) is a cast to int&&. The result is an rvalue (an xvalue, S01E04) that refers to count. Thus the second declaration compiles, and r refers to count itself, not to a copy.

Q38

L3 · Analyze Explain why rvalue-reference

Explain why const int& b = 42; compiles, but int& b = 42; does not compile. How long does the temporary live in the first case?

Show answerHide answer to Q38

Rule: a non-const lvalue reference binds only to a modifiable lvalue. The literal 42 is an rvalue, so int& b = 42; fails. GCC: cannot bind non-const lvalue reference of type 'int&' to an rvalue of type 'int'.

A const reference can bind to an rvalue. The compiler makes a temporary int with the value 42, and b refers to it. The reference b binds directly to the temporary. Thus the temporary lives to the end of the scope of b ([class.temporary]).

Q39

L3 · Analyze Explain why expression-vs-type

In ex01, r has the type int&&, but take(r) selects take(int&). Explain why.

Show answerHide answer to Q39

Rule: a name of a variable is an lvalue, for every declared type. The variable r has the declared type int&&. But the expression r is an lvalue of type int, because [expr.type]/1 removes the reference. An lvalue cannot bind to int&&, so only take(int&) is a candidate. Use take(std::move(r)) to select take(int&&) (ex15).

Q40

L3 · Analyze Explain why overload-on-reference

The overloads store(int) and store(int&&) make store(42) ambiguous (ex13). The overloads kind(const int&) and kind(int&&) do not make kind(42) ambiguous (ex12). Explain why.

Show answerHide answer to Q40

Rule: [over.ics.rank] 3.2.3 prefers T&& to const T& for an rvalue. That rule compares two reference bindings only. In kind(const int&) and kind(int&&), both parameters are references, so int&& wins (ex12). In store(int) and store(int&&), one parameter is not a reference. Both conversions are exact matches, and no rule ranks them, so the call is ambiguous (ex13).

Q41

L3 · Analyze Explain why overload-on-reference

Explain why keep(std::move(settings)) uses the copy constructor when settings is a const Buffer (ex20). Why does the compiler give no warning?

Show answerHide answer to Q41

Rule: the expression std::move(settings) has the type const Buffer&&. The move constructor Buffer(Buffer&&) cannot accept it, because const must stay. The copy constructor Buffer(const Buffer&) can accept a const rvalue. Thus overload resolution selects the copy constructor (ex20). The code is correct C++, so the compiler gives no warning. The tool clang-tidy has the check performance-move-const-arg for this mistake (clang-tidy documentation).

Q42

L4 · Senior Explain why expression-vs-type

The designers of C++11 decided that a named rvalue reference is an lvalue. Explain the reason. What can go wrong in a function body if the name t of a T&& parameter is an rvalue?

Show answerHide answer to Q42

Rule: a named rvalue reference is an lvalue (N2027, "A Brief Introduction to Rvalue References", 2006). A function body can use a name many times. If t is an rvalue, the first use can move from t. Then each later use sees a moved-from object. For example, log(t); store(t); can move t into log, and store then gets an empty value. With the rule, a move occurs only where you write std::move(t), so you can see it in the code.

Part F: Design and trade-offs

4 questions

Q49

L4 · Senior Design overload-on-reference

A class Player has a std::string name_ member. Compare three setters:

  1. Only void set_name(const std::string& name).
  2. Two overloads: set_name(const std::string&) and set_name(std::string&&) (ex25).
  3. One function that takes the string by value: void set_name(std::string name) { name_ = std::move(name); }.

For each design, count the copies and moves for an lvalue argument and for an rvalue argument. Give a recommendation for one string parameter, and for a function with three string parameters.

Show answerHide answer to Q49
Design lvalue argument rvalue argument
1. const std::string& only 1 copy 1 copy
2. const& + && overloads 1 copy 1 move
3. by value + std::move 1 copy + 1 move 1 move, or 2 moves for std::move(s)

Q24 shows design 3: the lvalue gives Cm, and the temporary gives only m.

  • Design 1 is simple, but it copies every temporary.
  • Design 2 is the fastest. But each new parameter doubles the overloads: three string parameters need 8 overloads.
  • Design 3 gives one function and costs one more move, which is cheap for std::string.
  • A copy assignment can use the old buffer of name_ again, so designs 1 and 2 can avoid an allocation for an lvalue. Design 3 always makes a new copy first.

Recommendation: for one hot setter, design 2 (as push_back). For many parameters or for code that is not hot, design 3. S01E05 shows a third choice: a template with perfect forwarding.

Q50

L4 · Senior Design rvalue-reference

A teammate writes std::string&& trimmed(std::string&& text) to avoid a copy (Q32). Compare this return type with std::string. Talk about the lifetime of the result, the cost of each choice and what the caller can do with the result.

Show answerHide answer to Q50
  • std::string&&: no move at the return. But the result refers to the argument. When the caller passes a temporary, the reference dangles after the statement (Q32, ex23). Lifetime extension does not pass through a function. GCC 14 warns, but only for some cases.
  • std::string: one move at the return, which costs a few word copies and no allocation. The caller gets a real object. A reference to the result extends its lifetime, and the caller can keep or change the result.

Recommendation: return by value. Return T&& only from a function that returns a member of an rvalue *this or a cast, such as std::move. A follow-up: "Does the by-value return copy?" No. The statement return std::move(text); moves. In C++20 and later, return text; moves too.

Q51

L4 · Senior Design overload-on-reference

A Watcher class keeps a pointer to a Config object: void watch(const Config& c) { config_ = &c; }. A caller writes w.watch(Config{});, and later the program reads a destroyed object. Design an overload that makes this call a compile error. Tell which standard library function uses the same method. Name one other design, and give its trade-off.

Show answerHide answer to Q51

Add a deleted overload: void watch(const Config&&) = delete;. An rvalue argument prefers it to const Config&, so w.watch(Config{}) does not compile. GCC: use of deleted function 'void Watcher::watch(const Config&&)'. Clang: call to deleted member function 'watch'. Use const Config&&, not Config&&. Then the compiler also refuses a const rvalue.

  • The standard library uses this method: std::ref and std::cref have a deleted const T&& overload (cppreference: std::ref).
  • Other design: keep a copy (Config config_;) or a std::shared_ptr<const Config>. Then no lifetime problem exists, but each call copies or shares ownership.
  • Limit: the deleted overload refuses only temporaries. A local variable that dies before the Watcher still dangles.

Q52

L4 · Senior Design value-category

make_title() = "final" compiles for std::string (ex08), but it usually shows a mistake. For your own class Title, how can you make an assignment to an rvalue a compile error? Give the declaration. Tell why the standard library types do not do this.

Show answerHide answer to Q52

Add the & qualifier to the assignment operator: Title& operator=(const Title&) & = default;. Then t = make_title(); compiles, but make_title() = t; does not. GCC: passing 'Title' as 'this' argument discards qualifiers. Clang: no viable overloaded '='. Add the same qualifier to the move assignment.

The standard library types do not do this:

  • Old code that compiles today can break.
  • Some types use assignment to an rvalue on purpose. For example, std::tie(a, b) = std::pair{1, 2}; assigns to a temporary std::tuple of references. std::vector<bool> returns a proxy object, and v[0] = true assigns to that rvalue.

Part G: Interview questions

Q53

L3 · Analyze Interview value-category

"What is the difference between an lvalue and an rvalue? Give examples, and tell why the difference matters in modern C++."

Show answerHide answer to Q53
  • Main fact: an lvalue names an object with an identity, so you can usually take its address. An rvalue is an expression that the program can move from. Most rvalues are values or temporaries with no name, but std::move(x) refers to x. Category is a property of an expression, not of a type.
  • Example: count, *p, a[i], ++x are lvalues. 42, x + 1, x++, make_name() are rvalues (ex11).
  • Why it matters: the category selects the overload. An lvalue selects the copy, and an rvalue selects the move. A move of a std::vector or std::string takes the buffer and allocates nothing.
  • Limit: C++11 splits rvalues into xvalues and prvalues (S01E04).
  • Follow-ups: "Is a string literal an lvalue?" Yes, an array lvalue (ex07). "Is x++ an lvalue?" No.

Q54

L3 · Analyze Interview expression-vs-type

"Inside void f(Widget&& w), is w an lvalue or an rvalue? What do you write to give w to another function as an rvalue?" Follow-up: "Does return w; copy or move?"

Show answerHide answer to Q54
  • Main fact: w is an lvalue. The name of a variable is always an lvalue, also when its declared type is Widget&& (ex01, ex15). Give it to the next function with std::move(w).
  • Example: store(w) copies, and store(std::move(w)) moves (ex16).
  • Limit: after std::move(w), do not use the value of w again.
  • How to find the bug: GCC and Clang give no warning (ex16). clang-tidy with the check cppcoreguidelines-rvalue-reference-param-not-moved reports rvalue reference parameter 't' is never moved from inside the function body for the original ex16.
  • Follow-up: return w; moves. In C++20 and later (P1825R0), a return of a T&& parameter name first tries a move. In the Docker toolchain, Widget give_back(Widget&& w) { return w; } writes move in C++23 mode. In C++17 mode, GCC 14 copies and Clang 19 moves, because Clang applies the change to older modes too.

Q55

L3 · Analyze Interview overload-on-reference

"Why does std::vector::push_back have two overloads? Which one does v.push_back(s) call, and which one does v.push_back(s + "!") call?"

Show answerHide answer to Q55
  • Main fact: push_back(const T&) copies an lvalue, and push_back(T&&) moves an rvalue. The caller can still use an lvalue, so the vector must copy it. Nobody can use a temporary again, so the vector can take its contents.
  • Example: v.push_back(s) calls the const T& overload. v.push_back(s + "!") calls the T&& overload, because s + "!" is a temporary (ex18).
  • Cost: for a long string, the copy allocates and copies each character. The move copies a few words.
  • Follow-up: "And emplace_back?" It builds the element in place from constructor arguments, so it needs no temporary.

Q56

L3 · Analyze Interview rvalue

"Can you assign to an rvalue in C++?"

Show answerHide answer to Q56
  • Main fact: not with the built-in =. x + 1 = 5 does not compile (ex04). For a class type, yes: make_title() = "final" compiles, because operator= is a member function (ex08).
  • Limit: a class can refuse it with T& operator=(const T&) & (Q52).
  • Follow-up: "Why can you call a non-const member function on a temporary?" A temporary of class type is a real object. Only the built-in operators need an lvalue.

Q57

L4 · Senior Interview overload-on-reference

"What is a ref-qualified member function? Give a use case."

Show answerHide answer to Q57
  • Main fact: a ref-qualifier (& or && after the parameter list, C++11) lets a member function overload on the category of the object expression.
  • Example: take_text() const& copies the member, and take_text() && moves it, because nobody uses the rvalue object again (ex24). std::optional::value() has &, const&, && and const&& overloads.
  • Use cases:
    • Move a member out of a temporary.
    • Refuse assignment to rvalues (Q52).
    • Make a getter safe on a temporary (Q31).
  • Limit: when one overload has a ref-qualifier, each overload with the same parameters must have one too ([over.load]).
  • Follow-up: "What does *this look like inside the && overload?" *this is still an lvalue, so you write std::move(member_).

Q58

L4 · Senior Interview overload-on-reference

"What does std::move do on a const object? How do you find this mistake in a large code base?"

Show answerHide answer to Q58
  • Main fact: std::move on a const object gives a const T&&. The move constructor T(T&&) cannot bind to it, so T(const T&) copies. The code compiles with no warning (ex20).
  • Example: const std::vector<int> data = load(); store(std::move(data)); copies the full vector.
  • How to find it: clang-tidy with the check performance-move-const-arg. Also look for const local variables that the code later moves.
  • Follow-up: "Why does the language allow it?" Generic code can call std::move on any type. A copy is a correct result when no move is possible.

Q59

L4 · Senior Interview lvalue

"What are the value categories of ++x and x++? Why are they different? Which one is cheaper for a class type, such as an iterator?"

Show answerHide answer to Q59
  • Main fact: ++x is an lvalue. It changes x and gives x itself. x++ is an rvalue: it gives a copy of the old value ([expr.pre.incr], [expr.post.incr]).
  • Example: ++count = 10 compiles, and count++ = 10 does not (ex05, ex06). ex26 shows lvalue and rvalue.
  • Cost: for a class type, the usual operator++(int) makes a copy of the old object and returns it by value. ++it needs no copy. For int, the optimizer makes both the same.
  • Follow-up: "How do you write the two operators?" T& operator++() returns *this. T operator++(int) copies, calls ++*this and returns the copy.

Q60

L4 · Senior Interview rvalue-reference

"When does a reference keep a temporary alive? Give one case where it does, and one case where the reference dangles. Which tools find the dangling case?"

Show answerHide answer to Q60
  • Main fact: a reference that binds directly to a temporary keeps it alive to the end of the scope of the reference ([class.temporary]).
  • Works: int&& r = count + 1; and const Tag& kept = Tag{2}; (ex22, Q21).
  • Dangles: the reference comes from a function that returns a reference to its argument or to a member of a temporary. Examples are int&& result = pass_on(input + 1); (ex23) and load_user().name() (Q31). The temporary dies at the end of the full expression.
  • Tools: ASan reports stack-use-after-scope. GCC 14 has -Wdangling-reference (in -Wall for C++), but it is a heuristic, and Clang 19 gives no warning for ex23.
  • Follow-up: "Does a reference parameter extend the lifetime?" No. A temporary that binds to a parameter lives to the end of the full expression with the call.
