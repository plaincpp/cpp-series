Question 1 of 35 L2 · Apply translation-unit In the video

Choose one: You compile a project with three .cpp files and five headers. How many object files do you get?

Each .cpp file makes one translation unit, and each unit makes one object file. The headers are part of the units that include them. They do not compile alone.

Question 2 of 35 L3 · Analyze linker In the video

Choose one: main.cpp includes util.h and calls add(2, 3). The build also compiles util.cpp. Which step fails?

Each file compiles. But add(long, long) is a different function with a different symbol. No object file defines add(int, int), so the link fails.

Question 3 of 35 L3 · Analyze compiler In the video

Choose one: Which step gives this error?

A redefinition of a type breaks a C++ rule in one translation unit, so the compiler reports it. The preprocessor only copied the header two times, because the header has no include guard. A link error starts with /usr/bin/ld and has words such as undefined reference or multiple definition.

Question 4 of 35 L1 · Recall compiler

Put in order: Put the four build steps in order, from main.cpp to the executable.

Drag the handle, or use the arrow buttons. With a row focused, press Alt + Up or Alt + Down.

  1. Compile: change the translation unit into assembly code
  2. Assemble: change the assembly code into an object file
  3. Link: join the object files into an executable
  4. Preprocess: copy the headers in and replace the macros

Each step uses the output of the step before it. One g++ command runs all four steps in this order.

Question 5 of 35 L1 · Recall compiler

Match the terms: Match each command to the output that it makes.

-E, -S and -c stop the build after the preprocessor, the compiler and the assembler. With no option, g++ also links.

Question 6 of 35 L1 · Recall preprocessor

Fill the blank: The g++ option ____blank stops the build after the preprocessor.

-E writes the translation unit to standard output. -S stops after the compiler, and -c stops after the assembler.

Question 7 of 35 L1 · Recall preprocessor

True or false: The preprocessor finds C++ syntax errors, such as a missing semicolon.

The preprocessor copies files and replaces macros. It does not check C++ rules. The compiler finds syntax errors.

Example ex06 has a missing semicolon. The error expected ';' comes from the compiler step.

Question 8 of 35 L2 · Apply preprocessor

Replace x with the text 2 + 3. Do not compute it first.

The preprocessor puts the text 2 + 3 on the two sides of the star. The multiplication comes first, so 2 + 3 * 2 + 3 is 11, not 25.

Question 9 of 35 L3 · Analyze preprocessor

Predict the output: What does this program write?

Write the text that the preprocessor makes for MAX(i++, 3).

The preprocessor makes ((i++) > (3) ? (i++) : (3)). The condition reads 5 and increments i, and the chosen branch reads 6 and increments i again. Thus m is 6 and i is 7.

Question 10 of 35 L2 · Apply preprocessor

Choose all that apply: Which lines are preprocessor directives? Select all correct answers.

Select all that apply.

A directive is a line that starts with a hash sign. A hash sign in a string literal is only text. The preprocessor removes a comment, so a directive in a comment has no effect.

Question 11 of 35 L4 · Senior compiler

Choose one: main.cpp calls add, and util.cpp defines it. With g++ -O2 main.cpp util.cpp, main still calls add. The compiler does not copy the body of add into main. Why, and what changes this?

When main.cpp compiles, the body of add is in another translation unit. With -flto, the compiler writes its internal form into the object files, and the link step optimizes the whole program. In cpptv-toolchain:1, -O2 keeps call add(int, int) in main, and -O2 -flto removes the call.

Question 12 of 35 L1 · Recall translation-unit

Choose one: What is a translation unit?

The compiler works on one translation unit at a time. The headers are part of each unit that includes them. The object file is the output of the unit, not the unit.

Question 13 of 35 L2 · Apply translation-unit

True or false: When g++ -c main.cpp compiles a call to add, the compiler also reads util.cpp to find add.

The compiler reads one translation unit at a time. It knows only the names that this unit declares, for example through #include "util.h".

Example ex05 shows the result. main.cpp has no declaration of add, so the compile fails, although util.cpp defines add.

Question 14 of 35 L2 · Apply translation-unit

Find the bug: This program must write 8. The compile fails with 'twice' was not declared in this scope. Which line does the compiler report?

The compiler reads from top to bottom. Line 4 uses twice before the translation unit declares it, so the compiler reports line 4. The definition on line 7 comes too late. Add int twice(int x); before main, or move the definition above main.

Question 15 of 35 L3 · Analyze translation-unit

Choose all that apply: Two .cpp files include the same header. Which header lines link with no error? Select all correct answers.

Select all that apply.

A declaration, an inline function and a type definition can be in many translation units. A plain function body and int counter = 1; make a definition in each unit, so the linker reports a multiple definition.

Question 16 of 35 L3 · Analyze translation-unit

Fill the blank: Two .cpp files each define a helper int scale(int). Write the keyword ____blank before each helper, so that each helper stays in its own translation unit.

static gives the function internal linkage, so the linker does not match it with other files. Without optimization, nm shows it with a lowercase t (a local symbol). With -O2, the compiler often copies the body into its callers, and the symbol disappears. An unnamed namespace has the same effect as static.

Question 17 of 35 L2 · Apply compiler

Choose one: g++ -c main.cpp gives no error. What does this result tell you?

-c stops after the object file, so only the compile step ran. The linker checks the definitions later, as in example ex08. A run-time error can also occur later.

Question 18 of 35 L2 · Apply translation-unit

Predict the output: What does this program write?

Line 3 declares twice, so the compiler accepts the call in main. The definition comes later in the same translation unit, and the linker connects the call to it.

Question 19 of 35 L3 · Analyze compiler

Choose all that apply: Which errors come from the compiler? Select all correct answers.

Select all that apply.

The compiler reports errors in one translation unit: syntax, names, types and static_assert. The linker reports undefined reference and multiple definition, because it needs all the object files to find them.

Question 20 of 35 L1 · Recall object-file

Choose one: In the output of nm main.o, what does the letter U before add(int, int) tell you?

U means undefined in this object file. The linker must find a definition of the same symbol in another object file or library. For a function, nm shows the definition with T (code). Data uses other letters, such as D or B.

Question 21 of 35 L1 · Recall object-file

Match the terms: Match each file extension to its content.

On Linux, these extensions are the usual names. Windows uses .obj, .lib and .dll for the last three types.

Question 22 of 35 L3 · Analyze object-file

Choose one: nm geometry.o shows T _Z4areaii. Which function does geometry.o define?

_Z starts a C++ name, 4area is a name with 4 letters, and ii lists two int parameters. With long parameters, the letters are ll, as in _Z3addll.

Question 23 of 35 L2 · Apply object-file

True or false: You can run the object file util.o as a program with ./util.o.

An object file is not an executable. It has no startup code, and the linker did not connect its symbols yet. The file tool calls it a relocatable file.

Only the linker output is an executable. In cpptv-toolchain:1, file util.o shows ELF 64-bit LSB relocatable. g++ writes the object file without execute permission, so ./util.o gives Permission denied. After chmod +x util.o, it gives cannot execute binary file: Exec format error.

Question 24 of 35 L3 · Analyze object-file

Choose one: A C library defines c_add. Your C++ file declares int c_add(int a, int b);. The link fails with an undefined reference. What corrects it?

C does not mangle names, so the C object file defines c_add. The C++ declaration asks for _Z5c_addii. extern "C" tells the C++ compiler to use the C name.

Question 25 of 35 L2 · Apply preprocessor

Choose one: util.h is in the same folder as main.cpp. You run g++ -c main.cpp with no -I option. Which #include line finds the header?

With quotes, the preprocessor looks first in the folder of the file that has the #include line, and then in the folders for angle brackets. With angle brackets, it looks only in the -I folders and the system folders. In cpptv-toolchain:1, #include <util.h> gives fatal error: util.h: No such file or directory, and -I. corrects it.

Question 26 of 35 L3 · Analyze linker

Find the bug: main.cpp and stats.cpp both include this header. The link fails with multiple definition of add(int, int). Which line has the bug?

Select the line or lines with the bug. Select a line again to clear it.

Line 4 starts a definition, so each translation unit gets its own add. #pragma once works only in one unit. Keep only int add(int a, int b); in the header and put the body in one .cpp file, or mark it inline.

Question 28 of 35 L4 · Senior linker

Choose all that apply: Which statements about static and shared libraries are true? Select all correct answers.

Select all that apply.

Static code becomes part of the executable, so the .a file is not necessary at run time. A shared library stays outside, so the executable is smaller, but the .so file must be there when the program starts. The link order rule is for GNU ld. Other linkers, such as LLVM lld, also accept the library first.

Question 29 of 35 L4 · Senior linker

Choose one: main.o calls shout, and libtextlib.a defines it. The linker is GNU ld. Why does g++ -L. -ltextlib main.o -o app fail with an undefined reference?

GNU ld reads its inputs from left to right. It takes an object file from an archive only for a symbol that is undefined at that time. Put the library after the object files: g++ main.o -L. -ltextlib -o app.

Question 30 of 35 L3 · Analyze executable

Put in order: Put these events in order, from the start of ./app to the end. The program uses shared libraries and has a global object.

Drag the handle, or use the arrow buttons. With a row focused, press Alt + Up or Alt + Down.

  1. main returns, and the destructors of the global objects run
  2. Startup code calls main
  3. Startup code constructs the global objects
  4. The operating system loads the executable into memory
  5. The dynamic linker loads the shared libraries, such as libstdc++.so.6

The program needs its libraries before any code can use them. Global objects exist before main starts, as example ex18 shows. Their destructors run after main returns.

Question 31 of 35 L2 · Apply executable

Predict the output: What does this program write?

Startup code constructs the global object logger before it calls main. After main returns, the program destroys logger.

Question 32 of 35 L2 · Apply executable

True or false: The value that main returns becomes the exit status of the program.

Startup code gives the return value of main to std::exit. In a Linux shell, echo $? shows it. On Linux, only the low 8 bits reach the shell, so return 256; gives 0.

By convention, 0 means success. Build tools and test scripts read the exit status.

Question 33 of 35 L2 · Apply executable

Fill the blank: If main ends with no return statement, the exit status of the program is ____blank.

This rule applies only to main. Each other function with a return type that is not void must return a value.

Question 34 of 35 L2 · Apply executable

True or false: If a program compiles and links with no error and no warning, it has no bugs.

The build checks only what the compiler and the linker know. Example ex20 builds, but it stops at run time with std::out_of_range for the index 5.

A clean build is the first test, not the last. Run the program and its tests too.

Question 35 of 35 L4 · Senior executable

Choose one: a.cpp and b.cpp each define a global object. The constructor of the object in b.cpp uses the object in a.cpp. What is the risk?

C++ does not specify the order of initialization between translation units. In cpptv-toolchain:1, the order of the constructors changes with the order of the files on the link line. Use a function that returns a static local object, because C++ initializes it on the first call.
