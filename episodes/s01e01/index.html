RAII and the Rule of Zero, Three and Five

About 12 min 40 quiz questions 62 workbook questions
Start the quiz Open the workbook Compiler Explorer (opens in a new tab)

What you learn

  • Explain how RAII ties a resource to the lifetime of an object, and why RAII makes code exception safe.
  • Name the six special member functions, and predict which of them the compiler declares for a class.
  • Find the double delete in a class that does not obey the rule of three, and correct the class.
  • Write a FileHandle class with the rule of five: no copy and a noexcept move.
  • Use the rule of zero: let members such as std::unique_ptr and std::vector own the resources.

Question 2 of 40 L3 · Analyze special-member-functions In the video

Choose one: Widget declares a default constructor and a copy constructor, both with = default. Which function does Widget b = std::move(a); call?

A copy constructor with = default is user-declared, so the compiler declares no move constructor. std::move(a) calls the copy constructor (ex14).

Question 3 of 40 L3 · Analyze rule-of-five In the video

Choose one: FileHandle deletes its copy operations. Its move constructor is not noexcept. A std::vector<FileHandle> grows. What does it do with the old elements?

It moves them. The vector copies only when a copy is possible. FileHandle cannot copy, so the vector uses the move (ex32).

Question 4 of 40 L1 · Recall raii

Choose one: In RAII, which code releases the resource?

The destructor releases the resource. C++ calls the destructor at each exit from the scope, so you do not write a release call on each path. C++ has no garbage collector for objects.

Question 9 of 40 L1 · Recall raii

Question 11 of 40 L4 · Senior raii

Choose one: std::fclose can fail. Which design is best for the destructor of a file owner?

A destructor is noexcept by default, so a throw from it calls std::terminate (ex30). A throw from a destructor during stack unwinding also calls std::terminate. A close() function lets the caller see the error, as std::fstream::close does.

Question 12 of 40 L1 · Recall resource-ownership

Choose one: Which type owns the memory that it points to?

A std::unique_ptr<int[]> deletes its array in its destructor. A raw int* releases nothing by itself, and a std::span only views memory that another object owns.

Question 13 of 40 L2 · Apply resource-ownership

True or false: The type T* tells the reader that the pointer owns the object.

A raw pointer does not show ownership, and nothing deletes the object when the pointer goes out of scope. The C++ Core Guidelines (R.3) treat a raw T* as a pointer that does not own.

Use an owner type, such as std::unique_ptr<T> or std::vector<T>. Then the type shows the owner.

Question 17 of 40 L2 · Apply special-member-functions

Question 23 of 40 L1 · Recall rule-of-three

Fill the blank: The rule of three names the destructor, the copy constructor and the copy ____blank.

A class that needs one of these three functions almost always needs all three. The usual reason is a raw handle to a resource.

Question 28 of 40 L2 · Apply rule-of-five

Put in order: Put the steps of the FileHandle move assignment in order.

Drag the handle, or use the arrow buttons. With a row focused, press Alt + Up or Alt + Down.

  1. Close the old file if file_ is not null
  2. Copy other.file_ into file_
  3. Set other.file_ to nullptr
  4. Check that this != &other
  5. Return *this

Close the old file first. If you copy the new pointer first, you lose the old pointer. Then the old file stays open. The call std::exchange(other.file_, nullptr) does steps 3 and 4 together.

Question 29 of 40 L2 · Apply rule-of-five

Fill the blank: Complete the move constructor: FileHandle(FileHandle&& other) noexcept : file_{std::exchange(other.file_, ____blank)} {}

std::exchange puts the new value into other.file_ and returns the old value. The source becomes empty, so its destructor does not close the file. The values 0 and NULL do not compile here, because std::exchange deduces an integer type.

Question 30 of 40 L3 · Analyze rule-of-five

Choose one: A class has a copy constructor and a move constructor without noexcept. Why does std::vector copy its elements when it grows?

std::vector uses std::move_if_noexcept. If a move throws during the growth, the vector cannot restore the old elements. Thus it uses the copy constructor. ex21 shows copies 2, moves 0 for the move without noexcept.

Question 35 of 40 L2 · Apply rule-of-zero

The implicit copy operations copy each member, and std::string and std::vector make deep copies. In ex24, a change to the copy does not change the original. This is the rule of zero.

Question 40 of 40 L4 · Senior rule-of-zero

Choose one: A Connection class uses a POSIX socket file descriptor and a receive buffer. Which design is best?

One small RAII class for each resource keeps the rule of five in one place, and Connection follows the rule of zero. The second design must manage two raw resources in each of the five functions. The third design closes one file descriptor twice after a copy.
