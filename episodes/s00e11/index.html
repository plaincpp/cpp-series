const Correctness in C++

About 12 min 43 quiz questions 62 workbook questions
Start the quiz Open the workbook Compiler Explorer (opens in a new tab)

What you learn

  • Use const to stop changes to a variable, to a class object and to an object behind a reference.
  • Read a pointer declaration from right to left and name the part that is const.
  • Write const member functions and explain why a const object needs them.
  • Compare const and constexpr, and use constexpr for a value that the compiler calculates.
  • Use mutable for a cache, and explain why a write through const_cast to a const object is undefined behavior.

Question 5 of 43 L2 · Apply const-variable

True or false: A const int must get its value from a constant that the compiler knows.

A const variable can get its value at run time, for example from std::cin (ex03). It only keeps that value after its initialization.

const means "this value does not change". constexpr means "the compiler knows this value". A const variable must have an initializer, but the initializer can come from run time.

Question 20 of 43 L3 · Analyze const-pointer

Question 21 of 43 L2 · Apply const-pointer

Drag the handle, or use the arrow buttons. With a row focused, press Alt + Up or Alt + Down.

Start at the name and go to the left. Each const applies to the part on its left, or to the type on its right when it is first (ex12).

Question 27 of 43 L3 · Analyze const-member-function

True or false: A const member function cannot change any object.

It cannot change the members of its own object. A pointer member stays a pointer to non-const, so the function can change the object at that address (ex23).

The const of a member function is shallow: the pointer member becomes int* const, not const int*. Use const int* for the member when the class must not change that object.

Question 34 of 43 L4 · Senior constexpr-basics

Choose one: square is constexpr int square(int n) { return n * n; }. Why does constexpr int big = square(100000); stop the build?

10000000000 does not fit in a 32-bit int, and signed overflow is undefined behavior. A constant expression cannot contain undefined behavior ([expr.const]/5), so the compiler stops (ex31).

Question 37 of 43 L3 · Analyze constexpr-basics

Choose one: square is constexpr int square(int n) { return n * n; }. In main, int n = 4;. Does static_assert(square(n) == 16); compile?

A constexpr function gives a constant only for constant arguments. Here, n is a normal int. GCC reports the value of 'n' is not usable in a constant expression. With constexpr int n = 4;, the line compiles.

Question 38 of 43 L3 · Analyze mutable

True or false: A write through a reference from const_cast is always undefined behavior.

It is undefined behavior only when the object itself is const. In ex35, the object max_users is not const, so the write is correct and writes 200.

If the object itself is not const, the write is correct (ex35). If the object is const, the write is undefined behavior (ex34). const_cast changes only the type of the reference or the pointer. Prefer an interface without const_cast.

Question 39 of 43 L4 · Senior mutable

Choose one: A const member function fills a mutable cache. Two threads call it on the same object at the same time. What is the problem?

A write to the same int from two threads without synchronization is a data race ([intro.races]/21). Callers expect a const call to be safe, so protect a mutable cache with a mutex or an atomic.

Question 43 of 43 L4 · Senior const-pointer

Choose one: A class has the data member int* const data_;. What is the effect on the copy operations that the compiler writes?

A copy initializes the new data_, so it works. An assignment must change data_, and a const member cannot change, so the compiler deletes operator= ([class.copy.assign]/7). Clang reports copy assignment operator is implicitly deleted. A const member is a design choice with this cost.
