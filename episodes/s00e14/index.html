Dynamic Memory: new, delete and Why to Avoid Them

About 12 min 37 quiz questions 61 workbook questions
Start the quiz Open the workbook Compiler Explorer (opens in a new tab)

What you learn

  • Use new and delete to make and destroy a heap object, and tell where the pointer and the object are.
  • Match new with delete and new[] with delete[], and find a mismatch with a compiler warning or AddressSanitizer.
  • Find a memory leak from an early return or an exception with LeakSanitizer.
  • Explain why a double delete and a use after delete are undefined behavior, and find them with AddressSanitizer.
  • Use std::unique_ptr and std::make_unique so that the program deletes the object on each path.

Question 11 of 37 L2 · Apply new-expression

Put in order: Put the steps of Ticket* t = new Ticket{7}; and delete t; in order.

Drag the handle, or use the arrow buttons. With a row focused, press Alt + Up or Alt + Down.

  1. The constructor Ticket(int) runs
  2. operator new allocates memory for one Ticket
  3. operator delete frees the memory
  4. delete t; runs the destructor ~Ticket()

new allocates, then constructs. delete does the two steps in the reverse order: it destroys, then frees (ex02, ex34).

Question 14 of 37 L4 · Senior new-expression

Question 20 of 37 L1 · Recall memory-leak

Choose one: Which statement about a memory leak is correct?

A leak is a heap object that the program cannot reach and never deletes. It is not undefined behavior, and the compiler gives no warning (ex15). A tool such as LeakSanitizer finds it.

Question 25 of 37 L1 · Recall double-delete

Choose one: What is a dangling pointer?

After delete, each pointer to the old object dangles (ex20). A read or a delete through it is undefined behavior. A null pointer does not dangle, because it points to no object.

Question 35 of 37 L4 · Senior unique-ptr-preview
