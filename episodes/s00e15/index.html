std::vector and std::map: Your First Containers

About 12 min 36 quiz questions 63 workbook questions
Start the quiz Open the workbook Compiler Explorer (opens in a new tab)

What you learn

  • Use std::vector as the default container, and read its elements with an index, at and a range-for loop.
  • Explain the difference between size and capacity, and predict when push_back moves the elements to a new block of memory.
  • Use std::map to keep values in key order, and find a key with find or contains.
  • Explain why operator[] on a map adds a missing key, and find this bug in code.
  • Compare the lookup cost of std::map and std::unordered_map, and select the correct container for a task.

Question 1 of 36 L3 · Analyze push-back In the video

True or false: This code calls reserve(8), takes a reference to the first element, and then calls push_back. True or false: the reference is still valid.

After reserve(8), the capacity is at least 8. The new size is 4, so push_back does not get a new block, and the elements stay where they are.

A reallocation occurs only when the new size is more than the capacity. Only a reallocation makes the references to the elements invalid. C++23 [vector.modifiers]/1.

Question 3 of 36 L3 · Analyze std-map

Choose one: A std::map has about one million keys. About how many key comparisons does one find use?

A map is a sorted tree, so the cost of find grows with log2 of the size. Two to the power 20 is about one million, so one find uses about 20 comparisons.

Question 9 of 36 L2 · Apply push-back

Put in order: The size of v equals its capacity. Put the steps of v.push_back(x) in order.

Drag the handle, or use the arrow buttons. With a row focused, press Alt + Up or Alt + Down.

  1. Free the old block
  2. Copy or move the elements to the new block
  3. Get a new, larger block of memory

The vector must get the new block before it copies the elements. It must copy them before it frees the old block. After these steps, each reference to an old element is not valid (ex13).

Question 10 of 36 L4 · Senior push-back

Choose one: An empty vector doubles its capacity when it is full. How many copies do 1024 push_back calls make for a type with only a copy constructor?

Each call copies its argument once: 1024 copies. The reallocations copy 1 + 2 + 4 + ... + 512 = 1023 elements, so the total is 2047 (ex14). A growth of one element each time gives about 524000 copies.

Question 22 of 36 L1 · Recall std-map

Fill the blank: By default, a std::map uses the operator ____blank to sort its keys.

The default comparison is std::less<Key>, and it calls <. With a key type that has no <, a call that adds or finds a key does not compile (ex20).

Question 23 of 36 L3 · Analyze std-map

Choose one: With libstdc++, about how many key comparisons does one find use in a std::map with 65536 keys?

libstdc++ uses a balanced tree, a red-black tree. One find compares the key at about log2(n) levels. Then it compares the key one more time to check for equality. The average for 65536 keys is 17.5 comparisons (ex29). A linear search needs 32768 comparisons on average.

Question 24 of 36 L2 · Apply std-map

True or false: A struct with two int members can be the key of a std::map with no more code.

std::map compares keys with <. The struct has no operator<, so a call that adds or finds a key does not compile (ex20, the line with operator[]).

False. Add bool operator<(const Point&) const, or add auto operator<=>(const Point&) const = default; (C++20). Source: https://en.cppreference.com/w/cpp/language/default_comparisons.

Question 25 of 36 L4 · Senior std-unordered-map

Choose one: You keep 10 million user IDs. You look up one exact ID many times, and you never need the IDs in order. Which container is the best fit?

A hash table finds an exact key in O(1) time on average. A std::map needs about 24 comparisons for 10 million keys, and a linear search needs about 5 million. Use std::map when you need sorted order.

Question 26 of 36 L3 · Analyze std-unordered-map In the video

True or false: A lookup in a std::unordered_map takes constant time in every case.

Lookup is O(1) on average and O(n) in the worst case. A hash that puts all 1000 keys in one bucket makes find compare 500 keys on average (ex30).

False. Lookup is O(1) on average and O(n) in the worst case. A good hash spreads the keys over the buckets: with std::hash<int>, one find compares 1 key (ex30).
