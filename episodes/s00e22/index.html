What you learn

  • Write a CMakeLists.txt that builds a static library and an executable, and link them with target_link_libraries.
  • Use a separate build folder and the Ninja generator: cmake -S . -B build -G Ninja, then cmake --build build.
  • Set the C++ standard and the warnings on a target, and explain why CMAKE_CXX_FLAGS is the wrong place.
  • Find the step that gives an error (configure, compile or link), and correct a missing link or include folder.
  • Predict the flags and the NDEBUG setting of the Debug and Release build types.

Question 2 of 41 L3 · Analyze build-target In the video

Choose one: app links to geometry, and main.cpp includes geometry.h. Which step fails?

The include folder is PRIVATE, so only geometry gets it. The compiler cannot find geometry.h for main.cpp. Use PUBLIC to give the folder to app too.

Question 3 of 41 L3 · Analyze compile-options In the video

Choose one: After the correction, a user configures with -DCMAKE_CXX_FLAGS=-fsanitize=address. Which targets get -Werror, and which targets get -fsanitize=address?

target_compile_options with PRIVATE gives -Werror only to app. The file does not set CMAKE_CXX_FLAGS now, so the user value goes to each target (ex10).

Question 4 of 41 L1 · Recall cmake

Choose one: What does CMake make from a CMakeLists.txt file?

CMake is a build system generator. It writes the build files, and the build tool (Ninja or Make) calls the compiler. CMake does not compile your source files.

Question 5 of 41 L2 · Apply cmake

Put in order: Put the steps in order, from cmake -S . -B build -G Ninja to the executable.

Drag the handle, or use the arrow buttons. With a row focused, press Alt + Up or Alt + Down.

  1. Ninja calls g++ to link the object files into the executable
  2. cmake --build build starts Ninja
  3. CMake writes build.ninja in the build folder
  4. CMake reads CMakeLists.txt and finds the C++ compiler
  5. Ninja calls g++ to compile each .cpp file into an object file

The first command reads the project and writes the build files. Then cmake --build runs the build tool. The build tool calls the compiler and the linker.

Question 6 of 41 L2 · Apply cmake

Match the terms: Match each message to the step that gives it.

CMake reads CMakeLists.txt in the configure step. The compiler opens the headers. The linker finds the definitions. assert checks the condition when the program runs.

Question 7 of 41 L2 · Apply cmake

Choose one: You run cmake --build build two times, with no change between the two runs. What does the second run print?

Ninja compares the time of each output file with the time of its input files. All outputs are newer than their inputs, so Ninja does nothing. This is an incremental build.

Question 8 of 41 L3 · Analyze cmake

Choose all that apply: In ex03, main.cpp and geometry.cpp include geometry.h. You change geometry.h and build again. Which steps occur? Select all correct answers.

Select all that apply.

The compiler writes a dependency file for each object file (-MD), so Ninja knows the headers of each .cpp file. Both files include the header, so both compile again. CMakeLists.txt did not change, so the configure step does not run again.

Question 9 of 41 L3 · Analyze cmake

True or false: In ex03, you change only geometry.cpp. The next build also compiles main.cpp again.

main.cpp and its header did not change. Ninja compiles geometry.cpp, makes libgeometry.a again and links app again: 3 steps.

A change in one .cpp file compiles only that file. The link step runs again, because the library changed.

Question 10 of 41 L1 · Recall cmakelists

Fill the blank: The first line of a CMakeLists.txt is ____blank(VERSION 3.28).

cmake_minimum_required sets the oldest CMake version for the project. It also sets the policies of that version.

Question 11 of 41 L2 · Apply cmakelists

Find the bug: The configure step stops with Cannot specify link libraries for target "app" which is not built by this project. Which line has the bug?

Select the line or lines with the bug. Select a line again to clear it.

CMake reads the commands from top to bottom. On line 4, the target app does not exist yet. Put target_link_libraries after add_executable.

Question 12 of 41 L2 · Apply cmakelists

Choose one: CMakeLists.txt has add_executable(app mian.cpp), but the file is main.cpp. Which step gives the error?

The first command (cmake -S . -B build) checks each source file before it writes build.ninja. It stops before the build tool and the compiler start.

Question 13 of 41 L3 · Analyze cmakelists

True or false: After the error Cannot find source file: mian.cpp, the build folder has a build.ninja file from the failed configure step.

The first command stops with an error, so CMake writes no build.ninja. The build folder has only CMakeCache.txt and CMakeFiles.

CMake writes build.ninja only when the first command has no error. Correct the file name and run the first command again. A cmake --build with no build.ninja cannot start.

Question 14 of 41 L1 · Recall build-target

Choose one: What is a target in CMake?

add_executable and add_library make targets. Each target_* command changes one target only.

Question 15 of 41 L2 · Apply build-target

Match the terms: Match each keyword of target_include_directories(geometry <keyword> include) to the targets that get -I.../include.

These keywords set the usage requirements of a target. PUBLIC is PRIVATE and INTERFACE together.

Question 16 of 41 L3 · Analyze build-target

Find the bug: geometry.h is in the folder include. geometry.cpp and main.cpp include it. The compile of geometry.cpp stops with fatal error: geometry.h: No such file or directory. Which line has the bug?

Select the line or lines with the bug. Select a line again to clear it.

Line 7 gives the include folder only to app. The library geometry gets no folder, so the compiler cannot find the header for geometry.cpp. Give the folder to the library: target_include_directories(geometry PUBLIC include). Then app gets it too, through the link.

Question 17 of 41 L4 · Senior build-target

Choose all that apply: report and words are static libraries. report links words with PRIVATE, and app links report. Which statements are correct? Select all correct answers.

Select all that apply.

A static library does not record its dependencies, so CMake adds libwords.a to the link of app (ex17). GNU ld reads archives from left to right, so libwords.a must come after libreport.a.

Question 18 of 41 L1 · Recall add-executable

Fill the blank: add_executable(____blank main.cpp) makes the program build/hello.

The first argument is the target name. On Linux, the executable has the same name.

Question 19 of 41 L2 · Apply add-executable

Predict the output: add_executable(greeter main.cpp greet.cpp) builds this program. The comments show the three files. What does it write?

CMake compiles main.cpp and greet.cpp and links the two object files. greeting("CMake") returns Hello, CMake!.

Question 20 of 41 L3 · Analyze add-executable

Choose one: main.cpp calls greeting() from greet.cpp. CMakeLists.txt has add_executable(greeter main.cpp). What occurs?

CMake compiles only the files in the list. main.cpp compiles, because the header declares greeting. No object file defines it, so the linker stops.

Question 21 of 41 L2 · Apply add-executable

True or false: You must write each header file in add_executable, or the compiler cannot find the header.

The compiler finds a header through #include and the include folders. ex02 lists only main.cpp and greet.cpp, and it builds.

List the .cpp files. Each .cpp file becomes one object file. The compiler does not compile a header alone.

Question 22 of 41 L1 · Recall add-library

Choose one: Which file does add_library(geometry STATIC geometry.cpp) make on Linux?

A static library is an archive of object files with the name lib<name>.a. SHARED makes lib<name>.so.

Question 23 of 41 L2 · Apply add-library

Predict the output: The library geometry and the executable app build with this code. The comments show the files. What does app write?

area(3, 4) is 3 * 4 = 12. perimeter(3, 4) is 2 * (3 + 4) = 14.

Question 24 of 41 L3 · Analyze add-library

Choose one: libgeometry.a builds, but the link of app fails with undefined reference to `geometry::area(int, int)'. Which line corrects CMakeLists.txt?

The linker needs libgeometry.a in the link of app. An include folder or a header helps the compiler, not the linker. The last choice links in the wrong direction.

Question 25 of 41 L3 · Analyze add-library

True or false: With add_library(units SHARED units.cpp), app needs libunits.so when it runs, and CMake writes a run path to the build folder into app.

readelf -d app shows NEEDED libunits.so and RUNPATH /work/weather/build.

If you move libunits.so, app stops at start with cannot open shared object file. The linker copies the needed object files of a static library into the executable, so the archive is not necessary at run time.

Question 26 of 41 L4 · Senior add-library

Choose one: Why does CMake add -fPIC when it compiles the files of a SHARED library?

-fPIC makes position-independent code (GCC manual, Code Gen Options). The loader selects the address of a shared library. CMake does not add -fPIC for the STATIC library of ex03.

Question 27 of 41 L4 · Senior add-library

This is a topological sort. GNU ld reads archives from left to right, so a library must come before the libraries that it uses. CMake does this for you with target_link_libraries.

Question 28 of 41 L1 · Recall build-directory

Choose one: Which command configures the project in the folder build with the Ninja generator?

-S gives the source folder, -B gives the build folder and -G gives the generator. cmake --build is the build step, not the configure step.

Question 29 of 41 L2 · Apply build-directory

Choose all that apply: You run cmake -S . -B build -G Ninja and cmake --build build for ex01. Which files are in build/? Select all correct answers.

Select all that apply.

The build folder holds only the files that CMake and Ninja make: the cache, build.ninja, CMakeFiles and the program. The source files stay in the source folder.

Question 30 of 41 L3 · Analyze build-directory

True or false: An in-source build (cmake . in the source folder) is easy to clean: you delete one folder.

cmake . writes CMakeCache.txt, CMakeFiles, build.ninja and cmake_install.cmake next to main.cpp. You must find and delete each file that CMake made.

cmake . writes its files between your source files, so no single folder holds them. With -B build, all the files that CMake makes are in build/. Delete that folder to start again.

Question 31 of 41 L4 · Senior build-directory

Choose one: You need a Debug build, a Release build and a Clang build of one source folder. Which layout is best?

Each build folder keeps its own CMakeCache.txt and object files, so each build stays incremental. One folder compiles all files again after each change of flags, and copies of the source go out of date.

Question 32 of 41 L2 · Apply build-directory

Fill the blank: cmake -S . -B build -D____blank=ON writes compile_commands.json in the build folder.

compile_commands.json lists the compile command of each file. Editors, clangd and clang-tidy read it.

Question 33 of 41 L1 · Recall compile-options

Fill the blank: target_compile_features(app PRIVATE ____blank) asks for C++23.

cxx_std_23 is a compile feature. CMake adds a -std= flag when the default standard of the compiler is older.

Question 34 of 41 L2 · Apply compile-options

Predict the output: You build this program with the Debug build type. What does it write?

Debug does not define NDEBUG, so assert calls load_settings() one time. A Release build writes settings loaded: 0.

Question 35 of 41 L3 · Analyze compile-options

Choose one: You build the same program (ex15) with -DCMAKE_BUILD_TYPE=Release. What does it write?

Release adds -O3 -DNDEBUG. With NDEBUG, assert(...) becomes an empty expression, so the program never calls load_settings(). Do not put an action that the program needs inside assert.

Question 36 of 41 L1 · Recall compile-options

Match the terms: Match each CMake build type to its compiler flags for GCC (CMake 3.28).

The flags are in CMakeCache.txt as CMAKE_CXX_FLAGS_<TYPE>. With no build type, CMake adds none of them.

Question 37 of 41 L3 · Analyze compile-options

Find the bug: vendor_log is library code that you do not own. The build stops with unused parameter 'level' in vendor_log.cpp. Which line causes it?

Select the line or lines with the bug. Select a line again to clear it.

CMAKE_CXX_FLAGS goes to every target, also to vendor_log. Remove line 4 and write target_compile_options(app PRIVATE -Wall -Wextra -Werror) after add_executable.

Question 38 of 41 L3 · Analyze compile-options

Choose all that apply: A target has only target_compile_features(app PRIVATE cxx_std_23). Which statements are correct for GCC 14? Select all correct answers.

Select all that apply.

CXX_EXTENSIONS is ON by default, so CMake writes -std=gnu++23. The value of __cplusplus is the same. Set CXX_EXTENSIONS OFF to get -std=c++23 and __STRICT_ANSI__.

Question 39 of 41 L2 · Apply compile-options

True or false: With no C++ standard in CMakeLists.txt, GCC 14 compiles the code as C++23.

With no standard, GCC 14 and Clang 19 use their default, C++17: __cplusplus = 201703.

GCC 14 and Clang 19 use C++17 by default: __cplusplus is 201703. Always set the standard on the target with target_compile_features. Then each compiler and each computer uses the same standard.

Question 40 of 41 L4 · Senior cmake

Choose one: Your team uses Ninja on Linux and the Visual Studio generator on Windows. One CI script must build the target app on both. Which build command do you use?

cmake --build reads the generator from CMakeCache.txt and runs the correct build tool. The other commands work with one generator only.

Question 41 of 41 L4 · Senior cmakelists

A policy keeps an old behavior or turns on a new one. For example, policy CMP0155 (new in 3.28) makes CMake scan C++20 files for modules: the two extra Ninja steps in ex05.
