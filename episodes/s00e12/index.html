Namespaces, Header Files and the One Definition Rule

About 12 min 42 quiz questions 62 workbook questions
Start the quiz Open the workbook Compiler Explorer (opens in a new tab)

What you learn

  • Use a header file for declarations and one source file for each definition.
  • Use an include guard or #pragma once, and explain why a guard does not stop a multiple definition.
  • Explain the one definition rule, and correct a multiple definition error with inline.
  • Use namespaces to stop name clashes, and explain why a header must not contain using namespace.
  • Use an anonymous namespace for names that stay in one source file.

Question 1 of 42 L2 · Apply include-guard In the video

Choose one: Where does an include guard stop a second copy of a header?

Only in one source file. Each source file is a new translation unit, and the preprocessor starts again with no guard names (ex09, ex12).

Question 2 of 42 L2 · Apply inline-variable In the video

Choose one: Two source files include the same header. Which line in the header links with no error?

Only the inline variable. The other two lines define the same name in each object file, so the linker reports a multiple definition (ex14, ex15, ex12).

Question 3 of 42 L3 · Analyze namespace In the video

Choose one: The header stats.h contains using std::size;. The file main.cpp includes it and defines a global int size. What happens?

The #include directive copies using std::size; into main.cpp. So std::size and the global size clash in one scope (ex31).

Question 4 of 42 L1 · Recall declaration-vs-definition

Match the terms: Match each line at namespace scope to what it does.

A declaration gives a name and its type. A definition also makes the object or gives the body. Each definition is also a declaration.

Question 5 of 42 L2 · Apply declaration-vs-definition

Choose one: A file has extern int limit; and prints limit in main. No file defines limit. What happens when you build the program?

The declaration is enough for the compiler, so the file compiles (ex04). The linker finds no definition of limit, so the link fails. A global variable is 0 only when a definition exists.

Question 6 of 42 L1 · Recall declaration-vs-definition

True or false: One source file can declare the same function two times.

A name can have many declarations. ex02 declares square two times and limit two times, and it compiles on GCC and Clang.

The rule limits definitions, not declarations. Each file can have only one definition of square.

Question 7 of 42 L2 · Apply declaration-vs-definition

Predict the output: What does this program print?

The two declarations of square and of limit are correct. The file has one definition of each. square(4) is 16 and limit is 10.

Question 8 of 42 L3 · Analyze declaration-vs-definition

Choose one: struct Counter { static int created; Counter() { ++created; } }; No other line defines created. main makes two Counter objects. What happens?

A static data member in a class is only a declaration (ex17). Define it in one source file with int Counter::created = 0;, or write static inline int created = 0; in the class (ex18).

Question 9 of 42 L1 · Recall include-guard

Fill the blank: An include guard starts with #ifndef MONEY_H. The next line is ____blank MONEY_H.

#ifndef keeps the text only when no macro with that name exists. Then #define makes the macro. A second include skips the text up to #endif.

Question 10 of 42 L2 · Apply include-guard

Put in order: main.cpp includes money.h, then price.h. price.h also includes money.h, which has a guard. Put the preprocessor steps in order.

Drag the handle, or use the arrow buttons. With a row focused, press Alt + Up or Alt + Down.

  1. Read #include "money.h" again, in price.h
  2. Find the macro MONEY_H, and skip the text up to #endif
  3. Read the first #include "money.h" in main.cpp
  4. Find no macro MONEY_H, keep the text and define MONEY_H

The macro stays defined to the end of the translation unit. So the second include adds no text, and struct Money has one definition in the file (ex09).

Question 11 of 42 L3 · Analyze include-guard

Find the bug: A source file includes percent.h, then calendar.h. The compiler stops with 'days_in_year' was not declared. percent.h is correct. Which lines have the bug?

Select the line or lines with the bug. Select a line again to clear it.

The two headers use the same guard name. After percent.h, the macro UTILS_H exists, so the preprocessor skips all of calendar.h (ex11). Use a unique name such as CALENDAR_H.

Question 12 of 42 L3 · Analyze include-guard

Choose all that apply: Which statements about include guards and #pragma once are correct? Select all correct answers.

Select all that apply.

A guard works in the preprocessor, in one translation unit only. Each source file starts with no macros, so the guard cannot stop a multiple definition at link time (ex12). Two headers with one guard name hide the second header (ex11).

Question 13 of 42 L2 · Apply include-guard

True or false: counter.h has an include guard and defines int request_count = 0;. Two source files include it. The include guard prevents a link error.

The guard works only in one translation unit. Each object file gets a definition of request_count, so the linker reports multiple definition of request_count'` (ex14).

Write inline int request_count = 0; (ex15), or put extern in the header and one definition in a source file (ex05). A guard and inline solve two different problems.

Question 14 of 42 L1 · Recall header-file

Choose one: Many source files include tax.h. Which line do you put in tax.h?

A header holds declarations. Put the body of add_tax in one source file. A function body or a global variable in a header gives a multiple definition when two source files include it (ex12, ex14).

Question 15 of 42 L2 · Apply header-file

Choose one: car.h declares struct Engine; and holds an Engine* in Car. car.cpp includes engine.h. What does this program print?

main makes an Engine with 150 and gives its address to car. power in car.cpp reads horsepower through the pointer. Only car.cpp needs the full definition of Engine (ex07).

Question 16 of 42 L3 · Analyze header-file

Choose one: car.h has struct Engine; and struct Car { Engine* engine; };. Why does car.h not need to include engine.h?

The compiler knows the size of a pointer without the definition of Engine (ex07). A member Engine engine; needs the full definition, because the compiler must know its size (ex06). Fewer includes make builds faster.

Question 17 of 42 L2 · Apply header-file

Find the bug: The build command is g++ main.cpp convert.cpp. The linker stops with multiple definition of to_seconds(int)'`. Which line has the bug?

Select the line or lines with the bug. Select a line again to clear it.

#include pastes the text of convert.cpp, so both object files define to_seconds. Include a header with the declaration, convert.h, and never include a .cpp file.

Question 18 of 42 L1 · Recall one-definition-rule

Choose one: A program calls add_tax(int), which is not inline. How many definitions of add_tax(int) can the program have?

The one definition rule allows exactly one definition of each used non-inline function in the program. An inline function can have one definition in each translation unit, and all must be the same.

Question 19 of 42 L2 · Apply one-definition-rule

Choose one: tax.h has a guard and defines int add_tax(int cents) with a body. main.cpp and cart.cpp include it. What happens?

Each source file compiles with no error, because each has one definition. main.o and cart.o both have the symbol, so the linker stops (ex12). The compiler error is for two definitions in one file (ex03).

Question 20 of 42 L3 · Analyze one-definition-rule

Choose all that apply: Two source files include one header. Which lines can be in that header with no ODR violation? Select all correct answers.

Select all that apply.

A class definition and an inline definition can be in each translation unit, if they are the same. A non-inline function or variable needs exactly one definition in the program (ex12, ex14).

Question 21 of 42 L2 · Apply one-definition-rule

Put in order: tax.h defines int add_tax(int) with a body. main.cpp and cart.cpp include it. Put the steps that give the link error in order.

Drag the handle, or use the arrow buttons. With a row focused, press Alt + Up or Alt + Down.

  1. The compiler puts a global symbol add_tax(int) in main.o and in cart.o
  2. The preprocessor pastes the body of add_tax into main.cpp and into cart.cpp
  3. The linker finds a second add_tax(int) and reports multiple definition
  4. The linker reads main.o, then cart.o

Each step works on its input. Only the linker sees all object files, so only the linker finds the second definition (ex12).

Question 22 of 42 L3 · Analyze one-definition-rule

Match the terms: Match each nm -C letter on GCC 14 to the symbol that it shows.

ex12 shows T add_tax(int) in two files. That gives the error. ex13 shows W with inline, and ex28 shows t for the anonymous namespace. With -O2, the compiler can expand all calls and keep no add_tax symbol.

Question 23 of 42 L4 · Senior one-definition-rule

Choose one: Two source files each define struct Item, but with different members. A normal build on GCC and Clang shows no message. Which statement is correct?

Class definitions in different files must be the same ([basic.def.odr]). A class makes no linker symbol, so the build is silent on GCC and on Clang (ex19). GCC with -flto finds it and reports -Wodr.

Question 24 of 42 L2 · Apply inline-variable

Choose one: counter.h has inline int request_count = 0;. main.cpp and log.cpp include it. What does this program print?

An inline variable is one object for the whole program. log_request in log.cpp adds 1 two times, and main.cpp reads the same object (ex15).

Question 25 of 42 L3 · Analyze inline-variable

Choose one: config.h has constexpr int max_retries = 3; and inline constexpr int max_users = 100;. Two source files include it. What does this program print?

A constexpr variable at namespace scope has internal linkage. Each source file has its own copy at a different address. inline constexpr makes one object for the program (ex16).

Question 26 of 42 L1 · Recall inline-variable

True or false: The keyword inline forces the compiler to put the function body at each call.

inline lets the same definition be in many translation units. The optimizer decides about inline expansion with or without the keyword.

Today, inline is a rule for definitions, not an order to the optimizer (cppreference, inline specifier).

Question 27 of 42 L2 · Apply inline-variable

Fill the blank: Complete the member so that the class defines it, with no line in a source file: static ____blank int created = 0;

static inline (C++17) defines a static data member in the class (ex18). Without inline, the line in the class is only a declaration (ex17).

Question 28 of 42 L4 · Senior inline-variable

Choose one: A header has constexpr int max_retries = 3; at namespace scope. 20 source files include it. Which statement is correct?

A const or constexpr variable at namespace scope has internal linkage ([basic.link]). For a variable, constexpr makes only a static data member inline, not a namespace-scope variable. Use inline constexpr for one object (ex16).

Question 29 of 42 L3 · Analyze namespace

Predict the output: What does this program print?

A using-declaration in a block hides the global name in that block.

using b::x; makes x mean b::x in main. a::x is 1. ::x selects the global x, which is 3.

Question 30 of 42 L3 · Analyze namespace

Choose one: A file has #include <iterator>, using namespace std; and a global int distance = 0;. What happens when main uses distance?

The using-directive makes std::distance visible as distance. Name lookup finds two names at the same level, so GCC and Clang stop (ex36). Remove the using-directive or rename the variable.

Question 31 of 42 L2 · Apply namespace

Fill the blank: In C++17, namespace ____blank { } has the same effect as namespace app { namespace net { } }.

A nested namespace definition opens the inner namespace in one line (ex22). You can open the same namespace again in other places.

Question 32 of 42 L3 · Analyze namespace

Choose one: shop::Item tea{3}; print(tea); compiles, but the call has no shop::. Why?

For an unqualified function call, lookup also looks in the namespaces of the argument types (ex26). This rule finds operator<< for std::cout too.

Question 33 of 42 L4 · Senior namespace

Choose one: 200 files include your library header. Which choice keeps names short in your code and changes no name lookup in those files?

A using-directive or using-declaration in a header goes into each file that includes it (ex25). A using-declaration in a source file or a function changes only that place.

Question 35 of 42 L2 · Apply anonymous-namespace

Choose one: discount.cpp and invoice.cpp each define a helper int scale(int). The link fails with multiple definition of scale(int)'`. What is the best correction?

An anonymous namespace gives each scale internal linkage, so each file keeps its own helper (ex28). A guard has no effect on the linker, and extern keeps the external linkage.

Question 36 of 42 L3 · Analyze anonymous-namespace

Choose one: counter.h has namespace { int hits = 0; }. main.cpp and log.cpp include it. What does this program print?

Each translation unit has its own anonymous namespace. So each file has its own hits. log_hit changes the copy in log.cpp, and main changes its own copy (ex30).

Question 37 of 42 L2 · Apply anonymous-namespace

True or false: Another source file can call a function in an anonymous namespace if it declares the function first.

A name in an anonymous namespace has internal linkage. A declaration in another file names a different function, and the link fails with undefined reference.

nm shows the helper as a local symbol t, so the linker does not join it with names in other files (ex28).

Question 39 of 42 L4 · Senior anonymous-namespace

Choose one: Which thing can an anonymous namespace do that static at namespace scope cannot do?

static applies to variables and functions only. GCC rejects static struct Line { ... };, and Clang ignores static with a warning (ex34). ex29 puts a class Line in an anonymous namespace in two files.

Question 40 of 42 L4 · Senior include-guard

Choose one: A build copies money.h into two folders. One source file includes both copies. Which protection keeps one definition of Money on every compiler?

Both copies test the same macro, ACME_MONEY_H. So the second copy adds no text (ex32). The line #pragma once identifies a file by its path, or on GCC by its content and time. So two copies can both add text: Clang 19 reports redefinition of 'Money' (ex33). Source: cppreference, Implementation defined behavior control.

Question 41 of 42 L4 · Senior declaration-vs-definition

Choose one: parse.h declares int parse(const char* text);. A new parse.cpp defines int parse(std::string_view text). main.cpp includes parse.h and calls parse("abc"). What happens?

The symbol of a function includes its parameter types. nm -C shows U parse(char const*) in main.o, but parse.o defines only parse(std::basic_string_view<...>) (ex35). The compiler accepts parse.cpp, because the new function is a legal overload.

Question 42 of 42 L2 · Apply namespace

Choose one: The header report.h contains using namespace std. Which files does the directive change?

Every file that includes report.h. The #include directive copies the using-directive into each of these files (ex25).
