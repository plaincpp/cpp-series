Part A: Concept checks

12 questions

Q1

L1 · Recall Short answer inheritance

Write the first line of a class Square that derives from Shape with public inheritance. Which relation between the two classes does it show?

Show answerHide answer to Q1

class Square : public Shape {. Public inheritance shows an is-a relation: a Square is a Shape. So a Square* converts to a Shape*, and a Square binds to a const Shape& (ex01).

Q2

L1 · Recall Short answer inheritance

Which inheritance, public or private, does class Square : Shape give? Which inheritance does struct Square : Shape give?

Show answerHide answer to Q2

class Square : Shape gives private inheritance. struct Square : Shape gives public inheritance. Write public in every base list, so that the code does not depend on the default (ex06; cppreference: derived classes).

Q3

L1 · Recall Short answer base-class

Which code can use a public, a protected and a private member of a base class? Give one answer for each access specifier.

Show answerHide answer to Q3
  • public: all code.
  • protected: the base class and its derived classes (ex05).
  • private: only the base class itself (and its friends). A derived class gets the private members as a part of the object, but it cannot use their names (ex04).

Q4

L2 · Apply Multiple choice base-class

Shape has two constructors. The constructor Shape() sets the name "shape". The constructor explicit Shape(std::string name) sets the name that you give. Square derives from Shape. Its only constructor is explicit Square(int side) : side_{side} {}. What does Square{3}.name() return?

  • a) "shape", because the compiler calls Shape() for the base part
  • b) An empty string, because no Shape constructor runs
  • c) Nothing: the constructor does not compile, because it does not call a Shape constructor
Show answerHide answer to Q4

a) "shape". The Square constructor does not name a base constructor in its member initializer list. So the compiler calls the default constructor of the base (cppreference: constructors and member initializer lists). To get the name "square", write Square(int side) : Shape{"square"}, side_{side} {} (ex03). Without Shape(), the constructor does not compile.

Q5

L1 · Recall Short answer virtual-function

circle is a Circle, and Circle derives from Shape. After Shape* shape = &circle;, what is the static type of *shape? What is its dynamic type? Which one selects a virtual function?

Show answerHide answer to Q5

The static type of *shape is Shape, because the code declares Shape*. The dynamic type is Circle, because the real object is a Circle. The dynamic type selects a virtual function, and the static type selects a non-virtual function (ex07, ex08).

Q6

L1 · Recall Short answer override-specifier

What does override tell the compiler? Which C++ standard added it?

Show answerHide answer to Q6

override tells the compiler that the function must override a virtual function of a base class. If no base function matches, the program does not compile (ex12). C++11 added override and final (cppreference: override specifier).

Q7

L2 · Apply Multiple choice override-specifier

The base class has virtual void draw() const;. Which declaration in the derived class overrides it?

  • a) void draw();
  • b) void draw(int size) const;
  • c) void draw() const;
Show answerHide answer to Q7

c) void draw() const;. The name, the parameter types and const must match. Choice a) has no const, and choice b) has a different parameter. Each one is a new function that hides the base function (ex11).

Q8

L1 · Recall Short answer pure-virtual

What is an abstract class? Can you declare a pointer or a reference to an abstract class?

Show answerHide answer to Q8

An abstract class has at least one pure virtual function. You cannot make an object of it (ex16). You can declare a pointer or a reference to it, and this is the usual use of an interface (ex15).

Q9

L1 · Recall Short answer virtual-destructor

Write the destructor of a base class Shape that makes delete through a Shape* correct. Use the default body.

Show answerHide answer to Q9

With this destructor, delete shape; runs the destructor of the real object first, then ~Shape (ex19).

Q10

L1 · Recall Short answer runtime-polymorphism

Name the two ways to refer to an object, so that a virtual call runs the derived function. Why does a call on a Shape parameter by value not do this?

Show answerHide answer to Q10

A pointer and a reference. A Shape parameter by value is a new Shape object: the copy keeps only the Shape part of the argument. Its dynamic type is Shape, so the call runs the base version (slicing, ex10).

Q11

L2 · Apply Multiple choice runtime-polymorphism

Which container can hold circles and squares and keep the dynamic type of each object?

  • a) std::vector<Shape>
  • b) std::vector<Shape&>
  • c) std::vector<std::unique_ptr<Shape>>
Show answerHide answer to Q11

c) std::vector<std::unique_ptr<Shape>>. a) copies only the Shape part of each object (slicing). b) does not compile, because a std::vector cannot hold references. Each std::unique_ptr<Shape> points to an object of the real type and deletes it (ex30).

Q12

L2 · Apply Multiple choice pure-virtual

Shape has two pure virtual functions, int area() const and int perimeter() const. Each version of Square derives from Shape. For which version does Square square; compile?

  • a) Square declares only int area() const override.
  • b) Square declares int area() const override and int perimeter() const override.
  • c) Square declares int area() const override and int perimeter().
Show answerHide answer to Q12

b) Only this version overrides both pure virtual functions. In a), Square does not override perimeter, so it is abstract too (ex17). In c), int perimeter() has no const, so it is a new function and does not override (ex11). For a) and c), GCC writes cannot declare variable 'square' to be of abstract type 'Square'.

Part D: Explain why

9 questions

Q35

L2 · Apply Explain why inheritance

A Square* converts to a Shape* with no cast. A Shape* does not convert to a Square* with no cast. Explain why. Answer in two sentences.

Show answerHide answer to Q35

Rule: each Square contains a Shape subobject, so a Square* can always point to that Shape part. A Shape* can point to a Shape that is not a Square, so the compiler does not convert it with no cast. A later season shows dynamic_cast for this check at run time.

Q36

L3 · Analyze Explain why base-class

The base constructor runs before the derived constructor, and the destructors run in the reverse order (ex02). Explain why. Answer in two sentences.

Show answerHide answer to Q36

Rule: the derived constructor can use the base part, so the base part must exist first. The derived destructor can also use the base part, so the base part must still exist. Thus the base destructor runs last.

Q37

L3 · Analyze Explain why virtual-function

ex07 prints shape for shape->draw(), and ex08 prints circle. The only change is the word virtual. Explain why. Use the words "static type" and "dynamic type". Answer in three sentences.

Show answerHide answer to Q37

The static type is the type in the code (Shape*), and the dynamic type is the type of the real object (Circle). Without virtual, the compiler uses the static type, so ex07 calls Shape::draw. With virtual, the program uses the dynamic type at run time, so ex08 calls Circle::draw.

Q38

L3 · Analyze Explain why virtual-function

In ex21, the Shape constructor calls the virtual function name(), but the call runs Shape::name, not Circle::name. Explain why the language has this rule. Answer in three sentences.

Show answerHide answer to Q38

Rule: during the Shape constructor, the dynamic type of the object is Shape (cppreference: virtual function specifier, during construction and destruction). The Circle part does not exist yet, and its members have no values yet. A call to Circle::name could read these members, so the language runs Shape::name.

Q39

L3 · Analyze Explain why override-specifier

ex11 builds with no error and prints shape. ex12 adds only override, and it does not compile. Explain why. Answer in three sentences.

Show answerHide answer to Q39

In ex11, Circle::draw has no const, so it does not match Shape::draw() const and is a new function. The call through const Shape& runs Shape::draw, and only a -Woverloaded-virtual warning shows the problem. In ex12, override tells the compiler that the function must override, so the compiler stops with marked 'override', but does not override.

Q40

L3 · Analyze Explain why pure-virtual

Most pure virtual functions need no body. A pure virtual destructor must have a body (ex25). Explain why. Answer in two sentences.

Show answerHide answer to Q40

Rule: each derived destructor calls the destructor of its base class, also when the base destructor is pure. So a pure virtual destructor always needs a body. A virtual call never runs a pure virtual function. So another pure virtual function needs a body only when code calls it with a qualified name, such as Shape::describe() (Q22). Without the body, the linker stops with undefined reference.

Q41

L3 · Analyze Explain why virtual-destructor

In ex18, AddressSanitizer reports that the program allocated 40 bytes and deallocated 8 bytes. Explain why the delete is undefined behavior, and where the two numbers come from. Answer in three sentences.

Show answerHide answer to Q41

Rule: delete through a base pointer is undefined behavior when the base destructor is not virtual ([expr.delete]/3). The program allocated a Label: an 8-byte vptr and a 32-byte std::string, 40 bytes in total. The delete used the static type Shape, which has only the 8-byte vptr, so ASan saw a release with the wrong size.

Q42

L4 · Senior Explain why virtual-function

In ex20, one virtual function changes sizeof from 4 to 16. Explain the extra 12 bytes. Then tell what this change costs for a std::vector of 10 million objects. Answer in three sentences.

Show answerHide answer to Q42

The object gets an 8-byte vptr, and alignment to 8 bytes adds 4 bytes of padding after the int, so sizeof is 16 (ex20). For 10 million objects, the memory goes from 40 MB to 160 MB. Fewer objects fit in each cache line, so a loop over the vector reads 4 times more memory.

Q43

L3 · Analyze Explain why runtime-polymorphism

A std::vector<Shape> loses the behavior of the derived classes. A std::vector<std::unique_ptr<Shape>> keeps it. Explain why. Answer in three sentences.

Show answerHide answer to Q43

A std::vector<Shape> holds Shape objects of a fixed size, so push_back copies only the Shape part of a derived object (slicing). A std::vector<std::unique_ptr<Shape>> holds pointers to the real objects, which keep their dynamic type. A virtual call through each pointer runs the function of the derived class, and the virtual destructor deletes the full object (ex30).

Part F: Design and trade-offs

5 questions

Q51

L4 · Senior Design base-class

A team needs a Stack of int values. Design 1: class Stack : public std::vector<int>. Design 2: class Stack with a private member std::vector<int> items_. Compare the two designs. Talk about the public interface, the is-a rule, delete through a std::vector<int>*, and later changes. Give a recommendation.

Show answerHide answer to Q51

A strong answer covers these points:

  • Interface. Design 1 makes every std::vector function public, for example insert, erase and operator[]. Users can break the stack order. Design 2 shows only push, pop, top and size.
  • Is-a. A stack is not a vector, because it cannot do all that a vector can do. Public inheritance is for is-a. A data member is for has-a.
  • Delete. std::vector<int> has no virtual destructor. delete through a std::vector<int>* that points to a Stack is undefined behavior.
  • Changes. In Design 2, you can change the member to std::deque<int> and no user code changes.
  • Recommendation. Design 2 (composition). Use public inheritance only for a real is-a relation.

Q52

L4 · Senior Design runtime-polymorphism

Compare a virtual function in a base class and a function template for two cases. Case 1: a program loads export formats (CSV, JSON, XML) from a configuration file at run time. Case 2: a math library computes the length of a vector of float or of double. Talk about the time of the choice, the cost of each call, the size of the code and the compile time. Give a recommendation for each case.

Show answerHide answer to Q52

A strong answer covers these points:

  • Time of the choice. A virtual function selects the code at run time. A template selects the code at compile time.
  • Case 1. The format comes from a file at run time, so the compiler cannot know it. Use an interface Exporter with virtual functions and a factory that returns std::unique_ptr<Exporter> (ex27).
  • Case 2. The compiler knows the types float and double, and the program calls the small function often. A template gives one function for each type, and the compiler can inline each call.
  • Costs. A virtual call costs an indirect call and stops most inlining. A template makes more machine code and longer compile times, and its errors are long (S00E21).
  • Recommendation. Virtual functions for case 1, a template for case 2.

Q53

L4 · Senior Design virtual-destructor

A base class Plugin has virtual functions. Rule C.35 of the C++ Core Guidelines allows a public virtual destructor or a protected non-virtual destructor. Compare the two. Talk about who can delete through Plugin*, std::unique_ptr<Plugin>, the cost, and which mistakes each one stops. Give a recommendation for a plugin system that stores plugins in a std::vector.

Show answerHide answer to Q53

A strong answer covers these points:

  • Public virtual. Any code can delete a plugin through Plugin* or std::unique_ptr<Plugin>, and the destructor of the full object runs (ex19). The cost is small: the vtable gets entries for the destructor, and the object already has a vptr, because the class has virtual functions.
  • Protected non-virtual. delete plugin_ptr; and std::unique_ptr<Plugin> do not compile, because only Plugin and its derived classes can call a protected destructor. So the undefined behavior of ex18 cannot occur. But the code must delete each plugin through its real type.
  • Mistakes. Both rules stop the bad delete. A public non-virtual destructor stops nothing, and only a -Wall warning or ASan finds the bug.
  • Recommendation. For a std::vector<std::unique_ptr<Plugin>>, use a public virtual destructor. A protected non-virtual destructor is good for a base class that only adds functions. No code then owns objects through a base pointer.

Q54

L4 · Senior Design pure-virtual

A library has class Storage. Design 1: only pure virtual functions (an interface). Design 2: virtual functions with default bodies that derived classes can override. Compare the two. Talk about forgotten overrides, shared code, changes to the base class and tests with a fake storage class. Give a recommendation.

Show answerHide answer to Q54

A strong answer covers these points:

  • Forgotten overrides. With only pure virtual functions, the compiler stops when a derived class forgets a function (ex17). With default bodies, a forgotten override compiles and runs the default.
  • Shared code. Default bodies let derived classes share code. A pure virtual function can also have a body that overrides call with Storage::save() (Q22).
  • Changes. A new pure virtual function breaks every derived class, so each team must update. A new virtual function with a default body breaks nothing, but it can hide a wrong default.
  • Tests. A pure interface is easy to fake in tests, because a fake class has no base code that runs.
  • Recommendation. Use a pure interface for the public contract. Put shared code in a separate helper class or in a pure virtual function with a body.

Q55

L4 · Senior Design virtual-function

A game updates 10 million particles in each frame. Each particle is Fire, Smoke or Spark, and each has a virtual update(). A profile shows that the virtual calls cost too much time. Give two or three designs that cost less. Talk about the virtual call, inlining, the memory layout and the cache. Give a recommendation.

Show answerHide answer to Q55

A strong answer covers these points:

  • The cost. Each call reads the vptr and the vtable, and the compiler cannot inline it. The objects are on the heap at different addresses, so the loop also has cache misses.
  • Design 1: one vector for each type. std::vector<Fire>, std::vector<Smoke> and std::vector<Spark>, and a loop over each. The compiler can inline the direct calls, and the objects are next to each other in memory.
  • Design 2: final. Mark the classes final. When the compiler knows the real type, it can call the function directly. It does not help a loop over base pointers to objects of mixed types. It helps only where the code already knows the real type.
  • Design 3: a type field or std::variant (a later season). No vptr in each object. A switch on a small type field can be faster than an indirect call, but measure it.
  • Recommendation. Design 1. Measure before and after the change, because the cache effect is often larger than the cost of the call.

Part G: Interview questions

7 questions

Q56

L3 · Analyze Interview virtual-function

"What occurs, step by step, when you call a virtual function through a base pointer? What does it cost?"

Show answerHide answer to Q56

A strong answer covers these points:

  • Main fact. The standard tells only that the call runs the function of the dynamic type. GCC and Clang use the Itanium C++ ABI: each object has a hidden vptr to the vtable of its class.
  • Steps. Read the vptr from the object. Read the function address from the slot of draw in the vtable. Call that address with the object as this.
  • Cost. Two memory reads and one indirect call. The compiler usually cannot inline the call, and the vptr makes each object larger: in ex20, from 4 to 16 bytes.
  • Follow-up: "Who sets the vptr?" The constructor of each class sets it, base first. So in a base constructor, the vptr points to the base vtable (ex21).
  • Follow-up: "When can the compiler remove the virtual call?" It can do this when it knows the dynamic type. Examples: a direct call on an object, or a final class.

Q57

L3 · Analyze Interview virtual-destructor

"Why does a base class need a virtual destructor? When does a class not need one?"

Show answerHide answer to Q57

A strong answer covers these points:

  • Main fact. delete through a base pointer is undefined behavior when the base destructor is not virtual ([expr.delete]/3). Do not trust any result of such a program. Use AddressSanitizer to find the bug.
  • Example. ex18: ASan reports new-delete-type-mismatch, 40 bytes allocated and 8 bytes deallocated. std::unique_ptr<Shape> has the same problem.
  • When not needed. A class that is not a base class, a final class, or a base class that no code deletes through a base pointer. For the last case, rule C.35 of the C++ Core Guidelines recommends a protected non-virtual destructor.
  • Follow-up: "Does the compiler warn?" -Wall warns at the delete only when the class has virtual functions. Without a virtual function, no warning occurs, but the delete is still undefined behavior.

Q58

L4 · Senior Interview override-specifier

"What do override and final do? Why do many teams use override on every override?"

Show answerHide answer to Q58

A strong answer covers these points:

  • Main fact. The specifier override tells the compiler that a function must override a base virtual function. The specifier final on a function stops more overrides. On a class, it stops more derived classes. Both came in C++11.
  • Example. A missing const makes a new function that does not override (ex11). With override, the compiler stops (ex12).
  • Why every override. A base class can change later, for example a new parameter. Then each override that no longer matches becomes a compile error, not a silent bug.
  • Follow-up: "Is override a keyword?" No. It is an identifier with a special meaning after a function declarator (cppreference: override specifier). Old code that uses override as a name still compiles.
  • Follow-up: "Does final make code faster?" It can. When the type is final, the compiler can replace a virtual call with a direct call.

Q59

L4 · Senior Interview runtime-polymorphism

"What is slicing? Give two places where it occurs, and tell how you prevent it."

Show answerHide answer to Q59

A strong answer covers these points:

  • Main fact. Slicing occurs when you copy a derived object into a base object. The copy keeps only the base part, and its dynamic type is the base type.
  • Where. A parameter by value (ex10), a std::vector<Shape> (quiz q30), and a copy such as Shape copy = square; (Q20).
  • Prevention. Pass by reference or by pointer. Store std::unique_ptr<Shape> in containers. Make the base class abstract, or delete its public copy operations. Rule C.67 of the C++ Core Guidelines recommends this for polymorphic classes. Then a slicing copy does not compile.
  • Follow-up: "How do you copy a polymorphic object?" Give the base class a virtual clone() function that returns std::unique_ptr<Shape>. Each derived class makes a copy of its own type.

Q60

L4 · Senior Interview virtual-function

"Can you call a virtual function in a constructor? What occurs? What occurs when the function is pure virtual?"

Show answerHide answer to Q60

A strong answer covers these points:

  • Main fact. Yes, the call compiles. It runs the version of the class whose constructor runs now, not the override of a derived class (ex21).
  • Reason. The derived part does not exist yet, so its members have no values yet. The same rule applies in destructors (Q18).
  • Pure virtual. A virtual call to a pure virtual function from a constructor or a destructor of an abstract class is undefined behavior ([class.abstract]; cppreference: abstract class).
  • Correction. Give the data to the base constructor as a parameter. Or call the function after construction, for example in a factory function.

Q61

L3 · Analyze Interview pure-virtual

"What is an abstract class? Can a pure virtual function have a body? Give a reason to write one."

Show answerHide answer to Q61

A strong answer covers these points:

  • Main fact. An abstract class has at least one pure virtual function (= 0). You cannot make an object of it, but you can use pointers and references to it (ex15, ex16).
  • Body. A pure virtual function can have a body outside the class. A derived class must still override it, and the override can call the body with Base::function() (Q22).
  • A reason. Shared code for all overrides. Also, a pure virtual destructor must have a body, because each derived destructor calls it (ex25). Use it when a class needs to be abstract but has no other pure virtual function.
  • Follow-up: "Is a derived class abstract?" Yes, until it overrides every pure virtual function (ex17).

Q62

L4 · Senior Interview inheritance

"What is the difference between public, protected and private inheritance? When do you use private inheritance, and what do you use more often in its place?"

Show answerHide answer to Q62

A strong answer covers these points:

  • Main fact. The access of the base class sets the access of the inherited members. With public inheritance, public members stay public. With protected inheritance, the derived class has them as protected members. With private inheritance, it has them as private members. Then only the derived class can convert itself to the base type (ex06).
  • Public. Use it for is-a. Only public inheritance lets all code use a Derived* as a Base*.
  • Private. It means "is implemented with". The derived class uses the base code, but users do not see the base interface.
  • Usual choice. A private data member (composition) gives the same result with fewer surprises, so most teams prefer it (Q51). Private inheritance is useful when the derived class must override a virtual function of the base class.
  • Follow-up: "What is the default?" Private for class, public for struct.
