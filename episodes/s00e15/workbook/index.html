Part A: Concept checks

12 questions

Q1

L1 · Recall Short answer std-vector

What is a std::vector<T>? Where are its elements in memory? What occurs to the elements when the lifetime of the vector ends?

Show answerHide answer to Q1

A std::vector<T> is a dynamic array: a container that owns a sequence of elements of type T and can change its size at run time. The elements are in one contiguous block of memory on the heap, so v.data() and &v[0] give the same address (ex03). The vector object itself holds only pointers to that block (ex07). When the lifetime of the vector ends, its destructor destroys each element and frees the block. Source: cppreference, std::vector.

Q2

L1 · Recall Multiple choice std-vector

Which call checks the index and throws std::out_of_range for a bad index?

  • a) v[i]
  • b) v.at(i)
  • c) *(v.data() + i)
Show answerHide answer to Q2

b) v.at(i). The function at compares i with size() and throws std::out_of_range for a bad index (ex05). The expressions v[i] and *(v.data() + i) do no check, so a bad index is undefined behavior (ex06).

Q3

L1 · Recall Short answer push-back

What does push_back do? How is emplace_back different?

Show answerHide answer to Q3

push_back(value) adds a copy of value (or moves it) to the end of the vector. The function emplace_back(args...) makes the new element in place: it gives args to the constructor of T. So words.emplace_back(3, 'z') makes the string zzz with no temporary string (ex15). Both can cause a reallocation when the size equals the capacity.

Q4

L1 · Recall Short answer size-capacity

Define the size and the capacity of a vector. Which of the two is always larger or equal?

Show answerHide answer to Q4

The size (size()) is the number of elements in the vector. The capacity (capacity()) is the number of elements that fit in the current block without a new block. The capacity is always larger than or equal to the size. Source: cppreference, std::vector::capacity.

Q5

L2 · Apply Multiple choice size-capacity

The code is std::vector<int> v(5); v.reserve(2);. What are v.size() and v.capacity() now?

  • a) 5 and 5
  • b) 2 and 2
  • c) 5 and 2
Show answerHide answer to Q5

a) 5 and 5. reserve(n) does nothing when n is not more than the capacity. It never removes elements and never makes the capacity smaller, so the size and the capacity stay 5. Checked in cpptv-toolchain:1 on GCC, Clang and libc++. Source: cppreference, std::vector::reserve.

Q6

L1 · Recall Short answer std-map

What does a std::map<Key, T> hold? In which order does a range-for loop visit its elements? Can two elements have the same key?

Show answerHide answer to Q6

A std::map<Key, T> holds key-value pairs. Each element is a std::pair<const Key, T>: first is the key and second is the value. A range-for loop visits the elements in sorted key order, with < as the default comparison (ex16). Two elements cannot have the same key: each key is unique.

Q7

L2 · Apply Multiple choice std-map

What does m.find(key) return when the key is not in the map?

  • a) nullptr
  • b) It throws std::out_of_range.
  • c) m.end()
Show answerHide answer to Q7

c) m.end(). Compare the result with m.end() before you use it (ex17). The function find never throws for a missing key. It returns an iterator, not a pointer. Only at throws std::out_of_range.

Q8

L1 · Recall Short answer std-unordered-map

How does a std::unordered_map find the element for a key? Name the two operations that it uses on the key.

Show answerHide answer to Q8

The table calls the hash function std::hash<Key> on the key. The hash value selects one bucket. Then the table compares the key with each key in that bucket with ==. So the two operations are the hash and the equality comparison (ex31).

Q9

L2 · Apply Multiple choice std-unordered-map

What must a key type have for std::unordered_map<Key, int> with the default template arguments?

  • a) A specialization of std::hash<Key> and operator==
  • b) operator<
  • c) A default constructor
Show answerHide answer to Q9

a) A specialization of std::hash<Key> and operator==. The default template arguments are std::hash<Key> and std::equal_to<Key>. A struct with no hash does not compile: GCC writes use of deleted function 'std::hash<Point>::hash()' (ex32). operator< is what std::map needs.

Q10

L1 · Recall Short answer map-subscript

What does m[key] do when the key is not in the map? Which value does it give for a std::map<std::string, int> and for a std::map<std::string, std::string>?

Show answerHide answer to Q10

m[key] first adds the key with a value-initialized value. Then it returns a reference to that value. For a std::map<std::string, int>, the new value is 0. For a std::map<std::string, std::string>, the new value is an empty string (ex25). The size of the map increases by 1 (ex21). Source: cppreference, std::map::operator[].

Q11

Part D: Explain why

10 questions

Q35

L2 · Apply Explain why std-vector

Explain why std::vector<int> a(3); and std::vector<int> b{3}; make different vectors. Give the size and the elements of each.

Show answerHide answer to Q35

Rule: list-initialization with braces selects a constructor that takes a std::initializer_list first. So b{3} uses the list constructor and has one element, 3. Parentheses never select that constructor, so a(3) uses the count constructor and has three elements, 0 0 0 (ex02). Source: cppreference, List-initialization.

Q36

L3 · Analyze Explain why std-vector

A C function double average(const int* values, std::size_t count) reads count values from one block of memory. Explain why the call average(v.data(), v.size()) is correct for a std::vector<int> v. Explain why you cannot do the same with a std::map<int, int>.

Show answerHide answer to Q36

Rule: a std::vector keeps its elements next to each other in one block (ex03: data() equals &values[0], and &values[3] - &values[0] is 3). The function data() returns a pointer to the first element, and the range from data() to data() + size() is valid. So the C function can read the elements with values[i] for each i less than count.

A std::map keeps each element in a separate node on the heap. So its elements are not in one block, and it has no data() function. Copy the values into a vector first. Source: cppreference, std::vector::data.

Q37

L3 · Analyze Explain why push-back

Explain why a reference to v[0] can become invalid after v.push_back(x). When does it stay valid?

Show answerHide answer to Q37

Rule: when the new size is larger than the capacity, push_back gets a new block, moves the elements to it and frees the old block. All references, pointers and iterators to the old elements then refer to freed memory (ex13: heap-use-after-free). When the capacity is larger than the size before the call, there is no reallocation, and the references stay valid (quiz q01). So call reserve first, or keep an index instead of a reference. Source: cppreference, std::vector::push_back.

Q38

L4 · Senior Explain why push-back

Some push_back calls copy all elements of the vector. Explain why push_back is still amortized constant time. Use the numbers of ex14, and say what occurs if the vector adds only 10 elements of capacity each time.

Show answerHide answer to Q38

A reallocation copies all elements, but the capacity doubles each time, so reallocations become rare. For 1024 push_back calls, the reallocations copy 1 + 2 + 4 + ... + 512 = 1023 elements. With the 1024 copies of the arguments, the total is 2047 copies, less than 2 for each call (ex14). The cost for each call is thus a constant on average: amortized O(1). If the capacity grows by only 10 each time, the reallocations copy 10 + 20 + ... + 1020 = 52530 elements, about 51 for each call. That cost grows with the size, so the average cost is O(n) for each call.

Q39

L3 · Analyze Explain why size-capacity

ex10 counts 11 new blocks for 1000 push_back calls, and 0 new blocks after reserve(1000). Explain both numbers.

Show answerHide answer to Q39

Without reserve, libstdc++ doubles the capacity each time the vector is full: 1, 2, 4, 8, 16, 32, 64, 128, 256, 512 and 1024. These are 11 new blocks for 1000 elements (ex09, ex10). With reserve(1000), the vector gets one block for 1000 elements before the loop. No push_back in the loop finds the vector full, so the loop makes 0 new blocks.

Q40

L3 · Analyze Explain why std-map

ex29 counts 5.3, 11.5 and 17.5 comparisons on average for one find in a map with 16, 1024 and 65536 keys. Explain why the count grows so slowly.

Show answerHide answer to Q40

Rule: libstdc++ and libc++ implement std::map as a red-black tree, a balanced binary search tree. The header comments say so (bits/stl_tree.h, c++/v1/__tree). One find goes from the root down one path to the bottom of the tree, with one comparison at each level. Then it compares the key one more time to check for equality (_M_find in bits/stl_tree.h).

A balanced tree with n keys has about log2(n) levels. So each time the number of keys doubles, a find needs only one more comparison. The values of log2(n) are 4, 10 and 16, and the averages 5.3, 11.5 and 17.5 are about 1.5 more than these values (ex29).

Q41

L3 · Analyze Explain why std-unordered-map

With a good hash, one find in ex30 compares 1 key. With a hash that always returns 0, it compares 500 keys on average. Explain why.

Show answerHide answer to Q41

With a good hash, the keys spread over the buckets. The table keeps the load factor at 1 or less, so a bucket holds about one key, and find compares about 1 key (ex30, ex31). A hash that always returns 0 puts all 1000 keys in the same bucket. Then find compares the keys in that bucket one after the other, like a linear search: n / 2 = 500 comparisons on average.

Q42

L2 · Apply Explain why map-subscript

Explain why scores["Ali"] does not compile when scores is a const std::map<std::string, int>&, but scores.at("Ali") compiles.

Show answerHide answer to Q42

Rule: on a const object, you can call only const member functions. The operator [] adds a missing key, so it changes the map. Thus the class does not declare it const (ex23). The function at never adds a key: it throws std::out_of_range for a missing key. So at has a const overload that returns a const reference. Sources: cppreference, std::map::operator[], cppreference, std::map::at.

Q43

L3 · Analyze Explain why map-subscript

Point has only the constructor Point(int, int). Explain why places["home"] = Point{1, 2}; does not compile for a std::map<std::string, Point> (ex26). Which calls can add or change the element?

Show answerHide answer to Q43

Rule: operator[] must add a value-initialized value when the key is missing. The compiler builds that code for each call, also for a key that is there at run time. The type Point has no default constructor, so the call does not compile: GCC writes no matching function for call to 'Point::Point()' (ex26). These calls do not need a default constructor: insert({"home", Point{1, 2}}), emplace("home", Point{1, 2}), try_emplace("home", 1, 2) and insert_or_assign("home", Point{1, 2}). To change a value that is there, use places.at("home") = Point{3, 4};. All five calls compile and run on GCC and Clang.

Q44

L3 · Analyze Explain why std-unordered-map

In ex36, a reference to a value in a std::unordered_map stays valid after 1000 inserts and a rehash. A reference to a vector element does not stay valid after a reallocation (ex13). Explain the difference.

Show answerHide answer to Q44

Rule: std::map and std::unordered_map keep each element in its own node on the heap. A rehash makes a new bucket array and links the nodes to it, but the nodes stay at the same address. So references to the values stay valid (ex36), but iterators become invalid after a rehash. A vector keeps all elements in one block, and a reallocation moves each element to a new block (ex13). Source: cppreference, std::unordered_map::insert ("References are not invalidated").

Part F: Design and trade-offs

5 questions

Q52

L4 · Senior Design size-capacity

A program reads 1 million sensor values into a vector. It knows the count before it starts. Compare three designs: push_back with no reserve, reserve and then push_back, and resize and then values[i] = .... Give a recommendation.

Show answerHide answer to Q52
  • push_back with no reserve: 21 new blocks for 1 million values, with the capacities 1, 2, 4, ... 1048576. The reallocations copy 1 + 2 + ... + 524288 = 1048575 elements in total, about 1 for each value (ex14 uses the same logic). During the last reallocation, the old block (524288 elements) and the new block (1048576 elements) exist together. So the memory peak is about 1.6 times the final data. All numbers: checked in cpptv-toolchain:1.
  • reserve, then push_back: one block and no reallocation (ex10). The size always equals the number of values that the program read, so a short file gives a correct, shorter vector.
  • resize, then values[i] = ...: one block, but resize first writes 0 to each element. If the file has fewer values, the zeros at the end look like real data.
  • Recommendation: reserve(count) and then push_back. It has one allocation and the size is always correct.

Q53

L4 · Senior Design std-unordered-map

A phone book holds 10 million names. The program looks up one exact name many times each second. Once each day, it writes all names in alphabetical order. Compare std::map, std::unordered_map and a sorted std::vector. Give a recommendation.

Show answerHide answer to Q53
  • std::map: about 24 levels for 10 million names (log2 of 10 million is about 23.3). Each lookup does about 24 string comparisons and follows about 24 pointers to nodes in different places in memory. The output in alphabetical order needs no extra work.
  • std::unordered_map: O(1) lookup on average, with one hash and about one string comparison. The standard does not specify the order. So the daily output must copy the names to a vector and sort them: O(n log n) one time each day. The buckets use more memory.
  • Sorted std::vector: a binary search also needs about 24 comparisons. But the data is in one block, so it uses less memory and has fewer cache misses than the map. An insert or an erase in the middle moves all elements after it: O(n).
  • Recommendation: for many lookups and a daily sorted output, use std::unordered_map and sort a copy one time each day. If the names change almost never, a sorted vector is also a good choice. Measure with real data before you decide.

Q54

L4 · Senior Design std-map

A game keeps a score for each player name. It must find a player fast and also write the table in alphabetical order after each change. Players join and leave all the time. Compare std::map<std::string, int> and a std::vector of name-score pairs. Give a recommendation.

Show answerHide answer to Q54
  • std::map<std::string, int>: find, insert and erase are O(log n). The loop over the map gives the alphabetical table after each change with no sort (ex16).
  • Unsorted vector of pairs: an insert at the end is fast, but each find is O(n). Each output needs a sort: O(n log n) after each change.
  • Sorted vector of pairs: find is a binary search, O(log n), and the output is free. But each join and each leave moves the elements after the position: O(n).
  • Recommendation: std::map, because the program changes the data often and needs the sorted order after each change. A sorted vector is better only when changes are rare and the table is small.

Q55

L4 · Senior Design map-subscript

You write a function that reads a setting from a const std::map<std::string, int>. The setting can be missing. Compare four designs: operator[], at with an exception, a default value parameter, and a return of std::optional<int>. Give a recommendation.

Show answerHide answer to Q55
  • operator[]: does not compile on a const map (ex23). On a non-const map, it adds the missing setting with the value 0, and the caller cannot see that the setting is missing.
  • at with an exception: works on a const map (ex24). A missing setting is a normal case here, so an exception for it makes the code long and slow on that path.
  • A default value parameter, int setting(const map&, name, int fallback): short and clear for the caller. The caller cannot tell a missing setting from a setting equal to the default value.
  • std::optional<int> (C++17): the return type tells that the value can be missing, and the caller decides what to do. It uses one find.
  • Recommendation: use find inside the function and return std::optional<int>. Add a version with a default value when most callers have a clear default. Use at only when a missing setting is an error.

Q56

L4 · Senior Design std-vector

A program keeps a list of points. In one case the list always has 4 points. In a second case the count comes from a file. Compare a C array, std::array and std::vector for each case. Give a recommendation.

Show answerHide answer to Q56
  • Always 4 points: std::array<Point, 4> keeps the 4 points in the object, with no heap block. It knows its size, you can copy and compare it, and at checks the index. A C array has the same layout. But it converts to a pointer when you pass it to a function, so the function loses the size.
  • Count from a file: only std::vector can get its size at run time. It allocates one heap block and grows with push_back.
  • Recommendation: std::array<Point, 4> for the fixed case and std::vector<Point> for the case with the count from the file. Do not use a C array in new code. A std::vector is also correct for 4 points, but it costs one heap allocation.

Q57

L4 · Senior Interview push-back

What occurs, step by step, when you call push_back on a full std::vector? What does it cost?

Show answerHide answer to Q57

Main fact: push_back on a full vector makes a reallocation.

  1. It finds that size() == capacity().
  2. It gets a larger block. libstdc++ and libc++ double the capacity (ex09).
  3. It makes the new element in the new block, and it moves or copies the old elements to the new block.
  4. It destroys the old elements and frees the old block.
  5. It changes its three pointers to the new block.

Cost: this call is O(n), but the doubling makes the average cost of push_back O(1) amortized: 2047 copies for 1024 calls (ex14). Each reference, pointer and iterator to an old element is now invalid (ex13).

Follow-up questions:

  • Why does a noexcept move constructor matter? push_back has the strong exception guarantee. The vector moves the elements only when the move constructor cannot throw, or when the type has no copy constructor. If not, it copies them, so a throw leaves the old block unchanged. Source: cppreference, std::vector::push_back.
  • How do you avoid the reallocations? Call reserve with the final count (ex10).

Q58

L4 · Senior Interview std-unordered-map

When do you use std::map, and when do you use std::unordered_map?

Show answerHide answer to Q58

Main fact: use std::map when you need the keys in sorted order. Use std::unordered_map for fast lookup by an exact key.

  • std::map is a balanced tree: O(log n) for lookup, insert and erase in every case. It needs < on the key (ex20). A loop visits the keys in sorted order.
  • std::unordered_map is a hash table: O(1) on average, O(n) in the worst case (ex30). It needs a hash and == on the key (ex32). The standard does not specify the order of a loop.

Numbers: one find in a map with 65536 keys uses 17.5 comparisons on average (ex29). In an unordered_map with a good hash, it uses about 1 comparison (ex30).

Trade-offs: the hash table uses more memory for its buckets, and a bad hash or a rehash can make one operation slow. The tree gives a stable cost and sorted output.

Follow-up questions:

  • Can an attacker make an unordered_map slow? Yes. Keys that all go to one bucket make each lookup O(n). A map has no such worst case.
  • What does a struct key need? For std::map, operator< or a comparison type. For std::unordered_map, a hash type and operator==.

Q59

L3 · Analyze Interview map-subscript

Why is m[key] a bad way to look up a key that can be missing? Give three better ways.

Show answerHide answer to Q59

Main fact: m[key] adds a missing key with a value-initialized value. So a read can change the map.

  • It increases the size and uses memory for each missing key (ex21).
  • After the read, the code cannot tell a missing key from a key with the value 0.
  • It does not compile on a const map (ex23), and the value type needs a default constructor (ex26).

Better ways:

  1. find: returns an iterator, or end() for a missing key. It does one lookup and gives the value (ex22).
  2. contains (C++20): returns bool (ex17).
  3. at: returns the value, or throws std::out_of_range (ex24).

Follow-up question: When is m[key] correct? It is correct when you must add the key, for example ++counts[word] (ex19).

Q60

L4 · Senior Interview size-capacity

What is the difference between reserve and resize? Does clear free the memory of a vector?

Show answerHide answer to Q60

Main fact: reserve(n) changes only the capacity. It makes no elements, so the size does not change (ex11). resize(n) changes the size: it makes value-initialized elements or destroys elements at the end. It can also increase the capacity.

clear: it destroys the elements and sets the size to 0, but it keeps the capacity. The capacity stays as it was: 10 in ex11.

To free the memory:

  • shrink_to_fit() is a non-binding request. libstdc++ follows it and gives capacity 0 (ex11). Source: cppreference, std::vector::shrink_to_fit.
  • std::vector<int>().swap(v); gives v the empty block of a temporary vector. After it, the capacity is 0 on GCC and Clang.

Follow-up question: Why does clear keep the memory? A vector that you fill again needs no new block.

Q61

L4 · Senior Interview std-vector

Why is std::vector the usual default container in C++?

Show answerHide answer to Q61

Main fact: std::vector keeps its elements in one contiguous block.

  • A loop over the elements reads memory in order, so the CPU cache works well.
  • Index access is O(1), and push_back at the end has an amortized cost of O(1) (ex14).
  • It owns its memory: the destructor frees it, so there is no leak and no manual delete.
  • The object is small, 24 bytes on x86-64 (ex07). data() gives a pointer for C functions.

Limits: an insert or an erase in the middle is O(n). A reallocation makes references to elements invalid (ex13).

Follow-up questions:

  • When do you use something else? std::array for a size fixed at compile time. std::map or std::unordered_map for lookup by key.
  • What is the cost of the growth? Fewer than 2 copies for each element (ex14), and up to about 2 times the memory that the elements need.

Q62

L4 · Senior Interview std-map

How does a usual library implement std::map? Give the cost of lookup, insert and erase. Does a reference to a value stay valid after other inserts?

Show answerHide answer to Q62

Main fact: libstdc++ and libc++ implement std::map as a red-black tree, a balanced binary search tree (bits/stl_tree.h, c++/v1/__tree). Each element is a separate node on the heap, with pointers to its parent and its two children.

Cost: lookup, insert and erase are O(log n): 17.5 comparisons on average in a map with 65536 keys (ex29). The standard gives a limit: logarithmic complexity. Source: cppreference, std::map.

References: an insert does not move the nodes, so references to values stay valid after other inserts (ex36). An erase makes only references to the erased element invalid.

Trade-offs: each node is a separate heap allocation with extra pointers. A walk down the tree follows pointers to nodes in different places in memory. So a large map has more cache misses than a sorted vector.

Follow-up question: Why a red-black tree and not an unbalanced tree? An unbalanced tree becomes a list for sorted inserts, so its lookup is O(n).

Q63

L4 · Senior Interview size-capacity

A program does v.reserve(3); v[0] = 5;. Is this correct? Which tools find this bug?

Show answerHide answer to Q63

Main fact: the code is not correct. The call reserve(3) makes no elements, so the size is 0. Then v[0] writes to an element that does not exist. This is undefined behavior, also when the write seems to work.

Tools:

  • -D_GLIBCXX_ASSERTIONS (libstdc++): the program stops with Assertion '__n < this->size()' failed. (ex12).
  • ASan alone with libstdc++ finds nothing here: the write is inside the block that reserve allocated. The program writes 0.
  • ASan with -D_GLIBCXX_SANITIZE_VECTOR (GCC and libstdc++), or ASan with libc++ (clang++ -stdlib=libc++), reports container-overflow.
  • v.at(0) throws std::out_of_range for the same mistake (ex05).

Correction: v.push_back(5);, or v.resize(3); before v[0] = 5;.

Follow-up question: Why does ASan alone not find it? ASan checks the heap blocks. Without the container annotations, it does not know which part of the block holds elements.
