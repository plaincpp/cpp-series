Part A: Concept checks

12 questions

Q1

L1 · Recall Short answer function-template

What is a function template? Is max_of itself a function that the linker can find in an object file?

Show answerHide answer to Q1

A function template is a pattern for functions. It is not a function. The compiler makes a real function from it, for example max_of<int>, when the code uses it with a type. So max_of alone has no machine code and no symbol. nm -C shows only the instantiations, such as int max_of<int>(int, int) (ex16). Source: cppreference, function template.

Q7

L1 · Recall Short answer template-instantiation

What is template instantiation? When does the compiler do an implicit instantiation?

Show answerHide answer to Q7

Template instantiation is the step in which the compiler makes a real function or class from a template for one set of template arguments. The compiler does an implicit instantiation when the code uses the template with new arguments. Examples are the call max_of(3, 7) and the variable Stack<int> numbers; (ex16, ex17). Source: cppreference, function template, implicit instantiation.

Q9

L1 · Recall Short answer templates-in-headers

Why must the full definition of a template be in each translation unit that uses it? Where do you usually put the definition?

Show answerHide answer to Q9

To make max_of<int>, the compiler must see the body of the template in the same translation unit, not only a declaration. D

Part D: Explain why

9 questions

Q34

L2 · Apply Explain why function-template

The expression 3 < 2.5 compiles. Explain why std::max(3, 2.5) does not compile (ex01).

Show answerHide answer to Q34

Rule: template argument deduction does no conversions. The function std::max is a template with one type parameter for both arguments. The argument 3 gives int, and 2.5 gives double, so deduction fails with deduced conflicting types for parameter (ex01). The built-in < is not a template: it converts 3 to double with the usual arithmetic conversions. Write std::max<double>(3, 2.5) or std::max(3.0, 2.5).

Q35

L3 · Analyze Explain why function-template

Explain why max_of("pear", "apple") does not compare the two words. What do you use to compare them?

Show answerHide answer to Q35

Rule: a by-value parameter changes an array to a pointer. "pear" is a const char[5], and "apple" is a const char[6]. Both decay to const char*, so T = const char* (ex05). Then a < b compares two addresses, not the letters, and the result for two unrelated pointers is unspecified. Use std::string: max_of(std::string("pear"), std::string("apple")) gives pear. Source: cppreference, comparison operators, pointer comparison.

Q36

L3 · Analyze Explain why function-template

A program has void show(int) and template <typename T> void show(T) (ex06). Explain why show(3) calls the normal function, but show('x') calls the template.

Show answerHide answer to Q36

Rule: overload resolution compares the conversions first. When the conversions are equally good, a normal function wins over a template. For show(3), both functions are exact matches, so the normal function wins. For show('x'), the template gives T = char, an exact match. The normal function needs a promotion from char to int, so the template wins (ex06). Source: cppreference, overload resolution.

Q37

L2 · Apply Explain why class-template

Explain why Stack numbers; does not compile, but std::vector values{1, 2, 3}; compiles.

Show answerHide answer to Q37

Rule: class template argument deduction (C++17) uses only the initializer of the variable. It compares the initializer with the constructors and the deduction guides. The line Stack numbers; has no initializer, so nothing tells the compiler the type (ex11). A later push(10) does not help. The line std::vector values{1, 2, 3} has three int values in its initializer. The std::vector constructor for a list of values then gives T = int (ex12).

Q38

L3 · Analyze Explain why template-parameter

Explain why the argument for a non-type template parameter, such as the size of std::array, must be a constant expression.

Show answerHide answer to Q38

Rule: each template argument is part of the type, and the compiler must know every type at compile time. For example, std::array<int, 3> and std::array<int, 4> are different types with different sizes. A normal variable has its value only when the program runs, so it cannot be part of a type (ex14). A constexpr variable or a literal is a constant expression. For a size that you know only at run time, use std::vector.

Q39

L3 · Analyze Explain why template-instantiation

Point has no operator<<. Explain why Box<Point> corner{{3, 4}}; compiles (ex19), but the call corner.print(); does not compile (ex20).

Show answerHide answer to Q39

Rule: the compiler makes a member function of a class template only when the code uses it. Box<Point> makes the class with the member value. It does not make the body of print(), so the missing operator<< for Point gives no error (ex19). The call corner.print() makes the body. Then the compiler finds std::cout << value with a const Point, and GCC says no match for 'operator<<' (ex20).

Q40

L3 · Analyze Explain why templates-in-headers

A normal function int twice(int value) with its body in a header gives multiple definition of `twice(int)' when two .cpp files include the header. Explain why a function template with its body in a header does not give this error.

Show answerHide answer to Q40

Rule: the one-definition rule allows one definition of a template in each translation unit, if all the definitions are the same. For a normal function that is not inline, it allows only one definition in the full program. GCC marks each template instantiation as a weak symbol (W in nm), and the linker keeps one copy (ex23). The normal function is a strong symbol in each object file. So GNU ld reports multiple definition of `twice(int)', with the place of the first definition. Source: cppreference, definitions and ODR.

Q41

L4 · Senior Explain why templates-in-headers

In ex22, the compiler accepts main.cpp and max.cpp, and only the linker reports the error. Explain why the compiler cannot find this error.

Show answerHide answer to Q41

The compiler compiles each .cpp file alone and does not see the other files. In main.cpp, the declaration of max_of is correct. So the compiler writes a call to the symbol int max_of<int>(int, int). It expects another file to define it (U in nm). In max.cpp, the template is correct but nothing uses it, so the compiler makes no code. Only the linker sees all the object files together, so only the linker finds that no file defines the symbol (ex22).

Q42

L3 · Analyze Explain why template-errors

Explain why the error for std::sort on a std::list (ex26) starts in stl_algo.h and not in main.cpp.

Show answerHide answer to Q42

Rule: the compiler reports an error at the place where the code fails. For a template, this place is in the template body. The name std::sort is a function template in the library. The call in main.cpp makes std::sort<std::_List_iterator<int>>, and its body in stl_algo.h computes last - first. A std::list iterator has no operator-, so the first error is in stl_algo.h. The line main.cpp:6:14: required from here connects the error to your call (ex26).

Part F: Design and trade-offs

4 questions

Q50

L4 · Senior Design templates-in-headers

Your team writes a math library with the function template clamp_value<T>. Compare two designs. Design 1 puts the full template in the header. Design 2 puts the body in a .cpp file, with explicit instantiations and extern template lines in the header.

Talk about compile time, the types that users can use, and what users can see. Give a recommendation for a library with 3 known types. Then give one for a library that users use with their own types.

Show answerHide answer to Q50

A strong answer covers these points:

  • Full template in the header. Users can use every type with the operations that the template needs. Each translation unit compiles the body again, so the build is slower. Users see the full body.
  • Explicit instantiation in a .cpp file. The library compiles the body one time for each type (ex24). An extern template line stops the instantiation in each user file, so the build of the users is faster. Users can see only the declaration. A call with another type gives an undefined reference at link time.
  • Recommendation. For 3 known types, such as float, double and long double, use explicit instantiation and document the types. For a generic library, put the template in the header. Most of the standard library uses this design.

Q51

L4 · Senior Design template-instantiation

A program uses Stack<T> with 20 different element types. Each push has 40 lines of code that do not use T, such as logging and checks. What does this do to the size of the program? How can you change the design to make the program smaller? What do you lose?

Show answerHide answer to Q51

A strong answer covers these points:

  • Effect. Each element type makes its own copy of push, also of the 40 lines that do not use T. 20 types give 20 copies, so the program is larger and the build is slower.
  • Correction. Move the code that does not use T into a normal function, for example void log_push(std::size_t size). The template calls it, and the program has one copy of it.
  • Other option. One non-template class that keeps void* or a base class with virtual functions. It makes one copy of the code, but it loses type safety, and each call can cost an indirect call.
  • What you lose. A normal function cannot use T, so only the code without T can move. Measure the size first, for example with size or nm --size-sort.

Q52

L4 · Senior Design function-template

You need max_of for int, double and std::string. Compare three designs. Design 1 has three normal overloads. Design 2 has one function template. Design 3 has one function template and one normal overload for const char*.

Which design do you recommend for a library that other teams use? Give your reasons.

Show answerHide answer to Q52

A strong answer covers these points:

  • Three overloads. Each function is clear. But mixed calls such as max_of(3, 2.5) are ambiguous between the int and the double overloads. GCC says call of overloaded 'max_of(int, double)' is ambiguous, and Clang says call to 'max_of' is ambiguous (ex36). The three bodies are copies, and a new type needs a new function. Source: cppreference, overload resolution.
  • One template. One body works for every type with <. Deduction does no conversions, so max_of(3, 2.5) does not compile. Two string literals give T = const char* and compare addresses (ex05).
  • Template plus an overload for const char*. The normal function wins for an exact match (ex06), so it can compare the text with std::strcmp. It closes the main trap of the template.
  • Recommendation. Design 3. Design 2 is also good if its documentation tells users to pass std::string for text. Design 1 is a good choice only for a small, fixed set of types.

L4 · Senior Design template-errors

Show answerHide answer to Q53

A strong answer covers these points:

  • No check. The first error is in the body of the template, for example no match for 'operator<', and a required from here line names the call (ex25). In a deep library, the body can be far from the user's code (ex26).
  • static_assert in the body. You choose the text of the message, for example "max_of needs operator<". But the compiler checks it only after it selects the template, so other overloads cannot take the call.
  • C++20 constraint. The first error names the call, and a note says constraints not satisfied (ex28). A type that does not satisfy the constraint removes the template from overload resolution, so another overload can take the call. On GCC, the full message is not shorter: 31 lines, against 7 lines with no check.
  • Recommendation. Use a constraint in C++20 code. Use static_assert in older code when you need a clear message.

Q54

L3 · Analyze Interview function-template

What is template argument deduction? Why does std::max(3, 2.5) not compile, and how do you correct it?

Show answerHide answer to Q54
  • Main fact. Template argument deduction finds the template arguments from the types of the call arguments. Each argument gives one value for each parameter, and all the values must be the same. Deduction does no conversions.
  • Example. std::max(3, 2.5) gives T = int from the first argument and T = double from the second, so the call does not compile (ex01).
  • Correction. std::max<double>(3, 2.5): with an explicit argument, normal conversions apply. Or cast one argument: std::max(static_cast<double>(3), 2.5).
  • Follow-ups. "What is T for two string literals?" const char*, so the comparison uses addresses (ex05). "Does a normal overload win?" For an exact match, yes (ex06).

Q55

L3 · Analyze Interview class-template

What is the difference between a class and a class template? Is std::vector a type? Is std::vector<int> a type?

Show answerHide answer to Q55
  • Main fact. A class is a type. A class template is a pattern from which the compiler makes classes. std::vector is a class template and not a type. std::vector<int> is a type.
  • Example. You cannot declare std::vector v; with no initializer, but std::vector<int> v; compiles. std::vector<int> and std::vector<double> are two unrelated types (ex17, ex18).
  • Limit. In C++17 and later, CTAD can find the arguments from an initializer: std::vector v{1, 2, 3} is a std::vector<int> (ex12).
  • Follow-up. "Is std::string a template?" No. It is a type, the name of std::basic_string<char>.

Q56

L3 · Analyze Interview template-parameter

Is there a difference between template <class T> and template <typename T>? What kinds of template parameters are there?

Show answerHide answer to Q56
  • Main fact. In a template parameter list, class and typename mean the same thing (ex07). Many teams use typename, because T can also be a built-in type such as int.
  • Kinds. Type parameters (typename T), non-type parameters (std::size_t N, a compile-time value, ex13) and template template parameters. Each parameter can have a default argument (ex15).
  • Follow-up. "Where is only typename correct?" Before a dependent type name in a template body, for example typename T::value_type. Season 1 teaches this. Source: cppreference, dependent names.

Q57

L4 · Senior Interview template-instantiation

Templates have "zero run-time cost". Is this true? What is the real cost of templates, and how do you decrease it?

Show answerHide answer to Q57
  • Main fact. An instantiation is a normal function or class for one type. The compiler can inline it and optimize it as a function that you write by hand. So a call has no extra run-time cost against that function.
  • The real cost. Each new set of template arguments makes more machine code (code size) and more compile time. Templates in headers compile again in each translation unit. Errors can be long (ex26).
  • How to decrease it. Move the code that does not use T into normal functions. Use explicit instantiation and extern template for the usual types (ex24). Limit the number of different template arguments.
  • Follow-up. "Is a virtual function smaller?" Often yes, one copy of the code, but each call can be an indirect call that the compiler cannot inline.

Q58

L3 · Analyze Interview templates-in-headers

Why do we usually put templates in header files? Is there a way to keep the body in a .cpp file?

Show answerHide answer to Q58
  • Main fact. To make max_of<int>, the compiler must see the body in the same translation unit. A body in a .cpp file makes no code, and other files cannot make the instantiation. The link fails with undefined reference (ex22).
  • Why it links. The same template in many files does not break the one-definition rule. Each object file has a weak symbol (W in nm), and the linker keeps one copy (ex23).
  • Other way. Keep the body in a .cpp file. Add an explicit instantiation for each type, such as template int max_of<int>(int, int);. Put the extern template lines in the header (ex24). It works only for the types in the list.
  • Follow-up. "What about C++20 modules?" A module also exports templates, but this series covers modules later.

Q59

L4 · Senior Interview template-instantiation

What is two-phase lookup? Give an example of an error that the compiler finds before any instantiation. Then give an error that it finds only at the instantiation.

Show answerHide answer to Q59
  • Main fact. The compiler checks a template in two phases. At the definition, it checks the names and the expressions that do not depend on a template parameter. At the instantiation, it checks the names and the expressions that depend on T.
  • Phase 1 example. A call log_value(); with no arguments that depend on T fails at the definition, also with no instantiation (ex21).
  • Phase 2 example. a < b in max_of fails only when T = Point, at the instantiation (ex25). A member function such as print() fails only when the code calls it (ex20).
  • Follow-up. "Why do older MSVC versions accept the phase 1 error?" Older MSVC versions checked the full template only at the instantiation. Current MSVC with /permissive- uses two-phase lookup. Source: the C++ Team Blog of Microsoft, two-phase name lookup support comes to MSVC.

Q60

L3 · Analyze Interview template-errors

A colleague shows you a template error with 200 lines. How do you find the cause? What do C++20 concepts change in such errors?

Show answerHide answer to Q60
  • Method. Find the first error: line and read the cause: the operation and the types. Then find the required from here line (GCC) or the requested here line (Clang) that names your own file. Correct the call or the type there, not the library header.
  • Example. std::sort on a std::list gives 28 lines on GCC and 38 on Clang. The first error is no match for 'operator-' in stl_algo.h, and main.cpp:6:14 is the bad call (ex26). Use scores.sort() (ex27).
  • C++20 concepts. A constraint such as std::totally_ordered T puts the first error at the call, and a note says constraints not satisfied (ex28). The message is not always shorter: on GCC it has 31 lines, against 7 with no constraint.
  • Follow-up. "What do you do with an error that you cannot read?" Make a small example with the same call, and build it on a second compiler. Clang and GCC often give the cause in different words.
