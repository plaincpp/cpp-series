References vs Pointers in C++

About 12 min 38 quiz questions 61 workbook questions
Start the quiz Open the workbook Compiler Explorer (opens in a new tab)

What you learn

  • Use & and * to make a reference and a pointer, and predict each value after an assignment.
  • Use pass by reference to change a caller variable and const reference to pass a large object with no copy.
  • Find a null pointer dereference and a dangling reference or pointer with compiler warnings and sanitizers.
  • Compare a pointer and a reference, and tell when to use each one.

Select all that apply.

Question 13 of 38 L2 · Apply nullptr

True or false: A dereference of a null pointer always stops the program with a crash.

A dereference of a null pointer is undefined behavior. The standard gives no guaranteed result, and the optimizer can treat it as impossible (cppreference: undefined behavior).

Do not trust a crash or a quiet run. Check the pointer before the dereference, and build with UBSan: it reports load of null pointer (ex12).

Question 15 of 38 L3 · Analyze nullptr

Choose one: The overloads show(int) and show(int*) exist. What is the result of show(NULL); on GCC 14 and Clang 19?

On GCC 14 and Clang 19, NULL has the type long, not int. So show(int) also needs a conversion, and neither overload is a better match (ex14: call to 'show' is ambiguous). With a plain 0 (an int), show(int) is an exact match (ex13). Use nullptr: it selects show(int*).

Question 21 of 38 L2 · Apply pointer

Put in order: x is 1 and y is 2. Put the steps of swap_by_pointer(&x, &y) from ex16 in order.

Drag the handle, or use the arrow buttons. With a row focused, press Alt + Up or Alt + Down.

  1. The function copies old_a into *b, so y becomes 1.
  2. The function copies *a (the value 1) into old_a.
  3. The caller gives the addresses &x and &y to the parameters a and b.
  4. The function copies *b into *a, so x becomes 2.

The pointers are copies of the addresses. Each dereference reads or writes the variables of the caller.

Question 22 of 38 L3 · Analyze reference

Put in order: These steps make the reference first in ex27 dangle. Put the steps in the correct order.

Drag the handle, or use the arrow buttons. With a row focused, press Alt + Up or Alt + Down.

  1. On this toolchain the vector is full, so push_back(4) allocates a larger block.
  2. The read of first uses freed memory, and ASan reports heap-use-after-free.
  3. first refers to scores[0] in the memory block of the vector.
  4. The vector moves the elements to the new block and frees the old block.

When push_back makes the size larger than the capacity, each reference, pointer and iterator to an element becomes invalid (cppreference: std::vector::push_back). The standard gives no start capacity. Here (libstdc++), {1, 2, 3} gives a capacity of 3.

Question 23 of 38 L1 · Recall const-reference

True or false: An assignment to a const int& parameter changes the object of the caller.

An assignment through a const reference does not compile (ex20: assignment of read-only reference 'score').

A const reference gives read-only access with no copy. To change the object of the caller, use int&.

Question 24 of 38 L2 · Apply const-reference

A const reference gives read-only access with no copy (ex19 prints same). A value parameter copies all elements. A non-const reference lets the function change the vector, and a pointer can be null.

Question 32 of 38 L4 · Senior reference

Both functions compile to the same code: GCC addl $1, (%rdi), Clang incl (%rdi). The compiler usually gives a reference parameter as an address. The difference is in the rules of the language, not in speed.

Question 36 of 38 L4 · Senior pointer
