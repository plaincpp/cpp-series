C++ Lambdas: Captures and Closures

About 12 min 39 quiz questions 61 workbook questions
Start the quiz Open the workbook Compiler Explorer (opens in a new tab)

What you learn

  • Write a lambda expression, and pass it to std::sort and other standard algorithms.
  • Compare capture by value and capture by reference, and predict the value that a lambda reads when it runs.
  • Explain the closure type: the class with data members and an operator() that the compiler makes for each lambda.
  • Use mutable to change the copy that a lambda keeps, and use auto parameters to write a generic lambda.
  • Find a lambda that captures a local variable by reference and runs after the lifetime of that variable ends.

Question 3 of 39 L2 · Apply capture-by-reference In the video

True or false: A capture by reference keeps the local variable alive while the lambda exists.

A capture by reference does not change the lifetime of the variable. A local variable ends when its function returns, and a parameter is dead after the return. A later call of the lambda reads a dead object (ex28).

False. A lambda does not extend the lifetime of a variable that it captures by reference. If the lambda can run after the scope ends, capture by value (ex29).

Question 4 of 39 L1 · Recall lambda-expression

Choose one: Which part of the lambda [limit](int x) { return x > limit; } is the capture list?

The capture list is [limit]. It is the first part of a lambda, and it names the local variables that the body uses. The parameter list is (int x), and the part in braces is the body.

Question 5 of 39 L1 · Recall lambda-expression

True or false: A lambda with no parameters must have an empty () after the capture list.

The parameter list is optional when a lambda has no parameters. ex02 compiles [] { return "hello"; } on GCC and Clang.

False. [] { return 1; } and []() { return 1; } are the same lambda. Write () when the lambda has parameters.

Question 6 of 39 L1 · Recall lambda-expression

A trailing return type starts with ->, and it comes after the parameter list. Without it, the compiler deduces the return type from the return statements (ex02).

Question 15 of 39 L3 · Analyze capture-by-value

Question 23 of 39 L1 · Recall capture-by-reference

Match the terms: Match each capture to its effect.

A capture by value is a copy that the closure keeps. A capture by reference reads and changes the original variable. An init-capture (C++14) makes a new member with a name that you choose (ex11).

Question 24 of 39 L4 · Senior capture-by-reference

Choose one: A function sorts a vector of indexes by the values in a large local table. The lambda runs only during the std::sort call. Which capture is the best choice?

Use [&table]. The lambda runs only during the call, so the table is alive, and the reference is safe. The captures [table] and [=] both copy the large table, which costs time and memory. A reference capture is dangerous only when the lambda runs after the variable is dead.

Question 25 of 39 L1 · Recall closure-type

Choose one: What does the compiler make for each lambda expression?

Each lambda expression has a unique unnamed class type, the closure type (C++23 [expr.prim.lambda.closure]). The value of the expression is an object of this class. std::function is a different library type, which a later season shows.

Question 27 of 39 L2 · Apply closure-type

True or false: The operator() of a closure type is a const member function by default.

The compiler makes operator() a const member function unless the lambda has mutable. So the body cannot change its copies (ex26).

True. The struct in ex15 has bool operator()(int x) const, the same as the closure type. mutable removes the const (C++23 [expr.prim.lambda.closure]).

Question 28 of 39 L3 · Analyze closure-type

Choose all that apply: Which lambdas convert to the function pointer type int (*)(int)? Select all correct answers.

Select all that apply.

Only a lambda with an empty capture list converts to a function pointer, also a generic lambda. A function pointer has no place for captured data (ex18, ex19). The capture list [=] has a capture default, so it does not convert, also when the body uses no local variable. GCC and Clang agree.

Question 29 of 39 L3 · Analyze closure-type

Choose one: On x86-64 Linux, a is an int and d is a double. What is sizeof of the closure of [a, d]() { return a + d; }?

The size is 16 (ex16). The closure has an int member of 4 bytes and a double member of 8 bytes. The double must start on an 8-byte boundary, so the compiler adds 4 bytes of padding. A lambda with no captures has the size 1, because each object needs at least 1 byte.

Question 30 of 39 L1 · Recall generic-lambda

Choose one: What does an auto parameter give to the closure type of a lambda?

A lambda with an auto parameter is a generic lambda (C++14). Its operator() is a member template, so each call with a new type makes a new function. The type does not stay the same after the first call (ex20).

Question 36 of 39 L1 · Recall mutable-lambda
