Q1

L1 · Recall Short answer build-steps

You build with g++ main.cpp area.cpp -o app. Name the build steps in order. Give the output of each step for main.cpp.

Show answerHide answer to Q1
  1. The preprocessor pastes each #include and gives the translation unit of main.cpp.
  2. The compiler changes the translation unit into the object file main.o.
  3. The linker joins main.o, area.o and the standard library into the executable app.

The compiler works on one file at a time. Only the linker sees all the object files (ex04).

Q2

L2 · Apply Multiple choice build-steps

nm -C main.o prints the line U area(int, int). What does the U tell you?

  • a) main.o defines area.
  • b) main.o needs area, and a different object file must define it.
  • c) The compiler found no use of area.
Show answerHide answer to Q2

b) U means "undefined here": main.o calls area, but it does not contain its body. nm -C area.o shows T area(int, int), a definition in the text section. The linker connects the two (ex04).

Q3

L1 · Recall Short answer types-expressions-basics

What does 7 / 2 give in C++? What does 7 / 2.0 give? Give the rule that makes the difference.

Show answerHide answer to Q3

7 / 2 gives 3, and 7 / 2.0 gives 3.5. When the two operands are integers, the division is an integer division. It truncates the result toward zero. When one operand is a double, the other operand converts to double (ex06).

Q4

L2 · Apply Multiple choice types-expressions-basics

Which line stops the build with an error on GCC 14 and on Clang 19?

  • a) int count = 3.7;
  • b) int count(3.7);
  • c) int count{3.7};
Show answerHide answer to Q4

c) int count{3.7};. Brace initialization does not accept a narrowing conversion. GCC writes narrowing conversion of '3.7000000000000002e+0' from 'double' to 'int', and Clang writes type 'double' cannot be narrowed to 'int' in initializer list. Lines a) and b) compile and set the value 3: Clang warns with -Wliteral-conversion, and GCC 14 is silent with -Wall -Wextra.

Q5

L1 · Recall Short answer references-pointers

Give three differences between a reference and a pointer.

Show answerHide answer to Q5
  • A reference must refer to an object when you declare it. A pointer can be nullptr.
  • A reference always refers to the same object. You can change a pointer to point to a different object.
  • You use a reference with the syntax of the object. You use *p or p-> for a pointer, and you can do arithmetic on a pointer into an array.

Q6

L2 · Apply Multiple choice references-pointers

A function must add 10 to an int of the caller. Which declaration lets it do this?

  • a) void add_bonus(int score);
  • b) void add_bonus(int& score);
  • c) void add_bonus(const int& score);
Show answerHide answer to Q6

b) void add_bonus(int& score);. A non-const reference refers to the object of the caller. Choice a) changes a copy. Choice c) does not let the function change the value (ex09).

Q7

L1 · Recall Short answer classes-basics

What is slicing? Give one line of code that slices a Circle that derives from Shape.

Show answerHide answer to Q7

Slicing occurs when you copy a derived object into an object of the base type. The copy keeps only the base part, and its dynamic type is the base type. Examples: Shape copy = circle;, or a call to void show_copy(Shape shape) with a Circle (ex15).

Q8

L1 · Recall Short answer object-lifetime-basics

When does C++ initialize a static local variable? When does C++ destroy it?

Show answerHide answer to Q8

C++ initializes a static local variable the first time that the program runs through its declaration. It keeps its value between calls. C++ destroys it after main returns (cppreference: storage duration, static local variables; ex12).

Q9

L2 · Apply Multiple choice classes-basics

account is a const Account. Which line compiles?

  • a) account.deposit(5);
  • b) account.balance();
  • c) account.balance_ = 5;
Show answerHide answer to Q9

b) account.balance();. balance is a const member function, so a const object can call it. Line a) does not compile: deposit is not const, and GCC writes passing 'const Account' as 'this' argument discards qualifiers. Line c) does not compile: balance_ is private, and the object is const (S00E09, S00E11).

Q10

L1 · Recall Short answer containers-basics

stock is a std::map<std::string, int> with no key "pear". What does stock["pear"] do? Name two member functions that read a key and add nothing.

Show answerHide answer to Q10

stock["pear"] adds the key "pear" with the value 0. Then it returns a reference to the value. find and contains (C++20) read and add nothing (ex17). count also adds nothing.

Q11

L2 · Apply Short answer build-steps

Two .cpp files each define a function int area(int width, int height), and one program links both. What occurs? How does a namespace help? What does an include guard stop, and what does it not stop?

Show answerHide answer to Q11

The linker stops with multiple definition of `area(int, int)', because the program can have only one definition of the function (one definition rule). A namespace gives each function a different full name, for example geometry::area and image::area, so the two names do not clash (S00E12).

An include guard (#pragma once, or #ifndef with #define and #endif) stops a second copy of a header in one translation unit. Without it, the compiler stops with redefinition of 'struct Shape' (q08). It does not stop a non-inline function in a header that two .cpp files include: each object file then gets one definition (Q25).

Q12

L1 · Recall Short answer debugging-basics

Which compiler options do you add for a GDB session? Which options do you add to find memory errors and undefined behavior at run time?

Show answerHide answer to Q12

For GDB: -g -O0. -g adds the line information, and -O0 keeps each variable. For the run-time checks: -g -fsanitize=address,undefined. ASan finds memory errors and leaks, and UBSan finds undefined behavior such as a null pointer read (ex01, ex10, ex24).

Part D: Explain why

9 questions

Q34

L3 · Analyze Explain why build-steps

A CMakeLists.txt has add_executable(app main.cpp). main.cpp calls area, and area.cpp defines it. cmake --build build stops with undefined reference to `area(int, int)'. Explain why. Give the correction.

Show answerHide answer to Q34

add_executable lists the source files of the target. area.cpp is not in the list, so CMake does not compile it. The link step links only CMakeFiles/app.dir/main.cpp.o, and no object file defines area. So the linker stops, as in ex03. Write add_executable(app main.cpp area.cpp). CMake runs the same build steps as g++: it compiles each listed file, then links the object files (S00E22).

Q35

L3 · Analyze Explain why templates-basics

In ex05, the body of larger is in larger.cpp. Explain why the linker writes undefined reference to `int larger<int>(int, int)'.

Show answerHide answer to Q35

The compiler makes larger<int> only in a translation unit that sees the body and uses larger<int>. The file main.cpp sees only the declaration, so main.o needs larger<int> (U in nm). The file larger.cpp sees the body but does not use larger<int>, so larger.o does not define it. No object file has the definition (ex05).

Q36

L3 · Analyze Explain why references-pointers

In S00E08, main prints sizeof(scores) for int scores[5] and gets 20. The function void print_size(int values[5]) prints sizeof(values) and gets 8 (x86-64 Linux). Explain why the two values are different. How can the function know the number of elements?

Show answerHide answer to Q36

In main, scores is an array of five int values, so sizeof(scores) is 5 x 4 = 20 bytes. A parameter of type int[5] is a pointer: the compiler changes its type to int*. The call passes the address of the first element (array decay). So sizeof(values) gives the size of int*, 8 bytes on x86-64. GCC and Clang warn with -Wsizeof-array-argument. To know the number of elements, pass it as a second parameter, or use const std::array<int, 5>& (S00E08; cppreference: array-to-pointer conversion).

Q37

L3 · Analyze Explain why types-expressions-basics

In ex07, index is -1 and values.size() is 3, but the program does not print inside. Explain why. Which compiler option finds this compare?

Show answerHide answer to Q37

values.size() returns an unsigned type. The usual arithmetic conversions convert index to that type. So -1 becomes the largest std::size_t value, and the test gives false.

GCC turns on -Wsign-compare with -Wall. Clang turns it on with -Wextra. Build with -Wall -Wextra, and -Werror makes it an error (ex07). Use std::cmp_less(index, values.size()) (ex08).

Q38

L3 · Analyze Explain why references-pointers

ex01 keeps int& first = scores[0]; and then calls push_back. ASan reports heap-use-after-free. ex02 keeps the index 0 and has no error. Explain why.

Show answerHide answer to Q38

With libstdc++, scores has capacity 3 after the construction from three values, so it is full. The standard does not set this capacity. So push_back gets a larger block, moves the elements and frees the old block. The reference first still refers to the old block, so the read uses freed memory. An index does not hold an address. So scores[first] reads the new block (ex01, ex02).

Q39

L3 · Analyze Explain why classes-basics

In ex16, Shape has a virtual function but no virtual destructor. Explain why delete shape; is undefined behavior when shape points to a Label.

Show answerHide answer to Q39

delete shape; calls the destructor through the static type Shape. Without a virtual destructor, the standard makes this undefined behavior ([expr.delete]). In practice, the call usually runs only ~Shape. Then nothing destroys the std::string member. Label is larger than Shape, so ASan reports new-delete-type-mismatch, and GCC warns with -Wdelete-non-virtual-dtor (ex16).

Q40

L3 · Analyze Explain why object-lifetime-basics

ex13 prints open, close, caught. Explain why close comes before caught, and why load does not appear.

Show answerHide answer to Q40

The throw leaves load before the line that prints load. Before the catch block runs, stack unwinding destroys the local objects of load, so ~File prints close. Then the catch block prints caught (ex13).

Q41

L3 · Analyze Explain why classes-basics

S00E19 writes std::ostream& operator<<(std::ostream& out, const Money& m) as a free function. Explain why it cannot be a member function of Money. Why does it return std::ostream&?

Show answerHide answer to Q41

For a member operator, the left operand is the object of the class. In std::cout << m, the left operand is the stream, not Money. A member of Money would need m << std::cout, and std::cout << m does not compile. So operator<< is a free function with the stream as its first parameter (cppreference: operator overloading, stream insertion). It returns the stream so that the calls can chain: std::cout << a << b is (std::cout << a) << b (S00E19).

Q42

L3 · Analyze Explain why debugging-basics

For ex10 with the input 7, the shell prints Segmentation fault (core dumped), and echo $? prints 139. Explain the two lines. How does GDB show the line and the bad value?

Show answerHide answer to Q42

The input 7 makes price a null pointer, and *price reads address 0. The OS stops the program with the signal SIGSEGV (number 11 on Linux). The shell prints Segmentation fault (core dumped) and sets the status to 128 + 11 = 139 (Bash manual: exit status). In GDB, run stops at the crash, bt shows with_tax (price=0x0) at main.cpp:3, and frame 1 with print id shows the value 7 in main (ex10).

Part F: Design and trade-offs

4 questions

Q50

L4 · Senior Design classes-basics

A drawing program keeps circles and squares in one list and calls the virtual function area on each. Compare std::vector<Shape>, std::vector<Shape*> with new, and std::vector<std::unique_ptr<Shape>>. Give a recommendation.

Show answerHide answer to Q50

Structure of a strong answer:

  • std::vector<Shape>: it slices each circle and square, so each element is a Shape, and the virtual call runs Shape::area (ex15). Do not use it.
  • std::vector<Shape*> with new: the virtual call works, but each delete is manual. A missing delete leaks (ex24), and a second delete is a double free. The base needs a virtual destructor (ex16).
  • std::vector<std::unique_ptr<Shape>>: the virtual call works, and the vector destructor frees each object. It needs virtual ~Shape() = default;.
  • Recommendation: std::vector<std::unique_ptr<Shape>>. Cost: one heap allocation for each object and a pointer read for each call.

Q51

L4 · Senior Design object-lifetime-basics

A function needs a buffer of n integers for one call. Compare new int[n] with delete[], std::unique_ptr<int[]> and std::vector<int>. Talk about leaks, exceptions and size information. Give a recommendation.

Show answerHide answer to Q51

Structure of a strong answer:

  • new int[n] with delete[]: each return and each throw before delete[] leaks (ex24). The pointer does not know its size.
  • std::unique_ptr<int[]> (std::make_unique<int[]>(n)): the destructor frees the memory on every path (ex25). It does not keep the size.
  • std::vector<int>: frees the memory on every path, keeps the size, can grow, and gives at() with a bounds check.
  • Recommendation: std::vector<int> buffer(n);. Use std::unique_ptr<int[]> only when a fixed size and the smallest object are important. Do not use a raw new[] in new code.

Q52

L4 · Senior Design build-steps

Many files use a small function int square(int x). Compare two designs. Design 1 is an inline definition in the header. Design 2 is a declaration in the header and the definition in one .cpp file. Talk about the one definition rule, the build time and what changes force a new build. Where must a function template go?

Show answerHide answer to Q52

Structure of a strong answer:

  • inline in the header: each file sees the body. So the compiler can inline the call. inline lets each translation unit have one definition (one definition rule). A change to the body makes each file that includes the header compile again.
  • Declaration in the header, definition in one .cpp file: the program has one definition. The build time is smaller, and a change to the body compiles one file. The compiler cannot inline the call in other files without link-time optimization.
  • A function template goes in the header, because each file that uses it must see the body (ex05).
  • Recommendation: a small function that many files call often can go inline in the header. Put larger functions in a .cpp file.

Q53

L4 · Senior Design debugging-basics

You prepare the builds for a new team project. Which builds do you make, with which options, to find bugs early? Talk about warnings, -Werror, a GDB build and a sanitizer build, and their costs.

Show answerHide answer to Q53

Structure of a strong answer:

  • Each build: -Wall -Wextra -Wpedantic. In CI, add -Werror, so a new warning stops the merge (ex07, ex22).
  • A debug build: -g -O0 for GDB (ex10).
  • A sanitizer build: -g -fsanitize=address,undefined. Run all tests with it in CI. It finds use-after-free, overflows, leaks, double free and null reads (ex01, ex18, ex24, ex26). The usual slowdown of ASan is about 2x (Clang AddressSanitizer documentation), so do not ship it.
  • A release build: -O2 for the product.
  • Cost: more CI time, and some warnings need work to correct. A bug that a tool finds early costs less than a crash in production.

Part G: Interview questions

7 questions

Q54

L3 · Analyze Interview build-steps

"Tell me, step by step, how a program with two .cpp files becomes an executable. Where does an undefined reference error come from?"

Show answerHide answer to Q54

Structure of a strong answer:

  1. Main fact: the preprocessor and the compiler work on each .cpp file alone and make one object file each. The linker joins the object files and finds a definition for each symbol.
  2. Example: main.o needs area (U in nm), and area.o defines it (T) (ex04).
  3. Limit: an undefined reference comes from the linker, when no object file or library defines a symbol. Usual causes: a missing .cpp file in the build, a missing body, or a template body in a .cpp file (ex03, ex05).
  4. Follow-up: "And multiple definition?" Two object files define the same non-inline function, for example a body in a header with no inline.

Q55

L3 · Analyze Interview references-pointers

"When do you use a reference parameter, a pointer parameter and a value parameter?"

Show answerHide answer to Q55

Structure of a strong answer:

  1. Main fact: use a value for small types that you only read (int, double). Use const T& for large types that you only read. Use T& when the function must change the object of the caller.
  2. Use a pointer when "no object" is a valid input, and check it for nullptr (ex10).
  3. Limit: a reference or pointer parameter must not outlive the object. Do not keep it after the call (ex23).
  4. Follow-up: "Why not always const T&?" For small types, a copy in a register costs less than a read through an address.

Q56

L4 · Senior Interview containers-basics

"What occurs, step by step, when you call push_back on a full std::vector? What does it mean for references and iterators into the vector?"

Show answerHide answer to Q56

Structure of a strong answer:

  1. Main fact: when size() == capacity(), push_back gets a larger block. It moves or copies the elements into it, frees the old block and adds the new element.
  2. Example: with libstdc++ (GCC 14), the capacity grows 1, 2, 4, 8, 16. The standard needs amortized constant time. It does not specify the growth factor, so the factor is different for each library.
  3. Limit: after a reallocation, all references, pointers and iterators into the vector are invalid (ex01). reserve stops reallocation up to a known size.
  4. Follow-up: "Why does a move constructor need noexcept?" The vector moves the elements when the move cannot throw, or when the type has no copy constructor (std::move_if_noexcept). Else it copies them to keep its strong exception guarantee (Season 1).

Q57

L4 · Senior Interview classes-basics

"Why does a base class with virtual functions need a virtual destructor? Is there a different solution?"

Show answerHide answer to Q57

Structure of a strong answer:

  1. Main fact: delete through a base pointer calls the destructor through the static type. Without virtual, the behavior is undefined. In practice, the call usually runs only the base destructor (ex16).
  2. Example: Shape* shape = new Label; delete shape; ASan reports new-delete-type-mismatch.
  3. Other solution: make the base destructor protected and non-virtual. Then code cannot delete through a base pointer (C++ Core Guidelines, rule C.35).
  4. Follow-up: "What does a virtual destructor cost?" The class already has a vtable when it has a virtual function. So the cost is one or two more vtable entries and an indirect call at destruction. The Itanium ABI of GCC and Clang on Linux adds two entries.

Q58

L3 · Analyze Interview object-lifetime-basics

"Explain RAII. Why is it important when code can throw exceptions?"

Show answerHide answer to Q58

Structure of a strong answer:

  1. Main fact: RAII ties a resource to the lifetime of an object. The constructor gets the resource, and the destructor releases it.
  2. Example: std::unique_ptr, std::vector, std::string, std::ifstream, std::lock_guard. ex25 has no leak on the early return.
  3. Why exceptions: stack unwinding runs the destructors of all local objects (ex13), so an RAII object releases its resource also when a function throws. A manual delete after a throw does not run.
  4. Follow-up: "Can a destructor throw?" It must not let an exception leave it. Destructors are noexcept by default, and a second throw while C++ unwinds the stack calls std::terminate.

Q59

L4 · Senior Interview templates-basics

"Why do function templates usually go in headers? Can you put the body in a .cpp file?"

Show answerHide answer to Q59

Structure of a strong answer:

  1. Main fact: the compiler makes larger<int> only in a translation unit that sees the body. Each file that uses the template must see the body, so the body goes in the header (ex05).
  2. Option: keep the body in larger.cpp and add an explicit instantiation such as template int larger<int>(int, int);. Then larger.o defines larger<int>, but only for the listed types.
  3. Trade-off: a header body is flexible, but each file compiles it again. An explicit instantiation makes builds faster, but a new type needs a new line.
  4. Follow-up: "Does the same template body in many object files break the one definition rule?" No. The rule allows one definition of a template in each translation unit, when all the definitions are the same.

Q60

L4 · Senior Interview debugging-basics

"A program gives the correct result on your PC but crashes on the server. How do you find the bug?"

Show answerHide answer to Q60

Structure of a strong answer:

  1. Main fact: a different result on a different machine often comes from undefined behavior. Examples: a dangling reference, a use-after-free, an out-of-bounds read or an uninitialized value. UB can seem correct on one build (ex01).
  2. Steps: build with -Wall -Wextra and read each warning. Run the tests with -fsanitize=address,undefined (ex18, ex23). Get a core dump or the input from the server, and open it in GDB with a -g build. Use bt (ex10).
  3. Limit: sanitizers find only the bugs on the paths that the tests run. Use the input from the server.
  4. Follow-up: "And a crash only in the optimized build?" Build the sanitizer build with -O2, too. The optimizer can change the result of UB.
