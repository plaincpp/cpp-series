Part A: Concept checks

12 questions

Q1

L1 · Recall Short answer arithmetic-operators

Name the five binary arithmetic operators of C++. For each operator, give the result for the int operands 20 and 6.

Show answerHide answer to Q1

+ gives 26, - gives 14, * gives 120, / gives 3 and % gives 2. On two int operands, each result is an int. So / removes the fraction, and % gives the remainder: 20 = 3 * 6 + 2 (ex01).

Q2

L1 · Recall Short answer integer-division

Both operands of / are integers. Is the fraction of the result kept? Give the values of 7 / 2 and -7 / 2.

Show answerHide answer to Q2

C++ removes the fraction. The quotient truncates toward zero. So 7 / 2 is 3 and -7 / 2 is -3, not -4 (ex02, ex03). C++11 made truncation toward zero a rule. Source: cppreference, Arithmetic operators.

Q3

L1 · Recall Multiple choice integer-division

a and b are int values, and a % b is not zero. Which value sets the sign of a % b?

  • a) The sign of b, the right operand.
  • b) The sign of a, the left operand.
  • c) No value. The result is always positive.
Show answerHide answer to Q3

b) The sign of a, the left operand. The rule (a / b) * b + a % b == a is always true, and the quotient truncates toward zero. So -7 % 2 is -1 and 7 % -2 is 1 (ex03, ex04).

Q4

L1 · Recall Short answer operator-precedence

What is precedence, and what is associativity? Give one expression that shows each rule.

Show answerHide answer to Q4

Precedence sets which operator takes its operands first. For example, 2 + 3 * 4 is 14, because * comes before +.

Associativity sets the grouping of operators with the same precedence. For example, 10 - 4 - 3 is (10 - 4) - 3, because - groups from left to right. And a = b = 7 is a = (b = 7), because = groups from right to left (ex13, ex14).

Q5

L1 · Recall Short answer implicit-conversion

What do the usual arithmetic conversions do? Which conversion occurs first to a char or a short operand?

Show answerHide answer to Q5

The usual arithmetic conversions give the two operands of a binary operator one common type before the operation. Integer promotion occurs first: bool, char, short and std::uint8_t operands become int. So char + char gives an int (ex20, ex21).

Q6

L1 · Recall Short answer comparison-operators

Name the six basic comparison operators. Which type does each one give? How do you make std::cout print true and false in place of 1 and 0?

Show answerHide answer to Q6

The six basic operators are ==, !=, <, <=, > and >=. Each gives a bool. Write std::cout << std::boolalpha; before the output, and std::cout prints true and false (ex28). C++20 adds a seventh comparison operator, <=>. Its result is not a bool, and a later episode shows it. Source: cppreference, Comparison operators.

Q7

L1 · Recall Short answer logical-operators

Name the three logical operators. What is short-circuit evaluation?

Show answerHide answer to Q7

The three logical operators are && (and), || (or) and ! (not). Short-circuit evaluation: when the left operand is false, && does not evaluate its right operand. When the left operand is true, || does not evaluate its right operand (ex33).

Q8

L1 · Recall Short answer increment-operators

i is an int with the value 5. Give the value of the expression and the value of i after the expression, for ++i and for i++.

Show answerHide answer to Q8

++i gives 6, and then i is 6. i++ gives 5, the old value, and then i is 6. The two forms change i in the same way. Only the value of the expression is different (ex37).

Q9

L2 · Apply Multiple choice arithmetic-operators

Which code gives the remainder of the division of two double values?

  • a) The operator %, after #include <cmath>.
  • b) The function std::fmod from <cmath>.
  • c) The function std::mod from <numeric>.
Show answerHide answer to Q9

b) std::fmod from <cmath>. The operator % accepts only integer operands, also after #include <cmath> (ex07). The standard library has no std::mod. std::fmod(-7.5, 2.0) gives -1.5: the result has the sign of the left operand, the same as % (ex08).

Q10

L2 · Apply Multiple choice implicit-conversion

Which type does the expression 'a' + 1 have?

  • a) char
  • b) int
  • c) unsigned char
Show answerHide answer to Q10

b) int. Integer promotion makes the char an int before the addition. So 'a' + 1 is the int 98 in ASCII, and std::cout prints 98, not b (ex20).

Q11

L2 · Apply Multiple choice comparison-operators

balance is an int and limit is an unsigned int. Which flag makes GCC warn about balance < limit?

  • a) -Wall
  • b) -Wpedantic
  • c) -Wconversion only
Show answerHide answer to Q11

a) -Wall. GCC reports comparison of integer expressions of different signedness: 'int' and 'unsigned int' [-Wsign-compare] with -Wall in C++. Clang reports comparison of integers of different signs only with -Wextra (ex22, ex23). Use -Wall -Wextra on both compilers.

Q12

L2 · Apply Short answer increment-operators

Write the long form of each compound assignment: x += y, x -= y, x *= y, x /= y and x %= y. What is the one difference between x += y and its long form?

Show answerHide answer to Q12

x = x + y, x = x - y, x = x * y, x = x / y and x = x % y. The difference: the compound form evaluates x only once. This is important when x is an expression with a side effect or a slow calculation. Source: cppreference, Assignment operators. The compound form also converts the result back to the type of x with no warning (ex39).

Part D: Explain why

9 questions

Q35

L2 · Apply Explain why integer-division

n is an int. Explain why n % 1 is 0 for every value of n. Then explain why 0 % n is 0 for every n that is not 0. What occurs for n % 0?

Show answerHide answer to Q35

The rule (a / b) * b + a % b == a is always true when a / b fits in the type ([expr.mul]/4). For n % 1, the quotient n / 1 is n, so the remainder is n - n * 1, which is 0. This is true also for INT_MIN. For 0 % n, the quotient 0 / n is 0, so the remainder is 0 - 0, which is 0.

n % 0 is undefined behavior, the same as n / 0. UBSan reports division by zero (ex09). Source: cppreference, Arithmetic operators.

Q36

L2 · Apply Explain why arithmetic-operators

Explain why 7.5 % 2 does not compile. What do you use for the remainder of double values?

Show answerHide answer to Q36

The built-in % accepts only integer operands. 7.5 is a double, so GCC reports invalid operands of types 'double' and 'int' to binary 'operator%' and Clang reports invalid operands to binary expression ('double' and 'int') (ex07). Use std::fmod from <cmath>: std::fmod(7.5, 2.0) gives 1.5 (ex08).

Q37

L3 · Analyze Explain why implicit-conversion

Explain why -1 < 1u gives false. Name each conversion in the expression.

Show answerHide answer to Q37

-1 is an int and 1u is an unsigned int. The two types have the same rank, so the usual arithmetic conversions convert the signed operand to the unsigned type. The conversion of -1 to a 32-bit unsigned int gives 2 to the power 32 minus 1, which is 4294967295. And 4294967295 < 1 is false (ex22). Use std::cmp_less(-1, 1u), which gives true (ex24).

Q38

L3 · Analyze Explain why implicit-conversion

level and bonus are std::uint8_t with the values 200 and 100. std::cout << level + bonus prints 300. But std::uint8_t stored = level + bonus; gives 44. Explain the two results (ex20).

Show answerHide answer to Q38

In level + bonus, integer promotion makes the two std::uint8_t operands int first. So the sum is the int 300, and std::cout prints 300. In the initialization of stored, the int 300 converts to std::uint8_t. A conversion to an unsigned type keeps the value modulo 2 to the power 8, so 300 - 256 is 44. GCC and Clang give no warning, also with -Wconversion (ex20).

Q39

L3 · Analyze Explain why operator-precedence

Explain why low < value < high compiles but does not test a range. Which warning finds it?

Show answerHide answer to Q39

The operators group from left to right, so the expression is (low < value) < high. The left part gives a bool, which converts to 0 or 1. So the code compares 0 or 1 with high. With low 1, value 9 and high 5, the result is true (ex15). -Wall finds it with -Wparentheses: comparisons like 'X<=Y<=Z' do not have their mathematical meaning (ex16). Write low < value && value < high.

Q40

L3 · Analyze Explain why operator-precedence

In f() + g(), the program can call g() first. In std::cout << f() << g(), it always calls f() first. Explain why.

Show answerHide answer to Q40

Precedence sets only the grouping. The order of evaluation of the two operands of + is unspecified, so the compiler can call g() first. C++17 added a rule for << and >>: the program evaluates the left operand before the right operand. The rule applies also to an overloaded <<, such as the one of std::cout.

So std::cout << next_id() << ' ' << next_id() prints 1 2 (ex18). Source: cppreference, Order of evaluation.

Q41

L3 · Analyze Explain why logical-operators

Explain why count != 0 && total / count > 10 never divides by zero. Then explain why count != 0 & total / count > 10 can divide by zero.

Show answerHide answer to Q41

&& evaluates the left operand first, and it does not evaluate the right operand when the left operand is false. So when count is 0, the division does not occur (ex32).

The bitwise & has no short-circuit evaluation. It evaluates the two operands, so the program divides by zero (ex36). Precedence gives the grouping (count != 0) & (total / count > 10). GCC warns with -Wall: suggest parentheses around comparison in operand of '&' [-Wparentheses]. Clang gives no warning here (ex47). Clang warns with -Wbitwise-instead-of-logical only when the right operand calls a function, as in ex36.

Q42

L4 · Senior Explain why increment-operators

A programmer runs int total = count++ + count++; and sees the output 3. The programmer says: "The code is correct, because I see the correct number." Explain why this statement is wrong. How do you find this bug?

Show answerHide answer to Q42

The expression changes count two times with no sequence between the changes, so the behavior is undefined (ex40). The standard gives no requirement for the result. A different compiler, version or optimization level can give a different value. So an output that "looks correct" proves nothing.

Find the bug with -Wall: GCC reports -Wsequence-point and Clang reports -Wunsequenced. Add -Werror so that the build stops.

Q43

L3 · Analyze Explain why comparison-operators

balance is an int with the value -1, and limit is an unsigned int with the value UINT_MAX. Explain why balance == limit gives true. What does std::cmp_equal(balance, limit) give, and why?

Show answerHide answer to Q43

== uses the usual arithmetic conversions, the same as <. int and unsigned int have the same rank, so -1 converts to unsigned int. The result is 2 to the power 32 minus 1, which is 4294967295, and that value is UINT_MAX. So balance == limit gives true (ex22). GCC warns with -Wall, and Clang warns with -Wextra: both report -Wsign-compare (ex23).

std::cmp_equal(balance, limit) gives false. The function compares the mathematical values, and -1 is not equal to 4294967295 (ex24). Source: cppreference, std::cmp_equal.

Write int floor_div(int a, int b). It returns a / b rounded down, as in math. Precondition: b != 0, and the division does not overflow.

Show answerHide answer to Q46

Q47

Q49

Q50

L4 · Senior Write code arithmetic-operators

Write int clamp_multiply(int a, int b). It returns a * b. When the product is more than INT_MAX, it returns INT_MAX. When the product is less than INT_MIN, it returns INT_MIN. The function must not have undefined behavior for any input.

Show answerHide answer to Q50

The product of two 32-bit values always fits in 64 bits, so the long long multiplication cannot overflow (ex27). The comparisons then convert INT_MAX and INT_MIN to long long. INT_MIN * -1 is the special case that many hand-written tests forget.

Part F: Design and trade-offs

5 questions

Q51

L4 · Senior Design integer-division

A ring buffer has n slots (n > 0). A function moves a position by an int offset that can be negative. The result must be a slot from 0 to n - 1. Compare three designs: (a) (pos + offset) % n, (b) ((pos + offset) % n + n) % n, (c) the remainder, then an if that adds n to a negative remainder. Give one risk of each design and a recommendation.

Show answerHide answer to Q51

A strong answer compares the three designs:

  • (a) (pos + offset) % n: short. Risk: for a negative sum, the result is negative, for example -3 for 24 slots (ex12). The program then reads outside the buffer.
  • (b) ((pos + offset) % n + n) % n: correct for a usual n. Risk: % n + n can overflow when n is near INT_MAX. It also uses two divisions.
  • (c) remainder, then if (r < 0) r += n;: correct for every n > 0, with one division and no extra overflow.

Recommendation: (c), in a small function with a name such as wrap (q15). All three designs have one more risk: pos + offset can overflow. Limit the offset, or add in long long. When the offset is always from -n to n, one comparison and one addition do the work with no division.

Q52

L4 · Senior Design implicit-conversion

A library gives sizes as std::size_t. Your code keeps positions and offsets in int, and some offsets are negative. Compare three designs:

  • Design (a) uses a static_cast at each comparison.
  • Design (b) uses std::cmp_less and the other functions from <utility>.
  • Design (c) uses std::size_t for all positions.

Give one risk of each design and a recommendation.

Show answerHide answer to Q52

A strong answer compares the three designs:

  • (a) static_cast at each comparison: works in every standard. Risk: many casts make the code difficult to read, and one wrong cast hides a bug. For example, static_cast<int>(size) is wrong when the size is more than INT_MAX.
  • (b) std::cmp_less and the other functions: correct for all values, and the code shows the intent (ex24). Risk: they need C++20, and they help only for comparisons, not for arithmetic.
  • (c) std::size_t for all positions: no mixed comparisons. Risk: a negative offset cannot exist, and pos - 1 at 0 wraps to a very large value (ex25).

Recommendation: keep signed types for values that can be negative. Use (b) at the boundary to the library, or convert the size one time with std::ssize (C++20, <iterator>). Source: cppreference, std::size, std::ssize. Build with -Wall -Wextra, so -Wsign-compare finds each mixed comparison (ex22, ex23).

Q53

L4 · Senior Design arithmetic-operators

An order system multiplies a quantity by a price in cents. Both values are int. Large orders can overflow. Compare three designs:

  • Design (a) uses a wider type, such as std::int64_t, for the calculation.
  • Design (b) tests the values before the multiplication.
  • Design (c) uses __builtin_mul_overflow, a checked arithmetic function of GCC and Clang.

Give one risk of each design and a recommendation.

Show answerHide answer to Q53

A strong answer compares the three designs:

  • (a) A wider type: convert one operand to std::int64_t before the multiplication (ex27). It is simple and fast. Risk: the conversion must occur before the multiplication, not after it (ex26). The 64-bit limit is far away but still exists.
  • (b) A test before the multiplication: for example if (b != 0 && a > INT_MAX / b). It works without a wider type. Risk: the test for negative values has many cases, and a small error gives undefined behavior.
  • (c) __builtin_mul_overflow: it gives the result and a flag for every sign. Risk: it is not standard C++. GCC and Clang have it, but other compilers can have a different function. Source: GCC manual, Integer Overflow Builtins.

Recommendation: (a), with a range check of the input values. Test the code with UBSan (-fsanitize=undefined), which finds signed overflow at run time (ex26). C++26 adds saturation functions such as std::mul_sat. Source: cppreference, std::mul_sat.

Q54

L4 · Senior Design logical-operators

A function accepts a request when five conditions are true. One condition calls a slow database. One condition divides by a count that can be 0. One condition mixes && and ||. Design the order of the conditions and the form of the code. Compare one long expression with named bool variables.

Show answerHide answer to Q54

A strong answer gives an order and a form:

  • Order: put each safety test before the operation that it protects, for example count != 0 before the division (ex32). Put the cheap tests before the slow database call. Then short-circuit evaluation skips the call when a cheap test fails (ex33).
  • One long expression: short-circuit evaluation works. Risk: the expression is difficult to read, and a mix of && and || needs parentheses. -Wall warns about && in || (ex34).
  • Named bool variables: easy to read and to debug. Risk: each initialization runs, so the program evaluates every condition. bool high = total / count > 10; divides by zero before a later test can stop it.

Recommendation: use early return statements, or a small function for each condition. Then each condition has a name, and the order of the tests stays clear.

Q55

L4 · Senior Design increment-operators

Your team writes a coding rule for ++, -- and compound assignment. Compare two rules. Rule (a) is "Use ++ and -- only as a full statement, for example ++count;". Rule (b) is "Use ++ and -- in any expression." Give one risk and one benefit of each rule. Which compiler flags help each rule?

Show answerHide answer to Q55

A strong answer compares the two rules:

  • (a) ++ and -- only as a full statement: each statement changes a variable one time, so the undefined behavior of count++ + count++ cannot occur (ex40). The code is easy to read. Risk: the code is a little longer, and the rule stops some short idioms.
  • (b) ++ and -- in any expression: short code, such as buffer[size++] = value. Risk: two changes of one variable in one expression are undefined behavior. A reader must also remember the value of i++ and of ++i (ex37).

Compiler flags: -Wall finds two changes with no sequence (-Wsequence-point on GCC, -Wunsequenced on Clang). The flag -Wconversion finds total += 2.7 on an int, but not level += 10 on a std::uint8_t (ex39). Recommendation: rule (a) for most code, and -Wall -Wextra -Werror in the build.

Q56

L3 · Analyze Interview integer-division

What are -7 / 2 and -7 % 2 in C++? Why? What does Python give for -7 // 2 and -7 % 2?

Show answerHide answer to Q56

A strong answer:

  1. Main fact: -7 / 2 is -3 and -7 % 2 is -1. C++ truncates the quotient toward zero, and C++11 made this a rule. The remainder has the sign of the left operand, because (a / b) * b + a % b == a (ex03, ex04).
  2. Example: Python rounds the quotient down. -7 // 2 is -4, and -7 % 2 is 1, with the sign of the right operand. Source: Python reference, Binary arithmetic operations.
  3. Limit: n % 2 == 1 fails for negative odd numbers (ex05). Division by zero and INT_MIN / -1 are undefined behavior (ex09, ex10).
  4. Follow-up: "How do you round down in C++?" Subtract 1 when the remainder is not zero and the signs are different (Q46).

Q57

L4 · Senior Interview implicit-conversion

Explain the usual arithmetic conversions. What is the type of int + unsigned int? Give a real bug that this rule causes.

Show answerHide answer to Q57

A strong answer:

  1. Main fact: before a binary operation, both operands get one common type. Small integer types become int first. A floating-point type wins over an integer type. Of two integer types, the type with the higher rank wins. With the same rank, the unsigned type wins. Sometimes the signed type has the higher rank, but it cannot hold every value of the unsigned type. Then both operands convert to the unsigned version of the signed type. So unsigned long + long long is unsigned long long on x86-64 Linux (ex21).
  2. Example: int + unsigned int is unsigned int. So -1 < 1u is false, because -1 becomes 4294967295 (ex22). The difference of two unsigned values wraps before it goes into a long long (ex25).
  3. Limit: some results depend on the platform. unsigned int + long is long on x86-64 Linux, but unsigned long on 64-bit Windows (ex43).
  4. Follow-up: "How do you find these bugs?" Use -Wall -Wextra for -Wsign-compare (ex23), and std::cmp_less for the comparison (ex24).

Q58

L3 · Analyze Interview logical-operators

What is short-circuit evaluation? Give one real use. Does it apply to an overloaded operator&&?

Show answerHide answer to Q58

A strong answer:

  1. Main fact: && and || evaluate the left operand first. They skip the right operand when the left operand already sets the result (ex33).
  2. Example: count != 0 && total / count > 10 never divides by zero (ex32). Put the cheap test on the left, so the slow test runs less often.
  3. Limit: an overloaded operator&& or operator|| is a function call. It evaluates both operands, so it has no short-circuit evaluation. Source: cppreference, Logical operators.
  4. Follow-up: "What about & on two bool values?" It evaluates both operands (ex36). Clang warns with -Wbitwise-instead-of-logical.

Q59

L4 · Senior Interview increment-operators

Which is faster, ++i or i++?

Show answerHide answer to Q59

A strong answer:

  1. Main fact: for an int whose value the code does not use, the two forms give the same machine code with -O2. GCC makes addl $1, counter(%rip) for both, and Clang makes incl counter(%rip) for both (ex45).
  2. Example: ++i gives the variable itself (an lvalue). i++ gives a copy of the old value (a prvalue) (ex44).
  3. Limit: for a class type, such as an iterator, it++ usually makes a copy of the old object. The optimizer can remove the copy only when it sees all the code. So ++it is a good habit, and it is never slower.
  4. Follow-up: "When must you use i++?" Only when you need the old value, for example int before = score++; (ex37).

Q60

L4 · Senior Interview operator-precedence

What is the difference between precedence and the order of evaluation? What did C++17 change?

Show answerHide answer to Q60

A strong answer:

  1. Main fact: precedence and associativity set the grouping of the operands. The order of evaluation sets when the program computes each operand. These are two different rules.
  2. Example: in f() + g() * h(), the grouping is f() + (g() * h()), but the program can call the three functions in any order. In std::cout << f() << g(), C++17 makes the program call f() first (ex18).
  3. C++17 changes: the left operand of << and >> comes before the right operand. In an assignment, the right operand comes before the left operand. The function expression comes before the arguments. The arguments do not interleave, but their order stays unspecified. Source: cppreference, Order of evaluation.
  4. Follow-up: "Is count++ + count++ defined now?" No. The two operands of + still have no sequence, so it is undefined behavior (ex40).

Q61

L3 · Analyze Interview comparison-operators

Why is if (x = 0) legal C++? How does a team stop this bug?

Show answerHide answer to Q61

A strong answer:

  1. Main fact: an assignment is an expression whose value is the new value. In a condition, that value converts to bool. So if (x = 0) assigns 0, and the condition is always false.
  2. Example: if (errors = 3) is always true, and it changes errors (ex29).
  3. Prevention: build with -Wall -Werror. GCC reports -Wparentheses, and Clang warns also with no flags (ex30). Some teams write the constant on the left, if (0 == x), so = does not compile. The cost is code that is harder to read, and the warnings already find the bug.
  4. Follow-up: "How do you assign and test on purpose?" Put the assignment in a separate statement before the if. Or use a second pair of parentheses, if ((x = f())).

Q62

L4 · Senior Interview arithmetic-operators

A teammate writes this function to test if x + 1 overflows:

With -O2, GCC and Clang compile it to code that always returns true, also for INT_MAX. Why can the compiler do this? Write a correct test.

Show answerHide answer to Q62

A strong answer:

  1. Main fact: signed overflow is undefined behavior (episode three). So the compiler can think that x + 1 never overflows. Then x + 1 > x is always true, and the compiler removes the addition and the comparison. Source: cppreference, Undefined behavior.
  2. Proof (ex49): with -O2, GCC 14 compiles the function to movl $1, %eax and ret, and Clang 19 compiles it to movb $1, %al and retq. Both return true with no addition.
  3. Correct test: test before the operation, with no overflow: return x < INT_MAX; with #include <climits>. For two values, compare one value with the limit minus the other value, or use a wider type (Q50).
