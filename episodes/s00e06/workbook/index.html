Part A: Concept checks

12 questions

Q1

L1 · Recall Short answer function-declaration

What does a function declaration tell the compiler? Name the three parts of the declaration int square(int value);, and the character at its end.

Show answerHide answer to Q1

A declaration tells the compiler that a function with this name exists, and how to call it. The parts are the return type int, the name square and the parameter list (int value). A declaration with no body ends with ;. With the declaration, the compiler can check the type of each argument at a call. Source: cppreference, Function declaration.

Q2

L1 · Recall Short answer function-definition

What is the difference between a function declaration and a function definition? Is a definition also a declaration?

Show answerHide answer to Q2

A declaration gives the return type, the name and the parameter types. A definition also gives the body in { }, the code that runs. Every definition is also a declaration. A program can have many declarations of a function, but only one definition (ex01). Source: cppreference, Definitions and ODR.

Q3

L1 · Recall Short answer pass-by-value

A function has the parameter int score. The caller passes its variable points. What is score at the start of the call? What happens to points when the function changes score?

Show answerHide answer to Q3

score is a new local variable of the function. Its first value is a copy of points. A change to score does not change points, because the two are different objects (ex04).

Q4

L1 · Recall Short answer return-value

Name the two things that a return statement does in a non-void function.

Show answerHide answer to Q4
  1. It stops the function at once.
  2. It gives a value to the caller. The value converts to the return type (ex07, ex08).

Source: cppreference, return statement.

Q5

L1 · Recall Short answer function-overloading

What does function overloading mean? Which part of the functions must be different, and when does the compiler select the overload?

Show answerHide answer to Q5

Overloading means two or more functions with the same name and different parameter lists: different parameter types or a different number of parameters. The compiler selects one overload at compile time, from the types of the arguments (overload resolution). The return type alone cannot be the difference (ex18). Source: cppreference, Overload resolution.

Q6

L1 · Recall Short answer default-arguments

What is a default argument? Which parameters of a function can have one?

Show answerHide answer to Q6

A default argument is a value that the compiler uses when a call does not give that argument. Only the last parameters can have one: each parameter after a parameter with a default must also have a default (ex20, ex23). Source: cppreference, Default arguments.

Q7

L1 · Recall Short answer call-stack

Name three things that a frame on the call stack holds. When does the frame go away?

Show answerHide answer to Q7

A frame holds the parameters, the local variables and the return address (the place in the caller where the program continues). The frame goes away when the function returns. The newest frame goes away first: last in, first out (ex25, ex26).

Q8

L2 · Apply Multiple choice function-declaration

Three .cpp files call square. One more file, square.cpp, defines it. Where do you write the declaration of square?

  • a) In each of the three files, as a full definition
  • b) In a header that each of the four files includes
  • c) Only in the file that holds main
Show answerHide answer to Q8

b) In a header, for example square.h, that each of the four files includes. The callers need the declaration to compile the call. square.cpp includes it too, so the compiler checks that the declaration and the definition agree. Answer a) gives four definitions, and the linker stops.

Q9

L2 · Apply Multiple choice return-value

A function gets to its end with no return for some inputs. Which tool reports this when the program runs?

  • a) The linker
  • b) The compiler flag -Wall
  • c) UndefinedBehaviorSanitizer (-fsanitize=undefined)
Show answerHide answer to Q9

c) UndefinedBehaviorSanitizer. It reports runtime error: execution reached the end of a value-returning function without returning a value (ex09). -Wall (answer b) warns at compile time with -Wreturn-type, but it does not run the program. Source: Clang, UndefinedBehaviorSanitizer.

Q10

L2 · Apply Multiple choice default-arguments

A library has ruler.h and ruler.cpp. Where do you write the default arguments of draw_line?

  • a) In the declaration in ruler.h only
  • b) In the definition in ruler.cpp only
  • c) In both files, so that the two lists agree
Show answerHide answer to Q10

a) In the declaration in ruler.h only. Each caller includes the header, so each caller can use the defaults (ex21). The same default in the definition again does not compile (ex22). Defaults only in the .cpp file are not visible to the callers in other files (Q32).

Q11

L2 · Apply Short answer call-stack

Which shell command shows the stack size limit for the main thread on Linux? Which value does it give in the toolchain container, and in which unit?

Show answerHide answer to Q11

ulimit -s. It gives 8192 in the toolchain container. The unit is KiB, so the main thread has a stack of 8 MiB. Other platforms and other threads can have a different size.

Q12

L2 · Apply Multiple choice function-overloading

A file has void show(int); and void show(double);. Which call is ambiguous?

  • a) show('A')
  • b) show(2.5f)
  • c) show(42L)
  • d) show(true)
Show answerHide answer to Q12

c) show(42L). A long needs a standard conversion to int and a standard conversion to double. Both conversions have the same rank, so neither overload is better (ex16). 'A' and true promote to int, and 2.5f promotes to double (ex15).

Part D: Explain why

9 questions

Q35

L3 · Analyze Explain why function-declaration

main.cpp declares int square(int value); and calls square(7). square.cpp defines int square(long value). The build command has both files, but the linker reports undefined reference to `square(int)'. Explain why. Answer in two or three sentences.

Show answerHide answer to Q35

The compiler checks the call against the declaration in main.cpp. So main.o refers to the symbol of square(int), _Z6squarei. square.cpp defines a different function, square(long), with the symbol _Z6squarel. The linker matches only symbol names, so it finds no definition of square(int) (as in ex03). Correction: use the same parameter type in both files, and declare the function in one header that both files include.

Q36

L3 · Analyze Explain why function-definition

twice.h declares int twice(int value);. twice.cpp includes the header and defines int twice(const int value) { return value * 2; }. The program builds, and twice(21) gives 42. Explain why the declaration and the definition match, though only the definition has const. Answer in two or three sentences.

Show answerHide answer to Q36

A top-level const on a value parameter is not part of the function type, so both lines have the type int(int) and declare one function. The const only stops the body of the definition from a change to its own copy, and the caller cannot see it. For the same reason, two such definitions in one file give redefinition (ex19). Source: cppreference, Function declaration (section "Parameter list").

Q37

L2 · Apply Explain why pass-by-value

In ex05, add_item calls push_back(4) on its parameter, but main still writes 3. A Python programmer expects 4. Explain the difference. Answer in two or three sentences.

Show answerHide answer to Q37

C++ copies the full std::vector into the parameter, with all its elements. The call push_back(4) changes the copy, and the copy goes away after the call (ex05). In Python, a function gets a reference to the same list object, so a change in the function is visible to the caller.

Q38

L3 · Analyze Explain why pass-by-value

In ex12, show(next_id(), next_id()) writes 2 1 on GCC. A learner decides that GCC gives the second argument to the first parameter. Explain why this is wrong, and what the standard does not set. Answer in two or three sentences.

Show answerHide answer to Q38

The first argument always initializes the first parameter, first, and the second argument initializes second. The standard sets only this position, not the order of evaluation. GCC calls the right next_id() first, so that call returns 1 for second, and the left call returns 2 for first. Clang evaluates the left argument first and writes 1 2 (ex13). Sources: cppreference, Function call, cppreference, Order of evaluation.

Q39

L3 · Analyze Explain why return-value

ex09 compiles with only a warning, and a test run can write a letter that looks correct. Explain why the program is still wrong, and why the output of a test run is not a proof. Answer in three sentences.

Show answerHide answer to Q39

When a non-void function gets to its end with no return, the behavior is undefined. The standard then gives no rule for the program, so a test run can write any letter or crash. A different build, a different optimization level or a different input can change the result, so use -Werror=return-type (ex10) and UBSan to find it. Source: cppreference, return statement.

Q40

L3 · Analyze Explain why function-overloading

A file has void show(int); and void show(double);. Explain why show(count) with a long count is ambiguous, but show(level) with a short level selects show(int). Answer in three sentences.

Show answerHide answer to Q40

For short, the conversion to int is a promotion, and the conversion to double is a standard conversion. So show(int) has the better rank. For long, both conversions are standard conversions with the same rank, so the compiler reports an ambiguous call (ex15, ex16).

Q41

L3 · Analyze Explain why function-overloading

In ex17, report("disk full") selects report(bool), not report(std::string). Explain the two conversions that the compiler compares, and why bool wins. Answer in three sentences.

Show answerHide answer to Q41

The string literal converts to const char* and then to bool, which is a standard conversion. The conversion to std::string uses a constructor of std::string, which is a user-defined conversion. A standard conversion has a better rank than a user-defined conversion, so report(bool) wins (ex17). Source: cppreference, Overload resolution ("Ranking of implicit conversion sequences").

Q42

L3 · Analyze Explain why default-arguments

In ex20, draw_line has the defaults width = 8 and fill = '-'. With g++ -S, the call draw_line(4) gives the same assembly as the call draw_line(4, '-'). Explain why. Answer in two or three sentences.

Show answerHide answer to Q42

The compiler puts each missing default into the call, in the code of the caller. So draw_line(4) becomes draw_line(4, '-') at compile time, and the function gets two arguments in both cases. In the toolchain, both calls load 4 and 45 (the code of '-') and call _Z9draw_lineic. For this reason, a new default in a library has no effect until you compile each caller again (q34). Source: cppreference, Default arguments.

Q43

L4 · Senior Explain why call-stack

ex27 crashes for depth(100000000). A loop that counts to 100000000 does not crash. Explain the difference with the call stack, and give the size of the stack in the toolchain container. Answer in three or four sentences.

Show answerHide answer to Q43

Each recursive call puts a new frame on the call stack, and a frame goes away only when its call returns. So the call depth(100000000) needs 100000000 frames at the same time. The stack has a fixed size: 8192 KiB in the toolchain container (ulimit -s). A loop uses one frame for all its steps, so it needs no more stack space. AddressSanitizer reports the crash as stack-overflow (ex27).

Q50

Part F: Design and trade-offs

5 questions

Q51

L4 · Senior Design function-definition

Your team writes a small math library with 20 functions. Ten other .cpp files use it. Compare two designs: (1) declarations in math_utils.h and definitions in math_utils.cpp, (2) all definitions in the header, marked inline. Talk about build time, the one definition rule and what a change to a function body costs. Give a recommendation.

Show answerHide answer to Q51

A strong answer compares the two designs:

  • Header and .cpp file: each caller compiles only the declarations. A change to a function body compiles only math_utils.cpp again, and the link step. The one definition rule is easy: one definition in one file. The compiler cannot inline a call in other files, unless you use link-time optimization (-flto).
  • inline definitions in the header: the compiler sees each body at each call and can inline it. But each of the ten files compiles all 20 bodies. A change to one body compiles all ten files again. The one definition rule lets each translation unit have one definition, if all of them are the same.

Recommendation: use a header and a .cpp file for most functions. Put only very short functions, for example a one-line square, in the header as inline. Sources: cppreference, inline specifier, cppreference, Definitions and ODR.

Q52

L4 · Senior Design pass-by-value

Choose pass by value or a different method for each parameter below, and give the reason. Name the method for case 3 that S00E07 teaches.

  1. An int count.
  2. A double ratio.
  3. A std::vector<double> with 1000000 values that the function only reads.
  4. A std::string that the function changes and then returns.
Show answerHide answer to Q52

A strong answer chooses a method for each case:

  1. int count: pass by value. A copy of 4 bytes costs nothing, and the function cannot change the variable of the caller.
  2. double ratio: pass by value, for the same reason.
  3. std::vector<double> that the function only reads: do not pass by value. A copy of 1000000 elements costs about 8 MB of memory to copy at each call (ex05). Use a reference to const, const std::vector<double>&, from S00E07.
  4. std::string that the function changes and returns: pass by value. The function needs its own copy, and the return moves the copy out (Q48). A caller that does not need its string any more can move it in (S00E07 and later).

Rule: pass small types and objects that the function needs to copy by value. Pass large objects that the function only reads by reference to const.

Q53

L4 · Senior Design default-arguments

A library has void draw_line(int width, char fill). Many callers use the width 8 and the fill '-'.

Compare two designs. Design 1 has default arguments in the header. Design 2 has the overloads draw_line(), draw_line(int) and draw_line(int, char), with the values in the .cpp file.

Talk about the code of the callers, a later change of the default values and ambiguity. Give a recommendation.

Show answerHide answer to Q53

A strong answer compares the two designs:

  • Default arguments: one function in the header and one in the .cpp file, so the code is short. The default values are in the header, so a caller sees them. But the compiler puts the values into each call (Q42). A change of a default needs a new compile of every caller. A default argument and an overload with fewer parameters make a call ambiguous (ex24).
  • Overloads: more functions to write. But the values are in the .cpp file of the library. So a new library version can change them, and the callers need no new compile. No ambiguity, because each overload has a different number of parameters.

Recommendation: use default arguments in application code, where you compile everything together. Use overloads in the public interface of a library that you ship separately. Never use both for the same parameter.

Q54

L4 · Senior Design return-value

parse_port(std::string text) must give a port number from 1 to 65535, or tell the caller that the text is wrong. Compare three designs: (1) return int, with -1 for an error, (2) return std::optional<int>, (3) throw an exception. Talk about the risk that a caller ignores the error, and about [[nodiscard]]. Give a recommendation.

Show answerHide answer to Q54

A strong answer compares the three designs:

  1. int with -1: simple and fast, but a caller can use -1 as a port. The type does not show the error. [[nodiscard]] makes the compiler warn about a caller that ignores the result. It does not stop the build without -Werror (ex11), and it does not help with a caller that forgets the check.
  2. std::optional<int>: the type shows that the result can be absent. The caller must take the value out with *result or .value(), so the check is visible in the code. [[nodiscard]] helps here too. The cost is small.
  3. Exception: a caller cannot ignore it. The error goes up to a caller that can handle it. But an exception costs much more when the program throws it, and the signature does not show it. Exceptions come in a later episode.

Recommendation: [[nodiscard]] std::optional<int> parse_port(std::string text) for input that is often wrong, such as user input. Use an exception when a wrong value is rare and the direct caller cannot handle it. Sources: cppreference, std::optional, cppreference, nodiscard.

Q55

L4 · Senior Design call-stack

A program walks a chain of linked records. Most chains have 100 records, but some files have 10000000. Compare a recursive walk with a loop and with an explicit stack in a std::vector. Talk about the stack size (main thread and other threads), the code clarity and the cost. Give a recommendation.

Show answerHide answer to Q55

A strong answer compares the three methods:

  • Recursion: short and clear for a chain or a tree. But each record needs a frame. 100 records are no problem, but 10000000 records need 10000000 frames, and the stack of 8 MiB (ulimit -s 8192) overflows (ex27). The stack of a different thread can be smaller. The C++ standard does not guarantee that the compiler changes a tail call into a loop.
  • Loop: one frame for any length, and no stack risk. For a chain, a loop is also simple, because each record has only one next record.
  • Explicit stack in a std::vector: for a structure with more than one branch, such as a tree. The vector keeps the pending work on the heap, and the heap is much larger than the stack. The code is longer.

Recommendation: use a loop for a chain. Use an explicit stack for a deep tree from input that you do not control. Use recursion only when the depth has a small, known limit. Source: Clang, AddressSanitizer.

Q56

L3 · Analyze Interview function-declaration

What is the difference between a declaration and a definition of a function? What is the one definition rule, and which tool reports a violation of it?

Show answerHide answer to Q56

A strong answer has these parts:

  1. Main fact: a declaration gives the name, the return type and the parameter types. A definition also gives the body. Every definition is a declaration.
  2. Example: int square(int value); in a header, and int square(int value) { return value * value; } in one .cpp file (ex01, ex21).
  3. One definition rule: a program can have many declarations, but only one definition of a function that is not inline. Two definitions in one file give redefinition from the compiler (ex19). Two definitions in two files give multiple definition of from the linker (Q34). No definition gives undefined reference from the linker (ex03).
  4. Follow-ups: "What about inline functions?" They can have a definition in each translation unit, but all the definitions must be the same. If they are different, the program is ill-formed, but the compiler and the linker can stay silent. Source: cppreference, Definitions and ODR.

Q57

L3 · Analyze Interview function-overloading

Can you overload a function on its return type only? Why does C++ not let you do this?

Show answerHide answer to Q57

A strong answer has these parts:

  1. Main fact: no. Two functions with the same parameter list and a different return type do not compile (ex18).
  2. Why: overload resolution uses only the arguments of a call. A call such as parse(42); does not use the result, and auto x = parse(42); gives no type to compare. So the compiler cannot select by the return type.
  3. Options: use different names, such as to_int and to_double. Or use a template with an explicit type, such as parse<double>("2.5"), in a later episode.
  4. Follow-up: "Does const on a value parameter make an overload?" No, it is the same function (ex19). Source: cppreference, Overload resolution.

Q58

L4 · Senior Interview pass-by-value

In which order does C++ evaluate the arguments of f(a(), b())? What changed in C++17? Is f(i++, i++) undefined behavior?

Show answerHide answer to Q58

A strong answer has these parts:

  1. Main fact: the standard does not set the order. GCC 14 and Clang 19 give different results for the same program: 2 1 and 1 2 (ex12, ex13).
  2. C++17: the compiler sequences the arguments indeterminately. It evaluates one argument fully before it starts the next, but in any order. Before C++17, parts of two arguments could also mix.
  3. f(i++, i++): before C++17, it was undefined behavior. From C++17, it is unspecified: no undefined behavior, but the result depends on the compiler. In the toolchain, GCC passes 1 0 and Clang passes 0 1. GCC warns operation on 'i' may be undefined [-Wsequence-point], and Clang warns multiple unsequenced modifications to 'i' [-Wunsequenced]. The warnings use the words of the old rule. The code is still a bug, because the result depends on the compiler.
  4. Follow-up: "What about std::cout << a() << b()?" From C++17, the program evaluates the left operand of << first, so a() runs first (Q24). Source: cppreference, Order of evaluation.

Q59

L4 · Senior Interview function-overloading

What is name mangling? Why does C++ need it, and what does extern "C" change?

Show answerHide answer to Q59

A strong answer has these parts:

  1. Main fact: the compiler changes each function name into a symbol name. The symbol name includes the parameter types. For example, show(int), show(double) and show(const char*) become _Z4showi, _Z4showd and _Z4showPKc (ex14, nm).
  2. Why: the linker matches only symbol names. If two overloads have the same symbol, the linker cannot tell them apart.
  3. extern "C": it gives C language linkage to the function, so the symbol is the plain name. In the toolchain, extern "C" int show_c(int) has the symbol show_c, but int show_cpp(int) has _Z8show_cppi. C code and other languages can then call the function. But two extern "C" functions with one name do not compile: GCC reports conflicting declaration of C function.
  4. Follow-ups: "Is the mangling the same on every compiler?" No. GCC and Clang on Linux use the Itanium C++ ABI, and MSVC uses a different scheme. "How do you read a mangled name?" Use c++filt or nm -C. Source: cppreference, Language linkage.

Q60

L3 · Analyze Interview default-arguments

Where do you write default arguments, in the declaration or in the definition? What goes wrong in the other place?

Show answerHide answer to Q60

A strong answer has these parts:

  1. Main fact: write the defaults in the declaration in the header. Each caller includes the header, so each caller sees the defaults (ex21).
  2. In both places: the definition repeats the default, and that does not compile. Clang reports redefinition of default argument, and GCC reports default argument given for parameter 1 (ex22).
  3. Only in the definition: the callers in other files do not see the defaults, so draw_line() stops with too few arguments (Q32).
  4. Follow-ups: "When does the compiler evaluate a default?" At each call that leaves the argument out, in the code of the caller (Q21, Q42). "What about virtual functions?" The default comes from the static type of the object expression, not from the function that the call runs. Virtual functions come in a later season. Source: cppreference, Default arguments.

Q61

L4 · Senior Interview call-stack

What is a stack overflow? How deep can recursion go, and how do you find and prevent a stack overflow?

Show answerHide answer to Q61

A strong answer has these parts:

  1. Main fact: a stack overflow occurs when the frames use all of the stack. The program crashes, usually with a segmentation fault.
  2. Numbers: the main thread on Linux usually has 8 MiB (ulimit -s gives 8192 in the toolchain). To find the depth limit, divide the stack size by the frame size. The frame size depends on the function and on the build flags. ex27 crashes for depth(100000000). Other threads and other platforms can have a smaller stack.
  3. Find it: AddressSanitizer reports stack-overflow and the frames (ex27). A debugger shows a backtrace with thousands of frames of the same function.
  4. Prevent it: use a loop, or an explicit stack in a std::vector on the heap (Q55). Make the depth grow with log(n), not with n (Q50). Check the depth of input that you do not control.
  5. Follow-up: "Does the compiler remove the recursion?" An optimizer can change a tail call into a jump. But the C++ standard does not guarantee it, and a debug build does not do it. Source: Clang, AddressSanitizer.

Q62

L4 · Senior Interview return-value

Is it expensive to return a std::vector by value? Explain copy elision, and say what changed in C++17. Should you write return std::move(result);?

Show answerHide answer to Q62

A strong answer has these parts:

  1. Main fact: no. Return by value copies no element of a local std::vector. In ex28, the vector in main has the same element buffer as the local vector (true).
  2. Copy elision: the compiler makes the result directly in the place of the caller. For a prvalue, such as return std::vector<int>{1, 2, 3};, C++17 guarantees it. For a named local, such as return numbers;, the standard lets the compiler elide the copy (NRVO), but it does not guarantee it. If the compiler does not elide it, C++ moves the local, and a move of a vector copies only a few pointers.
  3. return std::move(result);: do not write it. It makes the expression an xvalue, and that stops copy elision. GCC and Clang warn moving a local object in a return statement prevents copy elision [-Wpessimizing-move].
  4. Follow-up: "When is a copy still made?" When the function returns a member or a global object, or when the type has no move constructor. Source: cppreference, Copy elision.
