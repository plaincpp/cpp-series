Scope, Storage Duration and Lifetime

About 12 min 34 quiz questions 62 workbook questions
Start the quiz Open the workbook Compiler Explorer (opens in a new tab)

What you learn

  • Compare the scope of a name and the lifetime of an object, and find where each one ends.
  • Name the four storage durations, and predict when an object of each duration starts and ends.
  • Explain when the initializer of a static local variable runs, and use one to prevent the static initialization order problem.
  • Explain the stack frame of each call, and tell why a large local array must go into dynamic storage.
  • Find a dangling reference to a local variable or to a temporary with warnings and AddressSanitizer, and correct it.

Question 4 of 34 L1 · Recall block-scope

Scope is a property of a name in the source code. Lifetime is a property of an object at run time. The two can end at different points, as a static local variable shows (ex05).

Question 8 of 34 L2 · Apply block-scope

True or false: In if (int left = 7 - 9; left > 0) { ... } else { ... }, the else branch can use left.

A name in the init-statement of if is visible in the condition, in the first branch and in the else branch. After the whole if statement, the name is not visible.

ex26 has this if, and it writes else -2 on GCC 14 and Clang 19. The rule is in C++23 [stmt.if] and [basic.scope.block].

Question 9 of 34 L1 · Recall automatic-storage

Choose one: Which variable has automatic storage duration?

A local variable without static or thread_local has automatic storage duration ([basic.stc.auto]). A variable at namespace scope and a static local have static storage duration. A thread_local variable has thread storage duration.

Question 11 of 34 L3 · Analyze automatic-storage

Select all that apply.

Parameters and local variables without static are automatic, and the pointer data is one of them. The array from new has dynamic storage duration (ex17). runs and limit have static storage duration.

Question 12 of 34 L3 · Analyze automatic-storage

Choose one: A function declares the local array int readings[4'000'000];. AddressSanitizer reports stack-overflow. Which change corrects the bug?

The array needs 16,000,000 bytes. The stack of the main thread in the toolchain container has only 8 MiB (ex07). A std::vector keeps its elements in dynamic storage (ex08). An inner block or an initializer keeps the array on the stack. An option of the optimizer is not a correction.

Question 13 of 34 L1 · Recall automatic-storage

Fill the blank: Each function call gets its own stack ____blank for its parameters and its local variables.

A call makes a new stack frame. When the function returns, the frame goes away, and its automatic objects end (ex06).

Question 14 of 34 L1 · Recall static-storage

Match the terms: Match each object to its storage duration.

A global lives for the whole program. A local lives until its block ends. Each thread has its own thread_local object. An object from new lives until delete (ex09, ex14).

Question 15 of 34 L2 · Apply static-storage

Predict the output: What does this program write?

A variable with static storage duration and no initializer is zero-initialized ([basic.start.static]; ex12). An automatic int with no initializer gets no value, so a read of it is undefined behavior (S00E03).

Question 16 of 34 L2 · Apply static-storage

Put in order: A program has a global object, an automatic object in main and a static local object. The program calls the function of the static local one time. Put the events in order for GCC and Clang.

Drag the handle, or use the arrow buttons. With a row focused, press Alt + Up or Alt + Down.

  1. The function call starts the static local object
  2. The automatic object ends at the closing brace of main
  3. The global object starts
  4. The automatic object in main starts
  5. The static local object ends
  6. The global object ends

On GCC and Clang, the global starts before main (ex09). The standard lets a compiler delay it until after main begins ([basic.start.dynamic]/5). Objects with static storage end after main, in the reverse order of their construction, so the static local ends before the global ([basic.start.term]).

Question 17 of 34 L3 · Analyze static-storage

True or false: The standard initializes the globals of two source files in the order of the files on the command line.

The standard gives no order for the dynamic initialization of globals in different translation units ([basic.start.dynamic]). On this toolchain the order follows the link order, but other toolchains can use a different order.

In ex15, one link order gives initialization-order-fiasco, and the other order gives a clean run. Do not make the correctness of a program depend on the link order.

Question 18 of 34 L4 · Senior static-storage

Choose all that apply: In ex15, greeting in greeting.cpp reads the global user_name from user.cpp. Which changes remove the initialization order problem? Select all correct answers.

Select all that apply.

The function starts its static local on the first call, before the first use (ex16). In one source file, globals start in the order of their definitions ([basic.start.dynamic]). A link order only hides the bug, static changes the linkage, and AddressSanitizer only finds the bug.

Question 19 of 34 L2 · Apply dynamic-storage

The int from new lives after make_counter returns. Only the pointer in make_counter ends. main adds 5 to 10, writes 15, and then calls delete.

Question 20 of 34 L2 · Apply dynamic-storage

Choose one: In ex17, make_counter makes int* counter = new int{10}; and returns counter. Which object ends when make_counter returns?

The pointer is an automatic local variable, so it ends with the stack frame. The int has dynamic storage duration and lives until delete ([basic.stc.dynamic]). The caller gets a copy of the address.

Question 21 of 34 L1 · Recall dynamic-storage

True or false: An object from new ends at the closing brace of the block that makes it.

An object from new has dynamic storage duration. It lives until delete ends it, also after its function returns.

Only the pointer variable ends at the closing brace (ex17). If no delete runs, the object leaks. S00E14 shows leaks and std::unique_ptr.

Question 22 of 34 L2 · Apply dynamic-storage

Choose one: std::vector<int> readings(4'000'000); is a local variable. Where are its 4,000,000 elements?

The vector object itself is automatic and small. It keeps its elements in dynamic storage and frees them in its destructor. So ex08 works, but the local array of 16,000,000 bytes in ex07 overflows the stack.

Question 23 of 34 L3 · Analyze static-local In the video

How many times does the initializer of a static local variable run?

The initializer runs only on the first call, with n equal to 1. The second call skips it, so cached stays 10 and the argument 2 has no effect (ex10).

Question 24 of 34 L1 · Recall static-local

Fill the blank: The initializer in static int limit = load_limit(); runs the first time that control passes through the ____blank of limit.

An initializer that calls a function runs on the first pass, not at program start ([stmt.dcl]/3). In ex10, main comes before load. If the function never runs, the initializer never runs (ex11). A constant initializer such as = 0 is ready before main ([basic.start.static]/2).

Question 25 of 34 L2 · Apply static-local

True or false: Eight threads call a function for the first time at the same time. The initializer of its static local variable runs one time only.

From C++11, the initialization of a static local variable is thread-safe. The other threads wait until the initialization ends ([stmt.dcl]).

In ex13, eight threads call get_config, and the program writes loads: 1. Only the initialization is thread-safe. Later changes to the variable from many threads need a mutex or an atomic.

Question 27 of 34 L4 · Senior static-local

Choose one: get_config has static int config = load_config();. What does GCC or Clang add to each call after the first one?

GCC and Clang keep a guard variable for the static local, and each call reads it. Only the first call takes the slow path with __cxa_guard_acquire (Itanium C++ ABI 3.3.2). A static local with a constant initializer, such as = 0, needs no guard, because it gets its value before main ([basic.start.static]/2).

Question 29 of 34 L3 · Analyze dangling-reference

Choose all that apply: make_name() returns a std::string by value. Which declarations keep the temporary alive until the end of the block? Select all correct answers.

Select all that apply.

A const reference or an rvalue reference that binds directly to a temporary extends its life ([class.temporary]; ex21). A std::string_view is not a reference, so the string ends at the ; (ex23). Question 30 of 34 L3 · Analyze dangling-reference

The warnings find only some cases. The sanitizers (-fsanitize=address,undefined) find all four at run time. So build your tests with sanitizers, and do not trust a silent build.

Question 31 of 34 L3 · Analyze dangling-reference

True or false: The program in ex18 writes 42 on my computer, so its reference to the local result is safe.

A read through a dangling reference is undefined behavior. A correct value on one computer does not prove that the code is correct.

Clang's AddressSanitizer reports stack-use-after-return. GCC changes the returned reference to null, and UBSan reports reference binding to null pointer. Return by value (ex19).

Question 32 of 34 L4 · Senior dangling-reference

Choose one: Greeter keeps a name that a caller gives to its constructor. Callers often give a temporary string. Which member type is safe for all callers?

A std::string member owns a copy, so it lives as long as the Greeter. The other three types only refer to text that the caller owns, and a temporary ends at the ; (ex24). The copy costs one allocation for a long name, which is a small price for safety.

Question 34 of 34 L2 · Apply static-storage

Choose one: A source file has static int hits = 0; at namespace scope. A function in the same file has static int calls = 0;. What does the keyword static change?

At namespace scope, hits already has static storage, so static gives it internal linkage (S00E12). In a block, static gives calls static storage duration instead of automatic (ex05). A local variable has no linkage.
