Error Handling and Exception Basics in C++

About 12 min 40 quiz questions 65 workbook questions
Start the quiz Open the workbook Compiler Explorer (opens in a new tab)

What you learn

  • Compare error codes and exceptions, and use [[nodiscard]] to find an error code that the caller does not check.
  • Use throw, try and catch with std::runtime_error, and predict which lines run after a throw.
  • Explain how stack unwinding calls the destructors of local objects, and name three cases that call std::terminate.
  • Catch an exception by const reference, and put the most specific handler first.
  • Find the slicing bug in a handler that catches an exception by value.

Question 34 of 40 L4 · Senior stack-unwinding

Choose all that apply: GCC and Clang on x86-64 Linux use the Itanium C++ ABI for exceptions. Which statements are correct? Select all correct answers.

Select all that apply.

The compiler puts unwinding tables next to the code, so the path with no throw has no extra checks. A throw calls __cxa_allocate_exception and a two-phase search through the tables, so it is much slower than a return. Sources: Itanium C++ ABI, Exception Handling; WG21 P0709R4, section 2.

Question 35 of 40 L1 · Recall catch-by-reference

Choose one: Which handler is the usual form to catch all standard exceptions?

A const reference makes no copy and keeps the full type, so what() gives the derived message (ex27). A handler by value slices the object (ex26). A pointer handler does not match an object that throw makes.
