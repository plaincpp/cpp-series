Part A: Concept checks

12 questions

Q1

L1 · Recall Short answer cmake

CMake is a "build system generator". What does CMake make, and which program calls the compiler? Answer in two sentences.

Show answerHide answer to Q1

CMake makes the build files for a build tool, for example build.ninja for Ninja or a Makefile for Make. The build tool calls the compiler and the linker. CMake itself does not compile code.

Q2

L1 · Recall Short answer cmake

Name the three steps from CMakeLists.txt to the executable. For each step, give the command or the file that it makes.

Show answerHide answer to Q2
  1. Configure: cmake -S . -B build -G Ninja. CMake reads CMakeLists.txt, finds the compiler (The CXX compiler identification is GNU 14.2.0) and writes CMakeCache.txt.
  2. Write the build files: in the same command, CMake writes build.ninja (-- Generating done).
  3. Build: cmake --build build. Ninja compiles each .cpp file to an object file and links the executable.

Q3

L1 · Recall Multiple choice cmake

You run cmake -S . -B build on Linux with no -G option. Which generator does CMake use?

  • a) Ninja
  • b) Unix Makefiles
  • c) Visual Studio
Show answerHide answer to Q3

b) Unix Makefiles. With no -G, CMake 3.28 on Linux writes CMAKE_GENERATOR:INTERNAL=Unix Makefiles in CMakeCache.txt. Use -G Ninja to select Ninja.

Q4

L1 · Recall Short answer cmakelists

What does the line cmake_minimum_required(VERSION 3.28) do? Give two effects.

Show answerHide answer to Q4
  1. It stops the configure step with an error if the CMake version is older than 3.28.
  2. It sets the policies of CMake 3.28, so a newer CMake keeps the behavior of 3.28.

Put it on the first line, before project().

Give the file name that each line makes on Linux: add_library(geometry STATIC geometry.cpp) and add_library(units SHARED units.cpp).

Show answerHide answer to Q8

Q9

L2 · Apply Multiple choice add-library

CMakeLists.txt has add_library(units units.cpp) with no type. You configure with -DBUILD_SHARED_LIBS=ON. Which file does the build make?

  • a) libunits.a
  • b) libunits.so
  • c) both files
Show answerHide answer to Q9

b) libunits.so. With no STATIC or SHARED, the variable BUILD_SHARED_LIBS selects the type. With -DBUILD_SHARED_LIBS=ON, Ninja prints Linking CXX shared library libunits.so. With no option, it prints Linking CXX static library libunits.a.

Q10

L1 · Recall Short answer build-directory

What does CMakeCache.txt keep? Name three values that it holds.

Show answerHide answer to Q10

CMakeCache.txt keeps the choices of the configure step. Examples: the compiler (CMAKE_CXX_COMPILER), the generator (CMAKE_GENERATOR), the build type (CMAKE_BUILD_TYPE) and the flags of each build type (CMAKE_CXX_FLAGS_RELEASE). A second configure step reads these values again.

Q11

L2 · Apply Multiple choice build-target

Which command builds only the library target geometry?

  • a) cmake --build build --target geometry
  • b) cmake -S . -B build --target geometry
  • c) ninja geometry.cpp
Show answerHide answer to Q11

a) cmake --build build --target geometry. Ninja builds only geometry.cpp.o and libgeometry.a (2 steps). Option b) is the configure step, and c) is not a Ninja target.

Q12

L1 · Recall Short answer compile-options

What does the macro NDEBUG do to assert? Which CMake build types define NDEBUG?

Show answerHide answer to Q12

With NDEBUG, assert(...) becomes an expression that does nothing. The program does not evaluate the condition. Release (-O3 -DNDEBUG), RelWithDebInfo (-O2 -g -DNDEBUG) and MinSizeRel (-Os -DNDEBUG) define it. Debug (-g) and no build type do not.

D

Part D: Explain why

10 questions

Q33

L2 · Apply Explain why cmake

Explain why the course uses cmake --build build and not ninja -C build or make -C build.

Show answerHide answer to Q33

cmake --build works with each generator. It reads the generator from CMakeCache.txt and runs the correct build tool. With --verbose, it shows that it runs /usr/bin/ninja -v. The same command works with Ninja, Make and the Visual Studio generator, so scripts and documents stay the same on each system. Options such as --target and -j also work with each build tool.

Q34

L3 · Analyze Explain why cmake

In ex03, a change in geometry.h compiles two files, but a change in geometry.cpp compiles one file. Explain how Ninja knows which files include geometry.h. CMakeLists.txt does not list the header.

Show answerHide answer to Q34

The compiler writes a dependency file for each object file. The compile command of CMake has -MD -MF CMakeFiles/app.dir/main.cpp.o.d. This file lists each header that the preprocessor opened. Ninja reads it, so Ninja knows that main.cpp.o and geometry.cpp.o depend on geometry.h. A change in geometry.cpp changes only the input of geometry.cpp.o.

Q35

L2 · Apply Explain why build-directory

Explain why a separate build folder (-B build) is better than an in-source build (cmake .). Give two reasons.

Show answerHide answer to Q35
  1. All the files that CMake makes are in one folder. Delete build/ to start again, and the source folder stays clean. An in-source build puts CMakeCache.txt, CMakeFiles, build.ninja and cmake_install.cmake next to main.cpp.
  2. You can make many build folders from one source: Debug, Release, a Clang build. Each folder has its own cache and its own object files.

A third reason: version control. The build files are not in the source folder, so they do not get into a commit by mistake.

Q36

L4 · Senior Explain why build-target

In ex17, report links words with PRIVATE. The link line of app still has libwords.a. Explain why CMake adds it, and why PRIVATE does not remove it.

Show answerHide answer to Q36

A static library is only an archive of object files (ar qc libreport.a report.cpp.o). It cannot record that it needs libwords.a. The symbol count_words stays undefined in libreport.a until the link of the executable. Thus CMake adds libwords.a to each link that uses libreport.a. The link of app is g++ main.cpp.o -o app libreport.a libwords.a.

The keyword PRIVATE keeps the usage requirements of words, for example its include folders, away from app. It cannot remove the library from the link. Source: the CMake documentation of target_link_libraries, and ex17.

Q37

L4 · Senior Explain why add-library

The command g++ main.cpp.o -o app libwords.a libreport.a fails with undefined reference to `count_words(...)'. The command g++ main.cpp.o -o app libreport.a libwords.a links. Explain why the order of the archives changes the result.

Show answerHide answer to Q37

GNU ld reads the files from left to right. It takes an object file from an archive only when that object file defines a symbol that is undefined at that point. In the first command, libwords.a comes first, and no symbol needs count_words yet, so ld takes nothing. Then libreport.a adds a new undefined symbol count_words, and ld does not go back. Thus a library must come before the libraries that it uses. Source: the GNU ld manual, option -l ("The linker will search an archive only once").

Q38

L3 · Analyze Explain why compile-options

cxx_std_23 alone gives -std=gnu++23. Explain the difference between -std=gnu++23 and -std=c++23, and why many projects set CXX_EXTENSIONS OFF.

Show answerHide answer to Q38

-std=c++23 is ISO C++23. -std=gnu++23 is C++23 plus the GNU extensions. In ISO mode, the compiler defines __STRICT_ANSI__ (ex07). For example, typeof(x) y = x + 1; compiles with -std=gnu++23 on GCC 14 and Clang 19. With -std=c++23, GCC stops with 'typeof' was not declared in this scope, and Clang stops with use of undeclared identifier 'typeof'. Projects set CXX_EXTENSIONS OFF, so that the code stays portable to other compilers, for example MSVC.

Q39

L3 · Analyze Explain why compile-options

ex09 has set(CMAKE_CXX_FLAGS "-Wall -Wextra -Werror"). A user configures with -DCMAKE_CXX_FLAGS=-fsanitize=address. The compile commands have no -fsanitize=address. Explain why. Then explain why ex10, which uses target_compile_options, keeps the user flag.

Show answerHide answer to Q39

set(CMAKE_CXX_FLAGS ...) makes a normal variable. A normal variable hides the cache variable with the same name, and -DCMAKE_CXX_FLAGS=... sets the cache variable. Thus the commands have only -Wall -Wextra -Werror. ex10 does not set CMAKE_CXX_FLAGS, so the user value stays. The compile of main.cpp gets -fsanitize=address -Wall -Wextra -Werror, and the link gets -fsanitize=address too. Keep CMAKE_CXX_FLAGS for the user, and put the project flags on the targets.

Q40

L3 · Analyze Explain why add-library

ex13 builds libunits.so and app. You move libunits.so to another folder, and you run ./build/app. It stops with error while loading shared libraries: libunits.so: cannot open shared object file. Explain why. Why does the same move of libgeometry.a in ex03 not stop app?

Show answerHide answer to Q40

app does not contain the code of libunits.so. It records only NEEDED libunits.so and a run path, RUNPATH /work/weather/build (from readelf -d app). When app starts, the dynamic loader looks for libunits.so in that folder and in the system folders. It cannot find it, so app stops with exit status 127. A static library is different: the linker copies the object files from libgeometry.a into app, so app does not need the archive when it runs.

Q41

L3 · Analyze Explain why cmakelists

In ex18, CMake prints two errors for one wrong file name, and the build folder has no build.ninja. Explain both facts.

Show answerHide answer to Q41

The first error, Cannot find source file: mian.cpp, comes from the check of each source file. The target has no other source file, so CMake also reports No SOURCES given to target: app. After errors, CMake prints CMake Generate step failed and writes no build.ninja. Q42

L2 · Apply Explain why add-executable

ex02 has add_executable(greeter main.cpp greet.cpp). Explain why greet.h does not need to be in the list. Explain why greet.cpp must be in the list.

Show answerHide answer to Q42

The compiler never compiles a header alone. The preprocessor copies greet.h into each .cpp file that includes it. The dependency file tells Ninja about the header. greet.cpp holds the definition of greeting. Each .cpp file in the list becomes one object file. If greet.cpp is not in the list, no object file defines greeting, and the link fails (Q25).

Part F: Design and trade-offs

5 questions

Q51

L4 · Senior Design add-library

A project has 20 .cpp files in one add_executable. The team needs unit tests for the parsing code. It also needs a second tool that uses the same code.

Compare two designs. Design (a) is one executable with all files. Design (b) is a static library core and two executables that link to it. Give a recommendation.

Show answerHide answer to Q51

Structure of a strong answer:

  1. Design (a): simple at the start. But the tests and the second tool must list the 20 files again or compile them again. The parsing code has no clear boundary.
  2. Design (b): add_library(core STATIC ...) compiles the shared code one time. target_link_libraries(tool PRIVATE core) and target_link_libraries(tests PRIVATE core) reuse it. The library has its own flags and include folders (PUBLIC include), and its users get them automatically.
  3. Incremental builds: a change in a file of core compiles that file, makes the archive again and links each executable again. It does not compile the other files.
  4. Recommendation: (b). Put only main() and the command-line code in each executable. Put the reusable code in the library.

Q52

L4 · Senior Design compile-options

Your project has your own code and a copy of a third-party library in third_party/. You need -Wall -Wextra -Werror on your code. Compare set(CMAKE_CXX_FLAGS ...), add_compile_options(...) at the top and target_compile_options(<target> PRIVATE ...) on each of your targets. Give a recommendation.

Show answerHide answer to Q52

Structure of a strong answer:

  1. set(CMAKE_CXX_FLAGS ...): goes to every target, also to third_party. -Werror then stops the build on warnings in code that you do not own (ex09). It also hides the flags that a user gives with -DCMAKE_CXX_FLAGS (Q39).
  2. add_compile_options(...) at the top: it goes to each target in this folder and in the folders below it, so add_subdirectory(third_party) gets the flags too. It is better than item 1, because the user flags stay. But it is still not clear which target gets which flag.
  3. target_compile_options(<target> PRIVATE ...): only your targets get the flags. The third-party library builds with its own flags (ex10).
  4. Recommendation: item 3. For many targets, make an INTERFACE library with the warning flags. Link each of your targets to it. Keep -Werror for CI, so that a new compiler warning does not stop a user build.

Q53

L4 · Senior Design add-library

Three executables use one internal library. Compare STATIC and SHARED for this library. Talk about the size of each executable, the start of the program and the deployment. Also talk about a correction of a bug in the library.

Show answerHide answer to Q53

Structure of a strong answer:

  1. STATIC: the linker copies the used object files into each executable. Each executable is larger, but it runs alone: no .so file is necessary when it runs. After a correction in the library, you must link all three executables again.
  2. SHARED: one libX.so is on disk and in memory, and the three executables use it. Each executable is smaller. The dynamic loader must find the library at start (RUNPATH, LD_LIBRARY_PATH or a system folder), or the program stops (Q40). To correct a bug, you replace one file, if the interface (the ABI) does not change.
  3. Cost: a shared library adds a small cost at start (the loader resolves the symbols) and needs position-independent code (-fPIC).
  4. Recommendation: for an internal library with three executables in one repository, STATIC is usually simpler. Use SHARED when many programs share the library in one installation, or when you must update the library alone.

Q54

L4 · Senior Design build-directory

You must build Debug, Release, a Clang build and an AddressSanitizer build of one project on your computer. Design the layout of the build folders and give the configure commands. Explain why your design keeps each build incremental.

Show answerHide answer to Q54

Structure of a strong answer:

  1. One source folder and one build folder for each configuration:
  1. Each folder has its own CMakeCache.txt, so the compiler, the build type and the flags stay the same between builds. A change of one file compiles only that file in each folder.
  2. One folder for all configurations is worse: each change of the compiler or the flags compiles all files again.
  3. The sanitizer build works only when CMakeLists.txt does not overwrite CMAKE_CXX_FLAGS (Q39). CMake also puts CMAKE_CXX_FLAGS on the link line, so the sanitizer library links.

Q55

L4 · Senior Design build-target

A library net has public headers for its users and private headers that only its .cpp files use. Design the folder layout and the target_include_directories lines. Which keyword do you give each folder, and what goes wrong with the other keywords?

Show answerHide answer to Q55

Structure of a strong answer:

  1. Layout: net/include/net/socket.h (public), net/src/socket.cpp and net/src/detail/buffer.h (private).
  2. Lines:
  1. include is PUBLIC: net uses it, and each user gets it. Users write #include "net/socket.h", so the folder name net/ stops name clashes with other libraries.
  2. src is PRIVATE: only net sees the private headers. The users cannot include them by mistake, so you can change them later.
  3. Other keywords. With PRIVATE include, the users cannot find the header (Q27). With INTERFACE include, the library itself cannot find it, because its .cpp files include the public header (Q28). With PUBLIC src, all users see the private headers.

Q56

L3 · Analyze Interview cmake

"What is CMake? How is it different from Make or Ninja?"

Show answerHide answer to Q56
  1. Main fact: CMake is a build system generator. It reads CMakeLists.txt and writes the input files of a build tool. Make and Ninja are build tools: they read a Makefile or build.ninja, compare file times and run the compiler.
  2. Example: cmake -S . -B build -G Ninja writes build.ninja. cmake --build build then runs Ninja, which compiles and links.
  3. Trade-off: one CMakeLists.txt works on Linux, macOS and Windows, with many generators and compilers. The cost is one more tool and one more language to learn.
  4. Follow-up: "Why Ninja and not Make?" A generator writes the Ninja files. People do not write them by hand. Ninja starts fast and runs jobs in parallel by default. "Is CMake a compiler?" No. It finds the compiler in the configure step.

Q57

L4 · Senior Interview build-target

"What is the difference between PRIVATE, PUBLIC and INTERFACE in target_link_libraries and target_include_directories? Give an example of each."

Show answerHide answer to Q57
  1. Main fact: these keywords set the usage requirements of a target. The keyword PRIVATE is only for the target. The keyword INTERFACE is only for the targets that link to it. The keyword PUBLIC is for both.
  2. Examples:
    • target_link_libraries(app PRIVATE geometry): app uses geometry in its .cpp files only.
    • target_include_directories(geometry PUBLIC include): geometry and its users find geometry.h (ex12).
    • INTERFACE: a header-only library (add_library(util INTERFACE)) gives its include folder to its users. It has no .cpp files of its own.
  3. Rule: use PUBLIC when a public header of the library needs the dependency. Use PRIVATE when only the .cpp files need it.
  4. Follow-up: "Does PRIVATE keep a static dependency out of the link?" No. A static library cannot record its dependencies, so CMake still adds them to the final link (ex17, Q36).

Q58

L4 · Senior Interview compile-options

"People say that modern CMake is target-based. What is wrong with CMAKE_CXX_FLAGS, include_directories() and other global settings?"

Show answerHide answer to Q58
  1. Main fact: target-based CMake puts each setting on the target that needs it. Global settings go to every target, and you cannot see which target needs which setting.
  2. Examples: set(CMAKE_CXX_FLAGS "-Werror") stops the build of library code that you do not own (ex09). It also hides the user value of CMAKE_CXX_FLAGS (Q39). The command include_directories() gives a folder to all targets in the folder, so a target can include a header that it does not link.
  3. Better: target_compile_features, target_compile_options, target_include_directories and target_link_libraries, with PRIVATE, PUBLIC and INTERFACE. A user that links to a target gets its PUBLIC settings automatically.
  4. Follow-up: "Where do global flags belong?" The user gives them on the command line, for example -DCMAKE_CXX_FLAGS=-fsanitize=address or a CMake preset. The project does not set them.

Q59

L4 · Senior Interview compile-options

"Your program works in a Debug build but fails in a Release build. Which differences between the two build types can cause this?"

Show answerHide answer to Q59
  1. Main fact: Release adds -O3 -DNDEBUG. Debug adds only -g. Two differences come from these flags.
  2. NDEBUG: each assert disappears. Code with an action inside assert does not run (ex15: settings loaded: 0). A check that stops a bug in Debug does not stop it in Release (ex16).
  3. Optimization: -O3 makes the compiler use the rules of the language fully. Code with undefined behavior, for example an uninitialized variable or a signed overflow, can give a different result at each optimization level. The standard sets no requirements for such code ([defns.undefined]).
  4. Diagnosis: build Release with -g (RelWithDebInfo), add AddressSanitizer and UndefinedBehaviorSanitizer, and turn on all warnings. Do not trust the output of UB as "the" result. Follow-up: "Why does a variable show as optimized out in GDB?" The optimizer removed it or keeps it in a register (S00E23).

Q60

L3 · Analyze Interview build-directory

"What is compile_commands.json? How do you make it with CMake, and which tools use it?"

Show answerHide answer to Q60
  1. Main fact: compile_commands.json is a JSON list with one entry for each source file: the folder, the full compile command, the file and the output.
  2. Make it: cmake -S . -B build -DCMAKE_EXPORT_COMPILE_COMMANDS=ON. CMake writes build/compile_commands.json. The Makefile and Ninja generators support it (CMake docs).
  3. Users: clangd and other editor tools, clang-tidy and other static analysis tools. They need the same flags (-std=, -I, -D) as the real build, or they report wrong errors (JSON Compilation Database).
  4. Follow-up: "Where does the editor find it?" Make a link to it in the source folder, or tell the tool the build folder.

Q61

L3 · Analyze Interview add-library

"The build of your CMake project stops with undefined reference to foo(), but foo is in the project. How do you find the cause?"

Show answerHide answer to Q61
  1. Main fact: undefined reference comes from the linker. The compiler saw a declaration, but no object file or library in the link has the definition.
  2. Steps:
    • Is the .cpp file with the definition in add_executable or add_library? If not, CMake does not compile it (Q25).
    • Does the target link the library that defines it? target_link_libraries(app PRIVATE geometry) (ex04).
    • Does the definition match the declaration? A different namespace, a different parameter type or a missing const makes a different symbol.
    • Read the link command with cmake --build build --verbose. Look in the library with nm -C libgeometry.a.
  3. Limit: a link command written by hand can also fail because of the order of the archives (Q37). CMake puts them in the correct order.
  4. Follow-up: "And for a template?" The definition must be in the header, or the compiler makes no code for the type (S00E21).

Q62

L4 · Senior Interview add-executable

"Do you list the source files in add_executable one by one, or do you use file(GLOB ...)? Explain your choice."

Show answerHide answer to Q62
  1. Main fact: list the files one by one. The CMake documentation does not recommend file(GLOB) for source files (file(GLOB)).
  2. Reason: CMake runs the configure step again only when CMakeLists.txt or another CMake input changes (Q23). A new .cpp file does not change these files, so a glob does not see it until you configure again. Then the build can fail or use old files.
  3. Trade-off: an explicit list is more text. But each change of the sources shows in a review of CMakeLists.txt. CONFIGURE_DEPENDS makes the glob check the files at each build. That costs time, and the documentation says that it may not work with all generators.
  4. Follow-up: "And headers?" A header does not need to be in the list. Some teams list the headers so that an IDE shows them in the project.
