Value Categories: lvalues and rvalues in C++

About 12 min 35 quiz questions 60 workbook questions
Start the quiz Open the workbook Compiler Explorer (opens in a new tab)

What you learn

  • Explain why a value category is a property of an expression and not a property of a type.
  • Use the address test and the assignment test to find the lvalues and the rvalues in code.
  • Predict which overload a call selects from f(T&), f(const T&) and f(T&&).
  • Explain why a named rvalue reference is an lvalue, and use std::move to make it an rvalue.
  • Predict when an object uses its copy constructor and when it uses its move constructor.

Question 1 of 35 L2 · Apply lvalue In the video

Choose one: p points to count. Which expression is an lvalue?

*p names the object count, so it has an identity. count + 1 and count * 2 make new values that have no name (ex11).

Question 2 of 35 L3 · Analyze overload-on-reference In the video

Choose one: f has three overloads. Which one does f(count + 1) call?

count + 1 is an rvalue, so f(int&) cannot take it. Both other overloads can, and an rvalue prefers int&& (ex11, ex12).

Question 3 of 35 L2 · Apply expression-vs-type

True or false: True or false: in void add(Track&& track), the expression track is an rvalue.

False. track is the name of a variable, so it is an lvalue. Its declared type is Track&&.

Use std::move(track) to give it to another function as an rvalue (ex15, ex16).

Question 4 of 35 L1 · Recall value-category

Choose one: A value category is a property of which part of a program?

Every expression has a type and a value category. The category is not part of the type: the expression r is an lvalue also when r has the type int&& (ex15).

Question 5 of 35 L2 · Apply lvalue

True or false: True or false: every lvalue can be on the left side of the built-in =.

A const lvalue has an identity and an address, but the built-in = cannot change it.

"An lvalue is on the left of =" is only a short hint, not a rule. Use the address test: &limit compiles for const int limit = 10;, but limit = 11 does not.

Question 6 of 35 L1 · Recall rvalue-reference

Match the terms: Match each reference type to the expressions that it can bind to.

ex09 shows the three rules. int& binds to count, const int& binds to 42, and int&& binds to count + 1 but not to count (ex10).

Question 7 of 35 L2 · Apply lvalue

Select all that apply.

*p names the object count. ++count gives count itself after the change. A string literal is an array lvalue, so &"abc" compiles (ex07). count + 1, count++ and 42 are rvalues (ex11).

Question 8 of 35 L2 · Apply rvalue

Choose all that apply: x is an int, and values is an int[3] array. make_title() returns std::string by value, and at(i) returns int&. Which expressions are rvalues? Select all correct answers.

Select all that apply.

A temporary object, a call that returns by value and nullptr are rvalues. The built-in x = 3 gives x itself (workbook Q14 proves x = y). at(2) names an element (ex05), and values[2] names an element (ex02). These three are lvalues.

An lvalue names an object. Most rvalues are new values with no name.

a[1], x += 1 and x name an object, so they select kind(int&). x * 2 and -x make new values, so they select kind(int&&).

Question 10 of 35 L2 · Apply rvalue

next_id(last) returns by value, so the call is an rvalue. The built-in & needs an lvalue (ex03). Keep the value in a variable: int id = next_id(last);.

Question 11 of 35 L1 · Recall rvalue-reference

Fill the blank: Complete the declaration, so that r is an rvalue reference to int: int____blank r = 42;

T&& is an rvalue reference (C++11). T& is an lvalue reference. int&& r = 42; keeps the temporary alive to the end of the scope of r.

Question 12 of 35 L2 · Apply rvalue-reference

Choose one: int count = 5; comes first. Which declaration does not compile?

int&& binds only to an rvalue, and count is an lvalue (ex10). const int& binds to an rvalue too. Use std::move(count) to give an rvalue.

Question 13 of 35 L2 · Apply rvalue-reference

True or false: True or false: after int&& r = count + 1;, the program destroys the temporary at the end of the statement, so r dangles.

False. A reference that binds directly to a temporary keeps the temporary alive to the end of the scope of the reference (lifetime extension).

This rule is lifetime extension ([class.temporary]). ex22 writes use before destroy. The rule does not pass through a function call (ex23).

Question 16 of 35 L3 · Analyze overload-on-reference

std::move does not remove const.

An rvalue prefers int&& to const int&. std::move(limit) is a const rvalue, and int&& cannot bind to const int, so the call selects const int&.

Question 17 of 35 L2 · Apply overload-on-reference

Choose one: Only void show(const int& value) exists. What occurs at the call show(42)?

const T& binds to lvalues and to rvalues (ex14). The temporary lives to the end of the full expression with the call ([class.temporary]/6). Only a non-const int& rejects an rvalue.

Question 19 of 35 L2 · Apply expression-vs-type

True or false: True or false: after int&& x = 42;, the declaration int& y = x; compiles.

True. The expression x is the name of a variable, so it is an lvalue, and int& binds to a modifiable lvalue.

The declared type of x is int&&, but that does not change the category of the expression x. Workbook Q22 compiles this declaration on GCC and Clang (ex15 shows kind(x) gives lvalue).

Question 20 of 35 L2 · Apply expression-vs-type

Fill the blank: Card has a member Item front;. In the move constructor Card(Card&& other), the member initializer front(____blank) must move other.front, not copy it.

The parameter other has a name, so it is an lvalue. The member other.front is an lvalue too, so front(other.front) copies. With std::move(other.front), the move constructor of Item runs (workbook Q28, Q46).

v binds to an rvalue, but the expression v is an lvalue. Thus take(v) selects take(int&). std::move(v) is an rvalue, so the second call selects take(int&&).

Question 22 of 35 L3 · Analyze overload-on-reference

Choose one: Buffer has a copy constructor and a move constructor, and each one writes a word. keep takes a Buffer by value. Which constructor makes the parameter in keep(Buffer{})?

In C++17 and later, a temporary of the same type makes the object directly. The example ex19 writes only make, with no copy and no move. A call keep(std::move(a)) uses the move constructor (ex17).

Question 23 of 35 L3 · Analyze overload-on-reference

Put in order: Buffer a; exists. Put the steps in order. The compiler uses them to select a constructor for Buffer b = std::move(a);.

Drag the handle, or use the arrow buttons. With a row focused, press Alt + Up or Alt + Down.

  1. Compare the remaining bindings: Buffer&& is better than const Buffer&
  2. Remove each candidate whose parameter cannot bind to that rvalue
  3. Find the value category of the argument: std::move(a) is an rvalue
  4. Call the selected constructor: the move constructor

Overload resolution first finds the candidates that can accept the argument. Then it ranks them. For an rvalue, T&& is a better match than const T& ([over.ics.rank] 3.2.3).

Question 24 of 35 L2 · Apply overload-on-reference

Match the terms: kind has the overloads kind(int&), kind(const int&) and kind(int&&). count is an int, and limit is a const int. Match each call to the overload that it selects.

A modifiable lvalue selects int&. A const lvalue can bind only to const int&. An rvalue prefers int&& (ex12).

Question 25 of 35 L3 · Analyze overload-on-reference

Both overloads accept an rvalue with an exact match, and no rule ranks one first. GCC and Clang both report an ambiguous call (ex13). Use const T& with T&&, or only T.

Question 27 of 35 L3 · Analyze rvalue

True or false: True or false: make_title() = "final" compiles when make_title returns std::string by value.

For a class type, = calls the member function operator=, and a member function can run on an rvalue.

Only the built-in = needs a modifiable lvalue on the left. ex08 writes final. A class can refuse this with a & qualifier on operator=.

Question 28 of 35 L3 · Analyze expression-vs-type

Choose one: int&& x = 42; comes first. Which pair gives the type and the value category of the expression x?

An expression never has a reference type: the compiler removes the reference ([expr.type]/1). The name x is an lvalue. decltype(x) gives int&&, but that is the declared type of the variable (ex15).

Question 29 of 35 L4 · Senior overload-on-reference

Choose one: A class has only the setter set_name(const std::string& name), and the body copies name into a member. What does the call set_name(first + last) cost, compared to an added std::string&& overload?

The temporary binds to const std::string&. A move cannot change a const object, so the body copies every character. The copy allocates only when the member has too little capacity (workbook Q49). A std::string&& overload moves: the member takes the buffer of the temporary (ex25).

Question 30 of 35 L3 · Analyze overload-on-reference

Choose all that apply: Which functions of std::vector<T> have one overload that takes a const lvalue reference and one overload that takes an rvalue reference? Select all correct answers.

Select all that apply.

push_back and one-element insert take const T& or T&& (ex18). The copy constructor takes const vector&, and the move constructor takes vector&& (cppreference: std::vector). Each pair copies an lvalue and moves an rvalue. operator[] overloads on the const of the object.

Question 31 of 35 L3 · Analyze overload-on-reference

Choose one: Report has take_text() const&, which copies, and take_text() &&, which moves. daily is a local Report. Which call moves the text?

The && overload runs only on an rvalue object. The temporary Report{"weekly"} is an rvalue, so this call moves. daily is an lvalue, so it uses the const& overload (ex24).

Question 32 of 35 L3 · Analyze rvalue-reference

Choose one: pass_on returns its int&& parameter. What is wrong with the last line?

Lifetime extension works only when a reference binds directly to the temporary. Here, result binds to the return value of a function, so the temporary dies at the end of the full expression. ASan reports stack-use-after-scope (ex23).

Question 33 of 35 L4 · Senior rvalue-reference

Choose one: int& r = count + 1; does not compile. Which reason for this rule is correct?

A non-const reference usually means "the function changes my object". The program cannot see a change to a temporary again. Thus C++ refuses this binding. const int& and int&& bind, because there the program uses the value on purpose. Source: Stroustrup, The Design and Evolution of C++, 3.7.

Question 34 of 35 L4 · Senior value-category

Choose one: Why does C++ keep the value category separate from the type?

A std::string lvalue and a std::string rvalue have the same type. The category tells the compiler if the program can use the object again. Then T&& overloads can move from objects that nobody uses again.

Question 35 of 35 L1 · Recall lvalue

Choose one: Which test tells you that an expression of a built-in type is an lvalue?

An lvalue has an identity, so &expr gives its address (ex02). An rvalue fails the test (ex03). An expression never has a reference type, and both categories can be on the right of =.
