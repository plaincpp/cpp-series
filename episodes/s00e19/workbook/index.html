Q2

L1 · Recall Short answer operator-overloading

Name four operators that you cannot overload. Can you add a new operator, such as ** for a power?

Show answerHide answer to Q2

You cannot overload :: (scope resolution), . (member access), .* (member access through a pointer to member) and ?: (the conditional operator). You also cannot add a new operator such as **. You can only overload the operators that C++ has. Source: cppreference, operator overloading, restrictions.

Q3

L2 · Apply Multiple choice member-vs-free-operator

Money has the constructor explicit Money(int cents) and a hidden friend operator+(Money a, Money b). price is a Money object. Which expression compiles?

  • b) 50 + price

Show answerHide answer to Q3

c) price + Money{50}. The constructor is explicit, so the compiler does not convert 50 to Money, also not for a hidden friend. Q4

L1 · Recall Short answer member-vs-free-operator

Name the four operators that must be member functions.

Show answerHide answer to Q4

operator=, operator[], operator() and operator->. A free operator= does not compile. GCC: must be a non-static member function. Clang: overloaded 'operator=' must be a non-static member function (ex12). Source: cppreference, operator overloading.

Q5

Write the declaration of operator<< that prints a Fraction. Why is the first parameter a reference that is not const?

Show answerHide answer to Q5

The operator writes characters into the stream, and this changes the state of the stream. So the stream cannot be const. A stream also has no copy constructor, so the operator cannot take it by value (ex17).

Q6

Show answerHide answer to Q6

It compares the members in declaration order: first x, then y. The result is true only when all members are equal (ex19). Source: cppreference, default comparisons.

Q7

L1 · Recall Multiple choice copy-assignment

a is a Tracer object. Which line calls the copy assignment operator?

  • a) Tracer b = a;
  • b) Tracer b{a};
  • c) b = a;, after the line Tracer b;
Show answerHide answer to Q7

c) b = a; after Tracer b;. This line changes an object that exists, so it calls operator=. The lines a) and b) make a new object b, so they call the copy constructor. The = in a declaration is not an assignment (ex24).

Q8

L1 · Recall Short answer canonical-forms

Give the canonical return type of each operator of a type T: operator+=, operator+, prefix operator++, postfix operator++ and operator<<.

Show answerHide answer to Q8
  • operator+=: T&, a reference to *this.
  • operator+: T, a new value.
  • prefix operator++: T&, a reference to *this.
  • postfix operator++: T, a copy of the old value.
  • operator<<: std::ostream&, the same stream.

An operator that changes the object returns a reference to it. An operator that makes a new value returns it by value (ex29, ex35).

  • b) 8, because + has a higher precedence than ^

b) 8. An overloaded operator keeps the precedence of the built-in operator, and + has a higher precedence than ^. So the expression is two ^ (2 + 1), 2 to the power 3 (ex06). With -Wall, GCC warns: suggest parentheses around arithmetic in operand of '^' (ex07).

Q11

L2 · Apply Multiple choice equality-operator

Version declares only std::strong_ordering operator<=>(const Version& other) const, with its own body. It is not = default. Which comparisons compile?

  • b) All six: ==, !=, <, <=, > and >=

Q12

L2 · Apply Short answer copy-assignment

When does the compiler delete the implicit copy assignment operator of a class? Name two kinds of members that cause it.

Show answerHide answer to Q12

The compiler deletes the implicit copy assignment when it cannot assign a member. Two examples: a const member, such as const int id; (ex28), and a reference member, such as int& total;. The copy constructor still works, because it makes a new object. Source: cppreference, copy assignment operator, deleted copy assignment.

Part D: Explain why

10 questions

Q35

L2 · Apply Explain why operator-overloading

Explain why int operator+(int a, int b) does not compile. Answer in two sentences.

Show answerHide answer to Q35

An operator overload needs at least one parameter of a class type or an enumeration type. The operators for the built-in types are part of the language, so you cannot change them. GCC: 'int operator+(int, int)' must have an argument of class or enumerated type (ex05).

Q36

L3 · Analyze Explain why operator-overloading

A programmer uses ^ as a power operator for Number. Explain why two ^ 2 + 1 gives 8, not 5. Why does GCC give a warning for this line? Answer in three sentences.

Show answerHide answer to Q36

An overloaded operator keeps the precedence, the associativity and the number of operands of the built-in operator. So two ^ 2 + 1 is two ^ 3, which is 8, because + has a higher precedence than ^ (ex06). GCC warns with -Wall (-Wparentheses), because many programmers make this mistake with ^. Clang 19 gives no warning here (ex07).

Q37

L3 · Analyze Explain why member-vs-free-operator

Money has the constructor Money(int) and a member operator+(Money) const. Explain why price + 50 compiles, but 50 + price does not compile. Answer in three sentences.

Show answerHide answer to Q37

For a member operator, the left operand is the object *this. In price + 50, price is the object, and the constructor converts 50 to Money for the parameter. In 50 + price, the left operand is an int. The compiler does not look for members in int, and it does not convert the left operand to Money (ex11). A free function or a hidden friend corrects this problem, because both operands are parameters (ex10).

Q38

L3 · Analyze Explain why stream-insertion

Explain why operator<< returns std::ostream&. Tell what goes wrong with the return types void and std::ostream. Answer in three sentences.

Show answerHide answer to Q38

std::cout << a << '\n' is the call operator<<(operator<<(std::cout, a), '\n'), so each call must return the stream for the next call (ex14). With void, the next << has no left operand, and the chain does not compile (Q26). With std::ostream, the return makes a copy, but a stream has a deleted copy constructor, so the function does not compile (ex17).

Q39

L2 · Apply Explain why stream-insertion

Explain why an operator<< for a type must not write '\n' at the end. Use ex18 as the example. Answer in two sentences.

Show answerHide answer to Q39

The caller decides where a line ends. In ex18, the operator writes '\n', so the text to starts a new line and the caller gets an empty line.

Q41

L3 · Analyze Explain why equality-operator

Version has a default operator<=> and no other comparison. Explain why std::sort works on a std::vector<Version>, and why a == b also compiles. Answer in three sentences.

Show answerHide answer to Q41

std::sort compares the values with <, and C++20 rewrites a < b as (a <=> b) < 0. The default <=> compares the members in declaration order, so 1.2.3 comes before 1.10.0 (ex22). A default operator<=> also declares a default operator==, so a == b compiles. A <=> that you write yourself does not declare == (Q49).

Q42

L3 · Analyze Explain why copy-assignment

Explain why Tracer b = a; calls the copy constructor, but b = a; calls the copy assignment operator. Answer in two sentences.

Show answerHide answer to Q42

A declaration with = makes a new object, so the compiler calls a constructor: here the copy constructor. The expression b = a; changes an object that exists, so it calls operator= (ex24).

Q43

L4 · Senior Explain why copy-assignment

Explain why copy-and-swap (ex27) is safe for self-assignment and for an exception in the copy. The strong exception guarantee means: on an exception, the object does not change. Name the cost of this form. Answer in four sentences.

Show answerHide answer to Q43

The parameter is a copy, so a self-assignment swaps with a copy and loses no data (ex27). The copy occurs before the function changes *this, so an exception in the copy leaves the object as it was. This is the strong exception guarantee. The cost is a new allocation and a copy for each assignment, also when the old memory is large enough to use again. Source: cppreference, operator overloading, assignment operator.

Q44

Part F: Design and trade-offs

4 questions

Q52

L4 · Senior Design member-vs-free-operator

You design a class Money with a private member long long cents_. It needs +, +=, ==, < and <<. Compare three designs: all operators as members, free functions that use public getters, and hidden friends. Choose a place for each operator, and give a recommendation. Should the constructor from long long be explicit?

Show answerHide answer to Q52

A strong answer chooses a place for each operator:

  • +=: a member. It changes *this and returns Money&.
  • +: a hidden friend that takes the left operand by value and returns a += b (ex36).
  • == and <: one hidden friend operator<=> with = default. It also declares == (ex36).
  • <<: a hidden friend that returns std::ostream&.

Members for all operators fail for <<, because the stream is the left operand (ex16). Free functions with public getters work, but they make cents_ visible to all code. Hidden friends read the private members, and only argument-dependent lookup finds them.

Recommendation: make the constructor explicit (ex36). Then price + 5 does not compile, and the reader cannot mistake 5 cents for 5 dollars. Without explicit, a hidden friend + accepts an int on both sides (ex10). That is easy to use, but it hides a unit.

Q53

L4 · Senior Design copy-assignment

A class owns a heap array. Look at three forms of operator=:

  1. A test for self-assignment, then delete[] and new.
  2. new and a copy first, then delete[] of the old array.
  3. Copy-and-swap (ex27).

Compare them for self-assignment, exceptions, speed and the amount of code. Give a recommendation.

Show answerHide answer to Q53

A strong answer compares the three forms:

Form Self-assignment Exception in new Speed Code
(1) test, delete[], new safe the object holds a dangling pointer one allocation short
(2) new and copy, then delete[] safe without a test the object does not change one allocation short
(3) copy-and-swap safe the object does not change one allocation and a swap shortest, it reuses the copy constructor

Form (1) is not exception-safe: if new throws after delete[], the destructor later deletes the array again. Forms (2) and (3) give the strong exception guarantee. A form that reuses the old array when the sizes are equal is the fastest, but it gives only the basic guarantee. Recommendation: use copy-and-swap by default. Write a special form only when a profiler shows that the allocation matters. Best of all, use std::vector<int> as the member and let the compiler write all copy functions (rule of zero).

Q54

L4 · Senior Design equality-operator

struct Employee has std::string name, int id and double salary. Each id identifies one employee. Compare three designs: a default operator==, an operator== that compares only id, and a default operator<=>. Talk about the meaning of equality, the cost and the sort order.

Show answerHide answer to Q54

A strong answer compares the meaning, the cost and the order:

  • Default operator==: compares name, id and salary. Two records of one employee with a new salary are not equal. That is the meaning of "same values", not of "same employee".
  • operator== on id only: matches "same employee", and it compares one int. But then == does not mean "all values are the same", which can surprise a reader. A named function, such as same_employee(a, b), is clearer.
  • Default operator<=>: sorts by name first, then id, then salary. That is one fixed order, and a program usually needs more than one order, for example by id or by salary.

Recommendation: keep the default operator== for value equality, and use a projection or a lambda for each sort order, for example std::ranges::sort(staff, {}, &Employee::id). Source: cppreference, default comparisons.

Q55

L4 · Senior Design canonical-forms

Your team reviews four operator ideas:

  • operator/ that joins two parts of a file path
  • operator^ as a power for Number
  • operator+ for Vector2
  • operator, that adds an item to a list

Apply the principle of least surprise to each idea. Which ideas do you accept, and which do you reject?

Show answerHide answer to Q55

A strong answer applies one test: does the operator do what a reader expects from the symbol?

  • operator/ for paths: accept. / is the path separator, and std::filesystem::path uses this operator. It has no side effect.
  • operator^ as power: reject. ^ has a low precedence, so two ^ 2 + 1 gives 8, not 5 (ex06). Readers also know ^ as XOR. Write a function pow(n, 2).
  • operator+ for Vector2: accept. It matches the mathematics and does not change its operands (ex35).
  • operator, to add an item: reject. The comma operator has the lowest precedence, and an overload of , changes the meaning of code that uses the built-in comma. Write add(item) or use an initializer list.

The rule: overload an operator only when its meaning is clear and it behaves like the built-in operator for int.

Q56

L3 · Analyze Interview operator-overloading

Which operators can you not overload in C++? Which properties of an operator stay the same when you overload it?

Show answerHide answer to Q56

A strong answer has these parts:

  1. Main fact: you cannot overload ::, ., .* and ?:. You cannot add new operators.
  2. Fixed properties: the precedence, the associativity and the number of operands stay the same. At least one operand must have a class type or an enumeration type (ex05).
  3. Example: two ^ 2 + 1 is two ^ 3, because ^ keeps its low precedence (ex06).
  4. Follow-ups: "Can an overloaded && short-circuit?" No (ex34). "Can you overload sizeof?" No. Source: cppreference, operator overloading, restrictions.

Q57

L3 · Analyze Interview member-vs-free-operator

When do you write an operator as a member function, and when as a free function? What is a hidden friend, and why do people use it?

Show answerHide answer to Q57

A strong answer has these parts:

  1. Main fact: an operator that changes the object (+=, ++, =) is a member. =, [], () and -> must be members. A symmetric operator (+, ==) or << is a free function or a hidden friend.
  2. Reason: for a member, the left operand must have the class type, and it does not convert. So 3 * v and 50 + price fail with a member (ex08, ex11).
  3. Hidden friend: a friend function that you define in the class. It reads private members, and only argument-dependent lookup finds it. So the compiler examines it only for expressions with that type (ex10).
  4. Follow-up: "Why not make every operator a friend?" An operator that only needs the public interface can be a normal free function. Source: cppreference, friend declaration.

Q58

L3 · Analyze Interview stream-insertion

How do you make your class work with std::cout << obj? Why can operator<< not be a member of your class?

Show answerHide answer to Q58

A strong answer has these parts:

  1. Main fact: write std::ostream& operator<<(std::ostream& out, const T& value) and return out (ex13).
  2. Why free: in std::cout << obj, the stream is the left operand. A member of T makes T the left operand: obj << std::cout (ex16). You cannot add a member to std::ostream.
  3. Details: take the value by const&. Return the stream by reference, because a stream has no copy constructor (ex17). Do not write a newline (ex18). Make it a friend to read private members (ex15).
  4. Follow-up: "Does it work with files and string streams?" Yes, std::ofstream and std::ostringstream are also std::ostream objects (ex15).

Q59

L4 · Senior Interview equality-operator

What did C++20 change for comparison operators? Explain = default, operator<=> and the rewritten forms of != and of the reversed ==.

Show answerHide answer to Q59

A strong answer has these parts:

  1. Default comparisons: bool operator==(const T&) const = default; compares the members in order. auto operator<=>(const T&) const = default; gives the four relational operators and also declares == (ex19, ex22).
  2. Rewritten forms: a != b becomes !(a == b), and a < b becomes (a <=> b) < 0. The compiler also tries the reversed form, so 250 == price can call operator==(price, 250) (ex20).
  3. Result: one or two functions replace six. In C++17, you write all six, and != without its own function does not compile (ex21).
  4. Limits: a default == compares pointers by address (ex23). A <=> that you write yourself does not declare ==. A double member gives std::partial_ordering.
  5. Follow-up: "What does <=> return?" std::strong_ordering, std::weak_ordering or std::partial_ordering. Source: cppreference, default comparisons.

Q60

L4 · Senior Interview copy-assignment

What is the difference between the copy constructor and the copy assignment operator? What is the rule of three? How do you write a correct operator=?

Show answerHide answer to Q60

A strong answer has these parts:

  1. Main fact: the copy constructor makes a new object (T b = a;). The copy assignment changes an object that exists (b = a;), so it must also release the old resources, after the new copy exists (ex24, ex26).
  2. Rule of three: a class that needs its own destructor usually also needs its own copy constructor and copy assignment. Without them, two objects own the same memory, and ASan reports a double free (Q31). Source: cppreference, the rule of three.
  3. Correct operator=: return *this by reference. Handle self-assignment: a delete before the copy reads freed memory (ex26). Copy-and-swap is safe for self-assignment and gives the strong exception guarantee (ex27).
  4. Follow-ups: "And move assignment?" Season 1 adds it with the rule of five. "When do you write none of them?" When the members manage themselves, for example std::vector and std::string: the rule of zero.

Q61

L4 · Senior Interview canonical-forms

Why must you not overload &&, || or the comma operator? Give an example of the bug.

Show answerHide answer to Q61

A strong answer has these parts:

  1. Main fact: the built-in && and || short-circuit. An overloaded &&, || or , is a function call, so the program evaluates both operands (ex34).
  2. Example: in_range(v, i) && positive(v, i) calls v.at(i) also when the index is out of range, so it throws (Q34). With a pointer check, the same pattern reads through a null pointer.
  3. History: from C++17, the program evaluates the left operand of an overloaded && first, the same as the built-in order. But it still does not short-circuit.
  4. Follow-up: "What do you do instead?" Give the type an explicit operator bool, and let the built-in && do the work. Source: cppreference, operator overloading, restrictions.

Q62

L3 · Analyze Interview canonical-forms

How do you write prefix and postfix operator++? Why can x++ cost more than ++x for a class type?

Show answerHide answer to Q62

A strong answer has these parts:

  1. Main fact: prefix T& operator++() changes *this and returns it. Postfix T operator++(int) copies the object, calls prefix and returns the copy. The int parameter only marks the postfix form (ex29).
  2. Cost: postfix makes a copy of the old value. For an int or a simple iterator, the optimizer usually removes it. For a large type, the copy can cost time and memory.
  3. Rule: write ++it when you do not need the old value. Write postfix with prefix, so that the two forms always agree.
  4. Follow-up: "Why does postfix return by value?" A reference to the local copy dangles. In C++23 it does not compile (Q32).
