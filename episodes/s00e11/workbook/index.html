A

Part A: Concept checks

12 questions

Q1

L1 · Recall Short answer const-variable

What does const in const int days = 7; tell the compiler? When must a const variable get its value?

Show answerHide answer to Q1

const tells the compiler that the value of days does not change after its initialization. The compiler stops each assignment to it (ex02). A const variable must get its value in its declaration, from an initializer. The initializer can come from run time (ex03). Without an initializer, GCC reports uninitialized 'const limit' and Clang reports default initialization of an object of const type 'const int'.

Q2

L1 · Recall Short answer const-reference

A function only reads a std::string. Give two reasons to declare its parameter as const std::string& and not as std::string&.

Show answerHide answer to Q2
  1. const std::string& accepts a const string, a string literal and a temporary std::string. A std::string& does not bind to these. ex04 shows the error for a const object.
  2. The const tells the caller that the function does not change the string, and the compiler checks it.

Both forms refer to the string and make no copy.

Q3

L1 · Recall Multiple choice pointer-to-const

In const int* p = &score;, which part is const?

  • a) The pointer p
  • b) The int that p points to
  • c) The pointer and the int
Show answerHide answer to Q3

b) The int that p points to. p itself can move to a different int (ex08), but *p = 15 does not compile (ex09).

Q4

L1 · Recall Short answer const-pointer

Write a declaration of a const pointer p to the int variable score. Which of these two statements compiles after it: *p = 5; or p = &other;?

Show answerHide answer to Q4

*p = 5; compiles and changes score (ex10). p = &other; does not compile, because the pointer itself is const (ex11).

Q5

L1 · Recall Short answer const-member-function

How do you declare a const member function? Name two ways to get an object through which you can call only const member functions.

Show answerHide answer to Q5

Write const after the parameter list: int balance() const; (ex18). Through a const object (const Account a;) and through a const reference or a pointer to const (const Account& r), you can call only const member functions (ex17, ex19). A static member function is different: it has no object, so a const object can also call it.

Q6

L1 · Recall Short answer constexpr-basics

Give the difference between const int a = f(); and constexpr int b = f();. What must be true for f and its arguments in the second line?

Show answerHide answer to Q6

The line const int a = f(); can call f at run time. After the initialization, a only keeps its value. The line constexpr int b = f(); needs a constant expression: the compiler must calculate the value (ex25, ex27). So f must be a constexpr function, and its arguments must be constant expressions. Its body must also have no undefined behavior for these arguments (ex31).

Q7

L1 · Recall Short answer mutable

What does the keyword mutable on a data member do? Give one good use.

Show answerHide answer to Q7

mutable lets a const member function change that data member (ex32). A good use is a cache: the class keeps a result that it calculated one time, and callers see the same value. Without mutable, the cache does not compile (ex33).

Q8

L2 · Apply Multiple choice pointer-to-const

Which two declarations have the same type?

  • a) const int* a and int* const b
  • b) const int* a and int const* b
  • c) int const* a and int* const b
Show answerHide answer to Q8

b) const int* a and int const* b. In both, const applies to int (ex12). int* const b is a const pointer to an int that can change.

Q9

L2 · Apply Multiple choice const-variable

const int limit = 100; Which type does a have after auto a = limit;?

  • a) const int
  • b) const int&
  • c) int
Show answerHide answer to Q9

c) int. auto makes a copy and removes the top-level const (ex16). The copy is a new variable, so it can change.

Q10

L2 · Apply Multiple choice const-member-function

const Account& r = account; The member function deposit(int) is not const. What is the result of r.deposit(5);?

  • a) It changes account, because account itself is not const.
  • b) The compiler stops with an error.
  • c) It changes a copy of account.
Show answerHide answer to Q10

b) The compiler stops with an error. Through a const reference, you can call only const member functions. GCC reports passing 'const Account' as 'this' argument discards qualifiers, and Clang reports 'this' argument to member function 'deposit' has type 'const Account', but function is not marked const.

Q11

L2 · Apply Multiple choice constexpr-basics

The program reads input from std::cin. Which n can be the size in std::array<int, n>?

  • a) const int n = input;
  • b) int n = 4;
  • c) const int n = 4;
Show answerHide answer to Q11

c) const int n = 4;. A const int with a constant initializer is a constant expression (ex29). The value of a) comes from run time (ex28), and b) is not const, so it can change.

Q12

L2 · Apply Short answer mutable

What does const_cast<int&>(r) change: the object or the type of the reference? When is a write through the result undefined behavior?

Show answerHide answer to Q12

const_cast changes only the type of the reference. The object keeps its own type. A write through the result is undefined behavior when the object itself is const (ex34, [dcl.type.cv]/4). When the object is not const, the write is correct (ex35). Source: cppreference, const_cast.

D

Part D: Explain why

9 questions

Q34

L2 · Apply Explain why const-variable

Explain why const int limit; does not compile. Answer in two sentences.

Show answerHide answer to Q34

A const variable cannot get a value after its declaration, so its initializer is the only place to give it a value. Without an initializer, the variable has no usable value, so the compiler stops (GCC uninitialized 'const limit', Clang default initialization of an object of const type 'const int').

Q35

L3 · Analyze Explain why const-reference

Explain why const int& r = 5; compiles, but int& r = 5; does not compile. Answer in three sentences.

Show answerHide answer to Q35

A reference that is not const must refer to an object that you can change. The literal 5 is not an object, so int& r = 5; does not compile. For const int& r = 5;, the compiler makes a temporary int with the value 5 and binds r to it. The temporary lives as long as r ([class.temporary]/6).

Q36

L2 · Apply Explain why pointer-to-const

A const int* can point to an int that is not const. Explain why an int* cannot point to a const int. Answer in two sentences.

Show answerHide answer to Q36

A const int* adds a rule: "do not write through this pointer". That rule is safe for any int, so the conversion from int* is automatic (ex08). An int* removes the rule, so it could change a const object, and the compiler stops it (ex14).

Q37

L3 · Analyze Explain why const-pointer

ex12 writes false for std::is_const_v<const int*> and true for std::is_const_v<int* const>. Explain why. Answer in two sentences.

Show answerHide answer to Q37

std::is_const_v checks the top-level type, which is the pointer itself. In const int*, only the pointed-to int is const, but in int* const, the pointer is const (ex12).

Q38

L3 · Analyze Explain why const-member-function

In ex19, account is a const Account. Explain why the compiler accepts account.balance() but stops at account.deposit(50). Answer in three sentences.

Show answerHide answer to Q38

A const object can call only const member functions. The function balance() is const, because it only reads. The function deposit(int) changes balance_, so it is not const, and the compiler stops the call (ex19).

Q39

L3 · Analyze Explain why const-member-function

In ex23, reset() is a const member function, but it changes value in main. Explain why this compiles. Answer in three sentences.

Show answerHide answer to Q39

In a const member function, each data member is const. The member reading_ has the type int*, so in reset() it becomes int* const. The pointer is const, but the int that it points to is not. So *reading_ = 0 compiles and changes value (ex23). The const of a member function is shallow.

Q40

L3 · Analyze Explain why constexpr-basics

Explain why const int size = 4; can be the size of a std::array (ex29), but const int size = input; cannot (ex28). Answer in three sentences.

Show answerHide answer to Q40

A template argument such as the size of std::array must be a constant expression. A const int with a constant initializer is a constant expression, so size = 4 works (ex29). With input, the compiler does not know the value until the program runs, so size is only a read-only value from run time (ex28).

Q41

L4 · Senior Explain why constexpr-basics

ex31 does not compile, because square(100000) overflows in a constant expression. A call square(input) with the same value at run time compiles. Explain the difference. Answer in three sentences.

Show answerHide answer to Q41

In a constant expression, the compiler must calculate the value, and an expression with undefined behavior is not a constant expression ([expr.const]/5). So the compiler finds the overflow and stops (ex31). At run time, the compiler does not know input, so the call compiles, and UBSan can find the overflow.

Q42

L4 · Senior Explain why mutable

With AddressSanitizer, ex34 stops with a SEGV. Explain why a different platform can give a different result. Explain why the code is wrong on all platforms. Answer in three sentences.

Show answerHide answer to Q42

The C++ standard says that a write to a const object is undefined behavior, so it gives no rule for the result ([dcl.type.cv]/4). GCC and Clang put the global max_users in read-only memory, so the write stops with a SEGV. A different platform can keep it in normal memory, and then the program continues with any result.

F

Part F: Design and trade-offs

5 questions

Q50

L4 · Senior Design const-reference

A function only reads three parameters: an int, a std::string and a struct Image of 4 MB. Choose a parameter type for each one. Explain your choice. Then tell when a parameter by value is better than const&.

Show answerHide answer to Q50

A strong answer has these parts:

  1. int: by value. A copy of an int is as fast as a pointer, and the function reads the value directly.
  2. std::string: const std::string&. It makes no copy and accepts literals and const strings (Q43). std::string_view (C++17) is another good choice for text that the function only reads (S01E27).
  3. Image: const Image&. A copy of 4 MB costs time and memory at each call.
  4. By value is better for small types that are cheap to copy, and when the function keeps its own copy anyway. Rule F.16 of the C++ Core Guidelines: "For 'in' parameters, pass cheaply-copied types by value and others by reference to const". Q62 explains the cost of a reference.

Q51

L4 · Senior Design const-member-function

Design the public interface of class BankAccount. It has balance, owner, history (a std::vector<int> of all deposits), deposit and withdraw. Mark each member function const or not. Choose the return types of owner and history. Tell what a caller with a const BankAccount& can do.

Show answerHide answer to Q51

A strong answer has these parts:

  1. int balance() const, const std::string& owner() const and const std::vector<int>& history() const. They only read, so they are const.
  2. void deposit(int amount) and bool withdraw(int amount) are not const, because they change the balance and the history.
  3. owner and history return a const reference: no copy, and the caller cannot change the account through it. A caller that needs a copy makes one.
  4. A function that takes const BankAccount&, for example a report, can call only the read functions. The compiler stops a call to deposit (ex17, ex19).
  5. A risk: a returned reference ends with the account. A caller must not keep it longer than the account.

Q52

L4 · Senior Design mutable

class Route has double length() const, and one calculation takes 50 ms. Compare three designs:

  • (a) Calculate in each call.
  • (b) Calculate in the constructor and in each change.
  • (c) Use a mutable cache.

Talk about time, memory, the code of the change functions and threads. Recommend one design for a route that changes often and that callers read rarely.

Show answerHide answer to Q52

A strong answer has these parts:

  1. (a) Calculate in each call: no extra memory, and the change functions stay simple. Each read costs 50 ms.
  2. (b) Calculate in each change: each read is fast, but each change costs 50 ms, also when no caller reads the length.
  3. (c) A mutable cache: the first read after a change costs 50 ms, and each later read is fast. Each change function must clear the cache flag. It costs a flag and a double.
  4. Threads: (a) and (b) need no extra work for many readers. In (c), length() const writes the cache, so two threads that read at the same time make a data race. Protect the cache with a mutable std::mutex (S02E02).
  5. Recommendation for a route that changes often and that callers read rarely: (c). If only one thread uses the class and reads are very rare, (a) is also good. Do not choose (b), because it pays for each change.

Q53

L4 · Senior Design constexpr-basics

#define gives a name to a text, and the preprocessor puts the text in place of the name before the compiler reads the code. Compare three ways to write a limit of 100 users: #define MAX_USERS 100, const int max_users = 100; and constexpr int max_users = 100;. Talk about type checks, scope, use as an array size and errors at compile time. Recommend one.

Show answerHide answer to Q53

A strong answer has these parts:

  1. #define MAX_USERS 100 is a text replacement by the preprocessor. It has no type and no scope, and a debugger does not show its name.
  2. const int max_users = 100; has a type and a scope. Its initializer is a constant, so it can be an array size (ex29). But the same declaration with a value from run time also compiles, so it does not guarantee a constant.
  3. constexpr int max_users = 100; has a type and a scope, and the compiler stops if the value is not a constant expression (ex27).
  4. Recommendation: constexpr. In a header, a const or constexpr variable at namespace scope has internal linkage. S00E12 explains headers and inline constexpr. Source: cppreference, Storage class specifiers.

Q54

L4 · Senior Design pointer-to-const

A function average only reads a sequence of int values. Compare three parameter lists: (const int* values, int count), (const std::vector<int>& values) and (std::span<const int> values) (C++20). A std::span holds a pointer to the first element and the number of elements. It does not own the elements. Talk about which callers each one accepts, safety and cost. Recommend one.

Show answerHide answer to Q54

A strong answer has these parts:

  1. (const int* values, int count) accepts a C array, a std::array and a std::vector through .data(). The caller can give a wrong count, and the compiler cannot find it.
  2. (const std::vector<int>& values) keeps the size with the data, but it accepts only a std::vector. A caller with a C array must copy it to a vector.
  3. (std::span<const int> values) holds a pointer and a size. It accepts a C array, a std::array and a std::vector with no copy. span<const int> gives read-only access, as a pointer to const does.
  4. Cost: all three make no copy of the elements. Pass a span by value.
  5. Recommendation: std::span<const int> in C++20. Use the pointer and count only for a C interface. Source: cppreference, std::span.
G

Part G: Interview questions

8 questions

Q55

L3 · Analyze Interview const-pointer

"What is the difference between const int*, int const* and int* const? How do you read them?"

Show answerHide answer to Q55
  1. Main fact: const int* and int const* are the same type, a pointer to const int. The pointer can move, but you cannot write through it. The type int* const is a const pointer: it cannot move, but you can write through it (ex08, ex10, ex12).
  2. Example: read from right to left. int* const p is "p is a const pointer to int". const int* const p stops both changes (ex13).
  3. Limit: a pointer to const does not make the object const. Other names can still change it (ex36).
  4. Follow-up: "Which one does a function that only reads take?" A pointer to const, const int*. "Is std::is_const_v<const int*> true?" No, the pointer itself is not const.

Q56

L3 · Analyze Interview const-member-function

"What is a const member function? Can it call a member function of the same object that is not const?"

Show answerHide answer to Q56
  1. Main fact: a const member function has const after its parameter list. In it, this has the type const T*, so it cannot change the data members (ex20, ex22).
  2. Example: a const object and a const reference can call only const member functions (ex17, ex19).
  3. Answer to the second part: no. A call from a const member function to a member function of the same object that is not const does not compile. GCC reports passing 'const Box' as 'this' argument discards qualifiers, and Clang reports 'this' argument to member function 'grow' has type 'const Box', but function is not marked const.
  4. Follow-up: "Can you overload on const?" Yes: int& at(int) and const int& at(int) const (ex21). "Is it deep?" No, a pointer member can still change its object (ex23).

Q57

L4 · Senior Interview mutable

"When is const_cast safe, and when is it undefined behavior? Give one real use."

Show answerHide answer to Q57
  1. Main fact: const_cast removes const from the type of a reference or a pointer. A write through the result is correct when the object itself is not const (ex35). A write is undefined behavior when the object is const (ex34, [dcl.type.cv]/4).
  2. Example of a real use: an old C function void print(char* text) that does not change text. You can call it with const_cast<char*>(s.c_str()), because the function only reads.
  3. Another use: write the overload without const with the const overload, for example return const_cast<int&>(std::as_const(*this).at(i));. This is safe, because *this is not const in that function.
  4. Limit: the compiler cannot check if the object is const. Prefer an interface that needs no const_cast.
  5. Follow-up: "How do you find the bug?" No compiler and no sanitizer finds it reliably. A global const object is often in read-only memory, so the write stops with a segmentation fault (SEGV), also without a sanitizer. AddressSanitizer only reports that signal (ex34). A write to a const local object usually gives no report and no crash. So prevent the bug. Do not cast away const on an object that can be const. This is rule ES.50 of the C++ Core Guidelines. Also check each const_cast in code review. Source: cppreference, const_cast.

Q58

L3 · Analyze Interview constexpr-basics

"What is the difference between const and constexpr? Does a constexpr function always run at compile time?"

Show answerHide answer to Q58
  1. Main fact: const means "this value does not change after its initialization". The value can come from run time (ex03). The keyword constexpr on a variable means "the compiler knows this value", and the variable is also const (ex25, ex30).
  2. Example: constexpr int limit = input * 2; does not compile (ex27), but const int limit = input * 2; compiles.
  3. Second part: no. A constexpr function runs at compile time when the result must be a constant, for example in a static_assert or a constexpr variable. With a value from run time, it runs at run time (ex26).
  4. Follow-up: "How do you force compile time?" Use a consteval function (C++20), or put the result in a constexpr variable. Source: cppreference, consteval.

Q59

L4 · Senior Interview const-member-function

"What is the difference between bitwise const and logical const? Which one does the compiler check, and how does mutable connect them?"

Bitwise const: no bit of the object changes. Logical const: the value that callers can see does not change.

Show answerHide answer to Q59
  1. Main fact: bitwise const means that no bit of the object changes. Logical const means that the value that callers can see does not change.
  2. The compiler checks only a form of bitwise const: a const member function cannot assign to a data member (ex20). It does not check the objects behind pointer members (ex23).
  3. mutable connects them: a cache can change in a const function, but the visible value stays the same (ex32). So the function is logically const, not bitwise const.
  4. Follow-up: "What about threads?" A const function that writes a mutable member is a data race when two threads call it. Protect it with a mutable std::mutex or an atomic ([intro.races]/21).

Q60

L3 · Analyze Interview const-reference

"A temporary object bound to a local const reference lives longer. Why? Name one case where a const reference does not keep the temporary alive."

Show answerHide answer to Q60
  1. Main fact: the standard extends the life of a temporary that you bind to a local reference. The temporary then lives as long as the reference ([class.temporary]/6). A const reference is needed, because a reference that is not const does not bind to a temporary.
  2. Example: in ex05, const Tracer& kept = make("kept"); keeps the object to the end of main, but make("temp") ends at its ;.
  3. Cases with no extension: a temporary bound to a function parameter ends at the end of the full expression of the call. A reference that a function returns does not extend anything: a reference to a local variable dangles (Q33).
  4. Follow-up: "Does a member function call on the temporary extend it?" No. Only a direct binding to the temporary extends its life.

Q61

L4 · Senior Interview const-variable

"Does const make code faster?"

Show answerHide answer to Q61
  1. Main fact: usually const does not make code faster. It is a check for correctness.
  2. Behind a const reference or a pointer to const, the object can still change through another name (Q23). So the compiler must read the value again after a write through another pointer.
  3. A const object with a constant initializer is different. The compiler knows the value, so it can use it as a constant and put it in read-only memory. The SEGV in ex34 shows that GCC and Clang put max_users in read-only memory.
  4. Follow-up: "So why use const?" The compiler finds accidental writes, and the interface tells callers what does not change. Use constexpr when you need a value at compile time.

Q62

L4 · Senior Interview const-reference

"Why can a const int& parameter be slower than an int parameter? Which rule do you use to choose?"

Show answerHide answer to Q62
  1. Main fact: a const int& parameter is an address. The function must read the value from memory through it. On x86-64, an int parameter usually arrives in a register.
  2. Aliasing: another pointer can change the object behind the reference (Q23). So the compiler must read it again after each write to memory.
  3. Rule: F.16 of the C++ Core Guidelines, "For 'in' parameters, pass cheaply-copied types by value and others by reference to const". Its check suggests by value for types up to two pointers in size.
  4. Follow-up: "And a std::string?" Use const std::string& or std::string_view, because a copy can allocate memory. Source: C++ Core Guidelines, rule F.16.
