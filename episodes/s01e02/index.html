Copy vs Move Semantics in C++

About 12 min 38 quiz questions 63 workbook questions
Start the quiz Open the workbook Compiler Explorer (opens in a new tab)

What you learn

  • Compare the deep copy and the move of a class that owns heap memory, and their cost.
  • Write a noexcept move constructor and a move assignment operator that is safe for a self-move.
  • Explain the moved-from state, and name the operations that are safe on a moved-from object.
  • Explain why std::move is only a cast, and find the code where a move gives a copy.
  • Use copy-and-swap to give an assignment operator the strong exception guarantee.

Question 1 of 38 L3 · Analyze move-constructor

Choose one: The move constructor of Throwing is not noexcept, and Throwing has a copy constructor. Which constructor makes t2?

The copy constructor. std::move_if_noexcept gives an rvalue only if the move cannot throw, or if there is no copy constructor. Here the move can throw, so it gives an lvalue, and the copy constructor runs (ex13).

Question 2 of 38 L3 · Analyze move-assignment

Choose one: This move assignment has no self check. What does b = std::move(b); do to b?

b holds a dangling pointer. The function deletes the block of b, then takes the same address back. The next read is undefined behavior (ex07).

Question 3 of 38 L2 · Apply std-move

Choose one: Widget has a copy constructor and a noexcept move constructor. Which constructor makes b?

The copy constructor. std::move(a) gives a const Widget&&. It cannot bind to Widget&&, but it can bind to const Widget& (ex16).

Question 4 of 38 L1 · Recall copy-constructor

Choose one: Box has a copy constructor and a move constructor. The object a is a Box. Which line calls the copy constructor?

The line Box b = a; makes a new object from an lvalue, so it calls the copy constructor. The line b = a; changes an object that exists, so it calls the copy assignment operator. The argument std::move(a) is an rvalue, so it selects the move constructor.

Question 5 of 38 L2 · Apply copy-constructor

True or false: A copy of a std::vector<int> with 1000 elements takes the same time as a move of it.

The copy allocates a new block and copies each element, so its time increases with the size. The move takes the block of the source, in constant time.

cppreference gives the complexity of the std::vector constructors. The copy is linear in the size, and the move is constant. After a move of a buffer of 1000 int values, ex05 shows the same block address.

Question 8 of 38 L2 · Apply move-constructor

Fill the blank: Write the type trait that is true only when the move constructor of T cannot throw: static_assert(std::____blank<T>);

std::is_nothrow_move_constructible_v<T> checks the move constructor at compile time. It gives false for a move constructor without noexcept, and true for std::string and std::vector (ex13). A static_assert with this trait stops a slow vector growth before the program runs.

Question 12 of 38 L3 · Analyze move-assignment

Put in order: This move assignment has no self check: delete value; value = std::exchange(other.value, nullptr);. Put the steps of the self-move b = std::move(b); in order.

Drag the handle, or use the arrow buttons. With a row focused, press Alt + Up or Alt + Down.

  1. delete value deletes the block of b
  2. The assignment writes the old address back into b.value
  3. std::exchange reads the old address and sets b.value to null

The source and the target are the same object, so other.value is b.value. The function deletes the block first, and then its address comes back into b. AddressSanitizer reports heap-use-after-free at the read (ex07).

Question 13 of 38 L3 · Analyze move-assignment In the video

The old block of b leaks. The assignment writes over the only pointer to that block, so no destructor deletes it. The source a gets a null pointer, so there is no double free. LeakSanitizer reports the leak at the end of the program.

Question 15 of 38 L2 · Apply move-assignment

Question 16 of 38 L2 · Apply moved-from-state

Choose one: std::string t = std::move(s); moves the string s. Which statement about s is correct after this line?

A moved-from std::string is in a valid but unspecified state, so an assignment works and gives a known value (ex21). The standard does not say that the string is empty or that it keeps the text. Calls with no precondition are not undefined behavior.

Question 17 of 38 L1 · Recall moved-from-state

The standard specifies this state: the move constructor of std::unique_ptr sets the source to null (ex22).

Most standard types give only a valid but unspecified state. The type std::unique_ptr is one of the types that specify the moved-from state.

Question 25 of 38 L2 · Apply std-move

True or false: The statement std::move(name); alone makes the string name empty.

The function std::move only casts. No constructor or assignment gets the result, so nothing moves.

libstdc++ marks std::move with [[nodiscard]], so GCC and Clang warn: ignoring return value (ex15). To empty a string, call name.clear().

Question 26 of 38 L3 · Analyze std-move

The cast adds && to the type without its reference. So std::move(x) gives an rvalue, and the move constructor or the move assignment can take it (ex14).

Question 27 of 38 L2 · Apply copy-and-swap

Choose one: Box has Box& operator=(Box other), a copy constructor and a move constructor. Which constructor makes other for b = std::move(a);?

The parameter is a value, so a constructor makes it. The argument is an rvalue, so the move constructor runs. For b = a;, the copy constructor runs, and one operator does both jobs (ex25).

Question 28 of 38 L3 · Analyze copy-and-swap

True or false: With copy-and-swap, a throw in the copy constructor leaves the target object unchanged.

The copy is complete before the operator body starts. If the copy throws, the body never runs, so the target keeps its old value.

This is the strong exception guarantee. The implicit copy assignment assigns member by member, so a throw on the second member leaves the first member changed (ex27).

Question 29 of 38 L4 · Senior copy-and-swap

Choose all that apply: Which statements about copy-and-swap are correct? Select all correct answers.

Select all that apply.

The copy occurs first, so a throw changes nothing (ex27). A self-assignment copies before the swap (workbook Q24), and a self-move is also safe (ex30). The cost is one new block for each copy assignment (ex28). A move assignment allocates nothing. The swap must be noexcept, or the operator loses the guarantee.

Question 31 of 38 L2 · Apply copy-and-swap

Drag the handle, or use the arrow buttons. With a row focused, press Alt + Up or Alt + Down.

  1. The destructor of other deletes the old block of b
  2. The copy constructor makes other from a
  3. swap exchanges the pointers of *this and other
  4. The operator returns *this

The copy occurs before the body. The swap gives b the new block and gives other the old block. When other goes out of scope, its destructor deletes the old block (ex25).

Question 35 of 38 L2 · Apply copy-constructor

Choose one: A std::vector<std::string> holds 3 strings, and each string is too long for the small string buffer. With libstdc++ (GCC or Clang on Linux), how many heap allocations does a copy of the vector make?

The copy allocates one block for the vector and one block for each string: 1 + 3 = 4. A move of the same vector allocates nothing, because it takes the block of the source (ex03). Other standard libraries can add allocations, for example a debug build of the MSVC library.

Question 37 of 38 L4 · Senior move-constructor

Choose one: Image has two members: std::vector<std::byte> pixels and const std::string name. A std::vector<Image> grows. What does the growth do with pixels in each old element?

The implicit move constructor of Image copies the const member name, and a std::string copy can throw. So the move constructor of Image is not noexcept, and the vector copies the whole element, also pixels. Without const, the vector moves (ex32).
