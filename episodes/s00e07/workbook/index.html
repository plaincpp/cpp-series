A

Part A: Concept checks

12 questions

Q1

L1 · Recall Short answer reference

What is a reference? Give the two rules that a reference declaration must follow.

Show answerHide answer to Q1

A reference is another name (an alias) for an object that already exists.

  1. A reference must get its object in the declaration: int& alias = score;. int& alias; does not compile (ex02).
  2. A reference cannot change its object later. An assignment to the reference changes the value of the object (ex03).

A valid program also has no null reference. Source: cppreference, Reference declaration.

Q2

L1 · Recall Short answer pointer

What is a pointer? What does it hold, and what does sizeof(double*) give on x86-64 Linux?

Show answerHide answer to Q2

A pointer is an object that holds the address of another object, for example int* ptr = &score;. sizeof(double*) is 8 on x86-64 Linux. Each object pointer has 8 bytes there, whatever the size of the object (ex08). Source: cppreference, Pointer declaration.

Q3

L1 · Recall Short answer address-of

The symbol & has two meanings in this episode. Give each meaning, with one line of code for each meaning.

Show answerHide answer to Q3
  • In a declaration, & makes a reference type: int& alias = score;
  • In an expression, the unary & gives the address of an object: int* ptr = &score;

The same symbol has two jobs. The position (declaration or expression) tells you which job.

Q4

L1 · Recall Short answer dereference

The symbol * has two meanings in this episode. Give each meaning, with one line of code for each meaning.

Show answerHide answer to Q4
  • In a declaration, * makes a pointer type: int* ptr = &score;
  • In an expression, the unary * dereferences a pointer and gives the object: *ptr = 25; (ex04)

Q5

L1 · Recall Multiple choice nullptr

What is the type of nullptr?

  • a) int
  • b) void*
  • c) std::nullptr_t
Show answerHide answer to Q5

c) std::nullptr_t. nullptr converts to each pointer type, but it is not an int and not a void*. Source: cppreference, nullptr.

Q6

L1 · Recall Short answer pass-by-reference

Write the declaration of a function reset that sets an int variable of the caller to 0. Then write a call for the variable count.

Show answerHide answer to Q6

The reference parameter value is another name for count, so value = 0; in the body changes count. The call looks the same as a call with pass by value (ex15).

Q7

L1 · Recall Multiple choice const-reference

A function reads a std::string and does not change it. Which parameter type gives read-only access with no copy?

  • a) std::string
  • b) std::string&
  • c) const std::string&
Show answerHide answer to Q7

c) const std::string&. The reference gives access with no copy, and const stops a change through this name. The type std::string makes a copy. The type std::string& lets the function change the string, and it does not accept a temporary (ex21).

Q8

L2 · Apply Multiple choice pointer

Which statement about the declaration int* a, b; is correct?

  • a) a and b are both pointers to int.
  • b) a is a pointer to int, and b is an int.
  • c) It does not compile, because one line can declare only one pointer.
Show answerHide answer to Q8

b). The * belongs to the name a, not to the type int. The example ex09 declares int* first, second; and prints 8 4. So first is a pointer and second is an int. Declare one variable on each line.

Q9

L2 · Apply Multiple choice reference

The code is int a = 5; int b = 8; int& big = b; big = a; a = 0;. What are the values of a, b and big after the last statement?

  • a) a is 0, b is 5 and big is 5.
  • b) a is 0, b is 8 and big is 0.
  • c) The statement big = a; does not compile, because a reference cannot get a new object.
Show answerHide answer to Q9

a). big = a; copies the value 5 into b, because big still refers to b. The later a = 0; changes only a. A reference cannot change its object (ex03, ex31).

Q10

L2 · Apply Short answer nullptr

The overloads show(int) and show(int*) exist. Which function does each call select: show(0), show(nullptr) and show(NULL)?

Show answerHide answer to Q10
  • show(0) selects show(int).
  • show(nullptr) selects show(int*) (ex13).
  • show(NULL) does not compile on GCC 14 and Clang 19, because the call is ambiguous (ex14). GCC writes call of overloaded 'show(NULL)' is ambiguous, and Clang writes call to 'show' is ambiguous.

Q11

L2 · Apply Multiple choice const-reference

The program includes the header <string>. Which declaration compiles?

  • a) std::string& name = "Ada";
  • b) const std::string& name = "Ada";
  • c) std::string& name = std::string("Ada");
Show answerHide answer to Q11

b). The literal "Ada" is a const char array, not a std::string. The declaration makes a temporary std::string from it. Only a const reference can refer to a temporary. C++ extends the life of the temporary to the life of the reference (ex22).

a) and c) do not compile. For both, GCC writes cannot bind non-const lvalue reference of type 'std::string&' ... to an rvalue of type 'std::string'. Clang writes non-const lvalue reference to type 'std::string' ... cannot bind to a value of unrelated type 'const char[4]' for a) and ... cannot bind to a temporary of type 'basic_string<...>' for c). Source: cppreference, Reference initialization.

Q12

L2 · Apply Short answer dereference

Which sanitizer finds a dereference of a null pointer, and which one finds a read through a dangling pointer? Give the compiler flag for each sanitizer.

Show answerHide answer to Q12
  • A null pointer dereference: UndefinedBehaviorSanitizer (UBSan), flag -fsanitize=undefined. It reports runtime error: load of null pointer of type 'int' (ex12).
  • A read through a dangling pointer: AddressSanitizer (ASan), flag -fsanitize=address. It reports stack-use-after-scope, stack-use-after-return or heap-use-after-free (ex25, ex26, ex27).

You can use both: -fsanitize=address,undefined -g. Source: Clang, AddressSanitizer, Clang, UndefinedBehaviorSanitizer.

Q26

L2 · Apply Find the bug reference

This program must print 0. It does not compile. Find the line with the bug, and correct it.

Show answerHide answer to Q26

Line int& sum;. A reference must get its object in the declaration. GCC writes 'sum' declared as reference but not initialized. Correction: int& sum = total; and remove the line sum = total; (ex02).

Q27

L2 · Apply Find the bug pointer

This program must print 1. With -Wall -Werror it does not compile. Find the line with the bug, and correct it.

Show answerHide answer to Q27

Line *count = 1; writes through a pointer that holds no valid address. This is undefined behavior. GCC writes 'count' is used uninitialized [-Werror=uninitialized] (ex10). Correction: give the pointer an object.

Q28

L2 · Apply Find the bug pass-by-reference

This program must print 2 4 6. It prints 1 2 3. Find the line with the bug, and correct it.

Show answerHide answer to Q28

Line void double_all(std::vector<int> values). The parameter is a copy, so the loop doubles the elements of the copy. Correction: void double_all(std::vector<int>& values).

Q29

L2 · Apply Find the bug pointer

This program must print 7, the difference between the two values. It does not compile. Find the line with the bug, and correct it.

Show answerHide answer to Q29

Line int* min_ptr = &low, max_ptr = &high;. The * belongs to the name min_ptr, so max_ptr is an int (ex09). An int cannot get the address &high. GCC writes invalid conversion from 'int*' to 'int', and Clang writes cannot initialize a variable of type 'int' with an rvalue of type 'int *'. The next line also fails, because *max_ptr dereferences an int. Correction: declare one pointer on each line.

Q30

L3 · Analyze Find the bug address-of

This program must print 16, the first square larger than 10. Find the line with the bug, and correct it. Which sanitizer report does the bug give?

Show answerHide answer to Q30

Line found = &square;. square lives only in one pass of the loop body, so *found reads a variable after the end of its block. ASan reports stack-use-after-scope on GCC and Clang. Correction: keep the value, not the address.

Q31

L3 · Analyze Find the bug const-reference

This program must print Ada Lovelace. Find the line with the bug, and correct it. Which warning does GCC give?

Show answerHide answer to Q31

Line const std::string& full_name(...): the function returns a reference to the local variable name, which ends at the return. GCC writes reference to local variable 'name' returned [-Wreturn-local-addr]. Clang writes reference to stack memory associated with local variable 'name' returned [-Wreturn-stack-address]. Correction: return by value, std::string full_name(...). A Clang build with ASan reports stack-use-after-return, as in ex24.

Q32

L3 · Analyze Find the bug reference

This program must change the first name to Grace and print Grace Linus. Find the line with the bug, and correct it. Which sanitizer report does the bug give?

Show answerHide answer to Q32

Line names.push_back("Linus");. On this toolchain (libstdc++), names{"Ada"} has a capacity of 1, so push_back allocates a new memory block and moves the elements to it. The standard gives no start capacity. Then it frees the old block, but first still refers to the old block. ASan reports heap-use-after-free on GCC and Clang.

Correction: change the element before the push_back, or use names[0] = "Grace"; after it. Source: cppreference, std::vector::push_back.

Q33

This program must print the first score above 50, and then the first score above 90. When no score is above the limit, it must print none. The program stops with a UBSan report. Find the line with the bug, and correct it.

Line std::cout << *none << '\n';. No score is above 90, so find_above returns nullptr, and the line dereferences it with no check. UBSan reports runtime error: load of null pointer of type 'int' at this line on GCC and Clang. Correction: compare the pointer with nullptr before the dereference.

A function that can return nullptr gives the caller a check to do at each call (ex28).

Q34

L4 · Senior Find the bug const-reference

add_into must set result to a + b. The call add_into(x, x, y) with x 3 and y 4 prints 4, not 7. Find the line with the bug, and correct it.

Part D: Explain why

9 questions

Q35

L2 · Apply Explain why reference

ex03 prints 2 3 2. Explain why first is 2 and not 1. Answer in two or three sentences.

Show answerHide answer to Q35

A reference cannot change its object after the declaration. ref = second; does not move ref to second. It copies the value 2 into first, the object of ref. The later second = 3; changes only second.

Q36

L2 · Apply Explain why address-of

ex16 calls swap_by_pointer(&x, &y) and swap_by_reference(x, y). Explain why only the pointer call needs &. Answer in two sentences.

Show answerHide answer to Q36

A pointer parameter needs an address, and the unary & gives the address of x. A reference parameter needs the object itself, and the compiler makes the reference refer to it with no operator at the call. So the call with references looks the same as a call with pass by value.

Q37

L3 · Analyze Explain why pointer

On x86-64 Linux, sizeof(char) is 1 and sizeof(double) is 8, but sizeof(char*) and sizeof(double*) are both 8. Explain why. Answer in two sentences.

Show answerHide answer to Q37

A pointer holds an address, not the object. On x86-64 Linux an address has 64 bits, so each object pointer has 8 bytes, whatever the type of the object (ex08).

Q38

L3 · Analyze Explain why nullptr

Explain why show(NULL) is ambiguous with the overloads show(int) and show(int*), but show(nullptr) is not. Answer in four to six sentences.

Show answerHide answer to Q38

The value nullptr has the type std::nullptr_t, which converts to each pointer type but not to int. So only show(int*) can accept it.

On GCC 14 and Clang 19, the macro NULL has the type long, not int. So show(int) needs an integral conversion, and show(int*) needs a null pointer conversion. Both conversions have the same rank, so neither overload is a better match (ex14). With a plain 0 (an int), show(int) is an exact match (ex13). Source: cppreference, NULL.

Q39

L3 · Analyze Explain why dereference

A program dereferences a null pointer. It prints a value and stops with no crash. Explain why this result does not prove that the program is correct, and name the tool that finds the bug. Answer in three sentences.

Show answerHide answer to Q39

A dereference of a null pointer is undefined behavior, so the standard gives no rule for the result. A crash, a value or a quiet run are all possible, and a different compiler or flag can change the result. UBSan (-fsanitize=undefined) reports load of null pointer at the line of the bug (ex12). Source: cppreference, Undefined behavior.

Q40

L3 · Analyze Explain why pass-by-reference

Explain why add_bonus(50) does not compile for void add_bonus(int& score), but show(50) compiles for void show(const int& value). Answer in three sentences.

Show answerHide answer to Q40

A non-const reference parameter must refer to an object that the function can change. So it accepts only a variable (an lvalue). The literal 50 is a temporary value, so GCC writes cannot bind non-const lvalue reference of type 'int&' to an rvalue of type 'int' (ex21). A const reference can refer to a temporary, because the function cannot change it (ex22).

Q41

L3 · Analyze Explain why const-reference

In ex19, the value parameter prints copy and the const reference parameter prints same. Explain the cost of the copy for a vector of 1,000,000 int values. Answer in three sentences.

Show answerHide answer to Q41

The value parameter is a new vector. So the call allocates memory for 1,000,000 int values (4,000,000 bytes) and copies each element. At the end of the function, the copy frees its memory. The const reference parameter refers to the vector of the caller, so the call needs no allocation and no copy.

Q42

L3 · Analyze Explain why address-of

With -std=c++23 -Wall -Wextra -Wpedantic and no -O option, GCC and Clang warn for ex24, but neither compiler warns for ex26. Both functions give the address of a local variable to the caller. Explain the difference. Answer in two or three sentences.

Show answerHide answer to Q42

In ex24, return text; names a local variable directly, and both compilers check the return statement for this case. In ex26, the function returns the pointer variable result. Without optimization, no check follows the address through that variable. GCC finds it only with -O2, because its check runs after the optimizer, and Clang does not find it (captured ex26.o2.*.txt). A warning finds only some dangling pointers, so also use ASan, which reports stack-use-after-return for ex26.

Q43

L4 · Senior Explain why reference

int& make_score() { int score = 42; return score; } does not compile with -std=c++23, but it compiles with a warning with -std=c++20. Explain the C++23 rule that causes the difference. Answer in three sentences.

Show answerHide answer to Q43

From C++23, a local variable in a return statement is "move-eligible": the compiler treats score as an rvalue (an xvalue). A non-const reference int& cannot refer to an rvalue, so the return does not compile. In C++20, score is an lvalue, so the code compiles, and GCC warns reference to local variable 'score' returned (ex23). Sources: P2266, Simpler implicit move, cppreference, return statement.

Q49

Q50

L4 · Senior Write code const-reference

Show answerHide answer to Q50

The function returns one of its reference parameters, so the result refers to an object of the caller and no copy occurs. This is safe only while the arguments live. Part F: Design and trade-offs

4 questions

Q51

L4 · Senior Design pointer

You design a function that finds a user by name in a std::vector<User>. Sometimes no user has the name. Compare three return types:

  • User*, with nullptr when no user has the name
  • User&, with an exception when no user has the name
  • bool, with an output parameter User& out

Give a recommendation.

Show answerHide answer to Q51

A strong answer compares the three return types:

  • User* with nullptr: the type tells the caller that no result is possible, and the check is cheap (ex28). Risk: the caller can forget the check, and the pointer dangles when the vector changes its capacity (ex27).
  • User& with an exception: the normal call is short. Risk: "no user with this name" is a normal result, not an error. An exception for a normal result makes the code slow and difficult to read. The caller must also catch the exception.
  • bool with User& out: the caller must make a User before the call, and the function copies into it. An output parameter is harder to read than a return value.

Recommendation: return User* (or const User*), with nullptr for no match. The rule F.60 in the C++ Core Guidelines gives the same advice: use T* when "no object" is a valid option. Tell the caller not to keep the pointer after a change to the vector.

Q52

L4 · Senior Design const-reference

Your team writes a rule for parameters. Rule 1: "Pass every parameter by const reference." Rule 2: "Pass small types by value and large types by const reference." Compare the two rules for int, double, a pointer, std::string and std::vector<int>. Give a recommendation.

Show answerHide answer to Q52

A strong answer compares the two rules:

  • Rule 1, const reference for all: one rule, and no copy of a large object. Risks: for int, double and a pointer, a reference is an address, so the function reads the value through the address. Two parameters can also refer to one object, so a const reference value can change during the call (ex18, Q34).
  • Rule 2, small types by value: a copy of an int, a double or a pointer costs the same as the copy of an address. The function also gets its own value. A std::string or a std::vector<int> can hold much data, so pass it by const reference (ex19).

Recommendation: Rule 2. The rule F.16 in the C++ Core Guidelines gives the same advice: pass cheap types by value and other types by const reference. A usual limit for "cheap" is about two or three words (16-24 bytes).

Q53

L4 · Senior Design pass-by-reference

A function reads a number from a text and must tell the caller if the text is a valid number. Compare three designs: bool parse(const std::string& text, int& out), bool parse(const std::string& text, int* out) and a return value that holds the number and the result. Give a recommendation.

Show answerHide answer to Q53

A strong answer compares the three designs:

  • int& out: the caller must give a variable, so out is never null. Risk: the call parse(text, n) does not show that n changes.
  • int* out: the call parse(text, &n) shows the change, and nullptr can mean "I want only the check". Risk: the function needs a null check.
  • A return value with the number and the result: for example a struct with bool ok and int value, or std::optional<int> (C++17). The caller needs no variable before the call, and the caller always sees the result.

Recommendation: return the value. The C++ Core Guidelines prefer return values to output parameters (F.20) and a return type with more values to more output parameters (F.21). Source: cppreference, std::optional.

Q54

L4 · Senior Design reference

A program shows a list of names in a std::vector<std::string>, and the user selects one name. The program can add names later. Compare three ways to remember the selected name: a reference, a pointer and an index. Give a recommendation.

Show answerHide answer to Q54

A strong answer compares the three ways:

  • Reference: it cannot change its object, so the user cannot select a different name later (ex03). It dangles after a push_back that changes the capacity (ex27).
  • Pointer: it can change its target and can be nullptr for "no selection". It also dangles after a push_back that changes the capacity, and ASan reports heap-use-after-free.
  • Index: a number such as 2 stays valid after a push_back, because the element keeps its position. Risk: you must check the index against size(), and an insert or an erase before the element moves it to a different index.

Recommendation: keep an index (or a stable ID), and use a value such as -1 for "no selection". Do not keep a reference or a pointer to an element of a container that can grow. Source: cppreference, std::vector, iterator invalidation.

Part G: Interview questions

7 questions

Q55

L3 · Analyze Interview reference

What are the differences between a pointer and a reference in C++?

Show answerHide answer to Q55

A strong answer has these parts:

  1. Main fact: a reference is another name for an object, and a pointer is an object that holds an address.
  2. Rules: a reference must get its object in the declaration (ex02), cannot change its object (ex03) and cannot be null. A pointer can be null (ex11), can change its target (ex05) and has its own address, so int** exists (ex07). There is no reference to a reference.
  3. Syntax: a pointer needs & to get an address and * to dereference. A reference needs neither.
  4. Cost: a reference parameter and a pointer parameter usually give the same machine code. In ex29, GCC and Clang make the same code for the two versions with -O2. So choose by meaning, not by speed.
  5. Follow-up: "Can a reference dangle?" Yes: a returned reference to a local variable dangles (ex24).

Source: cppreference, Reference declaration.

Q56

L4 · Senior Interview reference

How does a compiler implement a reference? Does a reference use memory?

Show answerHide answer to Q56

A strong answer has these parts:

  1. Main fact: the standard does not specify if a reference uses memory. A compiler usually uses an address for a reference that it cannot remove, for example a reference parameter.
  2. Example: with -O2, add_one_ref(int&) and add_one_ptr(int*) compile to the same code: GCC addl $1, (%rdi) and Clang incl (%rdi) (ex29). The address arrives in the register rdi in both cases.
  3. Limit: sizeof on a reference gives the size of the object, not of the address (ex08), so you cannot measure a reference from C++.
  4. Follow-up: "Is a reference faster than a pointer?" Usually not: in ex29 the machine code is the same. The difference is the rules: not null, no change of object.

Source: the C++ standard, [dcl.ref]/4: "It is unspecified whether or not a reference requires storage" (eel.is/c++draft/dcl.ref).

Q57

L4 · Senior Interview nullptr

Why did C++11 add nullptr? What was wrong with NULL and 0?

Show answerHide answer to Q57

A strong answer has these parts:

  1. Main fact: nullptr (C++11) is a null pointer value with its own type, std::nullptr_t. It converts to each pointer type but not to int.
  2. Example: the overloads are show(int) and show(int*). The call show(0) selects the int version, and show(nullptr) selects the pointer version (ex13). On GCC 14 and Clang 19, show(NULL) is ambiguous (ex14).
  3. Limit: NULL is a macro. Each implementation chooses its definition (an integer zero such as 0 or __null, or nullptr), so the overload result changes between compilers. On GCC 14 and Clang 19, NULL has the type long.
  4. Follow-up: "Which header declares std::nullptr_t?" <cstddef>. You can use nullptr itself with no header.

Sources: cppreference, nullptr, cppreference, NULL, cppreference, std::nullptr_t.

Q58

L4 · Senior Interview const-reference

When do you pass a parameter by value, by reference, by const reference or by pointer?

Show answerHide answer to Q58

A strong answer gives a rule for each case:

  1. By value: for small types (int, double, a pointer) that the function only reads. Also when the function needs its own copy (rule F.16 in the C++ Core Guidelines).
  2. By const reference: for large types that the function only reads, such as std::string and std::vector (ex19).
  3. By reference: when the function must change an object of the caller, and the object must exist (F.17, ex15).
  4. By pointer: when "no object" is a valid input, and the caller gives nullptr (F.60, Q49).
  5. Follow-up: "What about an output value?" Prefer a return value to an output parameter (F.20).

Q59

L4 · Senior Interview address-of

What is a dangling pointer or a dangling reference? Give three ways to make one, and tell how you find them.

Show answerHide answer to Q59

A strong answer has these parts:

  1. Main fact: a dangling pointer or reference refers to an object whose life has ended. A read or a write through it is undefined behavior.
  2. Three ways:
    • a pointer to a variable after the end of its block (ex25)
    • a returned reference or address of a local variable (ex24, ex26)
    • a reference to a vector element after a push_back that changes the capacity (ex27)
  3. Tools: -Wall finds some cases, such as GCC -Wdangling-pointer for ex25 and -Wreturn-local-addr for ex24. At -O0, -Wall does not find ex26 or ex27 (GCC finds ex26 at -O2). ASan finds them at run time: stack-use-after-scope, stack-use-after-return and heap-use-after-free. For ex24, use Clang: the GCC build reports a null reference from UBSan instead.
  4. Follow-up: "How do you prevent it?" Return by value, and keep an index into a container. Do not keep an address longer than the life of its object (rule F.43 in the C++ Core Guidelines).

Q60

L4 · Senior Interview dereference

What happens when a program dereferences a null pointer? Is it always a crash?

Show answerHide answer to Q60

A strong answer has these parts:

  1. Main fact: it is undefined behavior. The standard gives no result, so the standard does not guarantee a crash.
  2. Example: on x86-64 Linux, the read often stops the program with a SEGV signal. In a test of the Q33 program with the default sanitizer options, ASan reported SEGV on unknown address 0x000000000000 after the UBSan report, on GCC and Clang.
  3. Optimizer: the compiler can use the rule that a dereferenced pointer is not null. It can then remove a later null check, so the bug can show up far from its cause (cppreference, Undefined behavior).
  4. Tools: UBSan reports load of null pointer at the line of the bug (ex12).
  5. Follow-up: "How do you prevent it?" Check with nullptr before the dereference, or use a reference when the object must exist.

Q61

L3 · Analyze Interview pass-by-reference

Can two reference parameters of one function refer to the same object? Why does it matter?

Show answerHide answer to Q61

A strong answer has these parts:

  1. Main fact: yes. Two reference parameters can refer to one object, for example add_twice(c, c) (ex18). This is aliasing.
  2. Example: in ex18, add_twice(a, b) gives 3, but add_twice(c, c) gives 4, because each write to total also changes amount.
  3. Limit: const does not help. A const int& stops a change only through its own name (Q34).
  4. Follow-up: "How do you write a safe function?" Copy the input values into local variables before the first write, or take small inputs by value. Test the function with the same object for two parameters (Q44).
