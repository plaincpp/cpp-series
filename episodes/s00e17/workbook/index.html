Part A: Concept checks

12 questions

Q1

L1 · Recall Short answer lambda-expression

Name the main parts of a lambda expression in their order. Which parts are optional?

Show answerHide answer to Q1
  1. The capture list [...]
  2. The template parameter list <typename T> (C++20)
  3. The parameter list (...)
  4. Specifiers, for example mutable
  5. The trailing return type -> T
  6. The body {...}

The template parameter list is optional (C++23 [expr.prim.lambda]), and most lambdas do not use it. The parameter list, mutable and the return type are also optional: [] { return "hello"; } compiles (ex02). The capture list and the body are necessary, but the capture list can be empty: [].

Q2

L1 · Recall Short answer capture-by-value

What does the capture [limit] do? When does the copy occur?

Show answerHide answer to Q2

[limit] copies the variable limit into the closure object. The copy occurs when the program evaluates the lambda expression, not when the lambda runs. A later change to limit does not change the copy (ex05).

Q3

L1 · Recall Short answer capture-by-reference

What does the capture [&total] do? Give one correct use and one danger.

Show answerHide answer to Q3

[&total] captures total by reference: the body reads and changes the original variable. A correct use: add values to a local total in std::for_each (ex07). The danger: if the lambda runs after the lifetime of total ends, it reads a dead object, which is undefined behavior (ex28).

Q4

L1 · Recall Short answer closure-type

What is the closure type of a lambda? What is the closure object?

Show answerHide answer to Q4

The closure type is the unique unnamed class type that the compiler makes for each lambda expression (C++23 [expr.prim.lambda.closure]). It has one data member for each capture by value, and its body is a member function operator(). The closure object is the value of the lambda expression: an object of that class.

Q5

L1 · Recall Short answer generic-lambda

What is a generic lambda? Which C++ standard added it?

Show answerHide answer to Q5

A generic lambda has one or more auto parameters, for example [](auto value) { return value + value; }. C++14 added it. Its operator() is a member template, so one lambda works with many types (ex20).

Q6

L1 · Recall Multiple choice mutable-lambda

What does mutable change in a lambda?

  • a) It removes the const from operator(), so the body can change its copies.
  • b) It changes each capture by value into a capture by reference.
  • c) It lets the body change the original variables that it captures by value.
Show answerHide answer to Q6

a) mutable removes the const from operator(). The body can then change its own copies, but the original variables do not change (ex25). Choice c) is the usual mistake: a capture by value is always a copy.

Q7

L2 · Apply Multiple choice lambda-expression

Which algorithm returns an iterator to the first element for which a lambda returns true?

  • a) std::count_if
  • b) std::for_each
  • c) std::find_if
Show answerHide answer to Q7

c) The algorithm std::find_if returns an iterator to the first element for which the predicate returns true. When no element matches, it returns end() (ex03). The algorithm std::count_if returns a count, and std::for_each calls the function for each element.

Q8

L2 · Apply Multiple choice capture-by-value

A lambda in main has the capture list [=]. The body uses a global variable and a static local variable. What does the body read when it runs?

  • a) The values that the two variables had when the program made the lambda
  • b) The current values of the two variables
  • c) Nothing, because the code does not compile without [&]
Show answerHide answer to Q8

b) The body reads the current values. A lambda captures only variables with automatic storage. Global and static variables have static storage, so the body uses them directly (ex10). The code compiles with [=] and also with an empty capture list.

Q9

L2 · Apply Short answer capture-by-value

Write a lambda with an init-capture. It keeps the value of price * count with the name total, and it returns total. Which C++ standard added init-captures?

Show answerHide answer to Q9

C++14 added init-captures. The compiler computes price * count one time, when the program makes the lambda, and keeps the result in the member total (ex11).

Q10

L2 · Apply Multiple choice closure-type

The function apply takes a parameter of the type int (*)(int). n is a local int. Which call compiles?

  • a) apply([=](int x) { return x * 2; })
  • b) apply([](int x) { return x * 2; })
  • c) apply([&](int x) { return x * 2; })
Show answerHide answer to Q10

b) Only a lambda with an empty capture list [] converts to a function pointer (ex18). A capture default [=] or [&] removes the conversion, also when the body uses no local variable. GCC writes cannot convert 'main()::<lambda(int)>' to 'int (*)(int)' for a) and c), and Clang writes no matching function for call to 'apply' (checked on both compilers).

Q11

L2 · Apply Multiple choice capture-by-value

A member function returns a lambda that reads a data member. The caller keeps the lambda, and then the lifetime of the object ends. Which capture is safe?

  • a) [this]
  • b) [=]
  • c) [*this]
Show answerHide answer to Q11

c) The capture [*this] (C++17) copies the full object into the closure, so the lambda does not use the original object (ex13). The captures [this] and [=] capture only the pointer this. After the lifetime of the object ends, a call reads through a dangling pointer, which is undefined behavior (Q29).

Q12

L2 · Apply Multiple choice generic-lambda

Which lambda accepts a std::vector of any element type, but not a std::string?

  • a) [](auto v) { return v.size(); }
  • b) []<typename T>(const std::vector<T>& v) { return v.size(); }
  • c) [](const auto& v) { return v.size(); }
Show answerHide answer to Q12

b) The template parameter list (C++20) gives the element type the name T, and the parameter must be a std::vector<T>. A std::string is not a std::vector, so a call with a std::string does not compile: GCC writes no match for call to, and Clang writes no matching function for call to object (checked). With auto, a) and c) accept each type that has size(), also std::string.

Q25

L2 · Apply Find the bug lambda-expression

This program must write 0.25. It does not compile. Find the bug and correct it.

Show answerHide answer to Q25

Lines 6 and 8: the lambda has no -> return type, so the compiler deduces it from each return statement. Line 6 gives int, and line 8 gives double. GCC writes inconsistent types 'int' and 'double' deduced for lambda return type (ex04). Correction: write [](int a, int b) -> double on line 4, or write return 0.0; on line 6. Both corrections write 0.25.

Q26

L2 · Apply Find the bug capture-by-value

This program must write the number of scores that are 50 or more. It does not compile. Find the bug and correct it.

Show answerHide answer to Q26

Line 9: the capture list [] is empty, so the body cannot use the local variable pass_mark. GCC writes 'pass_mark' is not captured, and Clang writes variable 'pass_mark' cannot be implicitly captured in a lambda with no capture-default specified (ex08). Correction: [pass_mark](int s) { return s >= pass_mark; }. The program then writes 2.

Q27

Q29

Part D: Explain why

9 questions

Q34

L2 · Apply Explain why lambda-expression

The lambda [](float x) { if (x < 0) { return 0.0; } return x / 2; } does not compile. The same lambda with -> float after (float x) compiles. Explain why. Answer in three sentences or fewer.

Show answerHide answer to Q34

Rule: when a lambda has no -> return type, the compiler deduces the type from each return statement. All the types must be the same. Applied: return 0.0; gives double, and return x / 2; gives float, so the deduction fails. GCC writes inconsistent types 'double' and 'float' deduced for lambda return type (checked on GCC and Clang; the same rule as ex04). With -> float, the compiler does not deduce: it converts 0.0 to float.

Q35

L2 · Apply Explain why capture-by-value

ex05 sets limit = 100 after it makes the lambda above, but above(50) still returns true. Explain why. Answer in two sentences.

Show answerHide answer to Q35

Rule: a capture by value copies the variable when the program makes the lambda. Applied: above keeps the copy 10, and limit = 100 changes only the original variable, so 50 > 10 gives true.

Q36

L3 · Analyze Explain why capture-by-value

In ex10, the capture list [=] does not copy global_count and static_count, and the program writes 221. Explain why. Answer in three sentences or fewer.

Show answerHide answer to Q36

Rule: a lambda captures only variables with automatic storage: local variables and parameters. Applied: global_count and static_count have static storage, so the body uses them directly and reads the new values 2 and 2. Only local_count is a copy, and it keeps 1: 2 * 100 + 2 * 10 + 1 = 221.

Q37

L4 · Senior Explain why capture-by-value

C++20 deprecates the implicit capture of this with [=] (ex14). Explain why this capture is a trap, and tell what to write in its place. Answer in four sentences or fewer.

Show answerHide answer to Q37

Rule: in a member function, [=] captures the pointer this, not a copy of the members. Applied: the code looks like a copy of value, but the lambda reads this->value. A later change to the object shows in the lambda, and the lambda dangles when the object dies. Write [this] when you need the pointer, or [*this] (C++17) when you need a copy. C++20 deprecates the implicit capture, and GCC and Clang warn (ex14).

Q38

L3 · Analyze Explain why capture-by-reference

GCC 14 compiles ex28 with no warning, but the program has undefined behavior. Explain why. Then name two tools that find the bug.

Show answerHide answer to Q38

Rule: a reference capture does not change the lifetime of the variable. Applied: after make_adder returns, the parameter amount is dead, and the later call reads it through the reference. This is undefined behavior. The standard does not tell the compiler to give a message for it, and GCC 14 gives none.

The lifetime of a parameter ends at the return or at the end of the full-expression of the call (C++23 [expr.call]/6). In both cases, amount is dead on line 11. Two tools find the bug:

  1. Clang warns address of stack memory associated with parameter 'amount' returned (-Wreturn-stack-address).
  2. AddressSanitizer (-fsanitize=address) reports stack-use-after-return at run time (ex28).

Q39

L3 · Analyze Explain why closure-type

A lambda with no captures converts to int (*)(int) (ex18), but [factor](int x) { return x * factor; } does not (ex19). Explain why. Answer in three sentences or fewer.

Show answerHide answer to Q39

Rule: a function pointer holds only the address of code. Applied: a lambda with no captures needs no data, so the closure type has a conversion function to a function pointer (C++23 [expr.prim.lambda.closure]). The lambda [factor] needs the value of factor in each call. A function pointer has no place to keep it, so the conversion does not exist (ex19).

Q40

L3 · Analyze Explain why closure-type

Two lambdas have the same text, but std::is_same_v gives false for their types (ex17). Explain why. Then give one result of this rule for your code.

Show answerHide answer to Q40

Rule: each lambda expression makes its own unique class type, also when the text is the same. Applied: first and second have two types, but copy has the type of first (ex17). Result: you cannot assign second to the variable first: GCC writes no match for 'operator=' (checked on GCC and Clang). Keep a lambda in an auto variable, or pass it to a template parameter.

Q41

L3 · Analyze Explain why generic-lambda

In ex23, the call twice(4) compiles, but the call twice(p) with a Point gives an error in the body of the lambda. Explain why the error shows only for that call, and why it points into the body.

Show answerHide answer to Q41

Rule: the operator() of a generic lambda is a member template, and the compiler makes it again for each new argument type. Applied: the call twice(4) makes the int version, and int + int is correct. The call twice(p) makes the Point version. The type Point has no +, so the error comes from the body. Compilers show the call in a note: GCC writes In instantiation of ... [with auto:38 = Point] (ex23).

Q42

L3 · Analyze Explain why mutable-lambda

ex27 writes 1 and then 5. Explain each number. Answer in four sentences or fewer.

Show answerHide answer to Q42

Rule: std::for_each takes the function object by value and returns its copy. Applied: the first loop changes a copy, so counter still has calls == 0, and counter(0) returns 1. The second loop copies counter with calls == 1. It adds 3 calls and returns the copy as used, so used(0) returns 5 (ex27).

Part F: Design and trade-offs

5 questions

Q50

L4 · Senior Design capture-by-reference

A Button object keeps a copy of a lambda and calls it after each click, also after the function that made the lambda returns. The function setup() has a local int clicks = 0;. Compare three designs: [&clicks], [clicks]() mutable and a counter in the owner of the button. Recommend one.

Show answerHide answer to Q50
  • [&clicks]: no copy, but clicks dies when setup() returns. Each later click reads and writes a dead object: undefined behavior (ex28). Do not use it.
  • [clicks]() mutable: safe, because the closure keeps its own counter. But the counter is inside the button, so other code cannot read it. A copy of the lambda also starts its own count (ex24).
  • A counter in the owner of the button: for example, a member of the window that owns the button. The lambda captures it with [this]. The lifetime is clear, and other code can read the count.
  • Recommendation: the counter in an owner object. Use [clicks]() mutable only when no other code needs the count. Never capture a local by reference in a lambda that runs later.

Q51

L4 · Senior Design lambda-expression

Compare three comparisons for std::sort: a lambda at the call, a named function and a struct with operator(). Tell when you use each one. Talk about the readability, the reuse and the state.

Show answerHide answer to Q51
  • A lambda at the call: the comparison is next to the std::sort call, so the reader sees it at once. It can capture local values, for example a target (q17). Use it for a short comparison that the code uses one time.
  • A named function: reuse in many places, and a name that tells the purpose, for example by_length. It cannot keep state, and std::sort gets it as a function pointer.
  • A struct with operator(): reuse and state, for example a member target, with a name and a constructor. It needs more code, but it is the same thing as a closure type (ex15).
  • Recommendation: start with a lambda. When two places need the same comparison, give it a name. Use a lambda in a named variable, a function or a struct.

Q52

L4 · Senior Design closure-type

A C library has the function void set_handler(int (*handler)(int)). Your handler must multiply by a factor that the program reads from a configuration file. A lambda with the capture [factor] does not compile here.

Compare two designs. The first design is a lambda with no captures that reads a static variable. The second design changes the API to void set_handler(int (*handler)(void*, int), void* context). Recommend one.

Show answerHide answer to Q52
  • A lambda with no captures that reads a static variable: it converts to int (*)(int) (ex18), and the API does not change. But there is only one factor for the full program. Two handlers with two factors are not possible, and threads that change the value need synchronization.
  • The API with void* context: the caller passes a pointer to its own data. A lambda with no captures converts the pointer back: [](void* context, int x) { return x * *static_cast<int*>(context); } (checked on GCC and Clang). Each handler can have its own data. The cost: the void* has no type safety, and the data must stay alive while the library can call the handler.
  • Recommendation: if you can change the API, use the void* context form, which most C libraries use. Use the static variable only when you cannot change the API and one value is enough.

Q53

L4 · Senior Design generic-lambda

You need a helper that writes the elements of a std::vector<int>, a std::vector<double> and a std::vector<std::string>. Compare three designs: a generic lambda with const auto&, a C++20 template lambda and three overloaded functions. The template lambda takes const std::vector<T>&. Talk about the errors, the code size and the reuse.

Show answerHide answer to Q53
  • A generic lambda with const auto&: short, and it works for each vector type. But it also accepts types that are not vectors, and the error then points into the body (ex23).
  • A template lambda with const std::vector<T>& (C++20): it accepts only vectors, so a wrong argument gives an error at the call. It gives a name T that the body can use (ex22).
  • Three overloaded functions: clear errors and a separate body for each type, but the same code three times.
  • Code size: the two lambdas make one function for each element type that a call uses. So the code size is about the same as three overloads.
  • Recommendation: the template lambda. It has one body, and it gives a clear error at the call.

Q54

L4 · Senior Design mutable-lambda

A program must give each new order a unique ID. Compare three designs: a mutable lambda with [id = 0], a lambda with [&counter] and a class with next(). Think about copies of the lambda and about algorithms that take a function object by value. Recommend one.

Show answerHide answer to Q54
  • A mutable lambda with [id = 0]: short, and the state is private. But each copy has its own id (ex24), and an algorithm that takes the lambda by value works on a copy (ex27). Two copies can give the same ID.
  • A lambda with [&counter]: all copies share one counter, so the IDs are unique. But the counter must live longer than each copy of the lambda (ex28).
  • A class with next(): the state has a clear owner and a name. You pass the object by reference, so no copy can give the same ID. The class can also add a reset or a check later.
  • Recommendation: the class, or a lambda that captures a counter that a long-lived object owns. A mutable lambda is good only for local work where nothing copies it.

Q55

L4 · Senior Interview closure-type

What does the compiler make for the lambda [factor](int x) { return x * factor; }? Write the class by hand, and name the parts that the hand-written class cannot copy exactly.

Show answerHide answer to Q55

Main fact: the compiler makes a unique unnamed class with one data member for each capture by value and a const operator() (C++23 [expr.prim.lambda.closure]).

Example: ex15 compares a struct like this with the lambda, and both give the same results. The closure of ex16 with one int capture has the size 4.

What the hand-written class does not copy exactly:

  • The type has no name, and each lambda expression has a different type (ex17).
  • If the capture list is not empty, the closure has no default constructor and no copy assignment. GCC and Clang show this with std::is_default_constructible_v and std::is_copy_assignable_v. In C++20, a lambda with an empty capture list [] has both. A capture default such as [=] removes them, also when the body uses no local variable (C++23 [expr.prim.lambda.closure]).
  • Only a lambda with no captures converts to a function pointer (ex18, ex19).

Follow-up questions:

  • Where does the closure object live? Where you keep it: in a local variable, a member or a parameter. The lambda expression does not use the heap.
  • What changes with mutable? The operator() is not const (ex24).

Q56

L3 · Analyze Interview capture-by-value

What is the difference between [=] and [&]? Which capture do you use by default, and why?

Show answerHide answer to Q56

Main fact: the capture [=] copies each local variable that the body uses, when the program makes the lambda. The capture [&] refers to each local variable that the body uses (ex09).

Example: in ex09, copy_all keeps the old values 1 and 2, and ref_all reads the new values 3 and 4.

Trade-offs:

  • [=] is safe when the lambda runs later, but it can copy large objects. In a member function, it captures this, not a copy of the members (ex14).
  • [&] costs no copy, but it dangles when the lambda runs after the variables die.

Default: the C++ Core Guidelines give two rules. Capture by reference in a lambda that runs locally, for example in an algorithm call (F.52). Do not capture by reference in a lambda that runs later (F.53). Named captures, for example [limit, &total], show each capture and its kind.

Follow-up questions:

  • Does [=] copy globals? No. Global and static variables have no capture (ex10).
  • Can you mix defaults and names? Yes: [=, &total] and [&, b] (ex09).

Q57

L4 · Senior Interview capture-by-reference

When is a capture by reference dangerous? How do you find this bug, and how do you prevent it?

Show answerHide answer to Q57

Main fact: a capture by reference is dangerous when the lambda runs after the variable dies. The usual cases: a function returns the lambda, the code keeps the lambda in a member or a container, or another thread runs it later.

Example: make_adder in ex28 returns [&amount], so the call reads a dead parameter. ASan reports stack-use-after-return.

How to find it:

  1. Clang warns for a returned lambda that captures a local by reference (-Wreturn-stack-address). GCC 14 does not warn.
  2. AddressSanitizer finds it at run time, but only on a path that the test runs.
  3. Code review: look at each [&] and [&x] in a lambda that leaves its scope.

How to prevent it: capture by value (ex29), or [*this] for an object. Use a reference only when the lambda runs during the lifetime of the variable, for example in a std::sort call.

Follow-up questions:

  • Is [this] safe? Only while the object is alive. It is a pointer, so it can dangle as a reference does.

Q58

L4 · Senior Interview capture-by-value

Explain [this] and [*this]. What did C++20 change for [=] in a member function?

Show answerHide answer to Q58

Main fact: the capture [this] copies the pointer this, so the lambda reads the current members of the object. The capture [*this] (C++17) copies the full object. So the lambda keeps the values from the time when the program made it (ex13: 15 and 5).

C++20: the implicit capture of this with [=] is deprecated. In a member function, [=] looks like a copy of the members, but it captures only the pointer. GCC writes implicit capture of 'this' via '[=]' is deprecated in C++20 (ex14). In C++20, you can write [=, this] to show the pointer capture clearly.

Trade-offs: the capture [*this] is safe after the object dies, but it copies the full object. The capture [this] costs one pointer, but the object must live longer than the lambda.

Follow-up questions:

  • Which capture is correct for a callback that runs after the object can die? Use [*this], or copy only the members that the lambda needs, for example [value = value_].

Q59

L3 · Analyze Interview generic-lambda

What is a generic lambda? How is it different from a function template?

Show answerHide answer to Q59

Main fact: a generic lambda has auto parameters (C++14). Its closure type has a member template operator(), so one lambda works with many types (ex20).

Compared with a function template:

  • A function template has a name, and you can declare it in a header and call it with explicit template arguments.
  • A generic lambda is an object. You can pass it to an algorithm or keep it in a variable, and it can capture local variables.
  • Both make one function for each new set of argument types, and both give errors only for a type that the body cannot use (ex23).

C++20: a template lambda []<typename T>(...) names the type, so the body can use T, and two parameters can have the same type (ex22).

Follow-up questions:

  • Does a generic lambda with no captures convert to a function pointer? Yes. int (*f)(int) = [](auto x) { return x + 1; }; compiles on GCC and Clang.

Q60

L3 · Analyze Interview mutable-lambda

Why is the operator() of a lambda const by default? What does mutable change? Why must you know that standard algorithms copy a lambda?

Show answerHide answer to Q60

Main fact: the operator() of a lambda is const by default, so a call does not change the captured copies. Most lambdas are predicates and comparisons, and a call that changes them is a usual bug. The keyword mutable removes the const, and the body can change its copies (ex24).

Example: without mutable, ++calls on a capture by value does not compile (ex26). With mutable, the closure keeps a counter between calls.

Why the copies matter: standard algorithms take the function object by value, and they can copy it more times. So the state of a mutable lambda changes in a copy, not in your variable (ex27). The algorithm std::for_each returns its copy, so you can read the state from the return value.

Follow-up questions:

  • How do you share the state with the caller? Capture a variable by reference while the algorithm runs (ex07).
  • Does mutable change the original variable? No, only the copy in the closure (ex25).

Q61

L4 · Senior Interview closure-type

What is the size of a lambda? Does a lambda expression allocate memory on the heap?

Show answerHide answer to Q61

Main fact: a closure object holds its captures as data members, so its size is about the size of the captures. On x86-64 Linux (ex16):

  • no captures: 1 byte, because each object needs at least 1 byte
  • one int: 4 bytes
  • an int and a double: 16 bytes, with 4 bytes of padding
  • one reference capture: 8 bytes in GCC and Clang (the standard does not specify it)

Heap: the lambda expression does not allocate memory on the heap. The closure object is a normal object, where you keep it. But a capture by value copies its object, and a copy of a long std::string can allocate.

Trade-off: a capture of a large object by value makes a large closure. Algorithms copy the closure, so capture large data by reference when the lambda runs at once.

Follow-up questions:

  • How do you keep different lambdas in one container? Each lambda has its own type (ex17), so you need type erasure. A later season shows std::function.
