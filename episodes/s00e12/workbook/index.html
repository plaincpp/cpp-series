Part A: Concept checks

12 questions

Q1

L1 · Recall Short answer header-file

Name three things that you put in a header file. Then name two things that you put in one source file only.

Show answerHide answer to Q1

In a header: function declarations, class definitions, inline functions and inline variables, and declarations with extern. Also constexpr constants and templates.

In one source file only: the body of each function that is not inline, and the definition of each global variable that is not inline. A body in a header gives a multiple definition when two source files include it (ex12, ex14).

Q2

L1 · Recall Multiple choice header-file

What does the line #include "convert.h" do?

  • a) The linker adds the object file convert.o to the program.
  • b) The preprocessor puts the text of convert.h into the file at this line.
  • c) The compiler reads only the declarations from convert.h and ignores the other lines.
Show answerHide answer to Q2

b). #include is a preprocessor directive. The preprocessor puts the full text of the file at that line, before the compiler starts. The linker knows nothing about headers. Source: cppreference, Source file inclusion.

Q3

L1 · Recall Short answer declaration-vs-definition

What is the difference between a declaration and a definition? Give one declaration and one definition for a function, and the same for a global variable.

Show answerHide answer to Q3

A declaration gives a name and its type. A definition also makes the object or gives the function body. Each definition is also a declaration.

ex02 has two declarations of each name and one definition of each. Source: cppreference, Definitions and ODR.

Q4

L1 · Recall Short answer include-guard

Write the three lines of an include guard for the header money.h. Tell where each line goes in the file.

Show answerHide answer to Q4

The first include defines MONEY_H. A second include in the same translation unit finds the macro and skips the text up to #endif (ex09).

Q5

L1 · Recall Short answer one-definition-rule

State the one definition rule in three short sentences. Write one for a translation unit, one for the program, and one for classes and inline definitions.

Show answerHide answer to Q5
  1. One translation unit has at most one definition of each variable, function, class and enumeration.
  2. The program has exactly one definition of each non-inline function and variable that it uses.
  3. A class, an inline function or an inline variable can have one definition in each translation unit, but all the definitions must be the same.

Source: cppreference, Definitions and ODR, the standard [basic.def.odr].

Q6

L1 · Recall Short answer namespace

Which problem does a namespace solve? Write the qualified name of the class Config in the namespace network.

Show answerHide answer to Q6

A namespace stops name clashes. Two libraries can each have a class Config when each class is in its own namespace (ex20, ex21). The qualified name is network::Config.

Q7

L1 · Recall Multiple choice inline-variable

Which C++ standard added inline variables, such as inline int request_count = 0;?

  • a) C++11
  • b) C++17
  • c) C++20
Show answerHide answer to Q7

b) C++17. Before C++17, a header needed extern int request_count; and one definition in a source file (ex05). Source: cppreference, inline specifier.

Q8

L1 · Recall Short answer anonymous-namespace

Which linkage does a name in an anonymous namespace get? What does this linkage mean for code in another source file?

Show answerHide answer to Q8

Internal linkage. Code in another source file cannot use the name. A declaration with the same name in another file names a different entity. The linker does not join the two names. nm shows the helper of ex28 as a local symbol t. Source: cppreference, Namespaces, unnamed namespaces.

Q9

L2 · Apply Multiple choice declaration-vs-definition

Each line is at namespace scope. Which line is a definition?

  • a) extern int limit;
  • b) int square(int value);
  • c) struct Engine;
  • d) extern int limit = 10;
Show answerHide answer to Q9

d). A declaration with an initializer is a definition, also with extern. Both compilers accept it, but they warn: GCC with 'limit' initialized and declared 'extern', Clang with 'extern' variable has an initializer. Write int limit = 10; for a definition. a), b) and c) are declarations only.

Q10

L2 · Apply Multiple choice namespace

Which line brings only the name cout from std into the current scope?

  • a) using std::cout;
  • b) using namespace std;
  • c) namespace cout = std::cout;
Show answerHide answer to Q10

a) using std::cout; is a using-declaration. It brings one name (ex23). b) is a using-directive. It brings all names of std. c) does not compile, because a namespace alias needs a namespace, not a variable.

Q11

L2 · Apply Multiple choice include-guard

Which statement about #pragma once is correct?

  • a) The C++11 standard added it, so every compiler must support it.
  • b) The compiler identifies the file, so you need no guard name, and no guard name can clash.
  • c) It also stops a multiple definition when two source files include the header.
Show answerHide answer to Q11

b). The compiler records the file that it has read. So you write no guard name. #pragma once is not in the C++ standard, but GCC, Clang and MSVC support it (ex10). Like a guard, it works only in one translation unit, so c) is wrong. Sources: cppreference, Implementation defined behavior control, Microsoft, once pragma.

Q12

L2 · Apply Short answer one-definition-rule

nm -C main.o and nm -C cart.o both show W add_tax(int). What does the letter W mean? Why does the link succeed?

Show answerHide answer to Q12

W is a weak symbol. GCC and Clang make an inline function a weak symbol in each object file that uses it (ex13). This is true in a build with no optimization, the default -O0. With -O2, both compilers can expand all calls and keep no symbol. The linker keeps one copy and discards the other copies. A normal function is a strong symbol T, and two strong symbols with one name give multiple definition (ex12).

main.cpp and cart.cpp include this header. Each file compiles, but the linker stops with multiple definition of add_tax(int)'`. Find the line with the bug and correct it.

Q26

L2 · Apply Find the bug one-definition-rule

main.cpp and log.cpp include this header. The linker stops with multiple definition of request_count'`. Find the line with the bug. Give two corrections.

Show answerHide answer to Q26

Line 5. Each source file that includes the header defines request_count (ex14). Correction 1 (C++17): inline int request_count = 0; (ex15). Correction 2: extern int request_count; in the header, and int request_count = 0; in one source file (ex05).

Q27

L2 · Apply Find the bug include-guard

main.cpp includes money.h two times: one time directly and one time through another header. The compiler stops with redefinition of 'struct Money'. Find the line with the bug.

Show answerHide answer to Q27

Line 3. #define MONY_H defines a different name, so the macro MONEY_H never exists, and the guard never works. The second include adds struct Money again. Correction: #define MONEY_H. Clang also warns: 'MONEY_H' is used as a header guard here, followed by #define of a different macro.

Q28

L3 · Analyze Find the bug include-guard

Two libraries each have a header with the name config.h. The compiler stops with 'max_files' was not declared in this scope. Find the lines with the bug, and give two corrections.

Lines 7 and 8. Both headers use the guard CONFIG_H. After network/config.h, the macro exists, so the preprocessor skips all of storage/config.h, and max_files has no declaration (ex11). Q34

L4 · Senior Find the bug anonymous-namespace

discount.cpp and invoice.cpp each define a helper class with the name Line. The program builds with no message on GCC and Clang. A code review says that the program is wrong. Find the bug, tell which tool can find it, and correct it.

Show answerHide answer to Q34

Lines 2 and 7. The program has two different definitions of the class Line with external linkage. This is an ODR violation. Part D: Explain why

10 questions

Q35

L2 · Apply Explain why include-guard

tax.h has an include guard and a function body. Two source files include it, and the link fails. Explain why the guard does not prevent the error. Answer in two or three sentences.

Show answerHide answer to Q35

The preprocessor works on one translation unit at a time, and each translation unit starts with no macros. So TAX_H from main.cpp does not exist when cart.cpp compiles, and both object files get the body of add_tax. The linker then finds two definitions (ex12).

Q36

L2 · Apply Explain why declaration-vs-definition

ex04 has extern int limit; and uses limit, but no file defines it. Explain why the file compiles, but the program does not link. Answer in two sentences.

Show answerHide answer to Q36

A declaration gives the compiler the name and the type, so it can compile each use of limit. The compiler leaves an undefined symbol U limit in the object file, and the linker finds no definition for it.

Q37

L3 · Analyze Explain why one-definition-rule

Explain why the definition struct Money { int cents; }; can be in a header that 50 source files include, but int add_tax(int c) { return c + c / 5; } cannot. Answer in three or four sentences.

Show answerHide answer to Q37

The one definition rule lets a class definition be in each translation unit, if all copies are the same. A class makes no symbol in the object file, so the linker has nothing to join. A non-inline function makes a strong symbol in each object file. The rule lets the program have only one definition. inline changes this for the function (ex13). Source: [basic.def.odr].

Q38

L3 · Analyze Explain why inline-variable

A header has constexpr int max_retries = 3;. Explain why two source files that include it link with no error. Then explain why ex16 prints false when it compares the address of max_retries in two files. Answer in three sentences.

Show answerHide answer to Q38

A const or constexpr variable at namespace scope has internal linkage, so each source file has its own private copy. Private copies do not clash at link time. They are two objects, so their addresses are different, and the comparison is false (ex16).

Q39

L3 · Analyze Explain why namespace

Explain why using namespace std; in a header is worse than the same line in a source file. Answer in two or three sentences.

Show answerHide answer to Q39

A header goes into each file that includes it, also the headers that include it. So the using-directive changes name lookup in files that you do not control. A name such as size or count can become ambiguous (ex24, ex25). In a source file, the effect stops at the end of that file.

Q40

L3 · Analyze Explain why namespace

In ex26, print(tea) calls shop::print with no shop::. Explain the rule. Then explain how the same rule finds operator<< in std::cout << text, where text is a std::string. Answer in three sentences.

Show answerHide answer to Q40

The rule is argument-dependent lookup. The compiler looks for an unqualified function call in the usual scopes. It also looks in the namespaces of the argument types. tea has the type shop::Item, so the compiler finds shop::print (ex26). In std::cout << text, the arguments have types from std, so the compiler finds std::operator<< for std::string. Source: cppreference, Argument-dependent lookup.

Q41

L3 · Analyze Explain why anonymous-namespace

Explain two reasons to put each helper function of a source file in an anonymous namespace. Answer in two or three sentences.

Show answerHide answer to Q41

First, the helper has internal linkage, so it cannot clash with a helper of the same name in another file (ex27, ex28). Second, no other file can call it, so the optimizer knows all calls. It can put the body in each call or remove an unused helper. With -Wall, GCC and Clang also warn about an unused function in an anonymous namespace (-Wunused-function).

Q42

L4 · Senior Explain why one-definition-rule

In ex19, two source files define struct Item with different members. A normal build on GCC and Clang shows no message. Explain why no tool must report this error. Tell what can go wrong when the program runs, and which tool can find it. Answer in four sentences.

Show answerHide answer to Q42

The two classes are in different translation units, and a class makes no symbol that the linker compares. So the standard calls the program ill-formed, no diagnostic needed. When it runs, one file can write an Item with one layout. The other file can read it with a different layout, which is undefined behavior.

A normal build is silent on GCC and on Clang (ex19). GCC with -flto compares the types and reports -Wodr (ex19). Do not run a program that has an ODR violation, because its behavior is undefined.

Q43

L3 · Analyze Explain why header-file

In ex07, car.h uses struct Engine; and not #include "engine.h". Explain two advantages of this forward declaration for a large project. Answer in two or three sentences.

Show answerHide answer to Q43

First, files that include car.h do not get the text of engine.h, so a change in engine.h recompiles fewer files. Second, a forward declaration can break a loop of headers, for example when Car points to Engine and Engine points to Car. The file that uses the members of Engine (car.cpp) includes engine.h.

Q44

L2 · Apply Explain why inline-variable

The optimizer can decide to call an inline function and not put its body at the call. Explain why inline corrects the multiple definition link error all the same. Answer in two sentences.

Show answerHide answer to Q44

In modern C++, inline means "this definition can be in many translation units". The linker keeps one copy, and this rule does not depend on the decision of the optimizer. Source: cppreference, inline specifier.

Part F: Design and trade-offs

4 questions

Q51

L4 · Senior Design inline-variable

30 source files must read and change one global counter. Compare three designs. Design 1 has extern in a header and one definition in a source file. Design 2 has an inline variable in a header. Design 3 has an inline function that returns a reference to a static local variable. Talk about the standard that you need, the start value and the control of changes, and give a recommendation.

Show answerHide answer to Q51

A strong answer compares the three designs:

  • extern in a header, one definition in a source file (ex05): works in every standard. The definition shows the start value in one place. Risk: a person can forget the definition (undefined reference, ex04), or write a second one.
  • inline variable in a header (ex15): one line, C++17 or later. The start value is in the header, so each file that includes it sees it. A change to the start value recompiles all those files.
  • inline function with a static local (Q50): works before C++17. The first call initializes the value, so the start value can come from other code with no initialization order problem between files. Each use is a function call, which the optimizer usually removes.

All three give the same problem: any file can change the counter. Recommendation: put the counter in one source file with internal linkage, and give the other files functions such as add_request() and request_count(). If a global variable is necessary, use an inline variable in C++17 and later. Source: cppreference, Static initialization order fiasco.

Q52

L4 · Senior Design header-file

You write a small library. Compare two designs: header-only (all definitions inline in headers) and a header with a separate source file. Talk about build time, the one definition rule, how a user adds the library, and what a change to a function body costs. Give a recommendation for a library of 50 small functions and for one of 20,000 lines.

Show answerHide answer to Q52

A strong answer compares the two designs:

  • Header-only: a user adds only one include path, and the compiler can inline each function. Risks: each source file that includes the header compiles all the bodies again, so builds become slower. A change to one body recompiles each file that includes the header. Each function must be inline, or the link fails (ex12).
  • Header and source file: the header has only declarations, so it is small and changes less often. A change to a body recompiles one source file. Risk: the user must also build and link the library, and the optimizer cannot inline across files without link-time optimization.

Recommendation: for 50 small functions, header-only is easy to use and the build cost is small. For 20,000 lines, use headers with declarations and source files, and keep only templates and very small functions in headers.

Q53

L4 · Senior Design namespace

Design the namespaces of a company library with the parts net, storage and log. Give the top namespace and the nested namespaces. Give a namespace for helpers that users must not call. Then give the rule for using in headers, and the rule for namespace aliases in source files.

Show answerHide answer to Q53

A strong answer gives a structure such as this one:

  1. Top namespace: one short, unique name for the company, for example acme. All library names go in it.
  2. Nested namespaces: one for each part, written in C++17 form: namespace acme::net, namespace acme::storage, namespace acme::log (ex22).
  3. Helpers: headers put helpers in acme::detail, which users must not call. Source files put helpers in an anonymous namespace (ex28).
  4. Headers: no using namespace and no using-declaration at namespace scope (ex25). Write qualified names such as std::string.
  5. Source files: a namespace alias, such as namespace net = acme::net;, and using-declarations in a function are acceptable, because they change only that file.

Q54

L4 · Senior Design anonymous-namespace

A source file has helper functions, a helper class and a constant that no other file uses. Compare three choices: an anonymous namespace, static on each function and variable, and a named namespace detail. Give a recommendation for a source file, and a different one for helpers that a header must hold.

Show answerHide answer to Q54

A strong answer compares the three choices:

  • Anonymous namespace: gives internal linkage to functions, variables and classes, with one block for all helpers (ex28, ex29). It is the C++ Core Guidelines advice, SF.22.
  • static: works for functions and variables, but not for a class. GCC rejects static struct Line { ... };, and Clang ignores static there with a warning (ex34). The keyword must be on each declaration.
  • Named namespace detail: the names keep external linkage, so two files can still clash, and the linker can still join them. Its advantage is for headers: each file sees the same helper, with no copy for each file.

Recommendation: in a source file, use an anonymous namespace. In a header, use a detail namespace with inline functions. An anonymous namespace in a header gives each source file its own copy (ex30, Guidelines SF.21). Source: C++ Core Guidelines, SF.21 and SF.22.

Part G: Interview questions

8 questions

Q55

L3 · Analyze Interview one-definition-rule

What is the one definition rule? What happens when a program breaks it?

Show answerHide answer to Q55

A strong answer has these parts:

  1. Main fact: each translation unit has at most one definition of an entity. The program has exactly one definition of each non-inline function and variable that it uses. Classes, inline functions and inline variables can have one definition in each translation unit, and all must be the same.
  2. Example: a function body in a header that two files include gives multiple definition of add_tax(int)'` from the linker (ex12).
  3. Limit: some violations have no diagnostic. Two different definitions of struct Item in two files build with no message and give undefined behavior (ex19).
  4. Follow-ups: "How do you find the silent case?" GCC -flto with -Wodr. "How do you correct a multiple definition?" inline, or the declaration in the header and the body in one source file.

Q56

L3 · Analyze Interview declaration-vs-definition

What is the difference between a declaration and a definition? Give an example for a function, a variable, a class and a static data member.

Show answerHide answer to Q56

A strong answer has these parts:

  1. Main fact: a declaration gives a name and its type. A definition also makes the object or gives the body. A name can have many declarations, but only one definition.
  2. Examples: function: int square(int); and int square(int v) { return v * v; }. Variable: extern int limit; and int limit = 10;. Class: struct Engine; (an incomplete type) and struct Engine { int horsepower; };. Static data member: static int created; in the class is a declaration, and int Counter::created = 0; or static inline int created = 0; is a definition (ex17, ex18).
  3. Limit: an incomplete type is enough for a pointer or a reference, but not for an object or a member (ex06, ex07).
  4. Follow-up: "Which error do you get for a missing definition?" The linker reports undefined reference (ex04).

Q57

L3 · Analyze Interview include-guard

Do you use include guards or #pragma once? Give the reasons.

Show answerHide answer to Q57

A strong answer has these parts:

  1. Main fact: both stop a second copy of a header in one translation unit. A guard is standard C++. #pragma once is not standard, but GCC, Clang and MSVC support it.
  2. Advantages of #pragma once: it is shorter, and no guard name can clash (ex11) or have a spelling mistake (Q27).
  3. Limit of #pragma once: Clang identifies a file by its path, and GCC by its content and modification time. If a project has two copies of one header in different folders, the preprocessor can include both copies (ex33). One guard name stops the second copy (ex32). Source: cppreference, Implementation defined behavior control.
  4. A good answer: follow the project rule. Many projects use #pragma once, and a project that must use only standard C++ uses guards with unique names, such as ACME_NET_CONFIG_H.
  5. Follow-up: "Does either one stop a multiple definition?" No. Both work only in one translation unit (ex12).

Q58

L4 · Senior Interview inline-variable

What does inline mean in modern C++? Is it a request for the optimizer?

Show answerHide answer to Q58

A strong answer has these parts:

  1. Main fact: inline lets the same definition be in many translation units. The linker keeps one copy (W in nm, ex13). For variables (C++17), it gives one object for the program (ex15).
  2. Optimizer: the optimizer decides about inline expansion with its own rules, with or without the keyword. The keyword has only a small effect on this decision.
  3. Limit: all definitions must be the same. Different inline definitions in two files are an ODR violation with no diagnostic.
  4. Follow-ups: "What about constexpr?" A constexpr function is implicitly inline, and a constexpr static data member too. A constexpr variable at namespace scope is not inline. It has internal linkage, so each file has a copy (ex16). Source: cppreference, inline specifier.

Q59

L3 · Analyze Interview namespace

Why do many teams not let you write using namespace std;? Where is it acceptable?

Show answerHide answer to Q59

A strong answer has these parts:

  1. Main fact: using namespace std; brings hundreds of names into the scope. A program name such as count or size can then become ambiguous (ex24, ex25).
  2. Worse in headers: the line goes into each file that includes the header, so other people get the errors (ex25).
  3. Future risk: a new standard adds names to std, so code that compiles today can fail later.
  4. Acceptable places: in a small .cpp file or a function body. A using-declaration, such as using std::cout;, brings only one name (ex23).
  5. Follow-up: "What about using namespace std::literals;?" It brings only the literal operators, such as "text"s, so the risk is small.

Q60

L4 · Senior Interview anonymous-namespace

What is the difference between static at namespace scope and an anonymous namespace? Which one do you use?

Show answerHide answer to Q60

A strong answer has these parts:

  1. Main fact: both give internal linkage. static works only for variables and functions. An anonymous namespace also works for classes and enumerations (ex29).
  2. Mechanism: each translation unit has its own anonymous namespace. GCC nm shows t (anonymous namespace)::scale(int) in each object file (ex28). From C++11, names in an anonymous namespace have internal linkage.
  3. Limit: an anonymous namespace in a header gives each source file its own copy (ex30). Use it only in source files.
  4. A good answer: an anonymous namespace for all helpers in a source file (C++ Core Guidelines SF.22).
  5. Follow-up: "Does static in a class mean the same thing?" No. A static data member is one object for the class, with external linkage (ex18).

Q61

L4 · Senior Interview namespace

What is argument-dependent lookup? Give one case where it helps and one case where it surprises you.

Show answerHide answer to Q61

A strong answer has these parts:

  1. Main fact: for an unqualified function call, the compiler also looks in the namespaces of the argument types.
  2. Helps: std::cout << text finds std::operator<< with no std::. print(tea) finds shop::print (ex26). The idiom using std::swap; swap(a, b); finds a swap in the namespace of the type when one exists.
  3. Surprises: a global print(const shop::Item&) and shop::print with the same parameter make the call ambiguous. GCC reports call of overloaded 'print(shop::Item&)' is ambiguous. A new function in a library namespace can also change which function a call selects.
  4. Follow-up: "How do you stop it?" Write a qualified name, such as ::print(tea) or shop::print(tea). Source: cppreference, Argument-dependent lookup.

Q62

L4 · Senior Interview header-file

Tell me, step by step, how a function body in a header gives multiple definition at link time. Which build step finds the error, and why not the compiler?

Show answerHide answer to Q62

A strong answer has these parts:

  1. Preprocessor: #include "tax.h" puts the body of add_tax into main.cpp and into cart.cpp. The include guard works only in one file at a time.
  2. Compiler: each source file has one definition, so each file compiles. Each object file gets a global symbol T add_tax(int) (ex12).
  3. Linker: the linker reads all object files and finds two strong symbols with one name. It reports multiple definition of add_tax(int)'; main.o ... first defined here`.
  4. Why not the compiler: the compiler sees one translation unit at a time. Only the linker sees all object files.
  5. Corrections: inline in the header (ex13), or the declaration in the header and the body in one source file (ex01).
