A

Part A: Concept checks

12 questions

Q1

L1 · Recall Short answer copy-constructor

Write the declarations of the copy constructor and the move constructor of a class T. Which one is usually noexcept?

Show answerHide answer to Q1

The move constructor is usually noexcept. It only takes pointers and sets the source to empty, so it cannot fail. The copy constructor allocates memory, so it can throw std::bad_alloc.

Q2

L2 · Apply Short answer copy-constructor

A class owns a heap block through a raw pointer. What is the difference between a shallow copy and a deep copy of this class? Which one does the implicit copy constructor make?

Show answerHide answer to Q2

A shallow copy copies the pointer. Then two objects point to one block, and both destructors delete it. A deep copy allocates a new block and copies the elements, so the two objects are independent (ex01). The implicit copy constructor copies each member, so for a raw pointer it makes a shallow copy (ex02).

Q3

L1 · Recall Short answer move-constructor

A class owns one heap block through int* value. Name the two steps of its move constructor.

Show answerHide answer to Q3
  1. Copy the pointer of the source into the new object.
  2. Set the pointer of the source to nullptr.

value{std::exchange(other.value, nullptr)} does the two steps in one expression (ex04). The constructor allocates nothing, so it takes constant time.

Q4

L2 · Apply Multiple choice move-constructor

When does the compiler declare an implicit move constructor for a class?

  • a) Always, for every class
  • b) Only when the class declares no copy constructor, copy assignment, move assignment or destructor
  • c) Only when all members are trivially copyable
Show answerHide answer to Q4

b) Only when the class declares no copy constructor, copy assignment, move assignment or destructor. A class with one of these gets no implicit move constructor, and a "move" then uses the copy constructor (ex19). Source: cppreference, move constructors, implicitly-declared move constructor.

Q5

L1 · Recall Short answer move-assignment

a and b are Box objects. Which special member function does each line call?

  • Box c = std::move(a);
  • b = std::move(a);
Show answerHide answer to Q5
  • Box c = std::move(a); calls the move constructor, because c is a new object.
  • b = std::move(a); calls the move assignment operator, because b exists before the line (ex04, ex06).

Q6

L2 · Apply Short answer move-assignment

Give one line of real code that can move an object to itself. Why does a programmer not see the self-move in this line?

Show answerHide answer to Q6

v[i] = std::move(v.back()); moves an object to itself when i is the last index. This line removes an element in constant time, and it is common in real code. The index comes from data at run time, so the code shows no self-move (ex07, ex08).

Q7

L1 · Recall Short answer moved-from-state

What does "valid but unspecified state" mean? Name three operations that are safe on a moved-from std::string.

Show answerHide answer to Q7

The object keeps its invariants, and each function behaves as its specification says. But you do not know the value. Source: cppreference, std::move, notes and the standard, [lib.types.movedfrom] and [defns.valid].

These operations are safe on a moved-from std::string:

  • the destructor
  • an assignment, such as s = "new"
  • a function with no precondition, such as s.clear(), s.size() or s.empty() (ex21)

Q8

L2 · Apply Multiple choice moved-from-state

Which standard type has a moved-from state that the standard specifies?

  • a) std::string: it is always empty
  • b) std::unique_ptr: its move constructor always leaves the source null
  • c) int: it is always 0
Show answerHide answer to Q8

b) std::unique_ptr: its move constructor always leaves the source null. The move constructor of std::unique_ptr has the postcondition u.get() == nullptr (ex22). A self-move-assignment is different: there the pointer stays unchanged ([unique.ptr.single.asgn]). Source: cppreference, std::unique_ptr constructors. The standard does not say that a moved-from std::string is empty. A move of an int copies the value, so the source keeps it (ex20).

Q9

L1 · Recall Short answer std-move

Which header declares std::move? Which type does std::move(name) give when name is a std::string variable?

Show answerHide answer to Q9

The header <utility> declares std::move. For a std::string variable name, std::move(name) gives std::string&& (ex14). The cast moves nothing.

Q10

L2 · Apply Multiple choice std-move

Widget has a copy constructor and a noexcept move constructor. The parameter w is const. Which constructor makes b?

  • a) The move constructor
  • b) The copy constructor
  • c) Neither, because the code does not compile
Show answerHide answer to Q10

b) The copy constructor. The parameter w is const, so std::move(w) gives const Widget&&. This type cannot bind to Widget&&, but it can bind to const Widget&, so overload resolution selects the copy constructor. This is the rule of ex16 with a const parameter in place of a const variable. The compilers give no warning. clang-tidy reports performance-move-const-arg. Do not make a parameter const if you move from it.

Q11

L1 · Recall Short answer copy-and-swap

The class T has a noexcept function swap(T&, T&). Write the declaration and the body of its copy-and-swap assignment operator.

Show answerHide answer to Q11

The parameter is a value. A copy constructor or a move constructor makes it, then the swap exchanges the contents (ex25, ex29).

Q12

L2 · Apply Short answer copy-and-swap

Which exception guarantee does copy-and-swap give? Define this guarantee in one sentence.

Show answerHide answer to Q12

The strong exception guarantee. If the operation throws an exception, the state of the program is the same as before the operation. For copy-and-swap, the copy is complete before the target changes (ex27).

10 questions

Q25

L2 · Apply Find the bug copy-constructor

This program must print 3 and stop with no error. ASan reports attempting double-free. Find the cause and give two corrections.

Show answerHide answer to Q25

Line 8, Counter b = a;. The cause is the class: it owns a block, but it uses the implicit copy constructor. The copy shares the pointer, so both destructors delete the same block (ex02).

Correction 1: write a copy constructor that makes a deep copy, Counter(const Counter& other) : count{new int{*other.count}} {}, and a matching copy assignment. Correction 2: use a value member, int count = 3;, or std::unique_ptr<int>. Then the compiler writes correct functions, or rejects the copy (ex24).

Q26

L4 · Senior Find the bug copy-constructor

The copy constructor must allocate an array of the same size as the source. Both compilers warn. Find the bug.

Show answerHide answer to Q26

Line 7. The constructor initializes the members in the order of their declaration, not in the order of the initializer list. The member data_ comes first, so new int[size_] reads size_ before it has a value. GCC: 'Buffer::size_' will be initialized after [-Wreorder] and '*this.Buffer::size_' is used uninitialized. Clang: field 'size_' will be initialized after field 'data_' [-Wreorder-ctor] and field 'size_' is uninitialized when used here.

Correction: use other.size_ in the allocation, data_{new int[other.size_]}, and write the initializers in declaration order. Source: cppreference, constructors and member initializer lists, initialization order.

Q27

L2 · Apply Find the bug move-constructor

After Box b = std::move(a);, only b must own the block. Find the bug.

Show answerHide answer to Q27

Line 4. The move constructor copies the pointer, but the source keeps it. So two objects own one block, and the second destructor deletes it again. Correction: value{std::exchange(other.value, nullptr)} (ex04).

Q28

L3 · Analyze Find the bug move-constructor

A std::vector<Row> holds one million rows. A profiler shows that each growth of the vector copies every row. Find the bug.

Show answerHide answer to Q28

Line 7. The move constructor has no noexcept. On growth, std::vector uses the same rule as std::move_if_noexcept, so it copies each Row (ex11). Correction: add noexcept, or write Row(Row&&) noexcept = default;. clang-tidy reports performance-noexcept-move-constructor.

Q29

L3 · Analyze Find the bug move-assignment

remove_at must remove the element at index i in constant time. The order of the elements is not important. A call with the last index fails under ASan with attempting double-free. Find the bug.

Show answerHide answer to Q29

Lines 7-11, the move assignment. When i is the last index, boxes[i] and boxes.back() are the same object. Line 8 deletes the block, and line 9 takes the same deleted pointer back (ex07). Then pop_back() runs the destructor, which deletes the block again. ASan: ERROR: AddressSanitizer: attempting double-free. Correction: add if (this != &other) around lines 8 and 9 (ex08), or use copy-and-swap (ex30).

Q30

L3 · Analyze Find the bug moved-from-state

The function must return {"x!", "x!!", "x!!!"}. Find the bug.

Q31

reset must make data empty. GCC and Clang warn. Find the bug.

Q33

Part D: Explain why

10 questions

Q35

L2 · Apply Explain why copy-constructor

auto second = owner; does not compile when owner is a std::unique_ptr<int> (ex24). Explain why. Answer in two or three sentences.

Show answerHide answer to Q35

The class std::unique_ptr deletes its copy constructor, because a std::unique_ptr must be the only owner of its object. A copy makes two owners. GCC: use of deleted function 'std::unique_ptr<...>::unique_ptr(const std::unique_ptr<...>&)'. Clang: call to deleted constructor (ex24). To give the ownership away, use std::move(owner).

Q36

L3 · Analyze Explain why copy-constructor

A copy of a std::vector<std::string> with 3 long strings makes 4 heap allocations. A move of the same vector makes 0 (ex03). Explain the two numbers. Answer in three sentences.

Show answerHide answer to Q36

The copy needs one new block for the elements of the vector. Each long string also needs its own new block, so 1 + 3 = 4. The move takes the block of the source vector, with the strings in it, so it allocates nothing (ex03). A short string fits in the small string buffer, so its copy allocates nothing.

Q37

L3 · Analyze Explain why move-constructor

std::vector copies its elements on growth when the move constructor is not noexcept, also when a move is available (ex11). Explain why the vector does this. Answer in three or four sentences.

Show answerHide answer to Q37

The functions push_back and emplace_back give the strong exception guarantee: if they throw, the vector does not change. On growth, the vector moves the old elements into a new block. If a move throws in the middle, the vector already moved some old elements, and a move back can also throw. So the vector cannot restore them.

The vector uses the same rule as std::move_if_noexcept: it copies when the move can throw and a copy constructor exists (ex11, ex13). The standard specifies this effect in [vector.modifiers], not a call to std::move_if_noexcept. Source: cppreference, std::vector::push_back.

Q38

L3 · Analyze Explain why move-constructor

In ex05, the moved object has the same block address as the source. The copy has a different address. Explain why. Answer in two or three sentences.

Show answerHide answer to Q38

The copy constructor allocates a new block with new int[other.size_] and copies 1000 elements. The move constructor takes the pointer of the source with std::exchange, so the new object owns the same block. The source gets nullptr and size 0 (ex05).

Q39

L3 · Analyze Explain why moved-from-state

Your class Buffer sets the source to empty after a move. Explain why the destructor and the assignment operators must accept an empty Buffer. Answer in two or three sentences.

Show answerHide answer to Q39

A moved-from object is still alive, so its destructor runs later. The program can also assign a new value to it (ex21). A destructor or an assignment that reads through the null pointer of an empty Buffer causes undefined behavior. The expression delete[] nullptr does nothing, so a destructor that calls it is safe.

Q40

L4 · Senior Explain why moved-from-state

The standard says that a moved-from std::string is in a "valid but unspecified state". Explain why the standard does not say "empty". Answer in three or four sentences.

Show answerHide answer to Q40

"Valid but unspecified" lets each implementation select the fastest move. In libstdc++, a long string moves its pointer, and the source becomes empty. A short string is in the small string buffer, so the move copies the characters. The standard does not force the implementation to clear the source after this copy. Source: [lib.types.movedfrom]/1 and cppreference, std::basic_string constructors.

Q41

L3 · Analyze Explain why std-move

std::move on a const object compiles with no warning, but it copies (ex16, ex17). Explain why. Answer in three sentences.

Show answerHide answer to Q41

std::move(a) on a const object gives const T&&. The move constructor takes T&&, and a const rvalue cannot bind to it. The copy constructor takes const T&, which binds to every value, so overload resolution selects it with no error (ex16, ex17).

Q42

L3 · Analyze Explain why std-move

After Point q = std::move(p);, p.x still holds 1 (ex20). Point is struct Point { int x; int y; };. Explain why. Answer in two sentences.

Show answerHide answer to Q42

Point is trivially copyable, so its implicit move constructor copies the bytes of each member. A move of an int cannot do more than a copy, so the source keeps its values (ex20).

Q43

L3 · Analyze Explain why copy-and-swap

In ex27, a throw during the implicit copy assignment leaves the target with the new name. Copy-and-swap leaves the old name. Explain the difference. Answer in three or four sentences.

Show answerHide answer to Q43

The implicit copy assignment assigns one member, then the next member. The name member gets the new value first. Then the copy of photo throws, so the target has a mix of new and old values (basic exception guarantee). Copy-and-swap copies the whole source into the parameter first. The copy throws before the body starts, so the target does not change (strong exception guarantee) (ex27).

Q44

L3 · Analyze Explain why copy-and-swap

A copy-and-swap assignment needs no self check (ex30). Explain why a = a; and a = std::move(a); keep the value of a. Answer in three sentences.

Show answerHide answer to Q44

For a = a;, the copy constructor makes a new block with the value of a before the swap. For a = std::move(a);, the move constructor moves the block of a into the parameter, and the swap gives it back. In both cases, the destructor of the parameter deletes only the block that a does not own (ex30).

Q50

Q51

Part F: Design and trade-offs

5 questions

Q52

L4 · Senior Design copy-and-swap

A Matrix class holds 1,000,000 double values in a heap block. A program assigns matrices of the same size many times in each second. Compare copy-and-swap with an in-place copy into the old block (ex28). Talk about allocations, exception safety and code size. Give a recommendation.

Show answerHide answer to Q52

A strong answer compares the two forms:

Form Allocations for each assignment Exception safety Code
Copy-and-swap 1 new block of 8 MB, 1 delete strong: a throw changes nothing short, it reuses the copy constructor
In-place copy when the sizes are equal 0 (ex28) basic: a throw can leave a part of the old values a second path for equal sizes

For a double copy, no element copy can throw, so the in-place copy cannot fail when the sizes are equal. Then the in-place copy keeps the strong exception guarantee in practice. Recommendation: use the in-place copy for equal sizes, and copy-and-swap for different sizes (ex28). Measure first: for small objects, the allocation is not important, and copy-and-swap is simpler.

Q53

L4 · Senior Design move-constructor

You must write a class that owns a block of int values. Compare two designs. Design (1) has a raw int* and the five special member functions. Design (2) has a std::vector<int> member and no special member functions (rule of zero). Talk about correctness, noexcept moves and the code that you must test. Give a recommendation.

Show answerHide answer to Q53

A strong answer compares correctness and cost:

  • Raw int* and five functions: you write and test the copy constructor, the copy assignment, the move constructor, the move assignment and the destructor. Each one can have a bug: a shallow copy (ex02), a self-move (ex07), a missing noexcept (ex11). You control every detail.
  • std::vector<int> member (rule of zero): the compiler writes all five functions, and they are correct. The vector move is noexcept (ex13), so a std::vector of your class moves on growth. The cost is one more size_t for the capacity.

Recommendation: use the rule of zero. Write the five functions only for a new resource type, such as a file handle (Q50). Keep that class small.

Q54

L4 · Senior Design moved-from-state

Your class Connection has the invariant "the socket is always open". A move must not allocate and must not open a socket. Compare two designs for the moved-from state. Design (1) has an "empty" state that breaks the old invariant. Design (2) has no move constructor, so a "move" copies. Give a recommendation.

Show answerHide answer to Q54

A strong answer names the conflict: a cheap move takes the socket, so the source has no socket.

  • (1) An "empty" state: the move is cheap and noexcept. But the invariant changes to "open or empty", and each function must check it or document a precondition. The destructor and the assignment must accept the empty state.
  • (2) No move: the invariant stays. But a "move" copies, and a copy of a connection is often impossible or expensive. std::vector<Connection> then copies on growth, or it does not compile.

Recommendation: usually (1), with a clear precondition: "do not call send() on a moved-from Connection". std::unique_ptr uses this model: a moved-from std::unique_ptr is null (ex22). Another option is to hold the class in std::unique_ptr<Connection>. Then the class keeps its invariant, and the pointer moves.

Q55

L4 · Senior Design std-move

A setter stores a std::string in a member. Compare three designs. Design (1) is set_name(const std::string&). Design (2) has two overloads, const std::string& and std::string&&. Design (3) is set_name(std::string) by value, with name_ = std::move(n);.

Count the copies and the moves for an lvalue and for a temporary argument. Give a recommendation.

Show answerHide answer to Q55

A strong answer counts the operations:

Design Lvalue argument Temporary argument
(1) const std::string& 1 copy assignment 1 copy assignment
(2) two overloads 1 copy assignment 1 move assignment
(3) by value, then std::move 1 copy constructor + 1 move assignment 1 move assignment

Design (1) copies a temporary, which wastes the temporary. Design (2) is the fastest, but it needs two functions, and for N parameters it needs 2^N overloads. Design (3) needs one function and adds only one cheap move.

But the copy constructor in design (3) always makes a new string. A copy assignment into name_ can use the old capacity of name_. A counter of allocations shows the difference for a second call with the same long lvalue. Design (1) makes 0 allocations, and design (3) makes 1 allocation (ex31, with libstdc++). Recommendation: use (3) for a constructor or a setter that stores the value. Use (2) for a hot setter that the program calls often with lvalues.

Q56

L4 · Senior Design move-assignment

Compare three forms of move assignment for a buffer class. Form (1) does a self check, then a delete, then it takes the pointer. Form (2) swaps with the source, so the source destructor deletes the old block. Form (3) is copy-and-swap with a by-value parameter.

Talk about self-moves, the time when each form releases the old block, and the overload set. Give a recommendation.

Show answerHide answer to Q56

A strong answer compares the three forms:

Form Self-move When the old block goes Overload set
(1) check, delete, take safe with the check (ex08) immediately copy assignment + move assignment
(2) swap with the source safe with no check when the source dies or gets a new value copy assignment + move assignment
(3) copy-and-swap safe with no check (ex30) at the end of the operator, with the parameter one operator; do not add operator=(T&&) (ex26)

Form (2) keeps the old resource alive in the source, which can surprise a caller for a lock or a file. Form (3) needs one more move constructor call for each move assignment. Recommendation: use (1) for a class that must release its resource at once. Use (3) when the strong exception guarantee for the copy is important and the extra move is cheap.

Part G: Interview questions

7 questions

Q57

L3 · Analyze Interview std-move

"What does std::move do? Does it move anything?"

Show answerHide answer to Q57

A strong answer:

  1. std::move is a cast to an rvalue reference: static_cast<std::remove_reference_t<T>&&>(x). It moves nothing (ex14).
  2. The move occurs in the constructor or the assignment that gets the rvalue. A statement std::move(x); alone has no effect, and GCC and Clang warn (ex15).
  3. Limit: the name says "move", but the result depends on the overloads of the type, for example a const object copies (ex16).
  4. Follow-up: "What is the state of x after the move?" Valid but unspecified for standard types, null for std::unique_ptr (ex22).

Q58

L4 · Senior Interview std-move

"When is a move not a move? Give as many cases as you can."

Show answerHide answer to Q58

A strong answer lists the cases and a tool for each one:

  1. A const source: const T&& binds to the copy constructor (ex16, ex17). clang-tidy: performance-move-const-arg.
  2. A class with a user copy constructor or a destructor and no move constructor: the compiler declares no move (ex19, Q16).
  3. A const member: the implicit move copies that member (ex18).
  4. A user move constructor without std::move on a member (ex10).
  5. A move constructor without noexcept in std::vector growth: the rule of std::move_if_noexcept selects the copy (ex11).
  6. A trivially copyable type: the move copies the bytes, and the source keeps its values (ex20).

Follow-up: "How do you find these cases?" A tracing class in a test, a counter of allocations (ex03), and clang-tidy.

Q59

L3 · Analyze Interview move-constructor

"Why must a move constructor be noexcept? What occurs if it is not?"

Show answerHide answer to Q59

A strong answer:

  1. std::vector growth and other code with the strong exception guarantee use the rule of std::move_if_noexcept. They move only when the move cannot throw, or when there is no copy constructor (ex13).
  2. Without noexcept, the vector copies each element on growth (ex11). For a move-only type, it moves anyway and loses the strong exception guarantee (quiz item q34).
  3. Check: std::is_nothrow_move_constructible_v<T>. It is true for std::string and std::vector (ex13).
  4. Follow-up: "Can a move constructor throw?" Yes, if it must allocate memory. Then the vector copies, or a move-only type loses the strong exception guarantee.

Q60

L3 · Analyze Interview moved-from-state

"What can you do with an object after a move? What must you not do?"

Show answerHide answer to Q60

A strong answer:

  1. Safe: destroy it, assign a new value to it, and call functions with no precondition, such as clear(), size() and empty() (ex21).
  2. Not safe: read the old value, or call a function with a precondition, such as back() on a string. For a std::unique_ptr, a read through the pointer is a null pointer read: UBSan reports reference binding to null pointer (ex23).
  3. Tool: clang-tidy bugprone-use-after-move reports 'score' used after it was moved (ex23).
  4. Follow-up: "Is a moved-from std::string empty?" The standard does not say so. Do not depend on it.

Q61

L4 · Senior Interview copy-and-swap

"Explain the copy-and-swap idiom. What does it give you, and what does it cost?"

Show answerHide answer to Q61

A strong answer:

  1. The operator takes its parameter by value, swaps the members with *this and returns *this (ex25). The destructor of the parameter deletes the old resource.
  2. Gains: one operator for copy and move assignment, the strong exception guarantee (ex27), and safe self-assignment with no check (ex30).
  3. Costs: a copy assignment always allocates, also when the old block has the correct size (ex28: 1 allocation against 0). A move assignment does one extra move constructor call.
  4. Follow-ups: "What if I also write operator=(T&&)?" The call is ambiguous (ex26). "Can I use std::swap(*this, other)?" No, it calls the operator again (Q33).

Q62

L4 · Senior Interview copy-constructor

"Your class holds an owning raw pointer and uses the implicit copy constructor. What goes wrong? Give three ways to correct it."

Show answerHide answer to Q62

A strong answer:

  1. The implicit copy constructor copies the pointer. Two objects own one block, and both destructors delete it: ASan reports attempting double-free (ex02). A write through one copy also changes the other copy.
  2. Correction 1: write a deep copy constructor and copy assignment (ex01, rule of three or rule of five).
  3. Correction 2: delete the copy operations and write moves. The type becomes move-only, as std::unique_ptr (ex24).
  4. Correction 3: replace the raw pointer with std::vector, std::string or std::unique_ptr, and write no special member functions (rule of zero).
  5. Follow-up: "What about the implicit copy assignment?" It has the same bug, and it also leaks the old block of the target.

Q63

L4 · Senior Interview move-assignment

"Can a standard library object move to itself? What must your own move assignment do for a = std::move(a)?"

Show answerHide answer to Q63

A strong answer:

  1. Yes. The standard allows a self-move of a standard library object. The object is then in a valid but unspecified state ([lib.types.movedfrom]/2).
  2. Your own class must stay valid after a self-move: no crash, no leak. A move assignment with no self check deletes its own block and reads it later: ASan reports heap-use-after-free (ex07).
  3. Two corrections: a self check if (this != &other) keeps the value (ex08), and copy-and-swap is safe with no check (ex30).
  4. Follow-up: "Does a self-move occur in real code?" Yes: v[i] = std::move(v.back()); when i is the last index.
