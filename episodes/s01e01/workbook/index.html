Part A: Concept checks

Q1

L1 · Recall Short answer raii

What does RAII stand for? In one sentence each, tell what the constructor and the destructor of an RAII class do.

Show answerHide answer to Q1

RAII is Resource Acquisition Is Initialization.

  • The constructor acquires the resource. If it cannot, it throws, so no object exists without its resource.
  • The destructor releases the resource. C++ calls it at each exit from the scope of the object.

ex01 writes acquire file, acquire lock, work, release lock, release file. Source: cppreference, RAII.

Q4

L1 · Recall Short answer resource-ownership

What is the owner of a resource? Why does a raw pointer T* not show the owner?

Show answerHide answer to Q4

The owner is the one object that must release the resource. A raw T* has no destructor that deletes, and its type does not tell if the code must delete the object. The C++ Core Guidelines (R.3, I.11) use a raw T* only for pointers that do not own. Use std::unique_ptr<T> or a container to show the owner.

Q5

L1 · Recall Short answer rule-of-three

State the rule of three. Name the usual type of member that makes a class need it.

Show answerHide answer to Q5

A class that needs a user-defined destructor, copy constructor or copy assignment almost always needs all three. The usual reason is a member that is a raw handle to a resource. Examples are an int* from new[], a std::FILE* and a file descriptor. The implicit copy copies the handle, not the resource (ex16). Source: cppreference, The rule of three/five/zero.

Q6

L1 · Recall Short answer rule-of-five

State the rule of five. Which two functions does it add to the rule of three, and which C++ standard added them?

Show answerHide answer to Q6

A class that declares one of the destructor, the copy operations or the move operations must declare all five. The rule adds the move constructor and the move assignment, which C++11 added. The reason: a user-declared destructor or copy operation stops the implicit move operations (ex14), so the class must declare them to keep fast moves.

Q7

L1 · Recall Short answer rule-of-zero

State the rule of zero. Name three standard library types that let a class obey it.

Show answerHide answer to Q7

A class that does not manage a resource directly declares none of the five special member functions. Its members own the resources, and the implicit functions copy, move and destroy each member correctly. Types: std::string, std::vector, std::unique_ptr (ex24, ex25). Source: C++ Core Guidelines, rule C.20.

Q8

L2 · Apply Multiple choice special-member-functions

When does the compiler declare an implicit move constructor for a class?

  • a) Always, also when the class has a user-declared destructor
  • b) Only when all the members of the class have a move constructor
  • c) Only when the class has no user-declared copy constructor, copy assignment, move assignment or destructor
Show answerHide answer to Q8

c). The compiler declares the move constructor only if the class has no user-declared copy constructor, copy assignment, move assignment or destructor ([class.copy.ctor]/8). A declaration with = default is also user-declared (ex14). Choice b) is wrong: the rule looks only at the functions that the class itself declares.

Q9

L2 · Apply Multiple choice raii

A function constructs the local objects a, b and c in this order. In which order does C++ destroy them at the end of the function?

  • a) a, b, c
  • b) c, b, a
  • c) The order is unspecified.
Show answerHide answer to Q9

b) c, b, a. C++ destroys the objects of one scope in the reverse order of construction (ex01). Then an object can use the objects that it got before it, also in its destructor.

Q10

L2 · Apply Multiple choice rule-of-five

Why do you mark a move constructor noexcept?

  • a) Without noexcept, the compiler does not use the move constructor in any expression.
  • b) If a copy constructor exists, std::vector uses the move constructor on growth only if it is noexcept.
  • c) noexcept makes the code in the move constructor faster.
Show answerHide answer to Q10

b). std::vector uses std::move_if_noexcept on growth. It moves an element only if the move constructor is noexcept or if the class has no copy constructor (ex21, ex32). Choice a) is wrong: a move constructor without noexcept still works in T b = std::move(a);. Choice c) is wrong: noexcept does not change the code in the function.

Q11

L2 · Apply Short answer special-member-functions

Does S s; compile for struct S { S(const S&) = default; };? Give the rule.

Show answerHide answer to Q11

No. The copy constructor is a user-declared constructor, and each user-declared constructor stops the implicit default constructor ([class.default.ctor]/1). Add S() = default; to get it back. ex10 shows the same rule with a different constructor.

Q12

L2 · Apply Multiple choice resource-ownership

a is a std::unique_ptr<int> that owns an int. What is the value of a after auto b = std::move(a);?

  • a) a still points to the same int.
  • b) a is null.
  • c) The value of a is unspecified.
Show answerHide answer to Q12

b) a is null. A move of a std::unique_ptr transfers the ownership and makes the source null. The standard gives this guarantee for std::unique_ptr. For most other library types, a moved-from object is only in a "valid but unspecified" state (S01E02).

Q26

L3 · Analyze Find the bug raii

LogFile must report a failed close. A test that makes std::fclose fail stops the program with terminate called after throwing an instance of 'std::runtime_error'. Find the bug and give the correction.

Show answerHide answer to Q26

Line 11: the destructor throws. A destructor is noexcept by default, so the throw calls std::terminate ([except.spec], ex30). GCC warns 'throw' will always call 'terminate' [-Wterminate], and Clang warns '~LogFile' has a non-throwing exception specification but can still throw [-Wexceptions]. Correction: add void close(), which calls std::fclose, sets file_ to nullptr and throws on an error. The destructor calls std::fclose only if file_ is not null and ignores the result.

Part D: Explain why

9 questions

Q34

L2 · Apply Explain why raii

ex03 leaks 1024 bytes when check throws, but ex04 does not leak. Explain why. Answer in two sentences.

Show answerHide answer to Q34

In ex03, the owner of the array is a raw int*, and the throw skips delete[], so LeakSanitizer reports 1024 bytes (256 int values). In ex04, a std::vector owns the array, and stack unwinding runs its destructor, which frees the memory.

Q35

L3 · Analyze Explain why raii

Explain why RAII makes code exception safe with no try and catch blocks for cleanup. Answer in three sentences.

Show answerHide answer to Q35

The rule: when an exception leaves a scope, stack unwinding destroys each complete local object of that scope before the handler starts ([except.ctor]). An RAII object releases its resource in its destructor, so the release occurs on the exception path as on the normal path. Thus the code needs no try and catch blocks for cleanup, and a later change cannot add a path that skips the release (ex02, ex05).

Q36

L3 · Analyze Explain why raii

In ex30, the destructor of Connection throws, and the catch block in main does not catch the exception. Explain why the program stops with terminate called after throwing an instance of 'std::runtime_error'.

Show answerHide answer to Q36

A destructor is implicitly noexcept, unless a member or a base has a destructor that can throw ([except.spec]/8). When an exception leaves a noexcept function, C++ calls std::terminate ([except.terminate]), so no handler gets the exception. The catch block in main cannot get the exception, because std::terminate stops the program first.

Q37

L3 · Analyze Explain why special-member-functions

In ex12, Widget b = std::move(a); calls the copy constructor of Tracer, and the compiler gives no error and no warning. Explain why. Name the two rules.

Show answerHide answer to Q37

Rule 1: a user-declared destructor, also an empty one, stops the implicit move constructor ([class.copy.ctor]/8). Rule 2: the copy constructor takes const Widget&, and a const lvalue reference binds to the rvalue std::move(a). So overload resolution finds a usable function, the code compiles, and the program copies each member. The implicit copy is only deprecated ([depr.impldec]), so GCC and Clang warn only with -Wdeprecated-copy-dtor or -Wdeprecated.

Q38

L3 · Analyze Explain why special-member-functions

A user-declared move constructor makes the implicit copy constructor deleted. Explain why this rule protects the class. Answer in two sentences.

Show answerHide answer to Q38

A class with a user-declared move constructor usually manages a resource in a special way. An implicit copy of each member is then almost always wrong, for example a copy of an owning pointer. Thus C++ deletes the implicit copy, and the error shows at compile time (ex11).

Q39

L2 · Apply Explain why rule-of-three

In ex16, Buffer has only a constructor and a destructor. Explain why Buffer b = a; makes the program delete one array twice.

Show answerHide answer to Q39

The implicit copy constructor copies each member, so b.data_ gets the same address as a.data_. At the end of main, the destructor of b deletes the array, then the destructor of a deletes it again. This is undefined behavior, and AddressSanitizer reports attempting double-free (ex16).

Q40

L3 · Analyze Explain why rule-of-five

Explain why the move constructor of FileHandle in ex19 must set other.file_ to nullptr. Tell what goes wrong without it.

Show answerHide answer to Q40

After the move, other still exists, and its destructor runs later. If other.file_ keeps the pointer, two objects own one FILE*, and both destructors call std::fclose on it: a double close, which is undefined behavior. With nullptr, the destructor of other sees an empty handle and does nothing (ex20 shows the same bug with an array).

Q41

L3 · Analyze Explain why rule-of-five

In ex21, the class Risky has a move constructor, but std::vector<Risky> copies the elements when it grows. Explain why.

Show answerHide answer to Q41

On growth, std::vector gives the strong exception guarantee: if the growth fails, the old elements are unchanged. A move that throws in the middle leaves some old elements moved-from, and the vector cannot restore them. Thus std::vector uses std::move_if_noexcept. It selects the copy constructor if the move constructor is not noexcept and a copy constructor exists. ex21 writes copies 2, moves 0 for Risky.

Q42

L3 · Analyze Explain why resource-ownership

ex28 leaks when the second new in the constructor of Engine throws. ex29 does not leak in the same case. Explain why. Name the rule about a constructor that throws.

Show answerHide answer to Q42

Rule: if a constructor throws, C++ destroys the members that are complete, but the destructor of the object does not run ([except.ctor]/3). In ex28, first_ is a raw pointer, so its destruction deletes nothing, and ~Engine does not run, so the first Part leaks (256 bytes). In ex29, first_ is a std::unique_ptr, and its destructor deletes the first Part (destroyed first).

Part F: Design and trade-offs

5 questions

Q50

L4 · Senior Design rule-of-zero

A Document class keeps a title, a list of pages and an open log file (std::FILE*). Compare three designs:

  1. raw members and the five special member functions in Document
  2. a std::unique_ptr<std::FILE, FileCloser> member and the rule of zero
  3. a std::shared_ptr<std::FILE> member

Give one risk of each design and a recommendation.

Show answerHide answer to Q50

Structure of a strong answer:

  1. Raw members and five functions in Document: all the code in one class, but each function must handle the file and the copy rules. A small error gives a leak or a double close (ex16, ex20).
  2. std::unique_ptr<std::FILE, FileCloser> and the rule of zero: no special members, a noexcept move, and no copy (ex25, ex27). A copy of a Document does not compile, which is correct for one open file.
  3. std::shared_ptr<std::FILE> with a deleter: copies compile and share the file, and the last owner closes it. It costs an atomic reference count, and two copies then write to one file, which is often a surprise.

Recommendation: design 2. Use design 3 only if the program must share the file on purpose.

Q51

L4 · Senior Design rule-of-five

Must a FileHandle copy? Compare three designs:

  1. deleted copy operations
  2. a copy that opens the same path again
  3. a copy that shares the file through a reference count

Tell what each design means for two writes through two copies. Give a recommendation.

Show answerHide answer to Q51

Structure of a strong answer:

  1. Deleted copy (ex19, ex22): one owner and one close. Two writes go through the one owner. The class is move-only, and it still works in a std::vector.
  2. Open the path again: two independent streams with two file positions. Two writes can overwrite each other, the path can change between the opens, and a temporary file has no path.
  3. Shared with a reference count: one stream, one position, and the last owner closes it. It costs a counter, and the ownership is less clear.

Recommendation: deleted copy, as std::fstream and std::unique_ptr do. If a program must share the file, use std::shared_ptr<FileHandle> at that place.

Q52

L4 · Senior Design raii

The release of a resource can fail, for example std::fclose or a database commit. Compare three designs:

  1. the destructor throws
  2. the destructor ignores the error
  3. a close() function that reports the error, and a destructor that releases silently if the caller did not call close()

Give a recommendation.

Show answerHide answer to Q52

Structure of a strong answer:

  1. Throw from the destructor: needs noexcept(false), and a throw during stack unwinding calls std::terminate (ex30, [except.terminate]). Containers also expect destructors that do not throw.
  2. Ignore the error: safe, but data loss is silent, for example a buffered write that std::fclose cannot flush.
  3. close() and a silent destructor: the caller sees the error on the normal path, and the destructor still releases on the exception path. The function std::fstream::close uses this design: it sets failbit on an error.

Recommendation: design 3. The destructor can also log an error that it ignores.

Q53

L4 · Senior Design rule-of-three

An old C++98 class Record owns a char* with the rule of three. Profiles show slow std::vector<Record> growth. Compare three changes:

  1. add a move constructor and a move assignment (rule of five)
  2. replace the char* with a std::string and remove the three functions (rule of zero)
  3. delete the copy operations

Give a recommendation.

Show answerHide answer to Q53

Structure of a strong answer:

  1. Add the moves (rule of five): fast growth if the moves are noexcept. Five functions to keep correct by hand, with a raw char*.
  2. std::string and the rule of zero: correct copies and noexcept moves with no code. The class gets small-string optimization too. Each place that uses the raw char* must change.
  3. Delete the copy: the code that copies Record no longer compiles. Without moves, std::vector<Record>::push_back does not compile.

Recommendation: design 2. Use design 1 only if the raw buffer is necessary, for example for a C interface.

Q54

L4 · Senior Design resource-ownership

A function store must keep a file open after it returns. Compare three parameter types:

  1. FileHandle by value
  2. FileHandle&
  3. std::FILE*

For each type, tell who owns the file after the call. Give a recommendation.

Show answerHide answer to Q54

Structure of a strong answer:

  1. FileHandle by value (a sink parameter): store owns the file after the call. The caller must write store(std::move(h)), which shows the transfer in the code.
  2. FileHandle&: the caller still owns the file. If store keeps the reference, it dangles when the caller's handle ends. If store moves from it, the caller's object becomes empty with no sign at the call site.
  3. std::FILE*: the type does not show the owner. Two owners can close the file, or nobody closes it.

Recommendation: design 1. It follows the C++ Core Guidelines, rule R.32: take a std::unique_ptr<T> or a move-only owner by value to show that the function takes the ownership.

Q55

L3 · Analyze Interview raii

"What is RAII? Give an example from the standard library."

Show answerHide answer to Q55

Structure of a strong answer:

  1. Main fact: RAII ties a resource to the lifetime of an object. The constructor acquires it, and the destructor releases it on each exit from the scope.
  2. Example: std::scoped_lock unlocks the mutex at the end of the scope, also after a throw (ex05). std::vector frees its elements (ex04).
  3. Limit: RAII works for objects with automatic storage or with an owner. A new without an owner, or a call to std::exit, skips the destructors.
  4. Follow-up: "Is RAII slower than manual cleanup?" No. The destructor call is the same code as a correct manual release, and the compiler often inlines it.

Q56

L4 · Senior Interview raii

"How does RAII make code exception safe? And what happens when a constructor throws in the middle of the member initializers?"

Show answerHide answer to Q56

Structure of a strong answer:

  1. Main fact: stack unwinding destroys each complete local object before the handler starts, so RAII releases each resource on the exception path (ex02, ex07).
  2. Constructor that throws: C++ destroys the complete members and base classes in reverse order, but the destructor of the object does not run ([except.ctor]/3). Thus each member must own its own resource (ex28 leaks, ex29 does not).
  3. Limit: the release must not throw. A throw from a destructor calls std::terminate (ex30).
  4. Follow-up: "Which exception guarantees do you know?" Basic (no leak, valid state), strong (no change on failure, as in copy-and-swap) and nothrow (moves, destructors, swap).

Q57

L3 · Analyze Interview special-member-functions

"Which special member functions does the compiler declare for a class, and when does it not declare them?"

Show answerHide answer to Q57

Structure of a strong answer:

  1. Main fact: the six are the default constructor, the destructor, the copy constructor, the copy assignment, the move constructor and the move assignment.
  2. Rules: no default constructor if the class declares any constructor. No implicit moves if the class declares a destructor or a copy operation. A user-declared move deletes the implicit copy. The implicit copy in a class with a user-declared destructor or copy is deprecated.
  3. Example: ex09 and ex14 show the rules with type traits and with a trace.
  4. Follow-up: "Is = default user-declared?" Yes. ~T() = default; stops the moves in the same way as ~T() {} (ex14).

Q58

L4 · Senior Interview special-member-functions

"A colleague adds ~Order() {} to a class with a std::vector member to set a breakpoint. The service becomes slower. Why?"

Show answerHide answer to Q58

Structure of a strong answer:

  1. Main fact: the user-declared destructor stops the implicit move operations ([class.copy.ctor]/8). Each move of an Order now copies the vector (ex12).
  2. Cost: std::vector<Order> growth, return of a local Order that the compiler cannot elide, and std::swap now copy heap memory. The code compiles with no warning in -Wall -Wextra.
  3. Correction: remove the destructor, or add = default for the four copy and move functions. -Wdeprecated-copy-dtor (GCC) or -Wdeprecated (Clang) shows the problem.
  4. Follow-up: "How do you prove it?" A static_assert(std::is_nothrow_move_constructible_v<Order>); in the code, or a trace as in ex13.

Q59

L3 · Analyze Interview rule-of-three

"What is the rule of three? Show a bug that occurs when a class does not obey it."

Show answerHide answer to Q59

Structure of a strong answer:

  1. Main fact: a class that needs a user-defined destructor, copy constructor or copy assignment almost always needs all three.
  2. Bug: a class with an int* and only a destructor. Buffer b = a; copies the pointer, and both destructors delete one array: AddressSanitizer attempting double-free (ex16). The "two of three" form leaks and double-deletes on b = a; (ex18).
  3. Correction: a deep copy constructor and a copy-and-swap assignment (ex17), or = delete, or the rule of zero.
  4. Follow-up: "And in C++11?" The rule of five adds the two moves, because the user destructor stops the implicit moves.

Q60

L4 · Senior Interview rule-of-five

"Write a move constructor and a move assignment for a class that owns a raw pointer. Why do you mark them noexcept?"

Show answerHide answer to Q60

Structure of a strong answer:

  1. Code: the move constructor takes the pointer with std::exchange(other.ptr_, nullptr). The move assignment checks this != &other, deletes its old resource, and then takes the pointer (ex19, quiz q34).
  2. Why noexcept: std::vector and other containers use std::move_if_noexcept, so a move without noexcept makes them copy (ex21). A move that only copies pointers cannot fail, so noexcept is true.
  3. Limit: the moved-from object must stay destructible and assignable. Here it is empty.
  4. Follow-up: "Can the move assignment use swap?" Yes: construct a local object from other and swap with it (workbook Q48). This also handles a self-move.

Q61

L4 · Senior Interview rule-of-zero

"What is the rule of zero? When can you not use it?"

Show answerHide answer to Q61

Structure of a strong answer:

  1. Main fact: a class that does not manage a resource directly declares none of the five special member functions. Its members do the work (C++ Core Guidelines, rule C.20).
  2. Example: std::string, std::vector and std::unique_ptr<std::FILE, FileCloser> members give correct copies, moves and destruction (ex24, ex25).
  3. When you cannot use it: in the one small class that wraps a raw resource with no library owner (a socket, a GPU handle). That class uses the rule of five. A polymorphic base also needs a virtual destructor, so it uses the five = default declarations.
  4. Follow-up: "Does the rule of zero cost speed?" No. The implicit functions are as fast as hand-written ones, and they are noexcept when the members are.

Q62

L4 · Senior Interview resource-ownership

"How do you show ownership in a function signature? Compare std::unique_ptr<T>, T* and T& as parameters and as return types."

Show answerHide answer to Q62

Structure of a strong answer:

  1. std::unique_ptr<T> by value as a parameter: the function takes the ownership (a sink). As a return type: the caller gets the ownership, as with a factory function.
  2. T*: no ownership. Use it for an optional object that the function only uses. A nullptr means "no object".
  3. T&: no ownership and never null. Use it as the default for a parameter that the function only uses.
  4. Follow-up: "And std::shared_ptr<T>?" Use it only when two or more owners share the object on purpose. Pass a const std::shared_ptr<T>& or a T& when the function does not keep a copy (C++ Core Guidelines R.30-R.36).
