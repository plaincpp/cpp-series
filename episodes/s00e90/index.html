Question 4 of 45 L1 · Recall build-steps

Put in order: You build with g++ main.cpp area.cpp -o app. Put the steps in the order that they occur for main.cpp.

Drag the handle, or use the arrow buttons. With a row focused, press Alt + Up or Alt + Down.

  1. The preprocessor pastes the text of area.h into main.cpp
  2. The linker joins main.o and area.o and finds the definition of area
  3. The compiler makes the object file main.o from the translation unit
  4. You run ./app, and it prints 12

The preprocessor runs first and pastes each #include. The compiler makes one object file for each translation unit. The linker joins the object files into the executable (ex04).

Question 5 of 45 L3 · Analyze build-steps

Choose one: A CMakeLists.txt has add_library(geometry STATIC geometry.cpp) and add_executable(app main.cpp). The build stops with undefined reference to `geometry::area(int, int)'. Which line after add_executable corrects the build?

CMake compiles geometry.cpp into the library, but the link step of app does not use the library. So the linker stops, as in ex03. target_link_libraries adds the library to the link step of app (S00E22).

Question 7 of 45 L3 · Analyze build-steps

True or false: larger.h declares the function template larger. larger.cpp has only the body of the template. main.cpp calls larger(3, 4). The build links.

The compiler makes larger<int> only in a file that sees the body and uses larger<int>. main.cpp sees only the declaration. larger.cpp does not use larger<int>. So the linker writes undefined reference to `int larger<int>(int, int)' (ex05).

False. Put the template body in the header. An explicit instantiation in larger.cpp, such as template int larger<int>(int, int);, is a second correction for a fixed list of types (workbook Q59).

Question 8 of 45 L2 · Apply build-steps

Choose one: shape.h defines struct Shape { int width; }; and has no include guard. main.cpp includes shape.h and area.h, and area.h also includes shape.h. What occurs when you compile main.cpp?

The preprocessor pastes shape.h two times into one translation unit, so the compiler sees two definitions of Shape. An include guard (#pragma once, or #ifndef with #define) skips the second copy. It does not stop a function definition in two translation units (q02, S00E12).

Question 13 of 45 L3 · Analyze references-pointers

Choose one: int scores[5]{1, 2, 3, 4, 5}; and void show(int values[5]) { std::cout << sizeof(values); }. What does show(scores) print on x86-64 Linux?

An array parameter is a pointer: in the call, the array decays to int*. So sizeof(values) gives the size of int*. GCC and Clang warn with -Wsizeof-array-argument. Pass the size as a second parameter, or use std::array<int, 5> (S00E08).

Question 14 of 45 L4 · Senior types-expressions-basics

Choose one: Many loops compare an int index with values.size(). Which test is correct for each value of index, and also for -1?

std::cmp_less (C++20) compares the mathematical values, so -1 is less than each size (ex08). A cast of -1 to std::size_t gives a very large value. A cast of the size to int works for small vectors, but it changes the value of a size larger than INT_MAX.

Question 16 of 45 L1 · Recall references-pointers

True or false: After its initialization, a reference can refer to a different object.

Question 18 of 45 L2 · Apply references-pointers

Choose one: A function reads a large std::string and does not change it. Which parameter is the best choice?

const std::string& reads the caller's string with no copy, and the compiler stops a change. A value parameter copies the string. A non-const reference does not accept a temporary such as "hi". A pointer can be nullptr.

Question 19 of 45 L3 · Analyze references-pointers

A std::map keeps each element in its own node. An insert does not move the other elements, so no reference becomes invalid (cppreference: std::map::insert).

True. A std::vector is different: push_back can move all the elements and make each reference invalid (ex01).

Question 22 of 45 L3 · Analyze classes-basics
