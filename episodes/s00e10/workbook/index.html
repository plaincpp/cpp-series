A

Part A: Concept checks

12 questions

Q1

L1 · Recall Short answer constructor

What is a constructor? Give three facts about its declaration and about the time when it runs.

Show answerHide answer to Q1

A constructor is a special member function that makes an object valid (ex01, ex02):

  1. It has the name of the class.
  2. It has no return type, not even void.
  3. It runs when C++ makes the object, before any other code can use the object.

A constructor can have parameters, and a class can have more than one constructor.

Q2

L1 · Recall Short answer member-initializer-list

Point has two private int members, x_ and y_. Write the constructor Point(int x, int y) with a member initializer list. Where in the constructor does the list go?

Show answerHide answer to Q2

The list starts with : after the parameter list and comes before the body (ex04). It initializes each member before the body runs. Write the entries in the order of the member declarations.

Q3

L1 · Recall Short answer default-constructor

What is a default constructor? Clock declares only the constructor Clock(int h = 0). Is this constructor a default constructor? Explain.

Show answerHide answer to Q3

A default constructor is a constructor that you can call with no arguments. So Clock(int h = 0) is a default constructor. When the caller gives no argument, the default argument gives the value. The declaration Clock c; compiles and calls it with h equal to 0. A Docker run on GCC 14 and Clang 19 writes 0 for c.hour_.

Because the class declares a constructor, the compiler does not declare its own default constructor (ex03). Sources: cppreference, Default constructors; C++23 [class.default.ctor]/1.

Q4

L1 · Recall Short answer destructor

Write the declaration of the destructor of the class Logger. How many parameters does it have? When does it run for a local object?

Show answerHide answer to Q4

A destructor has no parameters and no return type. For a local object, it runs when the object goes out of scope. That is the closing brace of its block, or a return that leaves the block (ex14, ex16).

Q5

L1 · Recall Multiple choice copy-constructor

Which declaration is the copy constructor of Tag?

  • a) Tag(Tag other);
  • b) Tag& operator=(const Tag& other);
  • c) Tag(const Tag& other);
  • d) Tag(const Tag* other);
Show answerHide answer to Q5

c) Tag(const Tag& other);. The copy constructor takes a reference to an object of the same class, usually a const reference (ex21). Answer a) does not compile (ex23). Answer b) is the copy assignment operator, which changes an object that exists. Answer d) takes a pointer, so it is a converting constructor, not a copy constructor.

Q6

L1 · Recall Short answer construction-order

A class has a destructor with a body and two members. When C++ destroys an object of this class, which runs first: the body of the destructor or the destructors of the members? In which order does C++ destroy the two members?

Show answerHide answer to Q6

The body of the destructor runs first. Then C++ destroys the members in the reverse order of their declaration: the last member first ([class.dtor]/13; ex30, ex37). So the body of the destructor can still use every member. In ex30, ~Car body comes before end w and end e.

Q7

L2 · Apply Multiple choice constructor

Account has explicit Account(int start). Which function compiles?

  • a) Account open() { return 70; }
  • b) Account open() { return Account{70}; }
  • c) Both functions
Show answerHide answer to Q7

b) return Account{70};. This line calls the constructor directly. A return statement copy-initializes the result, and explicit stops the silent conversion from int. So a) does not compile (ex33). GCC reports could not convert '70' from 'int' to 'Account'. Clang reports no viable conversion from returned value of type 'int' to function return type 'Account'.

Both messages come from a Docker build of the two functions.

Q8

L2 · Apply Multiple choice member-initializer-list

A class has the member const std::string code_; with no default member initializer. Where can a constructor give code_ its value?

  • a) In the constructor body, with code_ = code;
  • b) In the member initializer list, with code_{code}
  • c) In any member function, before the first use
Show answerHide answer to Q8

b) In the member initializer list. A const member gets its value only once, at its initialization. The body is too late, because the member already exists before the body runs (ex05, ex06). Answer a) gives no match for 'operator=' (GCC) or no viable overloaded '=' (Clang) for a const std::string.

Q9

L2 · Apply Multiple choice default-constructor

Point is struct Point { int x; int y; };. It has no default member initializers. Which line makes a Point with x and y equal to 0?

  • a) Point p;
  • b) Point p{};
  • c) Point p();
Show answerHide answer to Q9

b) Point p{};. Empty braces value-initialize the object, so each int member is 0. A Docker run on GCC 14 and Clang 19 writes 0 0 for p.x and p.y (cppreference, Value-initialization). Answer a) default-initializes p: the int members get no value, and a read of them is undefined behavior (cppreference, Default-initialization). Answer c) declares a function, not an object (ex12).

Q10

L2 · Apply Multiple choice destructor

show takes a const Tag&. Tag{'t'} is a temporary: an object with no name. In the statement show(Tag{'t'});, when does C++ destroy the temporary?

  • a) Before show starts
  • b) At the closing brace of the block
  • c) After show returns, at the ;
Show answerHide answer to Q10

c) After show returns, at the ;. C++ destroys a temporary object at the end of the full expression that makes it (ex17; [class.temporary]/4). The full expression is the whole call, so the temporary exists while show runs. A Docker run on GCC 14 and Clang 19 writes make t, show t, end t, then the next line of main.

Q11

L2 · Apply Short answer copy-constructor

a is a Tag. Give three statements that call the copy constructor of Tag. Then give two statements that use a or a Tag value and do not call it.

Show answerHide answer to Q11

Three statements that call the copy constructor (ex21, ex22):

  1. Tag b = a;
  2. Tag c{a};
  3. show(a);, where show takes a Tag by value.

Two statements that do not call it:

  1. peek(a);, where peek takes a const Tag&. A reference parameter refers to a.
  2. Tag d = Tag{'d'};. From C++17, an initialization from a prvalue of the same type makes d directly (cppreference, Copy elision).

Q12

L2 · Apply Multiple choice construction-order

Car declares the members Tag engine and Tag wheels, in this order. The constructor of Car has a body. What runs first in Car car;?

  • a) The body of the Car constructor
  • b) The constructor of wheels
  • c) The constructor of engine
Show answerHide answer to Q12

c) The constructor of engine. The members initialize in declaration order before the constructor body runs. So the order is engine, wheels, then the body (ex30; [class.base.init]/13).

Part D: Explain why

9 questions

Q34

L2 · Apply Explain why member-initializer-list

In ex07, InBody writes Part() and operator=, but InList writes only Part(int). Explain why. Answer in three sentences.

Show answerHide answer to Q34

A member initializes before the constructor body runs. The list of InBody does not name part, so C++ first calls Part(). Then the body calls operator=. The class InList gives the value in the list. So C++ calls only Part(int), one function instead of two (ex07; rule C.49 of the C++ Core Guidelines).

Q35

L2 · Apply Explain why destructor

In ex16, parse(-5) returns early, but the program still writes close log. Explain why, and tell why this is useful. Answer in two sentences.

Show answerHide answer to Q35

C++ destroys every local object when its scope ends, also at an early return, so ~Log() runs on both return paths (ex16). You cannot forget the clean-up code in a destructor on a new return path. This is the base of RAII (S01E01).

Q36

L3 · Analyze Explain why default-constructor

Settings declares no constructor. Its only member is const int max_;, with no default member initializer. The line Settings s; does not compile. Explain why. Give two corrections.

Show answerHide answer to Q36

The compiler declares a default constructor for Settings, because the class declares no constructor. But that constructor must default-initialize max_, and a const int with no initializer cannot get a value later. So the compiler defines the default constructor as deleted ([class.default.ctor]/2; [dcl.init.general], default-initialization of a const object). GCC reports use of deleted function 'Settings::Settings()' and uninitialized const member in 'struct Settings'. Clang reports call to implicitly-deleted default constructor of 'Settings'.

Two corrections, both proved in Docker on GCC 14 and Clang 19:

  1. Give the member a default member initializer: const int max_ = 10;. Then Settings s; compiles.
  2. Write a constructor with a list: explicit Settings(int max) : max_{max} {}, and make the object with Settings s{5};.

ex11 shows the same rule for a member with no default constructor.

Q37

L3 · Analyze Explain why copy-constructor

In ex22, Tag c = Tag{'c'}; writes no copy line. Explain why. Name the standard that makes this behavior a rule.

Show answerHide answer to Q37

Tag{'c'} is a prvalue of the same type as c. From C++17, the standard guarantees copy elision in this case: the prvalue initializes c directly, and no temporary exists (cppreference, Copy elision). So C++ does not call the copy constructor, and the program writes no copy line. Before C++17, a compiler could skip the copy, but the standard did not make it a rule.

Q38

L3 · Analyze Explain why construction-order

In ex27, the list is second{'2'}, first{'1'}, but the program writes make 1 first. Explain why. Name the warning that tells you about the different order.

Show answerHide answer to Q38

Members initialize in the order of their declaration in the class, and the order of the list has no effect ([class.base.init]/13.3). The class declares first before second, so make 1 comes first (ex27). GCC warns with -Wreorder ('Pair::second' will be initialized after), and Clang with -Wreorder-ctor. -Wall turns on both warnings.

Q39

L3 · Analyze Explain why constructor

A class can make its object valid with a constructor, or with an init() function that the caller must call after the declaration. Explain why the constructor is safer. Answer in three sentences.

Show answerHide answer to Q39

A constructor runs at each declaration, so no code can use the object before it is valid. With an init() function, the object is not valid until the call. A caller can forget the call or call it two times. Also, a const member or a reference member can get its value only in a constructor.

Q40

L3 · Analyze Explain why copy-constructor

Tag declares the copy constructor Tag(Tag& other), with no const. Tag b = a; compiles. But with const Tag c{'c'};, the line Tag d = c; does not compile. Explain why. Then give the usual form of the copy constructor.

Show answerHide answer to Q40

A reference to Tag with no const cannot refer to a const object, because the function could then change that object. So Tag(Tag& other) cannot copy c. GCC reports binding reference of type 'Tag&' to 'const Tag' discards qualifiers. Clang reports no matching constructor for initialization of 'Tag'. Both messages come from a Docker build.

The usual form is Tag(const Tag& other). A copy must not change its source, and a const reference accepts both a and c (a Docker build compiles both copies). The parameter must be a reference, not a value: a parameter by value needs a copy itself (ex23).

Q41

L4 · Senior Explain why destructor

C++ destroys local objects in the reverse order of their construction. Explain why this order is safe when a later object uses an earlier object. Give an example with two objects.

Show answerHide answer to Q41

An object that C++ makes later can use an object that C++ made earlier. With the reverse order, C++ destroys the later object first. So the later object never uses an object that C++ already destroyed. Example: Log log; Parser parser{log};. parser writes to log in its destructor. C++ destroys parser first, and log still exists at that time (ex15).

Q42

L4 · Senior Explain why default-constructor

After you declare Account(int start), the compiler no longer writes a default constructor. Explain why this rule protects the invariant of a class.

Show answerHide answer to Q42

A class with Account(int start) tells the compiler that an account needs a start value. A default constructor from the compiler can leave the int balance with no value, or give it a value that breaks the invariant. So the compiler writes no default constructor. You add one with = default or your own body only when a default value has a clear meaning (ex10).

Part F: Design and trade-offs

5 questions

Q50

L4 · Senior Design constructor

Percent must hold a value in the range 0 to 100. A caller gives 150. Compare three designs:

  1. The constructor changes the value to the nearest valid value (clamp).
  2. The constructor stops the program with assert.
  3. A factory function std::optional<Percent> make_percent(int) returns no value, and the constructor is private. A std::optional<Percent> holds one Percent or no value.

Give one advantage and one risk of each design. Then give a recommendation for user input and for a value from your own code.

Show answerHide answer to Q50

A strong answer has these parts:

  1. Clamp: the object is always valid, and the caller needs no error code (ex02). Risk: a wrong value from a bug becomes a correct-looking value, and nobody sees the bug.
  2. assert: a bug stops the program in a debug build, at the exact place. Risk: with -DNDEBUG, the check is gone, and the object can be invalid.
  3. Factory with std::optional: the caller must look at the result, and no invalid object can exist. Risk: more code at each call. A later episode shows exceptions, the usual C++ way for a constructor to refuse a value.
  4. Recommendation: for user input, refuse the value and tell the user (design 3, or an exception). For a value from your own code, a wrong value is a bug, so use assert or an exception. Clamp only when the domain says so, for example a volume control.

Q51

L4 · Senior Design member-initializer-list

A class can give a member its start value in three places: a default member initializer, the member initializer list, or the constructor body. Give a rule for each place. Use the rules C.48 and C.49 of the C++ Core Guidelines.

Show answerHide answer to Q51

A strong answer has these parts:

  1. Default member initializer: use it for a value that is the same for most constructors, for example int retries_ = 3;. Rule C.48: prefer default member initializers to member initializers in constructors for constant initializers.
  2. Member initializer list: use it for a value that comes from the parameters. It is the only place for a const member, a reference member and a member with no default constructor (ex05, ex11, ex36). A list entry replaces the default member initializer (ex08).
  3. Constructor body: use it for work that needs all members ready, for example a check of the invariant or a log line. Rule C.49: prefer initialization to assignment in constructors (ex07).
  4. Limit: write the list in declaration order, or -Wall warns (ex27).

Source: C++ Core Guidelines, C.48 and C.49.

Q52

L4 · Senior Design copy-constructor

Connection holds the handle of one open network connection, and its destructor closes it. Compare three copy designs: the copy constructor from the compiler, a copy constructor that opens a second connection, and = delete. Give a recommendation.

Show answerHide answer to Q52

A strong answer has these parts:

  1. Copy constructor from the compiler: it copies the handle. Then two objects close one connection. The second close uses a handle that is not valid: the same bug as the double free in ex25.
  2. Copy that opens a second connection: each object owns its own connection. Risk: a copy is slow and can fail, and a silent copy, for example a parameter by value, opens a network connection that nobody expects.
  3. = delete: the compiler refuses every copy (ex24). Callers pass a reference, or later move the object (S01E03). This makes the ownership clear.
  4. Recommendation: = delete for the copy, and give a clear function, for example reconnect(), when a second connection is necessary. Also delete the copy assignment (rule of three).

Q53

L4 · Senior Design default-constructor

Must Date have a default constructor? Compare a Date with no default constructor and a Date whose default constructor gives 1970-01-01. Talk about arrays, members of other classes and the meaning of the default value.

Show answerHide answer to Q53

A strong answer has these parts:

  1. No default constructor: each Date has a date that the caller chose. Risk: you cannot write Date days[7];, and each class with a Date member must give it a value in its list (ex11).
  2. Default 1970-01-01: arrays and members work, and the object is valid. Risk: a forgotten value looks like a real date, and the bug is difficult to see.
  3. Rule C.43 of the C++ Core Guidelines: a copyable class must have a default constructor, because arrays and many library types need one. This rule helps only when the default value has a clear meaning.
  4. Recommendation: usually no default constructor for Date. When you need "no date yet", use std::optional<Date> and not a magic date.

Q54

L4 · Senior Design destructor

The class LogFile opens a file. Compare two designs for the clean-up. In design 1, the caller must call a close() function. In design 2, the destructor closes the file. Talk about early returns, errors in the code and the cost.

Show answerHide answer to Q54

A strong answer has these parts:

  1. close() function: the caller controls the time. Risk: each return path must call it. An early return or an error path that you add later leaks the file.
  2. Destructor: C++ runs it on every return path and at the end of each scope (ex16). The clean-up is in one place. This is RAII (S01E01).
  3. Cost: the destructor call is the same work as a close() call. There is no hidden cost.
  4. Recommendation: close in the destructor. You can also give a close() function for a caller that must see a close error. Then the destructor does nothing for a file that is already closed.

Q55

L3 · Analyze Interview construction-order

A class has one base class and two members. A base class is the class after the : in struct Car : Vehicle (episode twenty). Tell the order of construction and the order of destruction.

Show answerHide answer to Q55

A strong answer has these parts (struct Car : Vehicle makes Vehicle the base class of Car; S00E20 teaches inheritance):

  1. Main fact: construction goes from the base class, to the members in declaration order, to the constructor body. Destruction is the exact reverse: the destructor body, the members in reverse declaration order, then the base class ([class.base.init]/13, [class.dtor]/13).
  2. Example: ex31 writes Vehicle body, make e, Car body, then ~Car body, end e, ~Vehicle body.
  3. Limit: the member initializer list does not change the order. -Wall warns when the list has a different order (ex27).
  4. Follow-ups: "And with two base classes?" They initialize in the order of the base class list. "Why the reverse?" A later part can use an earlier part, so the later part must go first.

Q56

L3 · Analyze Interview member-initializer-list

What is a member initializer list? Why do you use it instead of assignments in the constructor body?

Show answerHide answer to Q56

A strong answer has these parts:

  1. Main fact: the list after : in a constructor initializes each member before the body runs (ex04).
  2. Why: an assignment in the body comes after a default construction, so a class-type member does the work two times (ex07). A const member, a reference member and a member with no default constructor need the list (ex05, ex36, ex11).
  3. Limit: the list does not set the order. Members initialize in declaration order (ex27).
  4. Follow-ups: "And a default member initializer?" A list entry replaces it for that constructor (ex08). "Can one constructor call another?" Yes, a delegating constructor puts the other constructor in the list (ex13).

Q57

L3 · Analyze Interview copy-constructor

When does the compiler call the copy constructor? When does it not call it, although the code looks like a copy?

Show answerHide answer to Q57

A strong answer has these parts:

  1. Main fact: C++ calls the copy constructor when it makes a new object from an object of the same type. Examples: Tag b = a;, Tag b{a}; and a parameter by value (ex21).
  2. No copy: a reference parameter, and an initialization from a prvalue of the same type, for example Tag c = Tag{'c'}; or return Tag{c};. From C++17, the standard guarantees this copy elision (ex22).
  3. Limit: b = a; on an object that exists calls the copy assignment, not the copy constructor. The return of a named local object can skip the copy (NRVO), but the standard does not guarantee it.
  4. Follow-ups: "Why must the parameter be a reference?" A parameter by value needs a copy itself (ex23). "How do you stop all copies?" = delete (ex24).

Q58

L4 · Senior Interview copy-constructor

What is the rule of three? Give an example of a class that breaks it, and tell what goes wrong.

Show answerHide answer to Q58

A strong answer has these parts:

  1. Main fact: a class that needs its own destructor, copy constructor or copy assignment usually needs all three (cppreference, The rule of three/five/zero).
  2. Example: ex25 has a destructor that calls delete[], but no copy constructor. The copy from the compiler copies the pointer, and AddressSanitizer reports attempting double-free.
  3. Corrections: a deep copy, or = delete for the copy. Better: the rule of zero. Use a member that manages itself, for example std::vector<int>, and write none of the three.
  4. Follow-ups: "What is the rule of five?" C++11 adds the move constructor and the move assignment (S01E03). "Does = delete count?" Yes, a deleted function is a decision about the copy.

Q59

L4 · Senior Interview default-constructor

When does the compiler write a default constructor? When does it define it as deleted?

Show answerHide answer to Q59

A strong answer has these parts:

  1. Main fact: the compiler declares a default constructor only when the class declares no constructor (ex09). = default brings it back next to other constructors (ex10).
  2. Deleted: the compiler defines it as deleted when it cannot make a member or a base class with no arguments ([class.default.ctor]/2). Examples: a member with no default constructor (ex11), or a reference member with no default member initializer. A const int member with no initializer also deletes it.
  3. What it does: it uses each default member initializer and calls the default constructor of each class-type member. A member of a type such as int with no initializer gets no value.
  4. Follow-ups: "Does a copy constructor stop it?" Yes (ex26). "What does Tag t(); do?" It declares a function (ex12).

Q60

L4 · Senior Interview constructor

What does explicit do on a constructor? When do you use it, and when do you not use it?

Show answerHide answer to Q60

A strong answer has these parts:

  1. Main fact: a constructor that you can call with one argument is a converting constructor. The compiler uses it for silent conversions, for example show(50) and Account a = 70; (ex32). explicit stops these conversions. A direct call such as Account{50} still works (ex33).
  2. Use it: on most constructors with one parameter. The argument is usually a different type of value than the object. A customer ID is not an account.
  3. Do not use it: when the conversion has no surprise, for example std::string from a string literal. Rule C.46 of the C++ Core Guidelines: by default, declare single-argument constructors explicit.
  4. Follow-ups: "And with two parameters?" explicit also stops copy-list-initialization such as Account a = {1, 2};. "And copy constructors?" They are usually not explicit.

Q61

L4 · Senior Interview destructor

Name the cases in which a destructor runs. For each case, tell when it runs.

Show answerHide answer to Q61

A strong answer has these parts:

  1. Local object: at the end of its scope, also at an early return, break or continue (ex14, ex16).
  2. Temporary object: at the end of the full expression, at the ; (ex17).
  3. Members and base classes: after the body of the destructor of the class, in reverse order (ex30, ex31, ex37).
  4. Array elements: in reverse index order (ex18). Parameter by value: at the function return or at the end of the full expression of the call, which one is implementation-defined ([expr.call]; ex19).
  5. Other cases: delete on an object from new, and static objects after main returns (later episodes).
  6. Follow-ups: "In which order do locals end?" In the reverse order of construction (ex15). "Can you call a destructor two times?" Not on the same object: that is undefined behavior, as the double free in ex25.

Q62

L4 · Senior Interview construction-order

A member initializer uses another member of the same class. What can go wrong? How do you find the problem, and how do you correct it?

Show answerHide answer to Q62

A strong answer has these parts:

  1. Main fact: members initialize in declaration order. If a member uses a member that the class declares later, it reads a value that has no initialization. That is undefined behavior (ex28).
  2. Find it: -Wall gives -Wreorder and -Wuninitialized on GCC and Clang. At run time, MemorySanitizer reports use-of-uninitialized-value (Clang only).
  3. Correct it: compute the member from the constructor parameters, capacity_{size * 2}, or declare the members in dependency order (ex29). Write the list in declaration order, so that the code shows the real order.
  4. Follow-ups: "Why does C++ not use the list order?" The single destructor needs one fixed order for all constructors. "And base classes?" They initialize before all members, so a base class cannot use a member of the derived class.
