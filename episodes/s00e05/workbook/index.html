Q1

L1 · Recall Short answer if-statement

The condition of an if statement is an int or a double. Which values make the condition false?

Show answerHide answer to Q1

Only zero (0 or 0.0) makes the condition false. Each other value makes it true, also -1 and 0.5. The condition converts to bool: 0 and 0.0 become false, all other values become true (ex04). Source: cppreference, if statement.

Q2

L2 · Apply Multiple choice if-statement

  • a) The first if, because it has the same indentation as the else.
  • b) The second if, because it is the nearest if that has no else.
  • c) Neither. The code does not compile without braces.
Show answerHide answer to Q2

b) The second if. An else goes with the nearest if that has no else. The compiler ignores the indentation. The code compiles, and -Wall gives the warning -Wdangling-else (ex08). Use braces to show the meaning.

Q3

L1 · Recall Short answer switch-statement

Which types can the condition of a switch have?

Show answerHide answer to Q3

An integer type (int, char, long long, bool and the others) or an enumeration type. A class type that converts to one of these types also works. Other types do not compile. For example, a std::string gives the GCC error switch quantity not an integer (ex17). Source: cppreference, switch statement.

Q4

L1 · Recall Multiple choice switch-statement

A switch has no default label, and no case label has the value of the condition. What does the program do?

  • a) It runs the statements of the first case.
  • b) It runs none of the statements in the switch, and continues after the switch.
  • c) It stops with an error when it runs.
Show answerHide answer to Q4

b) With no match and no default label, none of the statements in the switch body runs. The program continues after the switch. The default label is optional, and it can be at any position. Source: cppreference, switch statement.

Q5

L1 · Recall Short answer fallthrough

What is fallthrough in a switch statement?

Show answerHide answer to Q5

Fallthrough occurs when a case has no break: the statements of the next labels also run (ex11). The C++17 attribute [[fallthrough]]; shows that a fallthrough is intentional, and the compiler then does not warn (ex13). Source: cppreference, fallthrough.

Q6

L1 · Recall Short answer for-loop

When does each of the three parts in the parentheses of a for loop run?

Show answerHide answer to Q6

for (init; condition; increment):

  • The init statement runs one time, before the first step.
  • The loop tests the condition before each step. When it is false, the loop stops.
  • The increment runs after each step, before the next test.

Source: cppreference, for loop.

Q7

L2 · Apply Multiple choice for-loop

How many times does the body of for (int i = 3; i < 10; i += 2) run?

  • a) 3
  • b) 4
  • c) 5
  • d) 7
Show answerHide answer to Q7

b) 4. The body runs for i = 3, 5, 7 and 9. Then i is 11, and 11 < 10 is false.

Q8

L1 · Recall Short answer while-loop

Give the minimum number of runs of the body of a while loop and of a do-while loop.

Show answerHide answer to Q8

A while loop tests the condition before each step, so its body runs zero or more times. A do-while loop tests the condition after each step, so its body runs one or more times (ex25). A do-while statement also ends with a semicolon after the condition (ex27).

Q9

L2 · Apply Multiple choice while-loop

A program shows a menu, reads a choice and does the action. It does this again until the choice is q. The menu must show one or more times. Which loop fits best?

  • a) A for loop with a counter
  • b) A do-while loop
  • c) A range-for loop
Show answerHide answer to Q9

b) A do-while loop. The menu must show before the first test, and nobody knows the number of steps before the loop starts. A for loop with a counter fits a known number of steps. A range-for loop visits the elements of a container, not user input.

Q10

L1 · Recall Short answer range-for

A range-for loop visits the elements of an array. Write the loop variable for these three tasks:

  1. Use a copy of each int element.
  2. Change each int element.
  3. Read each std::string element without a copy.
Show answerHide answer to Q10
  1. for (int value : values) — the loop variable is a copy (ex34).
  2. for (int& value : values) — the reference changes each element (ex35).
  3. for (const std::string& name : names) — no copy, and the loop cannot change the element (ex39).

Q11

L1 · Recall Short answer range-for

Which C++ standard added an init statement in the range-for loop?

Show answerHide answer to Q11

C++20, for example for (int i = 0; int score : scores) (ex38). The range-for loop itself is from C++11. Source: cppreference, range-for loop.

Q12

L2 · Apply Multiple choice break-continue

In ex43, a and b go from 1 to 4. The inner loop prints the pair when a * b == 6, and then runs break. How many pairs does the program print?

  • a) 1
  • b) 2
  • c) 4

b) 2: 2 x 3 and 3 x 2. A break stops only the innermost loop or switch that contains it. The outer loop then continues with its next step and finds the second pair (ex43). Source: cppreference, break statement.

9 questions

Q35

L2 · Apply Explain why if-statement

In ex07, balance is 50, but the program prints overdrawn. Explain why. Why does the indentation of the output statement not help? Answer in two or three sentences.

Show answerHide answer to Q35

The semicolon after if (balance < 0) is an empty statement, and it is the body of the if. The output statement is the next statement, after the if, so it always runs. The compiler ignores indentation. Both compilers warn (-Wempty-body), and GCC also gives -Wmisleading-indentation (ex07).

Q36

L3 · Analyze Explain why if-statement

Compare int rest = total % box; if (rest == 0) { ... } and if (int rest = total % box; rest == 0) { ... }. Explain why the second form is often better. Answer in two or three sentences.

Show answerHide answer to Q36

In the second form, the scope of rest is only the if and else branches (ex05). After the if, no code can use the variable by mistake (ex06), and the name is free for other code. The value and its test are also on one line, so the code is easy to read.

Q37

L3 · Analyze Explain why switch-statement

In ex15, a case declares int count = 10; without braces, and the code does not compile. Explain why. Then explain why braces around the body of the case correct the error (ex16).

Show answerHide answer to Q37

A switch jumps directly to the matching label. The scope of count continues to the end of the switch, so case 2 is in its scope. The jump to case 2 skips the initialization, and C++ does not let a jump skip the initialization of a variable in its scope. With braces, the scope of count ends at the closing brace, before case 2, so the jump skips nothing. Source: cppreference, switch statement.

Q38

L3 · Analyze Explain why switch-statement

Explain why each case label must be a constant expression, and why two labels must not have the same value.

Show answerHide answer to Q38

The compiler must know each label value when it compiles. It makes the jump code from the values: a table or a set of compares (ex22). A variable that is not const has no value at compile time, so it does not compile (ex19). A const int or constexpr variable with a constant initializer also works. Two labels with the same value make the jump ambiguous, so the compiler stops (ex18).

Q39

L3 · Analyze Explain why fallthrough

Fallthrough causes bugs, but C++ keeps it. Explain why. Give one switch where fallthrough is useful.

Show answerHide answer to Q39

C++ keeps the rule from C, and much old code uses it. Fallthrough is useful when each case adds to the next case. For example, backup level 3 copies logs, then data, then settings (ex13). Grouped labels with no statements between them are a different, safe form of the same rule (ex14). Today, mark each intentional fallthrough with [[fallthrough]];.

Q40

L3 · Analyze Explain why for-loop

In ex30, the loop for (double x = 0.0; x != 1.0; x += 0.1) does not stop at 1.0. Explain why. Then explain why an integer counter has no such problem.

Show answerHide answer to Q40

A double uses binary fractions, so it cannot hold 0.1 exactly. Each addition adds a small error. After ten additions, x is a little less than 1.0, so x != 1.0 stays true. ex30 stops only because of a second condition, steps < 100. An int holds each whole number exactly, so i != 10 is true until i is exactly 10.

Q41

L2 · Apply Explain why while-loop

In ex28, the loop while (std::cin >> value) adds numbers until the input ends. Explain why the loop stops. Answer in two or three sentences.

Show answerHide answer to Q41

std::cin >> value reads one value and gives std::cin as its result. In a condition, a stream converts to bool: true when the last read was successful, false when it failed. At the end of the input, the read fails, so the condition is false and the loop stops (ex28: 6 values, total 108). A wrong value, for example a letter, also stops the loop. Source: cppreference, basic_ios::operator bool.

Q43

L4 · Senior Explain why break-continue

In ex45, continue in a while loop skips the update, and only the limit steps < 50 stops the loop. The same continue in a for loop is safe. Explain why. What must you check when you change a for loop into a while loop?

Show answerHide answer to Q43

In a for loop, continue skips the rest of the body, and the loop still runs the increment. In a while loop, the update is in the body. In ex45, continue skips ++i, so i stays 0, and i < 6 stays true. Only the second condition, steps < 50, stops the loop (output i 0, steps 50).

Without such a limit, a loop that has no output and no other side effect is undefined behavior (C++23 [intro.progress]). Clang with -O2 can remove it. When you change a for loop into a while loop, look at each continue. Each path through the body must reach the update. Source: cppreference, continue statement.

Part F: Design and trade-offs

4 questions

Q51

L4 · Senior Design switch-statement

A program reads a command code, an int from 0 to 40, and selects one of 41 actions. Compare an else if chain and a switch for this task. Talk about the speed, the readability and the checks that the compiler does. Give a recommendation.

Show answerHide answer to Q51

A strong answer compares the two forms:

  • Speed: with dense values 0 to 40, GCC and Clang can make a table and one indexed jump with -O2 (ex22). An else if chain tests the conditions in order, so the last command needs up to 41 compares, unless the optimizer changes the chain.
  • Readability: a switch shows that all branches test one value. An else if chain can test a different variable in each branch, so the reader must read each condition.
  • Compiler checks: a duplicate case value does not compile (ex18). For an enumeration, -Wswitch warns about a missing value (ex20). An else if chain has no such checks.
  • Risk: a switch can fall through. Use break and the fallthrough warning.

Recommendation: use a switch. Use an else if chain for ranges (score >= 90), for strings and for different variables.

Q52

L4 · Senior Design while-loop

A program shows a prompt, reads one number and adds it to a total. It does this again until the input ends. Compare three loops for this task: while (std::cin >> value), a do-while loop and for (;;) with break. Give a recommendation.

Show answerHide answer to Q52

A strong answer compares the three loops:

  • while (std::cin >> value): short and correct. The read is the condition, so the loop stops at the end of the input or at a wrong value (ex28). But the prompt must go before the loop and again at the end of the body.
  • do-while: the body runs first, so the prompt shows one time before the first read. But the read is in the body, so the body must test the result of the read before it adds the value.
  • for (;;) with break: show the prompt, read, break when the read fails, then add. Each step is in one place, in order.

Recommendation: for (;;) with break, or a while loop with the prompt and the read in the condition. Do not add a value before you test the read.

Q53

L4 · Senior Design range-for

A program prints each element of an array with its position, and it stops at the first negative value. Compare these three loops for the task, and give a recommendation:

  • an index for loop
  • a range-for loop with a counter before the loop
  • a range-for loop with an init statement (C++20)
Show answerHide answer to Q53

A strong answer compares the three loops:

  • Index for loop: gives the position directly, and break stops at the negative value. But you write the bound, so an off-by-one error is possible (ex29).
  • Range-for with a counter before the loop: no bound to write. But the counter exists after the loop, and you must increment it in each path of the body.
  • Range-for with an init statement (C++20): no bound, and the scope of the counter is only the loop (ex38). The increment is still in the body, so a continue before it gives a wrong position.

Recommendation: the range-for loop with an init statement, with ++i at the start or the end of each path. Use the index loop when the code needs the position in the loop condition or must skip elements.

Q54

L4 · Senior Design fallthrough

Your team writes a coding rule for switch statements. Choose the compiler flags for GCC and for Clang. Write the rules for break, [[fallthrough]] and default. Give a reason for each choice.

Show answerHide answer to Q54

A strong answer gives flags and rules, each with a reason:

  • Flags: GCC with -Wall -Wextra, which contains -Wimplicit-fallthrough and -Wswitch. Clang with -Wall -Wextra -Wimplicit-fallthrough, because Clang does not put it in -Wextra (ex11). Make the warnings errors in the build, for example with -Werror=implicit-fallthrough.
  • break: each case that has statements ends with break, return or [[fallthrough]];. The last case also gets a break, so a case added later does not fall into it.
  • [[fallthrough]]: use it only immediately before the next label, for an intentional fallthrough (ex13, ex49). Grouped labels need no attribute (ex14).
  • default: use it for a switch on an integer, to handle wrong values. Do not add a default to a switch on an enumeration. A default stops the -Wswitch warning, so nobody finds a new enumeration value (ex20). Source: GCC, Warning Options.

Part G: Interview questions

Q55

L4 · Senior Interview switch-statement

How does a compiler make machine code from a switch? When is a switch faster than an else if chain, and when is it not faster?

Show answerHide answer to Q55

A strong answer has these parts:

  1. Main fact: for dense values, the compiler makes a table. One check of the range and one indexed jump select the case. GCC makes a jump table of addresses, and Clang can make a table of values (ex22, -O2).
  2. Example: a switch on the days 0 to 6 gives one indexed jump. A switch on 1, 100, 1000 and 10000 is sparse. With -O2, both compilers make compares and conditional jumps, with no table and no indirect jump (ex51; captured/ex51.o2-asm.gcc.txt and ex51.o2-asm.clang.txt).
  3. Limits: a tree of compares needs about log2(N) compares. An optimizer can also change an else if chain on one variable into a table. So measure before you choose a form only for speed. A switch cannot test a range or a string.
  4. Follow-ups: "How do you see what the compiler makes?" Use -S or Compiler Explorer and read the assembly. "Is a table always faster?" No. A table uses memory and an indirect jump, which the processor can predict incorrectly.

Q56

L3 · Analyze Interview fallthrough

What is fallthrough in a switch? How do you prevent fallthrough bugs in a large code base?

Show answerHide answer to Q56

A strong answer has these parts:

  1. Main fact: a case without break falls through: the statements of the next cases also run (ex11). For place 2, the program prints silver and bronze.
  2. Prevention: turn on the warning (GCC: -Wextra; Clang: -Wimplicit-fallthrough), make it an error, and mark each intentional fallthrough with [[fallthrough]]; (ex13). Then each warning is a bug.
  3. Limits: grouped labels with no statements between them do not cause a warning (ex14). An attribute [[fallthrough]] before the closing brace of the switch is an error on Clang (ex49).
  4. Follow-ups: "Why does C++ not stop at each case?" Compatibility with C. "Which C++ standard added [[fallthrough]]?" C++17.

Q57

L4 · Senior Interview for-loop

What is an off-by-one error? Give an example in a loop. How do you find it, and how do you prevent it?

Show answerHide answer to Q57

A strong answer has these parts:

  1. Main fact: an off-by-one error is a loop that runs one step too many or one step too few. The usual cause is the bound <= in place of <, or a start at 1 in place of 0.
  2. Example: for (int i = 0; i <= count; ++i) total += scores[i]; reads scores[5] in an array of 5 elements. This is undefined behavior. When count comes from the input (ex29), the compilers give no warning, and the printed total proves nothing. With a constant bound and -O2, GCC can warn (-Waggressive-loop-optimizations), but do not trust a warning to find this bug.
  3. Find it: UBSan (index 5 out of bounds) and ASan (stack-buffer-overflow) find it when the program runs (ex29). Tests with 0 and 1 elements also help.
  4. Prevent it: use half-open ranges, for (int i = 0; i < n; ++i). Use a range-for loop when you do not need the index (ex34).
  5. Follow-ups: "Why do half-open ranges help?" The number of steps is end - start, and an empty range has start == end.

Q59

L3 · Analyze Interview switch-statement

Why can you not use a switch on a std::string? What do you use to select an action from a string?

Show answerHide answer to Q59

A strong answer has these parts:

  1. Main fact: the condition of a switch must have an integer or enumeration type, and each label must be a constant integer value. A std::string is a class, and a string literal is not an integer (ex17).
  2. Options: an else if chain with == for a few strings. For many strings, a map from the string to a number or an action. A later episode shows std::map and std::unordered_map. You can also switch on the first character, if it is different for each string.
  3. Limits: an else if chain compares the strings in order, one after the other. A map has a cost for the lookup and for its memory.
  4. Follow-ups: "Can you switch on a hash of the string?" Yes, but two strings can have the same hash, so each case must compare the string too.

Q60

L4 · Senior Interview break-continue

Two nested loops search for a pair of values. How do you stop both loops at the first match? Compare the possible ways.

Show answerHide answer to Q60

A strong answer compares these ways:

  1. A bool flag: set it at the match, break the inner loop, and test the flag in the outer condition (ex44). It is clear, but it adds a variable and a test.
  2. A function with return: put the loops in a function. return stops both loops at the first match (the solution of the quiz item find_product). This is usually the best way, because the function also has a name.
  3. goto: goto done; with a label after the loops also stops both loops. It is correct C++, but many code rules do not let you use it. Source: cppreference, goto statement.
  4. Follow-ups: "Does C++23 have a break with a label, as in Java?" No. A break stops only the innermost loop or switch. Source: cppreference, break statement.

Q61

L4 · Senior Interview if-statement

C++17 added an initializer to the if and switch statements. What problem does it solve? Give an example.

Show answerHide answer to Q61

A strong answer has these parts:

  1. Main fact: the initializer limits the scope of a variable to the statement. Before C++17, you declared the variable before the if, so it existed until the end of the block.
  2. Example: if (int rest = total % box; rest == 0) { ... } else { std::cout << rest; } (ex05). rest exists in both branches and not after the if (ex06). A switch can do the same: switch (int group = code / 100; group) (ex21).
  3. Benefits: no code after the if can use the variable by mistake, and the name is free for other code.
  4. Follow-ups: "Which other statement has an init statement?" The for loop always had one, and C++20 added one to the range-for loop (ex38).
