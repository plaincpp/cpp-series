Q1

L1 · Recall Short answer c-array

Declare a C array prices of 4 double values: 1.5, 2.0, 2.5 and 3.0. Which index gives the last element? How many bytes does sizeof(prices) give?

Show answerHide answer to Q1

double prices[4] = {1.5, 2.0, 2.5, 3.0};. The last element is prices[3], because the index starts at 0. sizeof(prices) gives 32: 4 elements of 8 bytes each, with no gaps (ex01, ex03).

Q2

L1 · Recall Multiple choice c-array

int some[5] = {1, 2}; is a declaration in a function. Which values do some[2], some[3] and some[4] have?

  • a) Unknown values, because the list does not give them
  • b) 0, because missing values in the list get zero
  • c) 2, because the last value in the list repeats
Show answerHide answer to Q2

b) 0. When the list has fewer values than the array, the other elements get zero, so some holds 1 2 0 0 0 (ex02). A local array with no list at all has unknown values, so always give a list, also an empty one: int some[5]{};.

Q3

L1 · Recall Short answer array-decay

What is array-to-pointer conversion (also known as "decay")? Name three expressions where a C array does not convert to a pointer.

Show answerHide answer to Q3

In most expressions, a C array converts to a pointer to its first element: int* first = scores; gives first == &scores[0] (ex09). The conversion does not occur in these expressions (ex10):

  • sizeof(scores) gives the size of the full array (20 for int[5]).
  • &scores gives a pointer to the full array, with the type int(*)[5].
  • auto& same = scores; binds a reference with the type int(&)[5].

Q4

L2 · Apply Multiple choice array-decay

What is the real type of the parameter values in void fill(int values[10]);?

  • a) int[10]
  • b) int*
  • c) int(&)[10]
Show answerHide answer to Q4

b) int*. C++ changes an array parameter to a pointer parameter and ignores the 10. Because of this, void fill(int values[10]) and void fill(int* values) declare the same function (ex12).

Q5

L1 · Recall Short answer std-array

Which header declares std::array? Name four member functions of std::array, and tell what each one gives.

Show answerHide answer to Q5

The header is <array>. Four member functions:

  • size() gives the count of elements (a constant from the type).
  • front() and back() give the first and the last element.
  • data() gives a pointer to the first element.
  • at(i) gives element i, with an index check.

Q6

  • c) The code does not compile, because you cannot copy an array

Q7

L1 · Recall Short answer bounds-checking

Give the difference between operator[] and at() on a std::array. Which exception does at() throw, and which header declares it?

Show answerHide answer to Q7

The operator operator[] does not check the index, so a bad index is undefined behavior. The function at() checks that the index is less than size(). For a bad index, it throws std::out_of_range, which the header <stdexcept> declares (ex21).

Q8

L2 · Apply Multiple choice bounds-checking

scores.at(7) throws on a std::array<int, 5>, and no catch gets the exception. What occurs on Linux with libstdc++?

  • a) The program continues, and the expression gives 0.
  • b) std::terminate stops the program with a message, and the exit status is 134.
  • c) The compiler finds the bad index and reports an error.
Show answerHide answer to Q8

b). An exception that no catch gets calls std::terminate. Then libstdc++ prints terminate called after throwing an instance of 'std::out_of_range' and the what() text. The program aborts with exit status 134 (ex22). The compiler does not check a run-time index.

Q9

L1 · Recall Short answer std-string

Which header declares std::string? Name an operator that joins two strings and an operator that compares them. Name the member function that searches in a string.

Show answerHide answer to Q9

The header is <string>. The operators + and += join strings. The operators == and < compare them. The function find() searches for a character or a text. It gives the index of the first match (ex26, ex27).

Q10

L2 · Apply Multiple choice std-string

What does std::string("app") < std::string("apple") give?

  • a) false, because the first three characters are the same
  • b) true, because a string that is a prefix comes first
  • c) The code does not compile, because the lengths are different
Show answerHide answer to Q10

b) true. The comparison goes from left to right. When all characters of the shorter string agree with the start of the longer string, the shorter string comes first (ex28).

Q11

L1 · Recall Short answer string-literal

What is the type of the literal "hello"? What does sizeof("hello") give, and why?

Show answerHide answer to Q11

"hello" has the type const char[6]. sizeof("hello") gives 6: 5 characters and the null character '\0' at the end (ex34).

Q12

L2 · Apply Multiple choice string-literal

Which declaration gives a copy of "cat" that you can change with word[0] = 'b';?

  • a) const char* word = "cat";
  • b) char word[] = "cat";
  • c) char* word = "cat";
Show answerHide answer to Q12

b) char word[] = "cat";. It makes a new array of 4 char and copies the literal into it, so you can change it (ex34). In a), the characters are const, and the write does not compile (ex37). In c), C++11 and later do not allow a char* to point to a literal (ex38).

Part D: Explain why

10 questions

Q35

L3 · Analyze Explain why c-array

first and second are two int[3] arrays with the same values. Explain why first == second gives false. Name the warning that each compiler gives. Answer in three sentences.

Show answerHide answer to Q35

Both arrays convert to pointers to their first elements, so == compares two addresses. Two different arrays have different addresses, so the result is false, also when the values are equal. GCC warns with -Warray-compare, and Clang warns with -Wdeprecated-array-compare, because C++20 deprecates this comparison (ex06). To compare the values, use std::array, whose == compares the elements.

Q36

L2 · Apply Explain why c-array

count is an int that the program reads from std::cin. Explain why int values[count]; is not standard C++. Then explain why GCC accepts it with no message when you build without -Wpedantic. Answer in three sentences.

Show answerHide answer to Q36

The standard needs a constant expression for the size of an array, so the compiler knows the size of the type. GCC accepts a variable length array as an extension from C, and it warns only with -Wpedantic: ISO C++ forbids variable length array. Clang warns with no flags: variable length arrays in C++ are a Clang extension (ex04). Use std::vector for a size that comes at run time.

Q37

L3 · Analyze Explain why array-decay

In void print_size(int values[5]), sizeof(values) gives 8, not 20. Explain why. Answer in two sentences.

Show answerHide answer to Q37

C++ changes the parameter int values[5] to int* values, so values is a pointer. Thus sizeof gives the size of the pointer, which is 8 on x86-64, and both compilers warn with -Wsizeof-array-argument (ex11).

Q38

L4 · Senior Explain why array-decay

C and C++ change an array to a pointer in most expressions and in every function parameter. Explain one benefit of this rule and one cost. Answer in four sentences.

Show answerHide answer to Q38

Benefit: a function call does not copy the elements of an array; it gives only the address, which is 8 bytes on x86-64. One function can work with arrays of all lengths, and a[i] has one rule, *(a + i), for arrays and pointers.

Cost: the function loses the size, so sizeof and std::size do not work on the parameter. A wrong count gives undefined behavior. Also, you cannot assign, copy or compare C arrays as values.

The rule comes from C, and C took it from the languages B and BCPL. Sources: cppreference, Array-to-pointer conversion, and Dennis M. Ritchie, "The Development of the C Language" (1993).

Q39

L3 · Analyze Explain why std-array

You can copy a std::array<int, 5> with =, but you cannot assign one int[5] to another. Explain why. Answer in three sentences.

Show answerHide answer to Q39

std::array is a struct with one data member, a C array T[N]. The compiler makes the copy assignment for the struct, and a copy of a struct copies each member, also each element of a member array. A C array is not a class, and C++ does not allow an array on the left side of = (ex05). Source: cppreference, std::array and cppreference, Array, assignment.

Q40

L3 · Analyze Explain why bounds-checking

Example ex25 prints 5: out of range. The text 5: comes before out of range on the same line. Explain why. Answer in three sentences.

Show answerHide answer to Q40

The expression is ((std::cout << index) << ": ") << scores.at(index). From C++17, C++ evaluates the left operand of << before the right operand. Thus index and : go to the output before at() throws. The catch block then prints out of range on the same line. Source: cppreference, Order of evaluation, the rule "In a shift operator expression E1 << E2 and E1 >> E2, E1 is sequenced before E2" (C++17).

Q41

L3 · Analyze Explain why bounds-checking

scores is a std::array<int, 5>, and index is an int with the value -1. Explain why scores.at(index) throws std::out_of_range, and does not read the element before the array. Answer in two sentences.

Show answerHide answer to Q41

The parameter of at() has the unsigned type size_type (std::size_t), so the int -1 converts to the largest std::size_t value, 18446744073709551615. That value is not less than size(), so at() throws (ex25).

Q42

L3 · Analyze Explain why std-string

name is "Makefile", and dot is name.find('.'). Explain why name.substr(dot + 1) gives Makefile. Answer in three sentences.

Show answerHide answer to Q42

find() gives std::string::npos because the name has no dot, and npos is the largest std::size_t value. Unsigned arithmetic wraps around, so npos + 1 is 0. substr(0) gives the full string (ex45). Test dot == std::string::npos before you use dot.

Q43

L3 · Analyze Explain why string-literal

name is a std::string. Explain why line 1 does not compile and line 2 compiles. Answer in three sentences.

Show answerHide answer to Q43

The operator + groups from left to right, so line 1 is ("Hello, " + "world ") + name. On line 1, the first + has two literals, which convert to two const char* pointers, and C++ has no + for two pointers. On line 2, the first + has a literal and a std::string, so std::string gives the +. Its result is a std::string, which the second + can use.

Q44

L3 · Analyze Explain why string-literal

text is a const char* that points to the characters of a std::string with the value yes. Explain why text == "yes" can give false. Give a correct comparison. Answer in three sentences.

Show answerHide answer to Q44

== on two const char* values compares the addresses, not the characters. The characters of the std::string and the characters of the literal are at different addresses, so the result is false. GCC warns with -Waddress and Clang with -Wstring-compare (ex40); compare std::string values, for example answer == "yes", or use std::strcmp(text, "yes") == 0.

Part F: Design and trade-offs

4 questions

Q52

L4 · Senior Design c-array

A function keeps the totals of the 12 months of one year, and it gives them to other functions. Compare three designs: an int[12], a std::array<int, 12> and a std::vector<int>. Give one risk or cost of each design, and recommend one.

Show answerHide answer to Q52

A strong answer compares the three designs:

  • int[12]: no overhead, 48 bytes. Risk: it converts to a pointer when you give it to a function, so the function loses the size (ex11). You cannot copy, assign or compare it with = and == (ex05, ex06).
  • std::array<int, 12>: the same 48 bytes and no allocation (ex17). The size is part of the type, = copies and == compares the elements. Cost: a value parameter copies all 12 elements, so use const std::array<int, 12>& (ex18).
  • std::vector<int>: the size can change at run time. Cost: a heap allocation, and the object (24 bytes with libstdc++, ex48) is separate from the elements. The type does not show that the count is always 12.

Recommendation: std::array<int, 12>, because the count does not change and the compiler knows it.

Q53

L4 · Senior Design bounds-checking

Your team writes a program that reads indexes from files. Compare three ways to find a bad index: at() everywhere, operator[] with -D_GLIBCXX_ASSERTIONS, and operator[] with AddressSanitizer in the tests. Give the cost and the limit of each. Recommend a rule for the debug build and for the release build.

Show answerHide answer to Q53

A strong answer gives the cost and the limit of each way:

  • at() everywhere: a check and a branch for each access, in all builds. A bad index gives an exception that the program can handle (ex21). Limit: the code is longer, and in a hot loop with a known good index the check is waste. C arrays have no at().
  • -D_GLIBCXX_ASSERTIONS: libstdc++ adds a check to operator[] and stops the program with Assertion '__n < this->size()' failed (ex24). The cost is small, and you change no code. Limit: only libstdc++ containers; it does not check C arrays or pointers, and it aborts, so the program cannot continue.
  • AddressSanitizer: finds bad reads in C arrays, std::array and heap memory (ex23). Limit: the program is about 2 times slower and uses more memory, so it runs only in tests. It finds only the bad indexes that the tests use. Source: Clang, AddressSanitizer.

Recommended rule: check every index from a file or a user with an if or with at(), in all builds. Debug build and tests: -D_GLIBCXX_ASSERTIONS, and ASan with UBSan on the build server. Release build: keep the input checks, and use operator[] inside loops where the code already checked the index.

Q54

L4 · Senior Design string-literal

A function log_message takes one text. Callers give string literals and std::string values. Compare three parameter types: const char*, const std::string& and std::string by value. Give one cost or risk of each, and recommend one.

Show answerHide answer to Q54

A strong answer compares the three parameter types:

  • const char*: a literal goes in with no allocation. Risks: a caller with a std::string must call c_str(), and a null pointer is possible. The function must count the length with std::strlen, and a null character in the text ends it (ex42).
  • const std::string&: a std::string goes in with no copy. Cost: a literal makes a temporary std::string; a text of more than 15 characters then needs a heap allocation with libstdc++ (ex32).
  • std::string by value: each call makes a copy. This is good only when the function keeps the text, for example in a member variable, because the caller can then move the string in.

Recommendation: const std::string& for a function that only reads the text. A later episode shows std::string_view (C++17), which accepts both kinds of text with no copy. Source: cppreference, std::basic_string_view.

Q55

L4 · Senior Design array-decay

A function must find the largest value in an array of int, and the arrays have different lengths. Compare four parameter designs: a pointer and a count, a reference to a C array, a std::array and a std::span<const int>. Give one benefit and one limit of each, and recommend one.

Show answerHide answer to Q55

A strong answer compares the four designs:

  • Pointer and count: works with every array, also from C code (ex14). Limit: the two values can disagree, and the compiler cannot find a wrong count.
  • Reference to a C array, const int (&values)[5]: keeps the size, and std::size works (ex15). Limit: each length is a different type, so one function accepts only one length.
  • std::array<int, 5>: knows its size and copies as a value (ex18). Limit: the same as the reference: one function accepts only one length.
  • std::span<const int> (C++20): one object holds the pointer and the count. It accepts a C array, a std::array and a std::vector with no copy. Limit: it needs C++20, it does not own the elements, and its operator[] does not check the index.

Recommendation: std::span<const int> when the project uses C++20; else a pointer and a count, with a clear name for the count. Source: cppreference, std::span.

Show answerHide answer to Q56

A strong answer has these parts:

  1. Main fact: in most expressions, an array converts to a pointer to its first element. A function parameter of array type is a pointer.
  2. Example: int* first = scores; gives &scores[0] (ex09). The conversion does not occur for sizeof(scores) (20, not 8), for &scores (type int(*)[5]) and for a reference auto& same = scores; (ex10).
  3. Limit: the pointer does not keep the size, so sizeof in a function gives 8 (ex11).
  4. Follow-ups: "How do you keep the size?" Pass a count, a reference to the array, a std::array or a std::span. "Is &scores the same as scores?" The same address, but a different type (ex10).

Q57

L3 · Analyze Interview c-array

"scores is an int[5]. Does 2[scores] compile? If it compiles, what does it give, and why?"

Show answerHide answer to Q57

A strong answer has these parts:

  1. Main fact: yes, it compiles and gives scores[2], which is 77 for {90, 85, 77, 60, 95}. The standard defines the built-in E1[E2] as *((E1) + (E2)), and + with a pointer and an integer works in both orders.
  2. Example: with GCC 14 and Clang 19, std::cout << 2[scores]; prints 77 with no warning from -Wall -Wextra -Wpedantic (ex48).
  3. Limit: it does not work for std::array, because its operator[] is a member function. Never write it in real code; it shows only the rule.
  4. Follow-up: "Why can the index of a pointer be negative?" p[-1] is *(p - 1), which is correct when p points into an array after its first element.

Source: cppreference, Built-in subscript operator.

Q58

L4 · Senior Interview std-array

"When do you use std::array, and when do you use std::vector?"

Show answerHide answer to Q58

A strong answer has these parts:

  1. Main fact: use std::array when the compiler knows the count. Use std::vector when the count changes or comes at run time.
  2. Example: a std::array<int, 5> holds the elements in the object, with no allocation, and sizeof is 20 (ex17). A std::vector<int> keeps the elements on the heap; its object is 24 bytes with libstdc++ (ex48).
  3. Cost: a move of a std::array moves each element, but a move of a std::vector moves only three pointers. A very large std::array in a local variable can use all of the stack.
  4. Follow-ups: "Can std::array hold zero elements?" Yes, std::array<int, 0> compiles, and its size() is 0. "What does std::array add to a C array?" Value semantics, size(), at(), and no conversion to a pointer.

Source: cppreference, std::array.

Q59

L3 · Analyze Interview bounds-checking

"Why does operator[] on a std::array or std::vector not check the index? How do you find reads outside the array in a large program?"

Show answerHide answer to Q59

A strong answer has these parts:

  1. Main fact: C++ follows the rule "you do not pay for what you do not use". A check is a comparison and a branch on each access, and a loop with a known range does not need it.
  2. Example: at() checks and throws std::out_of_range (ex21). operator[] with a bad index is undefined behavior (ex23).
  3. Tools: AddressSanitizer reports stack-buffer-overflow and the line (ex23). UBSan reports a bad index on a C array (ex07). -D_GLIBCXX_ASSERTIONS adds checks to libstdc++ containers (ex24), and libc++ has hardening modes. Source: libc++, Hardening Modes.
  4. Follow-up: "Do sanitizers find all bugs?" No. They find only the paths that the tests run, so also check every index that comes from input.

Q60

L4 · Senior Interview std-string

"What is the short string optimization? How can you see it in a test program?"

Show answerHide answer to Q60

A strong answer has these parts:

  1. Main fact: a std::string object has a small buffer inside it. A short text goes into this buffer with no heap allocation. A longer text goes to the heap.
  2. Example: with libstdc++, sizeof(std::string) is 32 for every length, and an empty string has capacity() 15 (ex32). With libc++ (clang++ -stdlib=libc++), sizeof is 24 and the empty capacity() is 22 (ex32, captured/ex32.run.libcxx.txt).
  3. Test: print sizeof and the capacity() of an empty string, or compare data() with the address range of the object.
  4. Limit: the standard does not make the optimization necessary; each library chooses the size of the buffer. A move of a short string copies its characters.

Source: cppreference, std::basic_string.

Q61

L3 · Analyze Interview string-literal

"Where is a string literal in memory, and how long does it exist? What occurs when a program writes to it?"

Show answerHide answer to Q61

A strong answer has these parts:

  1. Main fact: a string literal has static storage duration: it exists for the full run of the program. The type is an array of const char, with a null character at the end (ex34).
  2. Example: a function can return const char* to a literal, and the pointer stays valid. Compilers usually put literals in a read-only memory section.
  3. Rule: a write to a literal is undefined behavior. C++11 and later do not allow char* p = "cat"; (ex38), and a write through const char* does not compile (ex37).
  4. Follow-up: "Do two equal literals have the same address?" The standard does not say. Because of this, text == "yes" with a const char* gives an unspecified result (ex40).

Source: cppreference, String literal.

Q62

L4 · Senior Interview std-string

"What does std::string full = a + b + c + d; cost when the four values are long std::string values? How can you make it faster?"

Show answerHide answer to Q62

A strong answer has these parts:

  1. Main fact: a + b + c + d groups as ((a + b) + c) + d. a + b makes a new string, with an allocation and a copy of a and b.
  2. Mechanism: from C++11, operator+ has overloads for a temporary left operand. They append to the temporary, so the next + can use its buffer. When the buffer is too small, the string allocates again and copies all characters again.
  3. Better: compute the total size, call full.reserve(total) once, then use += for each part. This gives one allocation and one copy of each character.
  4. Follow-up: "Is it always worth it?" No. For short strings, the small buffer prevents allocations. Measure before you change readable code.

Source: cppreference, operator+ (std::basic_string).
